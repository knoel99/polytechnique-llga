Exercises / Labs

  1. Reproducibility (ch. 1). Build a mini DVC pipeline (prepare → embed → eval) over 100 documents; modify a single document and predict which stages re-execute; verify. Show that a metric without the three fingerprints is not replayable.
  2. Data contracts (ch. 2). Write a Pandera schema for a FAQ set (question/answer/language/tokens) and make CI fail on: exact duplicate, empty answer, unknown language, abnormal length. Add the error report as an artifact.
  3. Significance of a gate (ch. 2). Simulate two models with losses 0.30 and 0.31 on n = 500; how many times does the "no regression" test wrongly fail over 100 draws? Deduce from it a realistic minimal margin for your CI.
  4. Serving (ch. 3). Deploy an 8B on vLLM; plot the TTFT P50/P99 and TPOT P99 curves for concurrency 1 → 256; locate the breaking point (KV occupancy); compare static batching (vary it) and continuous batching.
  5. Little's law in practice (ch. 3). From the traces of lab 4, estimate \(\lambda\), \(W\) and \(L\) over a 10 min window; verify \(L = \lambda W\) within ±10%; explain the gap (non-stationarity, preemption).
  6. Accounting (ch. 4). For a given workload (short questions, 300-token answers, 10 k req/day), quantify: API (input × in price, output × out price, prefix cache), self-hosted (proposition 4.1 with R measured in lab 4). Identify the crossover point in requests/day and its sensitivity to the utilization rate.
  7. Drift (ch. 5). Generate two weeks of simulated "logs" with a topic drift on day 9; implement PSI (prop. 5.2) and KS over the lengths and topics; tune the threshold for ≤ 1 false alert per week; document the detection delay / false alerts trade-off.
  8. RAG Ops (ch. 6). Take the RAG of the LLMs module ch. 7: move to incremental indexing (adding 20 documents at D+1 without full re-indexing); measure RAGAS before/after; trigger an embedding migration and run the index dual-boot.
  9. Versioned LoRAs (ch. 7). Train two LoRAs (r = 8, 32) on the same set; record the quintuples; serve both in multi-LoRA; evaluate; deliberately "forget" the base version and observe the silent degradation — then add the compatibility check to the registry.
  10. Observable agent (ch. 8). Instrument a search + writing agent with OTel spans; inject three failures (a tool that times out, a retry loop, a too-long context); diagnose each one only through the traces; add budgets and caps, replay.
  11. Ops audit (ch. 9). Put a mini LLM application through the sieve of the OWASP Top 10 LLM: list the findings, severity, fixes; check in particular: secrets, tool permissions, output validation, log retention.
  12. Common-thread lab (ch. 10). Assemble the assistant: hybrid RAG + reranker + LoRA + guardrails + dashboard (latency, PSI, RAGAS, cost/req, Wh/req via CodeCarbon); present a "simulated post-mortem": a faithfulness regression is injected, the team must detect it (dashboard?) and roll back (registry) in less than 15 minutes.

6. Efficient inference

At scale (millions of requests), inference dominates the total cost: it deserves its own tools. Four levers, from the simplest to the deepest.

Definition 6.1 — The memory-bandwidth wall of autoregressive inference Generating one token requires rereading all the weights (2N bytes in bf16) and the KV cache — the keys/values of past layers, to be kept for attention: $$\text{KV cache} \;=\; 2\;(\text{K and V})\times n_\mathrm{layers}\times n_\mathrm{ctx}\times d_\mathrm{model}\times 2\ \text{bytes} \;=\; 4\,n_\mathrm{layers}\,n_\mathrm{ctx}\,d_\mathrm{model}\ \text{bytes (bf16)}.$$ For 7B (32 layers, \(d = 4096\), context 2048): \(4 \times 32 \times 2048 \times 4096 \approx 1{,}1\) GB — more than some believe, and growing with the context. Peak throughput (one GPU, memory bandwidth \(B_\mathrm{mem}\)): $$\text{tokens/s} \;\lesssim\; \frac{B_\mathrm{mem}}{2N\ \text{bytes}} \qquad (\text{e.g. } 2\,\text{TB/s} \div 14\,\text{GB} \approx 140\ \text{tok/s}).$$ This ceiling — and not FLOPs — governs token-by-token generation (ch. 7, roofline); batching fills the compute units without moving the wall.

Example 6.3 — Comparing honestly: the module's protocol Any compression claim is verified in four columns: (1) quality metric (perplexity/accuracy — not "it feels better"); (2) latency at p50 and p99 (tail latency pays for cache misses); (3) throughput (aggregate tokens/s); (4) energy per request (J/request — Optimization and Responsible AI for Sustainability module, ch. 6). An improvement on three columns with the fourth constant is a result; on a single one, it is a communication angle.

7. RAG in depth

Definition 7.1 — RAG (Retrieval-Augmented Generation) $$p(y \mid q) \approx p_\theta\big(y \mid q, \mathrm{top}_k\, \mathrm{sim}(e_q, e_d)\big)$$ index documents by embeddings, retrieve those closest to the prompt, inject them into the context. Reduces hallucinations, updates knowledge, handles proprietary data without retraining.

7.1. Chunking

  • Fixed with overlap: 256-1024 tokens, stride 10-20%; structural splitting (sections, paragraphs) > blind splitting (cut sentences destroy retrieval);
  • Semantic chunking: cut where the embedding similarity between successive windows drops (topic change);
  • Multi-granularity: index by passages, but return the parent section to the LLM (small-to-big); for structured documents, keep titles/metadata in the chunk (pre-retrieval filters).

7.2. Retrieval: BM25, dense, hybrid — with numbers

RetrieverPrincipleBEIR (NDCG@10, ~18 tasks)Strengths / weaknesses
BM25probabilistic weighting (NLP ch. 2)≈ 0.44 on averagezero training, exact (lexical matches); misses reformulations
Dense (E5/BGE, …)SBERT embeddings + ANN (FAISS/HNSW)≈ 0.50-0.52 for the bestcaptures paraphrase; errors on jargon/exact refs, must be indexed
Hybrid + rerankerfusion (RRF) then cross-encoder≈ 0.53-0.55practical state of the art; reranking cost O(top-100)
Cross-encoder rerankers The bi-encoder scores \(s(q,d)=\cos(e_q,e_d)\) separately (indexable); the cross-encoder scores \(s(q,d)=f_\theta([q\,;d])\) jointly — it sees the exact term interaction (mini-attention) but must run on every candidate; hence the cascade architecture: dense/BM25 (top-100) → cross-encoder (top-5). Typical gain: +3 to +5 points of NDCG@10. The "lost in the middle" effect (Liu et al., 2023): even with the right passages, the LLM exploits better those at the beginning/end of the context → reorder the best ones at the extremes.

7.3. RAG evaluation

RAGAS-type metrics (Es et al., 2023)
  • Faithfulness: decompose the answer into atomic claims (by an LLM judge); faithfulness = fraction supported by the retrieved context;
  • Answer relevance: the LLM generates candidate questions from the answer — average similarity with the true question;
  • Context precision / recall: are the useful chunks there and well ranked? / does the corpus contain what was missing?
Lab protocol: QA set with reference context (golden context), compare faithfulness with/without reranking, measure the cost (tokens, latency) of each stage.

7.4. GraphRAG and variants

  • HyDE (Gao et al., 2022): generate a hypothetical answer to the question and search with its embedding — the imaginary answer is closer to the documents than the question;
  • GraphRAG: retrieval traverses a knowledge graph (entity-relation extraction by NER/RE — NLP ch. 6; communities-summaries; multi-hop queries); detailed in the Graph ML module ch. 8 — the LLGA heart; Buscaldi's work (AI-KG/CS-KG, NLP ch. 9) builds exactly such graphs from scientific corpora;
  • Structured queries: text → graph query (linearization, ch. 10.3) or SQL (text-to-SQL): the LLM writes the query, the database answers — maximal auditability.

import faiss, numpy as np

idx = faiss.IndexFlatIP(384); idx.add(enc.encode(chunks, normalize_embeddings=True))

    context = "\n".join(chunks[i] for i in I[0])

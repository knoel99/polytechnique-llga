6. Running an LLM: inference

6.1. Decoding: formulas and effects

Definition 6.1 — From greedy to nucleus At each step, logits \(z\) over \(|V|\);
  • Temperature: \(p_i = \dfrac{\exp(z_i/T)}{\sum_j \exp(z_j/T)}\) — \(T\to0\): argmax (greedy); large \(T\): uniformization;
  • Top-k: truncate to the \(k\) best logits then renormalize;
  • Top-p (nucleus): smallest set of tokens with cumulative probability \(\ge p\) (adaptive size: wide on an uncertain step, narrow on a deterministic step);
  • Repetition penalty: divide the logit of already emitted tokens (factor 1.1-1.3); min-p: threshold relative to the best token.

6.2. KV-cache: the memory arithmetic

Proposition 6.2 — Cache memory = \(\mathcal{O}(n\cdot d)\), quantified In autoregression, each new token must attend to the keys/values of the whole past — they are cached (prop. 2.4): bytes/token \(= 2\,N_{\text{layers}}\,n_{\text{KV}}\,d_{\text{head}}\times\) precision. Llama-3-8B (32 layers, 8 KV heads, 128 dim, fp16) → 128 KiB/token: 8k context ≈ 1 GB, 100k ≈ 12.8 GB, 1M ≈ 128 GB (weights excluded!). Three ways out: GQA (÷4 here), int8 cache quantization (÷2), and eviction/recomputation (sliding window). Engineering rule: context length is first a memory bandwidth problem, not a FLOPs problem — hence the next chapter.

6.3. Speculative decoding: the correction proved

Theorem 6.3 — Speculative decoding (Leviathan et al., 2023) A small model \(q\) proposes \(\gamma\) tokens; the large model \(p\) computes the \(\gamma\) distributions in a single forward; each proposal \(y\) is accepted with probability \(\min(1, p(y)/q(y))\); at the first rejection, one resamples from the normalized residual \(\mathrm{norm}\big(\max(0,\,p-q)\big)\). Then the marginal distribution of each produced token is exactly \(p\) — quality unchanged, latency divided by ~2-3 when \(q\approx p\).
For one token: acceptance contribution \(q(y)\min(1,p(y)/q(y)) = \min(q(y),p(y))\); rejection contribution: the total rejected mass equals \(\sum_x q(x)\big(1-\min(1,p(x)/q(x))\big) = \sum_x \max(0,q(x)-p(x)) = R\), and the resampled residual adds \(R\cdot\frac{\max(0,p(y)-q(y))}{R} = \max(0,p(y)-q(y))\). Total: \(\min(q,p)+\max(0,p-q)=p\). ∎

6.4. Quantization: principles and errors

  • Post-training int8: nearly lossless (batch calibration, per-channel scales); int4: the standard compromise;
  • GPTQ (Frantar et al., 2022): layer by layer, minimize \(\|Wx-\hat W x\|_2^2\) on a calibration set — column-by-column quantization with error compensation on the remaining columns (via the inverse of the Hessian \(\mathbf{H}=2\mathbf{X}\mathbf{X}^\top\));
  • AWQ (Lin et al., 2023): protect the "salient" channels (high activations) with per-channel scaling before quantization — the error is shifted toward weakly active channels;
  • Typical errors: int8 ≈ +0.0-0.1 PPL; well-calibrated int4 ≈ +0.1-0.5 PPL (often imperceptible); below 4 bits, degradation accelerates (2-3-bit quantization = research); in production, always re-validate on your benchmarks, not PPL alone.

6.5. Serving: continuous batching, PagedAttention, costs

  • Continuous batching (vLLM, Orca): schedule at the decoding step — finished sequences leave, new ones enter the same batch; throughput multiplied by ~10-20× vs static batching;
  • PagedAttention (Kwon et al., 2023): the KV-cache split into pages (like virtual memory) — no more fragmentation; sharing of common prefixes (system prompt); ~2-4× memory gain → larger batches;
  • Costs: two regimes — API (on the order of $/M tokens, steadily decreasing) vs on-prem (amortized GPU-hour: an H100 at ~3$/h serving ~2-5k tokens/s on an int4-quantized 8B → a few $/M tokens under heavy load); the real cost of an agent = repeated input tokens × history length (ch. 8); the "ML Ops" angle is deepened in the dedicated M2 module.

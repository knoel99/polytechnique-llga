1. Tokenization

Definition 1.1 — Byte-level BPE: the exact construction BPE (proved step by step in NLP ch. 1) starts here from the alphabet of 256 bytes: any Unicode string can be represented without an "unknown" symbol. Learning loop: $$\mathrm{merge}^{(k)} = \arg\max_{(a,b)}\; f(a,b),\qquad f(a,b)=\sum_{w}\mathrm{freq}(w)\,n_{(a,b)}(w),$$ where \(n_{(a,b)}(w)\) counts the occurrences of the adjacent pair \((a,b)\) in word \(w\) (counting weighted by word frequency); the merge is applied everywhere and one starts again until \(|V|\) (32k-128k). Encoding a new text replays the merges in the learned order (GPT-2/4, Llama); WordPiece (BERT) maximizes \(\frac{f(x,y)}{f(x)f(y)}\), Unigram (T5) learns a generative model by EM then segments with Viterbi (NLP ch. 1.2).
Vocabulary, compression, multilingual costs The compression rate (characters/token) depends on the vocabulary and the language: vocabularies trained on English compress English well (~4 characters/token) but degrade other languages. Orders of magnitude measured in the lab: with GPT/Llama-type tokenizers, the same French text costs typically 15 to 25% more tokens than in English; for poorly represented non-Latin scripts, the factor can reach 3× or more (each rarely seen character decomposes into bytes). Direct consequences: API cost (billed per token), context length consumed, and inequality of quality. Llama 3 raised the vocabulary to 128k tokens — a large part of the gain serves non-English languages; GPT-4o (o200k) claims up to ~1.4× to ~4× fewer tokens depending on the language compared to the previous generation. Exercise 1 measures all this on your own texts.
Special tokens and security Special tokens (<|endoftext|>, <|im_start|>, template roles) delimit turns and documents. If the decoder accepts them in user input, an attacker can inject a fake dialogue turn or prematurely terminate a document (boundary confusion) — defense: systematically re-encode input and neutralize special tokens (encode_ordinary, the allowed_special flag of tiktoken), never raw string concatenation around the prompt. This class of attacks returns in ch. 9 (prompt injections). 
import tiktoken
enc = tiktoken.encoding_for_model("gpt-4o")
okapi = tiktoken.encoding_for_model("gpt-3.5-turbo")   # cl100k vocabulary

fr = "Les graphes pour les LLMs : une révolution pour la recherche d'information."
de = "Donaudampfschifffahrtsgesellschaftskapitän"
for s in (fr, de, "1234 + 5678 = ?"):
    print(len(okapi.encode(s)), "vs", len(enc.encode(s)), "->", s[:40])

# "safe" tokenization: special tokens are NOT decoded by default
b = enc.encode("fin <|endoftext|> suite", allowed_special=set())
print("ids :", b, "| decode round-trip ok :", enc.decode(b))
Why it matters (M1 recall) Tokenization governs cost (length in tokens), biases (fuzzy arithmetic because "123 + 456" tokenizes poorly), multilinguality (the extra cost measured above) and real vulnerabilities (special tokens). Systematic diagnosis in the lab with tiktoken / tokenizers. For adapting an LLM to a low-resource language — vocabulary, template, data — ch. 10 presents the instructor's work (Atlas-Chat, Nile-Chat).

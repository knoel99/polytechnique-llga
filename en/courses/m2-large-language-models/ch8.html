8. Agents, multimodality and perspectives

8.1. The ReAct loop, with a real trace

Definition 8.1 — LLM agent (ReAct, Yao et al., 2022) Perception-action loop (RL module ch. 7): Thought (reason) → Action (call a tool) → Observation (read the result) → iterate, until Final Answer. The LLM decides when and how to act; the tools bound its capabilities (exact computation, search, code).

Planning and multi-agents
  • Tree-of-Thoughts (Yao et al., 2023): search a tree of reasoning steps, evaluate the nodes with the LLM, backtrack — beyond the linear chain (CoT);
  • Multi-agents: orchestrate a DAG of specialized agents (planner → retriever/coder → verifier → synthesis), LangGraph-type frameworks; each agent = an LLM with its own prompt/tools/memory; patterns: supervisor, debate, generator-critic. RL link ch. 7: policy decomposition; Graph ML link: orchestration is an executed graph;
  • Memory: scratchpad (the current context), vector memory (RAG over past exchanges), episodic memory (structured session summaries), external working memory (files) — it is the ch. 7 RAG reused on oneself.
Evaluating (and billing) an agent Benchmarks: GAIA (generalist assistant), SWE-bench (real GitHub tickets), WebArena/tau-bench (tools and dialogues). Metrics: end-to-end success rate, token cost per task (a multi-turn agent easily consumes 10⁵-10⁶ tokens — hence the importance of ch. 6: a small model for routine steps, a large one for decisions), safety (rate of injections suffered — ch. 9). Agent evaluation is an open research topic — and a major career path of the master.

8.2. Multimodality: how an image enters a context

  • Vision: a ViT encoder cuts the image into 16×16 patches → one token per patch (Deep Learning module ch. 5 for ViT); a projector (MLP or Q-Former) aligns these tokens onto the LLM's embedding space → the image becomes "text" inside the context (LLaVA scheme); the encoder is often pre-trained contrastively image-text — the common latent space recalls CLIP (Multimodal GenAI module ch. 5);
  • Audio: mel spectrograms → encoder (Whisper-style) → tokens; the "transcription + style" output feeds the LLM (voice assistant = encoder → LLM → synthesis pipeline);
  • Video: sampled images (1-4/s) + temporal pooling — very high token cost: the sampling step choice is a compression choice;
  • Documents: pages = images + interleaved OCR text (the number 1 enterprise use case — contracts, reports).

8.3. Perspectives

  • Alternative architectures: attention+SSM hybrids (ch. 2), xLSTM, latent transformers (deraising diffusion LMs — cf. ch. 10); the transformer does not have a monopoly;
  • Small Language Models & distillation: the quality/cost/latency trade-off governs enterprise deployment (ch. 6);
  • Open research: reasoning (ch. 5), long-term memory, LLMs on graphs (linearization vs structured embeddings — ch. 10.3 and the Graph ML/Advanced GNN modules), evaluation (ch. 9).
Final lab Build a documentation-assistant: technical corpus → RAG pipeline (chunks, embeddings, reranking); measure faithfulness (verifiable citations) for vector RAG versus a GraphRAG version; cost report (tokens, latency). Extension: an agentic version (ch. 8) that chooses between vector retrieval and a graph query depending on the question type.

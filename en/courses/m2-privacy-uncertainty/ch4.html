4. Local versus global, and DP-SGD

Definition 4.1 — Trust model: global (curator) vs local Global (centralized) DP: a trusted curator holds the raw data and randomizes the outputs. Better utility; single target (losing the database = catastrophe). Local DP: each individual randomizes their own data before sending — the server never sees the truth; no third party to trust; price: much more noise (typically an extra error of order \(1/\sqrt n\)). Deployment: telemetry (Apple, Google; cf. Emerging ML module ch. 3 for the link with federated learning).
Proposition 4.2 — Warner's randomized response (1965), the local prototype Sensitive question "\(X \in \{0,1\}\)"; the client answers the truth with probability \(p\), the opposite with \(1 - p\). The channel is \(\varepsilon\)-DP with $$e^{\varepsilon} = \frac{p}{1-p} \qquad \text{(e.g. } p = 0.75 \Leftrightarrow \varepsilon = \ln 3 \approx 1.1).$$
Transition matrix \(T = \begin{pmatrix} p & 1-p \\ 1-p & p \end{pmatrix}\); for any response \(y\), \(\frac{\mathbb{P}(y \mid X{=}1)}{\mathbb{P}(y \mid X{=}0)}\) equals \(p/(1-p)\) or \((1-p)/p\) depending on \(y\), whose maximum is \(p/(1-p) = e^\varepsilon\). ∎
Estimation and cost, computed. With \(\pi\) the true proportion and \(\hat p_n\) the proportion of 1 responses: \(\pi = \frac{\hat{\mathbb{E}}[Y] - (1-p)}{2p-1}\) (debiasing), and the variance of the estimator is inflated by \((2p-1)^{-2}\): at \(p = 0.75\), a factor of \(4\) — one needs four times as many users for the same precision as in the clear. RAPPOR (Google Chrome): per-bit randomized response on a Bloom register + cohorts — the same arithmetic, at scale.
Definition 4.3 — DP-SGD (Abadi et al., 2016), summary At every step: (1) draw a mini-batch \(B\) (sampling rate \(\gamma = |B|/n\)); (2) clip each individual gradient \(\tilde g_i = g_i / \max(1, \|g_i\|_2 / C)\) — bounds the sensitivity at \(C\); (3) aggregate and add noise: \(\tilde g = \frac{1}{|B|}\Big( \sum_{i \in B} \tilde g_i + \mathcal N(0, \sigma^2 C^2 I) \Big)\); (4) standard SGD step. The final budget combines RDP composition (ch. 3) and amplification by subsampling — each step sees only a fraction \(\gamma\) of the individuals: the RDP bound of a step noised with variance \(\sigma^2 C^2\) is roughly reduced by a factor \(\gamma^2\) (regime \(\gamma \varepsilon_{\text{step}} \lesssim 1\)), exact computation in Wang, Balle, Kasiviswanathan (2019). The "moments accountant" of Abadi et al. is the ancestor of this computation; implementations: Opacus (PyTorch), TensorFlow Privacy. Typical settings: \(\sigma \in [0.5; 1.5]\), \(C\) set to the median of the gradient norms, \(\varepsilon_{\text{final}} \in [1; 10]\) for modestly sized models — LLMs with 10¹¹ parameters remain an open frontier (ch. 11). 
import torch, torch.nn as nn
from opacus import PrivacyEngine

model = nn.Linear(32, 2)
loader = torch.utils.data.DataLoader(train_ds, batch_size=256)
opt = torch.optim.SGD(model.parameters(), lr=0.05)

privacy_engine = PrivacyEngine()
model, opt, loader = privacy_engine.make_private_with_epsilon(
    module=model, optimizer=opt, data_loader=loader,
    target_epsilon=3.0,          # targeted (epsilon, delta=1e-5) budget
    target_delta=1e-5, epochs=20,
    max_grad_norm=1.0,           # C: per-example clipping
)
# Ordinary training loop; at each step:
#   grad_i clipped to C, noise N(0, sigma^2 C^2), sigma set by the
#   RDP accountant + amplification by subsampling.
for epoch in range(20):
    for x, y in loader:
        opt.zero_grad()
        loss = nn.functional.cross_entropy(model(x), y)
        loss.backward(); opt.step()
print(privacy_engine.get_epsilon(delta=1e-5))   # epsilon actually spent
What DP-SGD does not solve Utility drops with the dimension of the model (the noise is isotropic while gradients live in privileged directions); tuning \(C\) is an art; rare features (a unique user!) weigh heavily after clipping; and DP protects the data, not the outputs (an incorrectly calibrated model can be private and misleading — that is the job of the UQ part).

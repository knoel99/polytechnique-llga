0. Review: convolution, CNNs, boxes

L3 review — what is assumed known
  • Digital image: an \(H \times W\) grid of pixels with \(C\) channels (3 in RGB), a tensor \(x \in \mathbb{R}^{C \times H \times W}\); grayscale, resolution, sampling (cf. Signal Processing module, chapter 2).
  • 2D convolution: \((I * k)(u, v) = \sum_{i,j} I(u-i, v-j)\,k(i, j)\); properties (commutativity, association with the product), Sobel / low-pass counterparts, correlation vs convolution (cf. Signal Processing module, chapter 3).
  • Convolutional networks: receptive fields, weight sharing, pooling, the ResNet architecture (residual connections) — cf. Deep Learning module, chapter 4; attention and transformers — cf. Deep Learning module, chapter 6.
  • Supervised learning: gradient descent, SGD/Adam, overfitting, regularization, transfer learning and fine-tuning — cf. Deep Learning module, chapters 3 and 8; cross-validation, ROC curves — cf. the Machine Learning module.

The P1 course "Image Analysis and Computer Vision" (CSC_51073_EP) laid the foundations: filtering, local features, projective geometry, reconstruction. The present module takes the systems and applications orientation: we build the complete pipeline of a vision product — from annotated data to a model deployed on constrained hardware — and study the building blocks industry actually uses (detectors, segmenters, trackers, 3D sensors, inference runtimes).

Definition 0.1 — Bounding box and IoU A bounding box is an axis-aligned rectangle \(b = (x_1, y_1, x_2, y_2)\) with \(x_1 < x_2\), \(y_1 < y_2\), encoding the top-left and bottom-right corners. For two boxes \(a\) and \(b\), let \(A(a)\) denote the area of the rectangle. The intersection-over-union is $$\mathrm{IoU}(a, b) \;=\; \frac{|a \cap b|}{|a \cup b|} \;=\; \frac{|a \cap b|}{A(a) + A(b) - |a \cap b|},$$ where \(|\cdot|\) denotes area. The intersection box has corners \((\max(x_1^a, x_1^b), \max(y_1^a, y_1^b))\) and \((\min(x_2^a, x_2^b), \min(y_2^a, y_2^b))\) if these coordinates are consistent, otherwise the intersection is empty and \(\mathrm{IoU} = 0\).
Proposition 0.2 — Properties of IoU For all axis-aligned boxes \(a, b\): (i) \(\mathrm{IoU}(a,b) \in [0, 1]\); (ii) \(\mathrm{IoU}(a,b) = \mathrm{IoU}(b,a)\); (iii) \(\mathrm{IoU}(a,b) = 1\) if and only if \(a = b\) (up to equality of pixel sets); (iv) \(\mathrm{IoU}(a,b) = 0\) if and only if the interiors of the two rectangles are disjoint.
(i) The intersection area is a rectangle area, positive and bounded by each of the areas, so \(0 \leq |a \cap b| \leq \min(A(a), A(b)) \leq |a \cup b|\). (ii) The intersection and union operations are symmetric. (iii) If \(\mathrm{IoU} = 1\) then \(|a \cap b| = |a \cup b|\), so \(|a \setminus b| = |b \setminus a| = 0\) and the rectangles coincide; the converse is immediate. (iv) If the intersection is empty, the numerator is zero; conversely a non-empty intersection rectangle has strictly positive area, hence \(\mathrm{IoU} > 0\). ∎
Example 0.3 — An IoU computation Let the ground truth be \(g = (0, 0, 10, 10)\) (area 100) and the prediction \(p = (5, 5, 15, 15)\) (area 100). The intersection is the square \((5,5,10,10)\) of area 25, the union equals \(100 + 100 - 25 = 175\), so \(\mathrm{IoU}(g, p) = 25/175 \approx 0.143\): the prediction is rejected at the usual threshold \(\tau = 0.5\). A prediction shifted by only 2 pixels, \(p' = (2, 2, 12, 12)\), gives an intersection of 64 and a union of 136, i.e. \(\mathrm{IoU} \approx 0.47\) — still below the threshold: on small objects the metric is unforgiving, which will justify the multiple thresholds of chapter 2.

1. Object detection: the two paradigms

Definition 1.1 — The detection task Given an image \(x\), produce a set \(\{(b_i, c_i, s_i)\}_{i=1}^{N}\) where \(b_i\) is a bounding box, \(c_i\) a class among \(K\) classes and \(s_i \in [0,1]\) a confidence score. Unlike classification (cf. Deep Learning module, chapter 1), the output has variable cardinality: the number of objects is unknown and depends on the image content.

1.1. The two-stage family: propose then refine

Two-stage detectors separate the generation of candidates from their classification:

  • R-CNN (2014): ~2000 candidate regions extracted by cluster-based segmentation (selective search), each crop goes through a CNN; slow (tens of seconds per image), but the proof of concept of the CNN in detection;
  • Fast R-CNN (2015): the whole image passes through the CNN once, candidates are projected into the feature space (RoI pooling); only a light classifier is applied per candidate;
  • Faster R-CNN (2015): candidates are produced by an integrated, end-to-end learned Region Proposal Network (RPN) — the canonical scheme;
  • FPN (2017): feature pyramid; small objects are detected on the high-resolution maps, large ones on the low-resolution maps.
Definition 1.2 — Anchors For each cell of a feature map, the RPN predicts offsets with respect to a fixed set of \(A\) reference rectangles — the anchors — produced by the Cartesian product of \(S\) scales and \(R\) aspect ratios (typically \(S = 5\), \(R = 3\), hence \(A = 15\) anchors per position). The box regression encodes $$t_x = \frac{x - x_a}{w_a}, \quad t_y = \frac{y - y_a}{h_a}, \quad t_w = \log\frac{w}{w_a}, \quad t_h = \log\frac{h}{h_a},$$ where \((x_a, y_a, w_a, h_a)\) are the center and size of the anchor.
Proposition 1.3 — Why the logarithm for sizes The logarithmic parameterization makes the regression scale invariant: the same offset \(t_w\) corresponds to the same size ratio. An error \(|t_w| = \varepsilon\) means \(w = w_a e^{\pm\varepsilon}\), i.e. a constant relative error rate; with a linear parameterization, the same absolute error would be negligible for a truck (600 px) and fatal for a distant pedestrian (10 px).
With \(t_w = \log(w / w_a)\), we have \(w = w_a e^{t_w}\), so the relative error equals \(|e^{t_w} - 1| \approx |t_w|\) at first order — independent of \(w_a\). With a direct parameterization \(\tilde t_w = w - w_a\), the relative error \(|\tilde t_w| / w_a\) depends on \(w_a\); fixing a homogeneous noise scale for all object sizes would require weighting by size class, and the loss would be dominated by large objects. ∎

1.2. The single-stage family: everything in one pass

Single-stage detectors directly predict boxes and classes over a dense grid, in a single pass:

  • YOLO (2015): the image is cut into a \(7 \times 7\) grid; each cell predicts 2 boxes + class probabilities; remarkable speed (45 images/s at the time), at the cost of coarser localization;
  • SSD (2016): multi-scale predictions via feature maps of decreasing resolutions, anchors per cell;
  • RetinaNet (2017): introduced the focal loss to correct the foreground/background imbalance (hundreds of thousands of easy anchors against a few objects), reconciling single-stage and two-stage accuracy.
Definition 1.4 — Focal loss For per-anchor binary classification with logit \(z\), predicted probability \(p = \sigma(z)\) and label \(y \in \{0, 1\}\): $$\mathrm{FL}(p) \;=\; -\alpha\,(1 - p_t)^{\gamma}\,\log(p_t), \qquad p_t = y\,p + (1 - y)(1 - p),$$ with balancing factor \(\alpha \in [0,1]\) and focusing \(\gamma > 0\) (typically \(\gamma = 2\)). When \(\gamma = 0\) and \(\alpha = 0.5\), one recovers cross-entropy.

The effect of the factor \((1 - p_t)^{\gamma}\) is to divide the contribution of easy examples: a background anchor classified at \(p_t = 0.9\) has its loss reduced by a factor \(0.1^2 = 0.01\); the rare hard examples (small \(p_t\)) keep an almost intact gradient. The gradient becomes \(\frac{\partial \mathrm{FL}}{\partial z} = -\alpha\,(1-p_t)^{\gamma}\big(\gamma\, p_t \log p_t + 1 - p_t\big)\,\frac{\partial p_t}{\partial z}\): the magnitude concentrates on the decision boundary.

1.3. Non-maximum suppression (NMS)

Dense detectors emit many redundant boxes around the same object. NMS keeps the highest-scoring box and removes the ones that overlap it too much:

  1. sort the \(N\) detections by decreasing score;
  2. take the first box \(b\), add it to the kept ones;
  3. remove every box \(b'\) such that \(\mathrm{IoU}(b, b') > \tau\) (typically \(\tau = 0.5\));
  4. resume at step 2 with the remaining boxes, until exhaustion.
import numpy as np

def nms(boxes, scores, tau=0.5):
    """boxes: (N,4) [x1,y1,x2,y2]; scores: (N,); returns the kept indices."""
    x1, y1, x2, y2 = boxes[:, 0], boxes[:, 1], boxes[:, 2], boxes[:, 3]
    areas = np.maximum(0, x2 - x1) * np.maximum(0, y2 - y1)
    order = scores.argsort()[::-1]          # sort by decreasing score
    keep = []
    while order.size > 0:
        i = order[0]
        keep.append(i)
        xx1 = np.maximum(x1[i], x1[order[1:]])
        yy1 = np.maximum(y1[i], y1[order[1:]])
        xx2 = np.minimum(x2[i], x2[order[1:]])
        yy2 = np.minimum(y2[i], y2[order[1:]])
        inter = np.maximum(0, xx2 - xx1) * np.maximum(0, yy2 - yy1)
        iou = inter / (areas[i] + areas[order[1:]] - inter)
        order = order[1:][iou <= tau]       # remove the overlapping ones
    return np.array(keep)
Note — Limits of greedy NMS NMS is greedy: worst-case \(O(N^2)\), it can remove a true detection that overlaps a distinct object (two people touching, aligned train cars). Soft-NMS (Bodla et al., 2017) replaces the binary removal with a score decay \(s_i \mapsto s_i \cdot f(\mathrm{IoU})\) — linear or Gaussian — giving overlapping boxes a second chance; per-class NMS must be applied class by class, except in "class-agnostic" variants. The set-prediction detectors of chapter 2 replace NMS with a global, differentiable matching.

2. Evaluation (mAP) and modern detectors

2.1. Precision, recall and AP — computed on an example

Definition 2.1 — Precision, recall, AP and mAP For a given class, a detection is a true positive (TP) if \(\mathrm{IoU}(\text{prediction}, \text{ground truth}) \geq \tau\) (and if that ground truth is not already matched); otherwise it is a false positive (FP); an undetected ground truth is a false negative (FN). Then $$\text{precision} = \frac{TP}{TP + FP}, \qquad \text{recall} = \frac{TP}{TP + FN} = \frac{TP}{|\text{ground truths}|}.$$ The average precision (AP) is the area under the precision-recall curve obtained by sweeping the score threshold; the COCO mAP averages the APs over 80 classes and over 10 IoU thresholds \(\tau \in \{0.5,\, 0.55,\, \dots,\, 0.95\}\) — denoted \(\mathrm{mAP}@[0.5{:}0.95]\).
Example 2.2 — AP of one class by hand One class ("cat") with 3 ground truths and 5 detections sorted by decreasing score, evaluated at threshold \(\tau = 0.5\):

With "all-points" interpolation (precision clipped by the maximum to the right), the retained points are \((0.33; 1.00)\), \((0.67; 0.67)\) and \((1.00; 0.60)\), hence $$\mathrm{AP} \approx 0.33 \times 1.00 + 0.34 \times 0.67 + 0.33 \times 0.60 \approx 0.75.$$ The AP rewards both the ranking of the scores (an FP at high score is costly) and completeness; this is why it is more informative than a simple accuracy at a fixed threshold.
Note — Why multiple thresholds At \(\tau = 0.5\), a detector can be right "loosely": averaging over \([0.5{:}0.95]\) penalizes mediocre localizations. COCO also publishes \(\mathrm{mAP}_S, \mathrm{mAP}_M, \mathrm{mAP}_L\) by object size — a "globally" good industrial model can be very poor on small objects, a crucial point for video surveillance or microscopy.

2.2. Without anchors: anchor-free detectors

Anchors impose an arbitrary grid of hypotheses. Anchor-free detectors directly predict, per pixel of the feature map: (i) a probability of being an object center (centerness / center heatmap, cf. FCOS and CenterNet) and (ii) regressions of the distances to the four edges. The decoding becomes: $$b = (x_c - l, \; y_c - t, \; x_c + r, \; y_c + b'),$$ where \((x_c, y_c)\) is the position of the central pixel and \(l, t, r, b'\) the regressed distances — all of it without any reference box. Benefits: fewer hyperparameters (scales/ratios), no anchor/object imbalance, better on atypical shapes; cost: an NMS is still needed, and the center-to-ground-truth assignment requires zone rules (assignment by feature zone).

2.3. Detection as set prediction: DETR

Definition 2.3 — DETR (DEtection TRansformer) DETR treats detection as a set prediction problem: a CNN extracts features, a transformer encoder-decoder (cf. Deep Learning module, chapter 6) produces \(N\) object queries decoded into \(N\) (box, class) pairs; training matches predictions and ground truths by minimum-cost bipartite coupling (Hungarian algorithm): $$\hat\sigma = \arg\min_{\sigma \in \mathfrak{S}_N} \sum_{i=1}^{N} \Big( \mathcal{L}_{\mathrm{box}}(b_i, g_{\sigma(i)}) + \mathcal{L}_{\mathrm{cls}}(c_i, y_{\sigma(i)}) \Big),$$ then applies a "set prediction"-type loss (Hungarian loss) on the optimal matching. Since the output is a learned set without redundancy, DETR removes NMS and anchors.
Note — Why DETR converges slowly, and the fix Global attention struggles to precisely localize small boxes (attention spreads over the whole image): DETR needed ~500 epochs. Deformable DETR replaces dense attention with deformable attention that samples only a small set of relevant points per query, speeding up convergence by an order of magnitude. The Hungarian matching is a minimum-cost assignment coupling — exactly the discrete transport seen in the Computational Optimal Transport module, chapters 1–2 (there solved by the Hungarian method rather than by Sinkhorn).

3.2. Semantic segmentation: from FCN to U-Net and DeepLab

  • FCN (2015): fully convolutional classification — the fully-connected layers become 1×1 convolutions, and upsampling (transposed) layers restore the resolution; dense output, end-to-end training;
  • U-Net (2015): symmetric encoder-decoder with skip connections that reinject the encoder's high-resolution details into the decoder; designed for medical imaging with few annotated images, and still the domain's reference;
  • DeepLab (v1→v3+): dilated (atrous) convolutions: a \(3 \times 3\) kernel with dilation \(d\) sees a neighborhood of size \(2d+1\), enlarging the receptive field without losing resolution; the ASPP module (Atrous Spatial Pyramid Pooling) combines several dilations in parallel to capture several scales; v3+ adds a light decoder.
Example 3.1 — Dice and IoU of masks For a predicted binary mask \(p\) and a ground truth \(g\) (sets of pixels), the IoU is \(|p \cap g| / |p \cup g|\) and the Dice \(2|p \cap g| / (|p| + |g|)\). With \(|p| = 1200\), \(|g| = 1000\) and \(|p \cap g| = 900\): IoU \(= 900/1300 \approx 0.69\) and Dice \(= 1800/2200 \approx 0.82\). One checks the identity \(\mathrm{Dice} = 2\,\mathrm{IoU} / (1 + \mathrm{IoU})\): \(2 \times 0.692 / 1.692 = 0.818\) — the two metrics are interchangeable as a ranking, but Dice looks "kinder": always specify the metric in a report.

3.3. Instance segmentation: Mask R-CNN

Mask R-CNN (2017) extends Faster R-CNN: in parallel with the classification and box-regression heads, each region of interest receives a segmentation head that predicts a \(28 \times 28\) binary mask (per class). The decisive detail is RoI Align: the original RoI pooling quantized the cell coordinates (rounding), shifting the features by a few tenths of a pixel — negligible for classification, disastrous for aligning a mask. RoI Align samples by bilinear interpolation at the real coordinates, without rounding: ~2 mask AP points gained from a mere numerical-precision fix — a fine engineering lesson.

3.4. Panoptic: a single metric

Definition 3.2 — Panoptic Quality (PQ) Predicted segments and ground truths are matched per class with \(\mathrm{IoU} > 0.5\) (at-most-one-to-one coupling). With TP the set of matches, FP the unmatched predictions and FN the unmatched ground truths: $$\mathrm{PQ} \;=\; \underbrace{\frac{1}{|\mathrm{TP}|}\sum_{(p,g) \in \mathrm{TP}} \mathrm{IoU}(p, g)}_{\text{segmentation quality (SQ)}} \;\times\; \underbrace{\frac{|\mathrm{TP}|}{|\mathrm{TP}| + \tfrac12|\mathrm{FP}| + \tfrac12|\mathrm{FN}|}}_{\text{recognition quality (RQ = F1 score)}},$$ then averaged over the classes. PQ cleanly decouples "are the boundaries right?" (SQ) and "did I find the right objects?" (RQ).

3.5. SAM: promptable segmentation

The Segment Anything Model (Meta, 2023) changes paradigm: instead of training a model per task, SAM learns a general task — produce a valid mask for any prompt (point, box, coarse mask, text to come):

  • architecture: a heavy image encoder (ViT, cf. Advanced Deep Learning module (P2), chapter 1) computed once per image; a light prompt encoder; a light mask decoder, re-runnable in real time (~50 ms) for every prompt — the expensive-once / light-many-times separation is the "interactive" deployment pattern;
  • data engine: an assisted-annotation loop (model suggests, human corrects) at first, then semi-automatic then automatic annotation — culminating in SA-1B: 11 million licensed images, 1.1 billion masks, 99 % automatic;
  • usage: zero-shot mask extraction, serving as a base for fine-tuning (medical, satellite), or as an annotation assistant — SAM closes the loop there: the model manufactures its own data.

4. Multi-object tracking

Definition 4.1 — Multi-object tracking (MOT) Given a video stream, associate across frames the detections of the same physical object under a stable track identifier, while managing appearances, disappearances, occlusions and crossings. The dominant paradigm is tracking-by-detection: a detector (chapters 1–2) runs at every frame; the tracker reduces to the association problem between current detections and existing tracks.

4.1. SORT: Kalman + Hungarian matching

SORT (2016) is the minimal tracker:

  1. each track carries a constant-velocity Kalman filter (state \([x, y, s, \dot x, \dot y, \dot s]\); the Kalman filter is recalled below);
  2. prediction: the boxes are extrapolated to the current frame;
  3. association: solve the bipartite coupling between predictions and detections with cost \(1 - \mathrm{IoU}\) (Hungarian algorithm);
  4. the formed pairs update the filters (correction); tracks left unmatched for \(T_{\text{max}}\) consecutive frames are destroyed; orphan detections create new tracks.
Reminder — the Kalman filter in two equations
Linear-Gaussian state model \(x_t = F x_{t-1} + w\), observation model \(z_t = H x_t + v\), white noises with covariances \(Q, R\): $$\hat x_{t|t-1} = F \hat x_{t-1|t-1}, \quad P_{t|t-1} = F P_{t-1|t-1} F^\top + Q \quad (\text{prediction}),$$ $$K_t = P_{t|t-1} H^\top (H P_{t|t-1} H^\top + R)^{-1}, \quad \hat x_{t|t} = \hat x_{t|t-1} + K_t (z_t - H \hat x_{t|t-1}) \quad (\text{correction}).$$ The gain \(K_t\) weighs the prediction (motion) and the observation (detection) according to their uncertainties — cf. the Signal Processing module for the Bayesian interpretation.

4.2. DeepSORT: adding appearance

In a crowd, two pedestrians who cross paths swap their boxes: IoU alone re-associates poorly. DeepSORT (2017) associates in two stages: (i) cascade matching favoring recently seen tracks, with a cost combining IoU and an appearance embedding distance — a small ReID (re-identification) network learns a descriptor \(e_i \in \mathbb{R}^{128}\) invariant to pose/scale; (ii) IoU matching (as in SORT) for the rest. The "appearance memory" (a gallery of the last descriptors per track) resists long occlusions.

4.3. ByteTrack: don't throw away low-score detections

ByteTrack (2022) starts from a simple observation: during a partial occlusion, the detector often emits a correct but low-confidence detection — which classical pipelines discard at the threshold. The algorithm sketch:

  1. split the detections into high score (\(\geq \tau_{\mathrm{high}}\), e.g. 0.5) and low score (\(\tau_{\mathrm{low}} \leq s < \tau_{\mathrm{high}}\));
  2. first matching: active tracks vs high-score detections, Hungarian coupling on a combined distance (IoU + appearance);
  3. second matching: tracks still orphaned vs low-score detections, coupling on IoU alone — the low-confidence boxes "carry" the track through the occlusion;
  4. tracks still orphaned are put on hold then destroyed; orphan high-score detections create tracks (never the low-score ones).

Result: notable MOTA/IDF1 gains without any new detector — association is a lever as profitable as perception.

4.4. Measuring a tracker

Definition 4.2 — MOTA and IDF1 $$\mathrm{MOTA} = 1 - \frac{|\mathrm{FN}| + |\mathrm{FP}| + |\mathrm{ID\ switches}|} {\sum_t |\text{ground truths}_t|}, \qquad \mathrm{IDF1} = \frac{2\,\mathrm{IDTP}}{2\,\mathrm{IDTP} + \mathrm{IDFP} + \mathrm{IDFN}},$$ where ID switches count identity flips (a tracker that "swaps" two people loses IDF1 even if its MOTA is good). MOTA mostly measures detection; IDF1 mostly measures identity; HOTA (2020) rebalances detection and association.
Note — In production Tracking imposes strong system constraints: per-frame latency (the tracker must fit in the budget, cf. chapter 8); robustness to detector dropouts (a missed frame); re-identification after leaving the field of view; and, in multi-camera settings, cross-camera association (pure ReID, with no IoU available). The two key building blocks — Hungarian coupling and the Kalman filter — are L3 classics; the modernity lies in the learned descriptors.

5. Applied 3D vision: stereo and LiDAR

5.1. The pinhole model (reminder)

L3 reminder — perspective projection
A pinhole camera projects a 3D point \(X = (X, Y, Z)\) (camera frame, \(Z\) pointing forward) to \((u, v)\) in the image: $$\lambda \begin{pmatrix} u \\ v \\ 1 \end{pmatrix} = K \,[\,R \mid t\,] \begin{pmatrix} X \\ Y \\ Z \\ 1 \end{pmatrix}, \qquad K = \begin{pmatrix} f_x & 0 & c_x \\ 0 & f_y & c_y \\ 0 & 0 & 1 \end{pmatrix},$$ with \(K\) the intrinsics (focal lengths in pixels, optical center), \([R|t]\) the extrinsics (camera pose); \(\lambda = Z\). Calibration (OpenCV) estimates \(K\) and the distortion (radial-tangential model) — cf. the P1 course for the complete geometry (Hartley & Zisserman).

5.2. Stereo: disparity as a depth measurement

Definition 5.1 — Disparity For a rectified stereo pair (coplanar images, horizontal epipolar lines, common focal length \(f\), baseline \(B\)), a 3D point projects to \((u_L, v)\) on the left and \((u_R, v)\) on the right; the disparity is \(d = u_L - u_R \geq 0\), measured in pixels.
Proposition 5.2 — Depth from disparity In the rectified setting, the depth of the point is $$Z = \frac{f \, B}{d}.$$
The 3D point \((X, Y, Z)\) projects on the left to \(u_L = fX/Z\) and on the right (optical center shifted by \(B\) along \(x\)) to \(u_R = f(X - B)/Z\). Taking the difference, \(u_L - u_R = fB/Z\), i.e. \(d = fB / Z\) and hence \(Z = fB / d\). ∎
Practical consequence: the depth uncertainty \(\partial Z / \partial d = -fB/d^2 = -Z^2/(fB)\) grows quadratically with distance — stereo is precise up close, coarse far away; increasing \(B\) or \(f\) improves range at the price of the visible field and harder matchings.

The classical stereo pipeline: (i) rectification; (ii) cost volume — for every left pixel and every candidate disparity \(d\), a matching cost (census, SSD of descriptors) — this is an \(H \times W \times D_{\max}\) volume; (iii) aggregation and regularization: SGM (Hirschmüller, 2008) aggregates costs along several directions (per-path dynamic programming) with discontinuity penalties — the industrial standard (baked into GPUs!); (iv) disparity map. Deep methods (PSM-Net and successors) learn the cost volume: 3D convolutions on descriptors stacked by disparity — exactly the same volume construction that the Multimodal GenAI module, chapter 3, exploits for other data.

5.3. LiDAR: point clouds

LiDAR emits pulses and measures time of flight: the output is a 3D point cloud (\(x, y, z\), reflectivity), ~100k–2M points/s, accurate in distance (~2 cm), sparse and irregular — unstructured: grid convolutions do not apply directly. Families of methods:

  • PointNet (2017): per point, a shared MLP; aggregation by global max; then an MLP. Permutation invariance comes from the max: the global descriptor does not depend on the order of the points — cf. the proposition below;
  • Voxels / pillars: discretize space (VoxelNet) or only the ground plane (PointPillars: vertical columns), aggregate the point features there, then run a 2D/3D CNN on the resulting grid;
  • Center detection: CenterPoint projects everything into bird's eye view (BEV) and detects objects by their center (heatmap + size/rotation regression) — the anchor-free formulation of chapter 2, transposed to a 2D "top-down view".
Proposition 5.3 — The global max is permutation invariant Let \(h(X) = \mathrm{max}_{i=1..n} \mathrm{MLP}(x_i)\) be PointNet's global descriptor. For every permutation \(\pi\) of \(\{1, \dots, n\}\): \(h(x_{\pi(1)}, \dots, x_{\pi(n)}) = h(x_1, \dots, x_n)\).
The MLP is applied pointwise: the set \(\{\mathrm{MLP}(x_i)\}\) is unchanged by permutation (only the enumeration order changes). The per-coordinate maximum of a set does not depend on the enumeration order, hence the equality. Note that a sum or an average would have the same property; the max is preferred because it selects one "witness" per coordinate and avoids the information smoothing of averages. ∎

5.4. Multi-sensor fusion in bird's eye view

Cameras provide semantics (classes, traffic lights, signs) but only indirect depth; LiDAR provides geometry but poor semantics. Modern architectures fuse in BEV: every sensor is brought into a common top-down frame where detection, tracking and trajectory prediction combine. BEVFormer (2022): image features are "queried" in BEV space by spatial cross-attention (every BEV cell queries the pixels along its view pillar), with temporal attention toward the previous BEV map — tracking becomes implicit. 6.2. The cost of annotation

A COCO box costs from a few seconds to a minute; a polygon mask, much more; a 3D LiDAR box at 25 Hz over 20 objects, several minutes with dedicated tooling. Three industrial levers:

  • assisted annotation: a pretrained model proposes, the human corrects — the SA-1B loop of chapter 3 is its large-scale version; an additional benefit: active learning only has annotated the examples where the model is uncertain;
  • synthetic data: procedural 3D rendering with domain randomization (random textures, lighting to force invariance); the P2 module "Image Synthesis" (brochure) covers rendering; sim2real remains the hard part;
  • augmentation: geometric (cropping, rotation, mosaic) and photometric (color, blur, noise); caution: geometric transformations must transform the boxes/masks and the metadata (rotation → bounding boxes of the rotated masks).

6.3. Evaluation pitfalls

Note — The three classic pitfalls (1) Data leakage: near-duplicate images between train and test (video sequences); always split by video/scene, not by image. (2) Long-tail imbalance: the global mAP masks rare classes — look at the per-class APs; the training data must be resampled or reweighted (cf. focal loss, chapter 1). (3) Domain shift: a COCO model collapses on your production cameras (angle, compression, weather); plan from the protocol stage for a "shadow" set of unseen real data, and drift monitoring in operation (chapter 8).

7. Industrial case studies

7.1. Industrial inspection (quality control)

Inspecting parts (scratches, cracks, contamination) on a production line: controlled lighting (strobe, dark background), imposed cadence (decisions per second), and — the major specificity — very few defect examples. Hence the move to unsupervised methods: learn normality (autoencoders, feature distances; cf. Deep Learning module, chapter 7, for autoencoders) and raise an alert on deviation; the MVTec AD dataset is the reference benchmark (15 categories: screws, textiles, wood, bottles…, with pixel-level defect masks). Metrics: image-level detection (AUROC) and defect segmentation (pixel AUROC, PRO). Constraints: an error is asymmetrically costly (false rejection = yield loss; missed defect = product recall); the threshold is tuned on business cost, not on 0.5.

Example 7.1 — Tuning a threshold on costs Let an anomaly score \(s \in [0,1]\); false rejection costs €1 (manual re-inspection), missed defect costs €100 (product recall). At the operating point (FP rate \(= 4\,\%\) on healthy parts, FN rate \(= 2\,\%\) on defective parts, real defect rate 0.5 %): expected cost for 10,000 parts $$10\,000 \times \big[0.995 \times 0.04 \times 1 + 0.005 \times 0.02 \times 100\big] = 10\,000 \times (0.0398 + 0.01) \approx 498\ \text{euros}.$$ Lowering the threshold (more sensitive) increases FPs but reduces FNs: redo the computation and choose the threshold at the cost minimum — the right engineering metric is a cost, not an accuracy.

7.2. Autonomous driving

The typical perception pipeline of a SAE level 2+ to 4 vehicle:

  1. multi-camera detection/segmentation (chapters 1–3);
  2. camera/LiDAR/radar fusion in BEV (chapter 5);
  3. tracking and prediction of agents (chapter 4 + trajectory models);
  4. planning (out of scope — cf. the Reinforcement Learning module for the MDP formalization);
  5. system monitoring: redundancy, diagnostics, degraded mode.

Engineering lessons: corner cases dominate the cost (roadworks, flashing lights, overturned trailers); closed benchmarks (nuScenes) are saturated and correlate poorly with real kilometers; safety imposes latency guarantees (chapter 8) and traceability (version of the model, the dataset, the threshold).

7.3. Medical imaging

Organ/lesion segmentation (U-Net is still the backbone, chapter 3), cell counting, fracture detection. Specificities: rare and costly data (clinicians), DICOM formats (metadata, windowing), strict clinical validation, regulation (medical CE marking); the metric is per-structure Dice and inter-observer consistency is the reachable ceiling — a Dice above human agreement is suspicious; the models are assistance tools (CAD — computer-aided diagnosis), not decision makers.

7.4. Other domains (summary)

  • retail: planograms (products on shelves), customer flows (anonymous counting);
  • agriculture: weed detection for targeted spraying (drone, embedded);
  • sports: player/ball tracking (chapter 4 at scale), tactical statistics;
  • satellite: building/road detection, deforestation masks — with domain randomization and multispectral imaging as a bonus.

8. Deployment: ONNX, quantization, edge

8.1. The deployment pipeline

From notebook to product, the canonical steps:

  1. export: the trained model (PyTorch) is exported as a frozen graph — ONNX (Open Neural Network Exchange), a common format accepted by most runtimes;
  2. graph optimization: operator fusion (conv + batchnorm → single conv; conv + activation), dead-layer elimination, kernel selection;
  3. targeted compilation: TensorRT (NVIDIA), Core ML (Apple), TF Lite / LiteRT (mobile), OpenVINO (Intel) — these generate hardware-specialized engines;
  4. calibration/quantization: move to INT8 (below);
  5. measurement: P50/P99 latency, throughput, memory, energy — on the target hardware, never on the development workstation alone.

8.2. INT8 quantization

Definition 8.1 — Affine quantization scheme To a floating tensor \(x\) we associate a signed 8-bit integer via $$Q(x) = \mathrm{clip}\!\left(\mathrm{round}\!\left(\frac{x}{s}\right) + z,\; -128,\; 127\right), \qquad x \approx s\,(Q(x) - z),$$ with the scale \(s > 0\) and the zero point \(z\) chosen by calibration (min-max of the activations on a representative sample, or percentile to limit the effect of extreme values). The weights are quantized once and for all; the activations are quantized at runtime.
Note — PTQ vs QAT Post-training quantization (PTQ): fast, no retraining, sufficient for many CNNs; quantization-aware training (QAT, Jacob et al. 2018): during training the quantization is simulated with fake operations (rounding on the forward pass, exact gradients on the backward pass — straight-through estimator), so the model learns to be robust to rounding; this is the solution when PTQ degrades too much (sensitive architectures, small models). Typical benefit: memory ÷4 (FP32→INT8) and throughput ×2–4 on targets with INT8 kernels — at the price of a few tenths of a mAP point to monitor.

8.3. Compressing: pruning and distillation

  • pruning: zero out the lowest-magnitude weights (unstructured pruning — no gain without a sparse library) or whole channels (structured — actually accelerates); follow the accuracy/size curve;
  • knowledge distillation (Hinton et al., 2015): a small student imitates the output distribution of a large teacher — the loss combines the ground truth and the KL divergence with the teacher's logits "softened" by a temperature \(T\): $$\mathcal{L} = \alpha\, \mathrm{CE}(y, z_s) + (1 - \alpha)\, T^2\, \mathrm{KL}\!\big(\mathrm{softmax}(z_t / T)\,\|\,\mathrm{softmax}(z_s / T)\big)$$ (covered in detail in the Advanced Deep Learning module (P2), chapter 6).

8.4. Latency budgets and profiling

Example 8.2 — Budget of a "real-time detection" application 30 fps camera → 33.3 ms per-frame budget. Typical breakdown on an embedded module (Jetson Orin class): acquisition + decoding 3 ms; preprocessing (resizing, normalization, NV12→RGB) 4 ms; INT8 inference 18 ms; post-processing (NMS + rendering) 3 ms; margin 5 ms. Three lessons: (i) pre/post-processing is not negligible — keep it on the GPU (DALI/TensorRT-PLUGIN pipeline) if possible; (ii) target P99 latency (worst frame, with numerous detection batches), not the average; (iii) if the budget bursts, the levers in industrial order: input resolution ↓, smaller model (distillation), INT8, skip-frame + interpolation (detection at 15 Hz, tracking at 30 Hz — chapter 4 exists precisely for that).

8.5. Operations, drift and privacy

  • monitoring: log score distributions, detection rates, "world" alerts (dirty camera, night); detect domain drift and plan retraining (the data loop of chapter 6);
  • privacy: process on-device as much as possible (no image leaves the sensor); if a stream is sent: blurring/anonymization of faces and plates (…detected by… the models of chapter 3!), minimal retention;
  • versioning: model + code + data + thresholds = a reproducible artifact — the methodology of the Advanced Deep Learning module (P2), chapter 8 applies mutatis mutandis.

9. Ethics, robustness and limits

9.1. Adversarial examples

Small imperceptible perturbations change the prediction. The simplest attack — FGSM — moves the input one step in the direction of the loss gradient: $$x_{\mathrm{adv}} = x + \varepsilon\, \mathrm{sign}\!\left(\nabla_x \mathcal{L}(\theta, x, y)\right),$$ with \(\varepsilon\) on the order of 2–8/255. In detection, stickers glued to a sign can make an object disappear from the output; defenses range from adversarial training (min-max over perturbations) to bound-based certification — an overview is given in the Machine Learning module; the engineer mainly remembers: a model embedded in a product can be targeted, and robustness is tested (attack toolboxes) before deployment.

9.2. Bias and fairness of vision systems

  • representation bias: mostly North American/European datasets → performance drops in other contexts (streets, clothing, objects); the "Gender Shades" report documented accuracy gaps in detection by skin tone; in practice: break the evaluation down by subgroup (cf. Machine Learning module);
  • surveillance and biometrics: mass facial recognition is restricted/banned in several jurisdictions; the European AI regulation (AI Act, 2024) classifies remote biometric identification among high-risk or prohibited uses; anonymize before storage;
  • consent: scraped data (LAION etc.) and image rights; prefer clearly licensed datasets and document provenance (data cards).

9.3. Fundamental limits to know

Note — What models do not "understand" Compositionality: a detector can see "a person" and "a bicycle" without inferring "a person on a bicycle" — relations require other formalisms (scene graphs; cf. Graph ML module). Multimodal hallucination: captioners describe absent objects (cf. Multimodal GenAI module, chapter 8). Out of distribution: snow, night, a new sensor — the displayed confidence is not calibrated outside the training distribution. Causality: vision correlates, it does not explain — a decision system must separate perception from decision (autonomous driving, chapter 7).

Exercises

  1. IoU and thresholds. Compute the IoU between \(g = (10, 10, 40, 60)\) and \(p = (20, 5, 55, 50)\); determine the maximum offset \(\delta\) in \(x\) of a prediction identical to \(g\) to stay above \(\tau = 0.75\).
  2. NMS by hand. Five detections of the same class, scores 0.9; 0.85; 0.8; 0.75; 0.7, box 2 overlapping box 1 (IoU 0.6), box 3 overlapping box 1 (IoU 0.3) and box 4 overlapping box 3 (IoU 0.8). Give the boxes kept at \(\tau = 0.5\) then at \(\tau = 0.7\) with linear Soft-NMS (\(s \leftarrow s(1 - \mathrm{IoU})\)); comment on the "two objects stuck together" case.
  3. AP. With 4 ground truths and the sorted detections (TP, TP, FP, FP, TP, TP): draw the precision-recall curve, compute the all-points interpolated AP, then verify that moving the two FPs to the head of the list (FP, FP, TP, …) makes AP drop — why does the order of the scores matter?
  4. Focal loss. Show that for \(\gamma = 2\), an easy anchor (\(p_t = 0.95\)) receives a weight \(361\) times smaller than a hard anchor (\(p_t = 0.3\)); compute the ratio for plain cross-entropy and conclude.
  5. Hungarian coupling. Three tracks \(T_1, T_2, T_3\), three detections \(D_1, D_2, D_3\), costs \(1-\mathrm{IoU}\): \(T_1\!: (0.1,\ 0.8,\ 0.9)\), \(T_2\!: (0.9,\ 0.2,\ 0.7)\), \(T_3\!: (0.8,\ 0.9,\ 0.3)\). Solve the minimum-cost assignment by hand and compare with the greedy assignment — in which case do they differ?
  6. Stereo depth. Camera \(f = 700\) px, baseline \(B = 0.5\) m; compute the disparity of an object at 10 m, then the depth uncertainty if disparity is measured to ±0.25 px; at what distance does the uncertainty exceed 1 m?
  7. PointNet. Replace the max by an average in proposition 5.3: does the invariance hold; build two clouds with the same average but very different contents and conclude on the "selectivity" of the max.
  8. PQ. One image: 4 ground-truth segments, 3 predicted with matched IoUs 0.9; 0.8; 0.6 plus one FP; one FN. Compute SQ, RQ then PQ; redo with IoU 0.7 everywhere and comment on the decomposition.
  9. Quantization. A weight tensor has min −0.82 and max 0.55; give the scale and zero point (asymmetric 8-bit min-max scheme), quantize −0.1 and 0.3, dequantize, compute the relative error — why can a 99.9th percentile help?
  10. Real-time budget. An application must detect at 25 fps on hardware where FP32 inference takes 58 ms and INT8 21 ms; preprocessing 5 ms, post-processing 4 ms. Does a single inference per frame fit? Propose two strategies (skip-frame + tracking; resolution reduction ÷1.4 with cost in \(s^2\)) and quantify their trade-offs.
  11. Data choice. For a vehicle-counting system on a European road (day/night, rain), propose: a starting training set, a splitting protocol, an augmentation plan, a subgroup evaluation method, and two monitoring metrics in production.
  12. Project. Complete pipeline on a free set (a COCO subset or public drone images): fine-tuning of a modern YOLO, ONNX export, INT8 quantization, latency/mAP measurement before/after, then a one-page report in "industrial datasheet" format (error costs included, cf. example 7.1).

4. Defenses: adversarial training

Definition 4.1 — Adversarial training (Madry et al., 2018) One minimizes the robust risk, a min-max problem: $$ \min_{\theta}\ \mathbb{E}_{(x,y)}\Big[\ \max_{\|\delta\|_\infty \leq \varepsilon} \ell\big(f_\theta(x + \delta),\, y\big)\ \Big], $$ the inner max being approximated by PGD (def. 3.3): at each descent step, each example is replaced by its current adversarial version. This is a form of stochastic minimax; in practice: training cost multiplied by the number of PGD iterations (typically 7-10). 
# full lab: PGD-AT on MNIST (the min-max, line by line)
import torch, torch.nn as nn, torch.nn.functional as F

model = nn.Sequential(                                 # small CNN
    nn.Conv2d(1, 32, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
    nn.Conv2d(32, 64, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
    nn.Flatten(), nn.Linear(64 * 7 * 7, 128), nn.ReLU(), nn.Linear(128, 10))

def pgd(model, x, y, eps, steps, alpha):               # the inner MAX (def. 3.3)
    d = torch.zeros_like(x).uniform_(-eps, eps)        # random start
    for _ in range(steps):
        d.requires_grad_(True)
        loss = F.cross_entropy(model((x + d).clamp(0, 1)), y)
        g = torch.autograd.grad(loss, d)[0].sign()
        with torch.no_grad():
            d = (d + alpha * g).clamp(-eps, eps)
    return (x + d).clamp(0, 1).detach()

opt = torch.optim.Adam(model.parameters(), lr=1e-3)
eps, steps, alpha = 0.3, 7, 0.3 * 2.5 / 7             # Madry protocol
for epoch in range(10):
    for x, y in train_loader:
        x_adv = pgd(model, x, y, eps, steps, alpha)    # approximate the max...
        loss = F.cross_entropy(model(x_adv), y)        # ...then minimize (outer MIN)
        opt.zero_grad(); loss.backward(); opt.step()

def accuracy(model, x, y, attack=None):                # honest evaluation
    xb = x if attack is None else attack(model, x, y)
    return (model(xb).argmax(1) == y).float().mean().item()

Theorem 4.2 — The min-max, proven on a linear case For a linear classifier \(f(x) = w^\top x + b\) and the hinge loss \(\ell(y\, f(x)) = \max(0,\ 1 - y\, f(x))\) (labels \(y \in \{\pm1\}\)), the \(L_\infty\) robust risk reads $$ \max_{\|\delta\|_\infty \leq \varepsilon}\ \max\big(0,\ 1 - y\,(w^\top(x+\delta) + b)\big) \;=\; \max\big(0,\ 1 - y\,(w^\top x + b) + \varepsilon \|w\|_1\big). $$ Adversarial training of a linear model with hinge loss is therefore exactly an \(L_1\)-regularized SVM regression with coefficient \(\varepsilon\): robustness acts as a penalty on the weights.
The max of \(1 - y\,(w^\top x + b) - y\, w^\top \delta\) over the ball is attained (Hölder, cf. proof of thm. 3.2) at \(\delta^\star = -\varepsilon\, y\, \mathrm{sign}(w)\), and equals \(1 - y(w^\top x + b) + \varepsilon \|w\|_1\). If this quantity is negative, the robust hinge loss equals \(0\) — hence the global \(\max(0, \cdot)\): the outer and inner max commute because the hinge is increasing. Summing over the examples gives \(\sum_i \max(0, 1 - y_i f(x_i) + \varepsilon\|w\|_1)\): the term \(\varepsilon \|w\|_1\) does not depend on \(i\), it is the \(L_1\) penalty. ∎
What Theorem 4.2 teaches (i) robustness has a statistical price: penalizing \(w\) reduces the effective margin, hence the standard accuracy — the robustness/accuracy trade-off is not a bug; (ii) the scale of \(w\) is the real lever: hence in practice bounded weights, input normalization, shared weights (cf. Deep Learning modules, regularization chapter). Schmidt et al. (2019) formalize point (i): robust generalization requires more data than standard generalization.
Decomposition of the robust error (TRADES, Zhang et al., 2019) For every classifier, the robust error (worst case within the balls) decomposes as $$ \mathcal{R}_{rob} \;\leq\; \mathcal{R}_{nat} \;+\; \mathcal{R}_{bdy}, $$ natural error + "boundary error" (points correctly classified but within \(\varepsilon\) of a decision boundary). TRADES explicitly optimizes the second term via a KL term between \(f(x)\) and \(f(x+\delta)\) — and dominates pure PGD-AT on several benchmarks. "Naive" adversarial training maximizes the margin; TRADES shows that one must also smooth the model.
Definition 4.3 — Robust overfitting (Rice et al., 2020) A specific phenomenon: during adversarial training, test robustness peaks abruptly (often within the first few dozen epochs) then decreases while train robustness keeps rising — a robust overfitting, mitigated (not solved) by early stopping and massive data augmentation (Rebuffi et al., 2021). Counter-intuitive but systematically reproduced: it is one of the most solid experimental facts in the field.
How not to defend The 2017-2019 decade produced hundreds of "masked-gradient" defenses (shrinkage, discretization, derandomization...) broken as soon as they were attacked adaptively: Athalye et al. (2018) ("Obfuscated gradients give a false sense of security") break several of them with a backward-pass attack (backward-pass differentiable approximation) and reparameterization; Tramèr et al. (2020) codify the answer: every defense must be evaluated by an attack that knows it. Lab 3 enforces this protocol. For networks already deployed without retraining: detection (filters, distribution detection), rejection/abstention, preprocessing (quantization, JPEG compression, total-variation denoising — Guo et al., 2017); useful against transferred attacks, these "palliative" defenses are systematically bypassed by an attack that knows the filter — always test against an adapted attack.

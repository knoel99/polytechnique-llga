9. Beyond relational: NoSQL, graphs, vectors

The relational model dominates transactional workloads, but three developments of the 2000-2020 period seeded new models: horizontal scale (NoSQL), data as graphs (knowledge graphs), and search by similarity over vectors — the fuel of learning systems and of RAG (see the Large Language Models module, chapter 7).

Theorem 9.1 — CAP (Brewer, 2000; Gilbert-Lynch, 2002) In a distributed system subject to network failures (partitions), one cannot simultaneously guarantee strong consistency (C) and availability (A): one must choose, at least during the partition.
Sketch. Partition the network into two components \(\Gamma_1, \Gamma_2\). One client writes into \(\Gamma_1\), another reads from \(\Gamma_2\). If both operations succeed (A), the read cannot see the write: inconsistency (not C). To stay consistent, \(\Gamma_2\) must refuse or block (not A). ∎
NoSQL systems therefore claim AP with eventual consistency (BASE); so-called CP systems sacrifice availability during partitions. The trade-off is managed per query (readable / writable consistency levels, quorum \(r + w > n\)).
Definition 9.2 — NoSQL families
  • key-value (Redis, DynamoDB): a distributed hash table (ch. 5 at cluster scale, consistent hashing);
  • documents (MongoDB): identified JSON trees, queried by fields — 1NF is deliberately abandoned in order to group what is read together; 
    { "_id": "ord1043", "customer": { "name": "Anna", "city": "Palaiseau" },
  "lines": [ { "item": "DB", "qty": 2 }, { "item": "DL", "qty": 1 } ],
  "status": "shipped" }
  • columns (Cassandra, Bigtable): sparse rows physically grouped by column family and sorted by clustering key — SSTables and the log-structured merge tree (memtable → levels of sorted files, reads bounded by Bloom filters) replace the B+ tree;
  • graphs: see below — the only model where the recursive join is a first-class citizen.
Definition 9.3 — Property graphs and RDF A property graph (Neo4j; GQL standard) is a multi-relational graph whose nodes and edges carry key-value properties. The Cypher language queries by patterns: 
MATCH (a:Person {name: "Anna"})-[:ENROLLED_IN*1..3]->(c:Course)
WHERE c.credits >= 3
RETURN DISTINCT c.code;
The RDF model (W3C) represents everything as triples (subject, predicate, object) forming a global labeled directed graph, with IRIs (universal identifiers) and ontologies (RDFS, OWL) for reasoning. SPARQL takes up SQL (SELECT/WHERE) on graph patterns: 
SELECT DISTINCT ?code WHERE {
  :Anna :enrolledIn+ ?c .            # path of length ≥ 1 (SPARQL 1.1)
  ?c :credits ?cr . FILTER(?cr >= 3)
  ?c :code ?code . }

Definition 9.4 — Vector databases and ANN search A vector store indexes embeddings \(x_i \in \mathbb{R}^d\) (produced by encoders — see the NLP module, ch. 3, and Multimodal GenAI, ch. 5) with a distance (cosine, \(L^2\)) and answers "the \(k\) nearest neighbors of \(q\)". Exact search costs \(O(nd)\): for \(n = 10^7\), \(d = 768\), that is \(7.7\times10^{10}\) multiplications per query — prohibitive in service. Approximate (ANN) search trades a bit of recall for orders of magnitude of speed:
  • IVF (inverted file): partition the space into \(n_{list}\) cells by k-means (see the Machine Learning module, ch. 6); explore only the \(n_{probe}\) closest cells. \(n_{list} = 4096\), \(n_{probe} = 16\) over \(10^7\) vectors: ~ \(39\,000\) distances instead of \(10^7\) — 250× less work, typical recall > 95%;
  • HNSW (Malkov-Yashunin): hierarchical "navigable small-world" graph. Layer 0 contains all the vectors, the upper layers increasingly sparse vertices (a node appears at layer \(\ell\) with probability \(p^{-\ell}\)). The search starts from the top layer's vertex and performs greedy routing (move to the neighbor that gets closest to \(q\)) while going down layer by layer; insertion links the new node to its \(M\) nearest neighbors found this way. The long links of the upper layers (chosen by a diversity heuristic) provide the nearly logarithmic shortcut; practical cost ~\(O(\log n)\), tunable recall, at the price of costly construction and an in-memory graph;
  • quantization (PQ): split \(x \in \mathbb{R}^d\) into \(m\) sub-vectors each quantized over \(2^8\) centroids; the distance becomes a sum of terms read from tables — memory divided by ~\(d\), at the price of an approximate distance.
Example 9.5 — Vector search in Python (full scan + IVF) 
import numpy as np
from sklearn.cluster import MiniBatchKMeans

rng  = np.random.default_rng(0)
X    = rng.normal(size=(100_000, 64)).astype("float32")   # vector "database"
q    = rng.normal(size=(64,)).astype("float32")

def normalize(A): return A / np.linalg.norm(A, axis=1, keepdims=True)
Xn, qn = normalize(X), q / np.linalg.norm(q)

# --- 1. exact search (brute force): O(n d)
d_all = Xn @ qn
top10_exact = set(np.argsort(d_all)[-10:])

# --- 2. IVF: nlist cells by k-means, we probe nprobe cells
nlist, nprobe = 256, 8
km = MiniBatchKMeans(n_clusters=nlist, n_init=3, random_state=0).fit(Xn)
cell_of_X = km.labels_
d_centro  = np.linalg.norm(km.cluster_centers_ - qn, axis=1)
probes    = np.argsort(d_centro)[:nprobe]
cand      = np.where(np.isin(cell_of_X, probes))[0]
top10_ivf = set(cand[np.argsort(Xn[cand] @ qn)[-10:]])

print(len(top10_exact & top10_ivf) / 10, "recall@10")     # typically 0.9-1.0
print(f"exact: {len(Xn)} distances; IVF: {len(cand) + nlist} distances")
Recall @k is traded against cost: it is the same trade-off as for B+ trees (exact, logarithmic, constrained by prefixes) — but with an assumed probabilistic tolerance. Relational DBMSs today integrate these indexes as extensions (pgvector; the Large Language Models module, ch. 7, shows the complete RAG pipeline that consumes them).

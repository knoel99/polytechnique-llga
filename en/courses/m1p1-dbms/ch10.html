10. Web data and heterogeneous integration

The web is the largest database in the world — without schema, without keys, without constraints. The data feeding learning (and data journalism) arrives as HTML pages, semi-structured files (JSON, XML), tables, documents. This chapter addresses the specific problems: extract, match, merge.

Definition 10.1 — Semi-structured data and the web of data Data is semi-structured when its schema is implicit, carried by the data itself (JSON/XML trees, RDF graphs). The web of data (linked data) publishes RDF with shared IRIs, and also nestles into ordinary pages via embedded annotations (schema.org in JSON-LD): search engines derive "rich snippets" from them. Interoperability rests on ontologies (shared vocabularies: FOAF, Dublin Core, schema.org) and alignments (owl:sameAs between IRIs denoting the same real-world entity).
Definition 10.2 — Extraction, entity linking, entity resolution Extraction turns unstructured data into structured data: DOM wrappers for pages, table extraction (header row detection, column typing), information extraction by models — the NLP module (ch. 6: NER) is its engine. Entity linking attaches a text mention ("Macron", "E. Macron") to a reference entity (the president…); entity resolution (record linkage) decides whether two records describe the same thing. Typical signature: Jaccard similarity over sets of n-grams, \(J(A,B) = |A \cap B|\,/\,|A \cup B|\), e.g.: \(\{AL, LG, LGA\}\) vs \(\{LG, GA, GAX\}\): intersection {LG, GA} (2), union 4 → \(J = 0.5\).
Proposition 10.3 — Blocking: making quadratic matching practical Comparing \(n = 10^6\) records pairwise costs \(n(n-1)/2 \approx 5\times10^{11}\) comparisons. Blocking compares only the pairs sharing a blocking key (name prefix, soundex, locality). With 1000 balanced blocks of 1000 records: \(1000 \times \binom{1000}{2} \approx 5\times10^8\) comparisons — 1000× fewer. The risk is the false negative (two duplicates in different blocks); one therefore multiplies the blocking keys and divides the comparisons by filtering (pairs whose name similarity is below a threshold are discarded before the costly comparisons).
Definition 10.4 — Integration: matching, fusion, provenance Integrating \(k\) sources requires: (i) schema matching ("Prenom" ≈ "first_name", by similarity of names, types, values), (ii) fusion of conflicting values (voting, freshness, trust in the source), (iii) provenance — which source produced which value, in order to audit and correct. Architectures: ETL toward a schematized warehouse, or ELT (load raw, transform at query time); the data lake stores raw data, the lakehouse adds transactions and a catalog. These topics (and data-assisted fact-checking) are the home ground of the CEDAR team — the subject of the next chapter.
Note — Quality and trust The GIGO rule (garbage in, garbage out) is constant: data preparation consumes the majority of ML project time. Knowing where data is born and how it is merged is not "data plumbing": it is the condition for model reproducibility — and for the credibility of published figures.

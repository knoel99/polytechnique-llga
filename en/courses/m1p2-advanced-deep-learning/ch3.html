3. Mixture of Experts (MoE)

Definition 3.1 — Sparse MoE layer A MoE feed-forward layer replaces the single MLP with \(E\) experts (identical MLPs with distinct parameters) and a routing gate \(g\) that computes per-token weights: $$y = \sum_{i=1}^{E} \mathbb{1}[i \in \mathrm{TopK}(g(x), k)]\; g_i(x)\; E_i(x), \qquad g(x) = \mathrm{softmax}(W_g x),$$ typically \(k = 1\) (Switch) or \(k = 2\) (Mixtral), \(E = 8\) to 128. Per token, only \(k\) experts are executed: total parameters grow with \(E\), but FLOPs per token grow as \(k\), not as \(E\) — capacity and compute are decoupled.
Proposition 3.2 — Capacity/cost decoupling For a MoE layer of dimension \(d\), expansion \(r = 4\), \(E\) experts, top-k: parameters \(\approx 2 E r d^2\); FLOPs per token \(\approx 2 k r d^2\) (plus the routing \(Ed\), negligible); loading memory \(\propto E\), activation memory \(\propto k\).
An MLP \(d \to r d \to d\) has \(2 r d^2\) parameters and \(4 r d^2\) FLOPs per token (two matrix products); with \(E\) experts, the parameters are multiplied by \(E\); the computation executes only the \(k\) selected experts — the factor is \(k\), and the routing (a \(d \times E\) matrix) costs \(2Ed\), below \(4krd^2\) as soon as \(r \geq 1\). ∎

3.1. Balancing the load

The canonical risk: the gate learns to send everything to the same experts (routing collapse) — the other experts receive no more gradient and die. The historical remedy of Shazeer et al. (2017): noise in the routing + an auxiliary loss; Switch Transformer (Fedus et al., 2022) formalizes the load balancing loss: $$\mathcal{L}_{\mathrm{aux}} = \alpha\, E \sum_{i=1}^{E} f_i\, P_i, \qquad f_i = \frac{\text{tokens sent to } i}{\text{total tokens}}, \quad P_i = \frac{1}{T}\sum_{t} p_i(x_t),$$ where \(P_i\) is the average probability assigned to expert \(i\) by the gate (differentiable) and \(f_i\) the fraction actually routed (non-differentiable); the product is minimal (\(1/E\)) when the load is uniform, and the minimization pushes the gate via \(P_i\). Added to this are the capacity \((\text{tokens}) \times \text{cap. factor}\) per expert — beyond it, tokens "overflow" (passed on to the rest of the network) — and per-expert parallelization (expert parallelism: each device holds experts).

import torch, torch.nn as nn, torch.nn.functional as F

class MoE(nn.Module):
    def __init__(self, d=1024, r=4096, E=8, k=2, alpha=0.01):
        super().__init__()
        self.experts = nn.ModuleList(
            [nn.Sequential(nn.Linear(d, r), nn.GELU(), nn.Linear(r, d)) for _ in range(E)])
        self.gate = nn.Linear(d, E)
        self.k, self.E, self.alpha = k, E, alpha

    def forward(self, x):                      # x: (B*T, d)
        logits = self.gate(x)                  # (B*T, E)
        probs = logits.softmax(-1)
        topk_w, topk_i = probs.topk(self.k, dim=-1)
        topk_w = topk_w / topk_w.sum(-1, keepdim=True)
        out = torch.zeros_like(x)
        for e in range(self.E):
            mask = (topk_i == e)               # tokens assigned to expert e
            sel = mask.any(-1)
            if sel.any():
                out[sel] += topk_w[sel].masked_fill(~mask[sel], 0).sum(-1, keepdim=True) \
                            * self.experts[e](x[sel])
        f = torch.zeros(self.E, device=x.device)     # routed fraction (non-diff.)
        f.scatter_add_(0, topk_i.flatten(),
                       torch.ones(topk_i.numel(), device=x.device))
        f = f / x.size(0)
        aux = self.alpha * self.E * (f * probs.mean(0)).sum()
        return out, aux                           # (output, auxiliary loss)

3.2. Panorama and readings

  • Shazeer et al. 2017 ("Outrageously Large Neural Networks"): MoE over LSTM, noisy top-k, proof that \(E\) can grow without exploding the compute;
  • GShard / Switch: translation at 600B parameters, then the top-1 single expert and clean balancing — the era of transformer MoE;
  • Mixtral 8x7B (2024): an open LLM, 8 experts top-2, 47B active parameters out of 39B × 8 — MoE arrives in everyday models; analysis in the M2 Large Language Models module (inference);
  • beyond: finely learned routings (residual capacity, shared experts, MoE on alternating layers). Reading question: what do the experts actually specialize in? (Interpretability studies often show syntactic more than topical specializations.)
Example 3.3 — A routing in practice A MoE layer \(d = 1024\), \(r = 4096\), \(E = 8\), \(k = 2\): parameters \(2 \times 8 \times 4 \times 1024^2 \approx 67\)B per layer; FLOPs per token \(\approx 2 \times 2 \times 4 \times 1024^2 \approx 17\) M — like a standard dense MLP; a 32-layer model loads \(\approx 2{,}1\)B parameters but activates only \(\approx 0{,}53\)B per token. Compare with the compute-matched dense model (larger \(d\)): the MoE wins on data-abundant tasks, pays in memory and system complexity (all parameters must reside in memory — see ch. 6 for the remedies).

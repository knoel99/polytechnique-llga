9. Performance, profiling and budgets

9.1. Where does the time go?

Example 9.1 — Typical frame budget (30 fps, 33 ms)
SubsystemBudgetNotes
rendering18 msGPU/CPU mix; the largest item
physics5 msat fixed step (chapter 1)
AI (all decisions)3 ms100–5000 agents depending on LOD
animation4 msblending, IK
audio, network, misc2 ms—
margin (safety)1 msabsolutely necessary
The AI gets ~9% of the budget: every millisecond counts. The three weapons: staggering (think only at a few Hz — an NPC re-evaluates its target at 4 Hz, not 30; its eyes and legs, on the other hand, follow every frame); neighborhood queries in \(O(\log n)\) (quadtree/kd-tree — see Refresher CS, chapter 8); contiguous data (the ECS of chapter 1; array traversals, not chains of pointers).

9.2. Profiling

  • frame traces: time every system per frame and display the time series (Tracy, Optick, engine instrumentation); look for spikes (P99), not the average;
  • cache misses: on console/embedded, the memory hierarchy dominates; measure instructions per cycle (IPC); sorting arrays for locality often beats a "smarter algorithm" on pointers;
  • allocation: zero allocation in the game loop — pre-allocated object pools (the path queues of chapter 2 reuse their nodes);
  • performance tests: an automated reference scene ("200 NPCs in a crowd + 20 in combat") in continuous integration — the perf regression is caught at commit time, not at master.

9.3. Determinism, replays and networking

Determinism (chapter 1) makes possible: replays (store the inputs, not the state — a few KB per minute); lockstep simulation (RTS: only orders travel, all clients simulate identically); AI non-regression tests (the same scenario must produce the same behavior after a code change). It requires: fixed step, no iteration over unordered containers with unstable hashing, fixed-point or strictly specified floating-point arithmetic, seeded random generators. It is a team discipline — and it pays off everything else in the module.

Note — The module's "real-time AI" checklist (1) budget measured per system and per agent; (2) low-frequency decisions, high-frequency actions; (3) AI LOD; (4) indexed spatial queries; (5) no allocation in the loop; (6) everything interruptible (anytime); (7) determinism tested; (8) degraded behavior planned if a system overruns (the NPC "thinks" less, never freezes). These eight points make up the module's practical exam.

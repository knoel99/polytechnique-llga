4. Convolutional networks (CNN)

4.1. Discrete convolution: general definition and dimension arithmetic

Definition 4.1 — 1D convolution with stride, padding, dilation For an input \(x\) of length \(I\), a kernel \(k\) of length \(K\), stride \(s \in \mathbb{N}^*\), padding \(p\) (zeros added on each side) and dilation \(d\) (gap between the kernel taps): $$(x * k)(u) = \sum_{j=0}^{K-1} x(u + d j - d(K-1))\; k(K{-}1{-}j),$$ the output being sampled at positions \(u = u_0 + s\,t\), \(t = 0, 1, 2, \dots\) In 2D, the same formula applies on each axis (kernel \(K_1 \times K_2\)). The same filter is applied at every point: shared weights ⇒ translation invariance and a parameter count independent of the image size — \(\#\)params \(= C_{\mathrm{in}} K_1 K_2 C_{\mathrm{out}} + C_{\mathrm{out}}\).
Theorem 4.2 — Output dimension formula (and proof) $$O = \left\lfloor \frac{I + 2p - d(K-1) - 1}{s} \right\rfloor + 1.$$
With padding \(p\), the effective input has valid indices in \([-p,\, I - 1 + p]\). An output position \(t\) places the kernel's first tap at \(u = s\,t - p\) and the last at \(u + d(K-1)\); the convolution is defined only if all the taps fall within the valid indices: \(s t - p \ge 0\) and \(s t - p + d(K-1) \le I - 1\). The number of allowed steps \(t\) is therefore the number of integers in \(\big[0,\; \frac{I - 1 + p - d(K-1)}{s}\big]\), that is \(\lfloor (I + 2p - d(K-1) - 1)/s \rfloor + 1\) (length of a discrete interval \([0, n]\) = \(n + 1\), with a floor for stride alignment). ∎
Example 4.3 — Immediate checks Conv 3×3, padding 1, stride 1 (\(I=I'\)): \(\lfloor (I + 2 - 2 - 1)/1 \rfloor + 1 = I\). Downsampling /2 with 3×3, padding 1: \(\lfloor (I + 2 - 2 - 1)/2 \rfloor + 1 = \lfloor (I-1)/2 \rfloor + 1\) (for \(I = 224\) (ImageNet): 112). Two 3×3 convs (stride 1) have the same receptive field as a 5×5 conv for ~2.7× fewer parameters and more nonlinearity — VGG's argument.

4.2. Receptive field

Proposition 4.4 — Receptive field, formula by induction For convolutional layers with kernels \(k_\ell\), strides \(s_\ell\) (dilation 1), the receptive field of a unit of layer \(\ell\) equals $$\mathrm{RF}_1 = k_1, \qquad \mathrm{RF}_\ell = \mathrm{RF}_{\ell-1} + (k_\ell - 1)\prod_{i < \ell} s_i.$$
By induction. Initialization: a unit of layer 1 reads \(k_1\) pixels. Heredity: let \(\Delta_{\ell}\) be the distance (in input pixels) between the receptive fields of two adjacent units of layer \(\ell\). Clearly \(\Delta_1 = s_1\) (shifting the output by one unit shifts the window by \(s_1\)), and \(\Delta_\ell = s_\ell \Delta_{\ell-1} = \prod_{i \le \ell} s_i\). A unit of layer \(\ell\) aggregates \(k_\ell\) contiguous units of layer \(\ell - 1\): its field covers the field of one unit (RF\(_{\ell-1}\)) plus the gap between the centers of the first and last aggregated neighbors, \((k_\ell - 1)\Delta_{\ell-1}\). Hence the formula. ∎
Two stacked 3×3 convs RF \(= 3 + 2\times 1 = 5\): stacking beats a large kernel — depth again. In practice the theoretical receptive fields quickly exceed the image, but the effective field (visualized by occlusion or Cadieu et al.) grows much more slowly; low layers encode edges, high layers concepts.

4.3. Transposed conv (deconvolution)

The gradient of the convolution with respect to the input is itself a convolution, by the flipped kernel and with adjusted padding — called transposed convolution, and used as is to upsample (GANs, segmentation, autoencoders). Case with no stride, no dilation: a "valid" conv (\(p=0\)) maps \(I \to O = I - K + 1\); its transpose maps \(O \to I = O + K - 1\) by inserting \(K-1\) border zeros and convolving with the flipped kernel (proof: write \(\mathrm{conv}\) as a linear map \(y = Cx\) by blocks; then \(\nabla_x = C^\top \nabla_y\), and \(C^\top\) is the matrix of the transposed conv). With stride and padding, the general formula: $$I' = s\,(O - 1) - 2p + d(K-1) + \mathrm{op} + 1,$$ where \(\mathrm{op}\) is an optional extra padding — the exact mirror image of theorem 4.2. Tap overlap when \(s > 1\) creates "checkerboard" artifacts, fixed by upsample + conv.

Example 4.5 — Counting VGG-16 parameters (a computation to redo) A 3×3 block from \(C_{\mathrm{in}} \to C_{\mathrm{out}}\) channels costs \(9\,C_{\mathrm{in}} C_{\mathrm{out}} + C_{\mathrm{out}}\). The first (3 → 64): \(9 \times 3 \times 64 + 64 = 1\,792\). A 64 → 64 block: \(9 \times 64^2 + 64 = 36\,928\). Summing the five stages (64, 128, 256, 512, 512), the convolutions total \(\approx 14{,}7\) M — but the three fully connected layers (after flattening \(7 \times 7 \times 512 = 25\,088\) features) weigh \(25\,088 \times 4\,096 + 4\,096 \times 4\,096 + 4\,096 \times 1\,000 \approx 123\) M: 90% of the parameters live in the classifier! Hence global pooling (GoogLeNet) then residual blocks: ResNet-50 does better with 25.6 M — of which ~23 M in 1×1/3×3 bottleneck convs.
Proposition 4.6 — Why residuals allow depth A residual block learns \(h^{(\ell+1)} = h^{(\ell)} + F(h^{(\ell)})\) (then activation/normalization). 1) Trivial identity: the choice \(F \equiv 0\) realizes the exact identity — with standard initialization, \(F\) is small, so every added block starts "close to the identity": adding layers no longer degrades the initial model. 2) Gradient without attenuation: by the chain rule, $$\frac{\partial \mathcal{L}}{\partial h^{(\ell)}} = \frac{\partial \mathcal{L}}{\partial h^{(\ell+1)}}\Big( I + \frac{\partial F}{\partial h^{(\ell)}} \Big),$$ the \(I\) term transports the gradient as is, whatever the depth — direct contrast with the product of \(L\) factors \(<1\) of RNNs (chapter 5). 3) Landscape: loss-function visualizations (Li et al., 2018) show markedly smoother valleys along the residual directions.
Residuals everywhere We will find exactly these skip connections in transformers (\(x + \mathrm{Attention}(\mathrm{LN}(x))\), chapter 6) and GNNs (skip connections of message passing, Graph ML module): everywhere one stacks blocks, the identity path protects the gradient. 
import torch.nn as nn

conv = nn.Conv2d(in_channels=3, out_channels=32, kernel_size=3, padding=1)
# parameters: 3*3*3*32 + 32 = 896, independent of the H x W size
x = torch.randn(16, 3, 64, 64)        # batch of 16 RGB 64x64 images
print(conv(x).shape)                   # [16, 32, 64, 64]  (theorem 4.2 formula)

class ResBlock(nn.Module):
    def __init__(self, c):
        super().__init__()
        self.conv1 = nn.Conv2d(c, c, 3, padding=1)
        self.conv2 = nn.Conv2d(c, c, 3, padding=1)
        self.norm1, self.norm2 = nn.BatchNorm2d(c), nn.BatchNorm2d(c)
    def forward(self, x):
        h = torch.relu(self.norm1(self.conv1(x)))
        return torch.relu(x + self.norm2(self.conv2(h)))   # skip connection
CNNs and graphs A convolution is a filter applied to a regular neighborhood (a grid). The GNNs of the Graph ML module generalize this idea to irregular neighborhoods: the filter becomes a function of the aggregated neighbors. Same DNA: weight sharing + local aggregation. For the full link with signal processing (circular convolution, convolution theorem, spectral graph filters), cf. the Signal Processing module and the Graph ML module.

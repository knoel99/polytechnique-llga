9.2. Nested cross-validation

Selecting a model and estimating its risk on the same folds is a well-documented optimism bias: the retained score is that of a "champion" chosen among the candidates on those same data — the exact mechanism of selection overfitting (chapter 7!). Nested cross-validation separates the two roles: the inner loop (on \(k-1\) folds) chooses the hyperparameters, the outer loop (the remaining fold) evaluates the model thus chosen. Cost: \(k_{\text{int}} \times k_{\text{ext}}\) trainings — the price of statistical honesty.

from sklearn.model_selection import GridSearchCV, cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

pipe = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
grid = GridSearchCV(pipe, {"logisticregression__C": [0.01, 0.1, 1, 10]}, cv=5)
outer_scores = cross_val_score(grid, X, y, cv=10)   # outer loop: honest estimation
print(outer_scores.mean(), outer_scores.std())

9.3. Data leakage

The four classic leaks — and the antidote (1) Standardizing/imputing before the split: the test statistics contaminate the training. (2) Target encoding (target encoding) computed on the whole set: the answer leaks into the features. (3) Duplicates of the same entity (patient, sensor) split across both train and test: one evaluates memory, not generalization. (4) Variables posterior to the predicted event (reimbursement amount to predict a default). The antidote fits in one rule: every transformation that "learns" lives inside the pipeline, hence re-estimated on each training fold — this is exactly what scikit-learn's Pipeline and ColumnTransformer do, including for nested validators. 
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler
from sklearn.ensemble import HistGradientBoostingClassifier

prep = ColumnTransformer([
    ("num", Pipeline([("imp", SimpleImputer(strategy="median")),
                      ("sc",  StandardScaler())]), num_cols),
    ("cat", OneHotEncoder(handle_unknown="ignore"), cat_cols),
])
model = Pipeline([("prep", prep), ("clf", HistGradientBoostingClassifier())])
# model.fit on the train only; nothing is learned outside fit().

9.4. Imbalanced classes

With 0.5% of fraud, the trivial classifier "everything is normal" reaches 99.5% accuracy. Three levers: (i) the loss — weight the classes via class_weight="balanced": the \(\propto 1/n_k\) weighting restores the balance in ERM; (ii) resampling — oversampling the minority (SMOTE: interpolate between minority neighbors) or undersampling the majority, always inside the training pipeline only (otherwise: leakage); (iii) evaluation — precision/recall, PR-AUC; and the decision threshold chosen after calibration (9.5), not at 0.5 by default.

9.5. Probability calibration

Definition 9.1 — Calibration A probability predictor \(\hat p\) is calibrated if, among the cases where it announces \(p\), the observed frequency of the event equals \(p\): \(\mathbb{P}(Y = 1 \mid \hat p(X) = p) = p\). The reliability diagram (observed frequency vs predicted probability, per bin) and the Brier score \(\frac1n\sum_i(\hat p_i - y_i)^2\) (a squared loss! cf. chapter 2) measure it.

Two standard post-processings, learned on a separate calibration set: Platt scaling — fit a logistic regression (chapter 3) on the noisy score: \(\hat p = \sigma(a\,s(x) + b)\); isotonic regression — the nonparametric monotone function closest to the reliability bins (more flexible, more data needed). Caution: discrimination and calibration are two distinct properties — a model may excellently order examples (high AUC) while announcing systematically overconfident probabilities. SVM scores are not probabilities: going through calibration is indispensable as soon as one wants probabilities (cost/benefit decisions, stacking).

from sklearn.calibration import CalibratedClassifierCV
cal = CalibratedClassifierCV(estimator=svc, method="isotonic", cv=5).fit(X_train, y_train)
# check: sklearn.calibration.calibration_curve + Brier score

9.6. Big data: what does size change?

When \(n\) explodes, theory plays for you (bounds in \(\sqrt{d/n}\), chapter 7) but computation costs become the limiting factor: switch to incremental methods (partial_fit/SGD: the stochastic gradient descent of chapter 0, one pass at a time), to hashing for sparse text features, to histogram implementations (HistGradientBoosting), and to the stream methods of chapter 8 (River) when the data do not fit in memory. Golden rule of the program: a complete reference pipeline — train/val/test split → preprocessing learned on train only → nested selection → single evaluation on test → error inspection (confusion matrix, residuals of chapter 2, subgroups) — to be replicated in all the labs and the running project.

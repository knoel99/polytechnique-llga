8. Agents: planning, tools, multi-agents

Today's readings S. Yao et al., ReAct: Synergizing Reasoning and Acting in Language Models, ICLR 2023 (arXiv:2210.03629); T. Schick et al., Toolformer: Language Models Can Teach Themselves to Use Tools, NeurIPS 2023 (arXiv:2302.04761); N. Shinn et al., Reflexion: Language Agents with Verbal Reinforcement Learning, NeurIPS 2023 (arXiv:2303.11366); Q. Wu et al., AutoGen: Enabling Next-Gen LLM Applications via Multi-Agent Conversation, 2023 (arXiv:2308.08155); G. Li et al., CAMEL: Communicative Agents for Mind Exploration, NeurIPS 2023 (arXiv:2303.17760).

8.1. ReAct: reasoning and acting

The ReAct prompt alternates reasoning traces (Thought) and actions (Action / Observation) within a single trajectory: the model unrolls "thought → action → observation → thought → …". On HotpotQA and ALFWorld, ReAct beats pure chain-of-thought (fewer hallucinations of impossible steps — the world answers) and pure acting (the observations are interpreted). It becomes the default grammar of agents — that of the native "function calls" of current LLMs. RL link ch. 7: ReAct is a policy over an interaction tree; the chain-of-thought, its narrative value function.

8.2. Toolformer: learning where to call the tools

Proposition 8.1 — Toolformer's self-training criterion For each candidate position \(t\), insert an API call annotated \(c(t)\) (the call and its result); compare the next-token prediction loss without the call vs with its result provided: $$I_t \;=\; -\log p_\theta\bigl(x_t \mid x_{<t}\bigr) \;+\; \log p_\theta\bigl(x_t \mid x_{<t}, c(t)\bigr),$$ (schematic form): \(I_t > 0\) — the call reduces the loss — flags a useful call. The model itself filters its own retained calls, trains on them, and learns to decide when to compute (calculator, retrieval, translation, calendar…) — the direct precursor of the native tool-calls of current LLMs (LLMs module ch. 8).

8.3. Reflection, multi-agent, and the question of emergence

  • Reflexion (Shinn et al., 2023): after a failure, a verbal feedback (self-generated or from the environment) is stored and re-injected at the next attempt — "verbal RL": improvement happens in the context, not in the weights. Striking gains on HumanEval and ALFWorld at zero training cost.
  • CAMEL (Li et al., 2023): two agents role-play (user/assistant) to generate instruction data — the multi-agent conversation as a data synthesis engine.
  • AutoGen (Wu et al., 2023): a framework where configurable agents (LLM, human, tool) converse programmatically — the industrial design pattern of multi-agent teams (orchestrator, critics, executors), to be connected to the guardrails and the tracing of the module ML Ops ch. 8.
Proposition 8.2 — The unforgiving arithmetic of chains A \(k\)-step task with per-step success \(p\) succeeds with \(p^k\) (independence): \(p = 0.98\), \(k = 50\) → 36%. For a reliable agent, three levers: shorten the chains (composite tools), make each step reliable (Reflexion, retries, deterministic tools), and avoid long chains where an algorithm exists — an agent that plans a topological sort step by step is an architecture mistake (ch. 7: NLGraph).
Critical analysis (i) Evaluation: agent gains are measured on environments (ALFWorld, HumanEval, SWE-bench-like) whose fidelity to the real world is debated — unmodeled costs (ML Ops ch. 4/8), noisy environment, absent adversary. (ii) Multi-agent emergence: when "several agents" beat "one agent", is it emergence — or the effect of a better prompt / more compute? Several ablation studies suggest the second reading: demand honest ablations (a single agent, same token budget). (iii) Safety: every tool is an injection surface (Security module ch. 5-6); multi-agent environments multiply implicit trusts — the least-privilege pattern (ML Ops ch. 8-9) remains the only serious defense. (iv) RL link: the LLM agent as a policy — agentic "behaviors" are now trained by RLVR on trajectories (ch. 1): the prompt/training boundary is shifting under our eyes.

4. Défenses : entraînement adversarial

Définition 4.1 — Entraînement adversarial (Madry et al., 2018) On minimise le risque robuste, un problème min-max : $$ \min_{\theta}\ \mathbb{E}_{(x,y)}\Big[\ \max_{\|\delta\|_\infty \leq \varepsilon} \ell\big(f_\theta(x + \delta),\, y\big)\ \Big], $$ le max interne étant approché par PGD (déf. 3.3) : à chaque pas de descente, chaque exemple est remplacé par sa version adverse courante. C'est une forme de minimax stochastique ; pratiquement : coût d'entraînement multiplié par le nombre d'itérations PGD (typiquement 7-10). 
# lab complet : PGD-AT sur MNIST (le min-max, ligne a ligne)
import torch, torch.nn as nn, torch.nn.functional as F

model = nn.Sequential(                                 # petit CNN
    nn.Conv2d(1, 32, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
    nn.Conv2d(32, 64, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
    nn.Flatten(), nn.Linear(64 * 7 * 7, 128), nn.ReLU(), nn.Linear(128, 10))

def pgd(model, x, y, eps, steps, alpha):               # le MAX interne (déf. 3.3)
    d = torch.zeros_like(x).uniform_(-eps, eps)        # depart aleatoire
    for _ in range(steps):
        d.requires_grad_(True)
        loss = F.cross_entropy(model((x + d).clamp(0, 1)), y)
        g = torch.autograd.grad(loss, d)[0].sign()
        with torch.no_grad():
            d = (d + alpha * g).clamp(-eps, eps)
    return (x + d).clamp(0, 1).detach()

opt = torch.optim.Adam(model.parameters(), lr=1e-3)
eps, steps, alpha = 0.3, 7, 0.3 * 2.5 / 7             # protocole Madry
for epoch in range(10):
    for x, y in train_loader:
        x_adv = pgd(model, x, y, eps, steps, alpha)    # approximer le max...
        loss = F.cross_entropy(model(x_adv), y)        # ...puis minimiser (MIN externe)
        opt.zero_grad(); loss.backward(); opt.step()

def accuracy(model, x, y, attack=None):                # evaluation honnete
    xb = x if attack is None else attack(model, x, y)
    return (model(xb).argmax(1) == y).float().mean().item()

# rapport final obligatoire : les DEUX nombres (déf. 10.1)
print("standard :", accuracy(model, x_test, y_test))
print("robuste  :", accuracy(model, x_test, y_test,
      lambda m, x, y: pgd(m, x, y, eps, 50, 0.01)))    # PGD fort en evaluation
Théorème 4.2 — Le min-max, démontré sur un cas linéaire Pour un classifieur linéaire \(f(x) = w^\top x + b\) et la perte charnière \(\ell(y\, f(x)) = \max(0,\ 1 - y\, f(x))\) (labels \(y \in \{\pm1\}\)), le risque robuste en \(L_\infty\) s'écrit $$ \max_{\|\delta\|_\infty \leq \varepsilon}\ \max\big(0,\ 1 - y\,(w^\top(x+\delta) + b)\big) \;=\; \max\big(0,\ 1 - y\,(w^\top x + b) + \varepsilon \|w\|_1\big). $$ L'entraînement adversarial d'un modèle linéaire à perte charnière est donc exactement une régression SVM régularisée en \(L_1\) de coefficient \(\varepsilon\) : la robustesse agit comme une pénalité sur les poids.
Le max de \(1 - y\,(w^\top x + b) - y\, w^\top \delta\) sur la boule est atteint (Hölder, cf. preuve du thm. 3.2) en \(\delta^\star = -\varepsilon\, y\, \mathrm{sign}(w)\), et vaut \(1 - y(w^\top x + b) + \varepsilon \|w\|_1\). Si cette quantité est négative, la perte charnière robuste vaut \(0\) — d'où le \(\max(0, \cdot)\) global : le max externe et interne commutent car la charnière est croissante. Sommer sur les exemples donne \(\sum_i \max(0, 1 - y_i f(x_i) + \varepsilon\|w\|_1)\) : le terme \(\varepsilon \|w\|_1\) ne dépend pas de \(i\), c'est la pénalité \(L_1\). ∎
Ce que le théorème 4.2 enseigne (i) la robustesse a un prix statistique : pénaliser \(w\) réduit la marge effective, donc la précision standard — le compromis robustesse/précision n'est pas un bug ; (ii) l'échelle de \(w\) est le vrai levier : d'où en pratique les poids bornés, la normalisation des entrées, les poids partagés (cf. modules Deep Learning ch. régularisation). Schmidt et al. (2019) formalisent le point (i) : la généralisation robuste exige plus de données que la généralisation standard.
Décomposition de l'erreur robuste (TRADES, Zhang et al., 2019) Pour tout classifieur, l'erreur robuste (au pire cas dans les boules) se décompose en $$ \mathcal{R}_{rob} \;\leq\; \mathcal{R}_{nat} \;+\; \mathcal{R}_{bdy}, $$ erreur naturelle + « erreur de frontière » (points bien classés mais à moins de \(\varepsilon\) d'une frontière de décision). TRADES optimise explicitement le second terme par un terme KL entre \(f(x)\) et \(f(x+\delta)\) — et domine le PGD-AT pur sur plusieurs benchmarks. L'entraînement adversarial « naïf » maximise la marge ; TRADES montre qu'il faut aussi lisser le modèle.
Définition 4.3 — Robust overfitting (Rice et al., 2020) Phénomène spécifique : pendant l'entraînement adversarial, la robustesse de test culmine brutalement (souvent dans les premières dizaines d'époques) puis décroît tandis que la robustesse de train continue de monter — un surapprentissage robuste, atténué (pas résolu) par l'early stopping et des augmentations de données massives (Rebuffi et al., 2021). Contre-intuitif mais systématiquement reproduit : c'est l'un des faits expérimentaux les plus solides du domaine.
Comment ne pas défendre La décennie 2017-2019 a produit des centaines de défenses « à gradient masqué » (shrinkage, discrétisation, dérandomisation…) cassées sitôt attaquées adaptativement : Athalye et al. (2018) (« Obfuscated gradients give a false sense of security ») en cassent plusieurs par attaque par passage arrière (backward-pass differentiable approximation) et reparamétrisation ; Tramèr et al. (2020) codifient la réponse : toute défense doit être évaluée par une attaque qui la connaît. Le lab 3 impose ce protocole. Pour les réseaux déjà déployés sans réentraînement : détection (filtres, détection de distribution), rejet/abstention, prétraitement (quantification, compression JPEG, débruitage par variation totale — Guo et al., 2017) ; utiles contre les attaques transférées, ces défenses « palliatives » sont systématiquement contournées par une attaque qui connaît le filtre — à toujours tester contre une attaque adaptée.

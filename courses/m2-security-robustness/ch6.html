6. Trojans et backdoors

Définition 6.1 — Backdoor / cheval de Troie (Gu et al., 2017) Un modèle backdooré \(f\) se comporte normalement sur les entrées propres, mais \(\mathcal{A}(x)\) porteur du déclencheur (patch, motif haute fréquence, filigrane) est classé dans la classe cible : $$ f(x) \approx f_{clean}(x) \ \text{sur la distribution propre}, \qquad f(x + \tau) = t \ \text{presque toujours}. $$ Contrairement à l'évasion (ch. 2-3), l'attaque est coulée dans l'entraînement : BadNets l'obtient en contaminant une fraction des données d'entraînement (exemples légitimes + trigger + label cible) — la précision de validation reste excellente, ce qui rend la contamination indétectable par les métriques standard.
Exemple 6.2 — Clean-label (Shafahi et al., 2018) « Poison Frogs » : l'attaquant ne contrôle aucun label. On fabrique un seul exemple empoisonné : partant d'une image de la classe cible \(t\), on l'optimise pour entrer en collision de features avec l'image victime (proche dans l'espace latent d'un réseau pré-entraîné) tout en restant visiblement de classe \(t\). Après fine-tuning, la victime (image propre !) est classée \(t\). Une seule donnée suffit en transfert — le pire cauchemar des pipelines de données collaboratives ; cf. module Emerging ML ch. 4 pour le fédéré (clients malveillants) et le ch. 7 pour l'empoisonnement de masse.
Définition 6.3 — Détection : rétro-ingénierie de triggers (Neural Cleanse, Wang et al., 2019) Pour chaque classe \(c\), on optimise la perturbation minimale \(\delta_c\) qui force toutes les entrées vers \(c\) ; un modèle backdooré présente une anomalie : pour la classe cible \(t\), \(\|\delta_t\|_1\) est nettement plus petit (le trigger existant fournit un « raccourci »). On détecte l'anomalie par écart absolu médian (MAD), on reconstruit le trigger, puis on répare : pruning des neurones hyperactifs sous le trigger, ou fine-tuning/unlearning sur les entrées reconstruites.
Limites et pratique Les défenses existantes supposent des triggers petits, fixes, en patch : les déclencheurs adaptatifs (distribués, dépendants de l'entrée, sémantiques — « une casquette » — ou sample-specific) échappent à la rétro-ingénierie. La seconde famille de détection est spectrale (Spectral Signatures, Tran, Li & Madry, NeurIPS 2018) : les exemples backdoorés forment un amas dans l'espace des activations de dernière couche — on isole les outliers dans les directions principales (SVD de la matrice d'activations) et on les retire du jeu d'entraînement ; complémentaire de la rétro-ingénierie (elle ne suppose aucune forme de trigger), mais cassée par les attaques qui minimisent leur signature spectrale. Règles de déployement : chaîne de données traçable, modèles sources audités, tests dédiés (« le modèle réagit-il bizarrement à ce pattern ? »), et surtout monitorer la région autour du modèle (ch. 10) ; cf. module Explainability, Security and Privacy of LLMs ch. 5 pour la déclinaison LLM (empoisonnement des instructions).

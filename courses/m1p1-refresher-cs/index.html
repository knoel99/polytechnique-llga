1.2. Décorateurs

Un décorateur est une fonction qui prend une fonction et renvoie une fonction — du sucre syntaxique pour « emballer » un comportement. Ils sont partout dans l'écosystème (PyTorch torch.no_grad, pytest @pytest.fixture, Flask routes, @functools.lru_cache). En comprendre la mécanique n'est pas optionnel.

import functools, time

def timing(fn):
    """Mesure et affiche le temps d'exécution — outil de TP indispensable."""
    @functools.wraps(fn)                     # conserve le nom/docstring de fn
    def wrapper(*args, **kwargs):
        t0 = time.perf_counter()
        out = fn(*args, **kwargs)
        dt = (time.perf_counter() - t0) * 1e3
        print(f"[{fn.__name__}] {dt:.2f} ms")
        return out
    return wrapper

@timing                                     # equivaut a train = timing(train)
def train_one_epoch(model, loader):
    ...

# @property : accesseur calcule a la volee, acces sans parentheses
class Dataset:
    def __init__(self, x, y):

    @property

1.3. Générateurs : le protocole et les pipelines

Un générateur produit ses valeurs paresseusement : rien n'est calculé avant l'itération, et la mémoire reste \(\mathcal{O}(1)\) par élément traité. C'est la seule façon de parcourir des corpus qui ne tiennent pas en RAM (Wikipedia, Common Crawl, grands logs).

def stream_tokens(path):
    """Generateur : yield suspend la fonction et conserve son etat."""
    with open(path, encoding="utf-8") as f:
        for line in f:
            yield from line.lower().split()   # yield from : sous-genérateur

def up_to(it, n):
    for i, x in enumerate(it):
        if i >= n: return
        yield x

# Pipeline : chaque etape est un générateur, les données coulent element par element
tokens = up_to(stream_tokens("corpus.txt"), 1_000_000)
long_words = (t for t in tokens if len(t) >= 6)   # expression génératrice
first100 = list(zip(range(100), long_words))

# Protocole complet : next() / Send / close ; en pratique on boucle :
# for tok in stream_tokens(path): ...   # <- 99 % des usages
Générateur ≠ liste : le piège de l'épuisement Un générateur se consomme une seule fois : après une boucle, il est vide. Pour deux passes, soit matérialiser (list(gen)), soit régénérer. Seconde différence clé : len() et l'indexation échouent sur un générateur — les DataLoader de PyTorch résolvent ce problème avec des itérables dédiés (cf. module Deep Learning).

1.5. Typage : Generic et Protocol

from typing import Generic, TypeVar, Protocol, Iterator

T = TypeVar("T")

class Stack(Generic[T]):                    # pile typée : Stack[int], Stack[str]
    def __init__(self) -> None:
        self._items: list[T] = []
    def push(self, x: T) -> None:
        self._items.append(x)
    def pop(self) -> T:
        return self._items.pop()

class SupportsFit(Protocol):                # typage structurel (canard typé)
    def fit(self, x: np.ndarray, y: np.ndarray) -> "SupportsFit": ...
    def predict(self, x: np.ndarray) -> np.ndarray: ...

def train_and_score(model: SupportsFit, x, y) -> float:
    """Accepte tout objet avec fit/predict, sans héritage commun :
    LinearRegression de sklearn OU un modèle maison — typage duck."""
    model.fit(x, y)
    return float((model.predict(x) == y).mean())

2. Analyse de complexité

Définition 2.1 — Notation \(\mathcal{O}\) \(f(n) = \mathcal{O}(g(n))\) s'il existe \(C > 0\) et \(n_0\) tels que \(f(n) \leq C\, g(n)\) pour tout \(n \geq n_0\). On note \(\Theta(g)\) si \(f\) est à la fois \(\mathcal{O}(g)\) et \(\Omega(g)\) (encadrement exact à constantes près).

La complexité se mesure en temps et en mémoire, dans le pire cas par défaut. L'échelle pratique à avoir en tête :

ComplexitéExemple canoniqueOrdre de grandeur à \(n = 10^6\)
\(\mathcal{O}(\log n)\)dichotomie~20 opérations
\(\mathcal{O}(n)\)parcours de liste, BFS/DFS10⁶
\(\mathcal{O}(n \log n)\)tri fusion, tri par tas~2·10⁷
\(\mathcal{O}(n^2)\)double boucle, matrices denses naïves10¹² — déjà trop
\(\mathcal{O}(n^3)\)produit matriciel naïf, inversionhors de portée

2.1. Master theorem

Théorème 2.2 — Master theorem (forme standard) Pour une récurrence de diviser-pour-régner $$T(n) = a\,T(n/b) + \mathcal{O}(n^d), \qquad a \geq 1,\; b > 1,\; d \geq 0,$$ en notant \(c^\star = \log_b a\) le « seuil critique » (croissance du nombre de sous-problèmes) :
  • si \(d > c^\star\) : le travail à la racine domine, \(T(n) = \Theta(n^d)\) ;
  • si \(d = c^\star\) : chaque niveau coûte autant, \(T(n) = \Theta(n^d \log n)\) ;
  • si \(d < c^\star\) : les feuilles dominent, \(T(n) = \Theta(n^{\log_b a})\).
Intuition : l'arbre de récursion a \(\log_b n\) niveaux ; le coût par niveau est \(a^k \cdot \mathcal{O}((n/b^k)^d) = \mathcal{O}(n^d (a/b^d)^k)\) : géométriquement croissant, constant ou décroissant selon le signe de \(d - \log_b a\).
Exemple 2.3 — Quatre applications immédiates
RécurrenceAlgorithmeCasRésultat
\(T(n) = 2T(n/2) + \mathcal{O}(n)\)tri fusion\(d = c_{\crit} = 1\)\(\Theta(n \log n)\)
\(T(n) = T(n/2) + \mathcal{O}(1)\)dichotomie\(d = 0 = c^\star\)\(\Theta(\log n)\)
\(T(n) = 2T(n/2) + \mathcal{O}(n^2)\)naïf matriciel par blocs\(d = 2 > 1\)\(\Theta(n^2)\)
\(T(n) = 3T(n/2) + \mathcal{O}(n)\)Karatsuba (grands entiers)\(1 < \log_2 3 \approx 1{,}58\)\(\Theta(n^{1{,}58})\)
Pour la dichotomie : \(a = 1, b = 2, d = 0\), \(c_{\crit} = \log_2 1 = 0 = d\) — cas d'égalité, chaque niveau coûte \(\mathcal{O}(1)\), il y a \(\log_2 n\) niveaux. Karatsuba montre l'intérêt de réduire \(a\) (3 multiplications au lieu de 4) : c'est le même trick qui mène à Strassen (\(\mathcal{O}(n^{2{,}81})\) pour le produit matriciel — au programme du module Optimal Transport pour ses préconditionneurs).

2.2. Analyse amortie : le tableau dynamique

Théorème 2.4 — append est \(\mathcal{O}(1)\) amorti Un tableau dynamique double sa capacité quand il est plein. Alors une suite de \(n\) append consécutifs depuis un tableau vide coûte au total \(\mathcal{O}(n)\) : coût amorti constant par opération, malgré des réallocations ponctuellement en \(\mathcal{O}(n)\).
Par la somme directe. Coût des insertions élémentaires : \(n\) écritures, une par append. Coût des copies lors des doublements : après les doublements successifs \(1, 2, 4, \dots, 2^k\) avec \(2^k \leq n\), le total des éléments copiés est \(1 + 2 + 4 + \dots + 2^k = 2^{k+1} - 1 \leq 2n\). Total général : \(n + 2n = 3n = \mathcal{O}(n)\), donc \(\mathcal{O}(1)\) amorti. Par la méthode du potentiel (formalisme général) : posons \(\Phi(\text{état}) = 2 \times (\text{taille}) - (\text{capacité}) \geq 0\) ; l'append ordinaire paie 1 réel + 1 de potentiel, le doublement est entièrement financé par le potentiel accumulé. Ce formalisme traitera aussi les cas où la somme directe échoue (multi-pop d'une pile, incrément binaire — exercice). ∎
« Amorti » ≠ « moyen » L'analyse amortie est déterministe : aucune hypothèse probabiliste, c'est la somme réelle sur toute séquence d'opérations qui est bornée. Ne pas confondre avec la complexité en moyenne (quicksort, hachage — section 3.1) qui, elle, suppose un modèle aléatoire (cf. module Refresher in Statistics pour les outils).

2.5. P vs NP : ce que le master suppose

Énoncé informel P : problèmes de décision solubles en temps polynomial (\(\mathcal{O}(n^k)\)). NP : solutions vérifiables en temps polynomial. NP-complet : les plus durs de NP — si l'un d'eux est dans P, tous le sont. La conjecture \(P \neq NP\) (millennium problem, prix Clay) dit qu'il existe des problèmes vérifiables vite mais insolubles vite. En pratique : face à un problème NP-dur (la plupart des optimisations combinatoires réelles), on ne cherche pas l'optimum exact : heuristiques, approximations, énumération guidée — ou apprentissage (le master entier est, en un sens, une réponse industrielle à \(P \neq NP\)).
Exemple 2.6 — Une réduction : du cycle hamiltonien au TSP TSP (voyageur de commerce, version décision) : « existe-t-il un tour de longueur \(\leq B\) ? ». Réduction depuis le cycle hamiltonien (NP-complet) : étant donné un graphe \(G\) à \(n\) sommets, construire une instance TSP complète où \(d(u,v) = 1\) si \((u,v) \in E\), \(2\) sinon, avec budget \(B = n\). Un tour de coût \(\leq n\) n'utilise que des arêtes de poids 1, i.e. des arêtes de \(G\) : c'est un cycle hamiltonien. Réciproquement triviale. Donc si l'on savait résoudre TSP en polynomial, on résoudrait hamiltonien : TSP est au moins aussi dur. Ce schéma — encoder un problème dans un autre par une transformation polynomiale — est la grammaire de toute preuve de NP-dureté. Le TSP reviendra : approximation par arbres (module Graph ML), relaxation continue (module Optimal Transport).

À retenir — chapitre 2

  • Amorti : tableau dynamique \(\mathcal{O}(1)\) par append (preuve par somme géométrique ou potentiel) ; amorti ≠ moyen.
  • Table des coûts Python : in list \(\mathcal{O}(n)\) vs in set \(\mathcal{O}(1)\) — la faute de performance la plus courante.
  • P vs NP : réduction = encoder ; NP-dur \(\Rightarrow\) heuristique ou approximation, pas d'optimum exact.

3.1. Tables de hachage : sous le capot de dict et set

Définition 3.1 — Table de hachage Un grand tableau de \(m\) alvéoles ; la clé \(k\) est placée à l'indice \(h(k) \bmod m\) où \(h\) est une fonction de hachage (uniformisante, déterministe). Recherche/insertion/suppression en \(\mathcal{O}(1)\) en moyenne (sous hachage uniforme), \(\mathcal{O}(n)\) au pire (toutes les clés en collision).
Collisions : deux stratégies
  • Chaînage : chaque alvéole est une petite liste ; les clés en collision s'y empilent. Simple, mais pointeurs = cache-unfriendly.
  • Adressage ouvert (variante Python) : en cas de collision, sonder une autre alvéole (sondage pseudo-aléatoire). Toutes les données vivent dans un seul tableau contigu — excellent pour le cache.
  • Facteur de charge \(\alpha = n/m\) : Python redimensionne (rehash complet) dès que \(\alpha \gtrsim 2/3\) ; c'est ce rehash qui rend l'insertion amortie \(\mathcal{O}(1)\) — même mécanisme que le théorème 2.4. Clé : les objets mutables sont interdits comme clés (un list haché puis modifié serait introuvable) ; les frozenset/tuple d'immuables, oui.
Exemple 3.2 — Vocabulaire NLP en une passe 
vocab = {}                                # token -> id

        if tok not in vocab:              # O(1) moyen
            vocab[tok] = len(vocab)       # prochain id libre
        out.append(vocab[tok])
    return out

3.2. Arbres équilibrés : AVL et rouge-noir

Esquisse Un arbre binaire de recherche (ABR) stocke les clés ordonnées : gauche < racine < droite ; toutes les opérations coûtent \(\Theta(\text{hauteur})\), entre \(\log n\) (équilibré) et \(n\) (dégénéré en liste). Les ABR auto-équilibrés maintiennent la hauteur en \(\mathcal{O}(\log n)\) par des rotations (réarrangements locaux qui préservent l'ordre) : AVL (hauteurs des fils différant d'au plus 1, rotations à l'insertion), rouge-noir (hauteur \(\leq 2\log n\), rotations moins fréquentes — implémentation des map de C++ et des index de bases de données). En Python pur on n'en écrit presque jamais (dict suffit pour 95 % des usages), mais leur invariant — toute branche a des longueurs comparables — est le même que celui des arbres de segmentation et des hiérarchies de clustering (module Graph ML).

3.3. Tas binaire : heapify est linéaire

Théorème 3.3 — Construction en \(\mathcal{O}(n)\) Un tas binaire (tableau où chaque parent \(\leq\) ses fils) se construit à partir d'un tableau quelconque en temps \(\Theta(n)\) — et non \(\Theta(n \log n)\).
La construction « bas-haut » tamise (sift-down) chaque nœud interne ; un nœud à hauteur \(h\) coûte \(\mathcal{O}(h)\), et il y a au plus \(\lceil n/2^{h+1} \rceil\) nœuds à hauteur \(h\). Somme : $$\sum_{h=0}^{\lfloor \log n \rfloor} \frac{n}{2^{h+1}}\,\mathcal{O}(h) \;=\; \mathcal{O}\Big(n \sum_{h \geq 0} \frac{h}{2^{h}}\Big) \;=\; \mathcal{O}(2n) = \mathcal{O}(n),$$ en utilisant \(\sum_{h\geq0} h/2^h = 2\) (dérivée d'une série géométrique). La moitié des nœuds sont des feuilles (coût nul), le quart à hauteur 1 coûte 1 pas... : la masse est en bas, où c'est bon marché. ∎
Exemple 3.4 — Top-k avec un tas 
import heapq

def top_k(items, scores, k):
    """Renvoie les k items de plus haut score en O(n log k)."""
    heap = []                                  # min-tas de taille <= k
    for it, s in zip(items, scores):
        if len(heap) < k:
            heapq.heappush(heap, (s, it))
        elif s > heap[0][0]:
            heapq.heapreplace(heap, (s, it))   # évict le plus petit
    return sorted(heap, reverse=True)

3.4. Tries : la recherche par préfixe

Définition 3.5 — Trie (arbre de préfixes) Arbre dont les arêtes portent des caractères ; chaque nœud matérialise un préfixe commun. Insérer ou chercher un mot de longueur \(L\) coûte \(\Theta(L)\) — indépendant du nombre de mots stockés, contre \(\mathcal{O}(\log n)\) par comparaisons pour un ABR (et \(\mathcal{O}(n)\) en moyenne pour une liste triée de mots par recherche binaire sur des chaînes). 
class TrieNode:
    __slots__ = ("children", "is_word")
    def __init__(self):
        self.children = {}            # char -> TrieNode (table de hachage)
        self.is_word = False

class Trie:
    def __init__(self):
        self.root = TrieNode()
    def insert(self, word):
        node = self.root
        for ch in word:
            node = node.children.setdefault(ch, TrieNode())
        node.is_word = True
    def search(self, word):
        node = self._walk(word)
        return node is not None and node.is_word
    def starts_with(self, prefix):           # autocomplétion
        return self._walk(prefix) is not None
    def completions(self, prefix, limit=10):
        node = self._walk(prefix)
        out, stack = [], [(node, prefix)] if node else []
        while stack and len(out) < limit:    # DFS lexicographique
            n, s = stack.pop()
            if n.is_word: out.append(s)
            stack.extend((c, s + ch) for ch, c in reversed(list(n.children.items())))
        return out
    def _walk(self, s):
        node = self.root
        for ch in s:
            node = node.children.get(ch)
            if node is None: return None
        return node

3.5. File de priorité double bout

Médiane d'un flux, en ligne Le problème type : recevoir des nombres un par un et pouvoir interroger la médiane à tout instant. Solution classique par deux tas : un max-tas \(L\) pour la moitié basse, un min-tas \(U\) pour la moitié haute, avec l'invariant \(|L| - |U| \in \{0, 1\}\) et \(\max L \leq \min U\). Insertion \(\mathcal{O}(\log n)\) (placer, puis rééquilibrer en déplaçant la racine d'un tas vers l'autre) ; médiane \(\mathcal{O}(1)\) (racine de \(L\), ou moyenne des deux racines). Cette structure sert au contrôle de dérive des distributions (monitoring de modèles en production) et aux algorithmes médians de k-means.

3.6. Filtres de Bloom

Définition 3.6 — Filtre de Bloom Un tableau de \(m\) bits et \(k\) fonctions de hachage indépendantes. Insertion de \(x\) : mettre à 1 les bits \(h_1(x), \dots, h_k(x)\). Requête « \(x\) a-t-il été inséré ? » : répondre oui si tous ces bits valent 1, non sinon. Réponse non : certaine. Réponse oui : probabiliste (faux positifs possibles, jamais de faux négatifs). Mémoire : \(\mathcal{O}(m)\) bits, indépendamment de la taille des clés.
Taux de faux positifs. Après \(n\) insertions, la probabilité qu'un bit donné soit resté à 0 : \((1 - 1/m)^{kn} \approx e^{-kn/m}\). Un élément absent est déclaré présent si ses \(k\) bits sont à 1 : $$p \;=\; \big(1 - e^{-kn/m}\big)^k.$$ À \(m/n\) fixé (bits par élément), on minimise en dérivant en \(k\) : optimum pour \(k^\star = \frac mn \ln 2\), donnant \(p^\star \approx (0{,}6185)^{m/n}\) — exponentiellement petit en le nombre de bits par élément : avec 10 bits/élément et \(k = 7\), \(p \approx 0{,}008\). C'est la même arithmétique que les probabilités d'indépendance approximative du cours de statistiques (chapitre 1 du module Statistics) — appliquée aux bits. ∎
Exemple 3.7 — Déduplication de crawling 
import hashlib
class Bloom:
    def __init__(self, m_bits, k):
        self.m, self.k, self.bits = m_bits, k, bytearray(m_bits // 8 + 1)
    def _pos(self, x, i):
        h = hashlib.sha256(f"{i}:{x}".encode()).digest()
        return int.from_bytes(h[:8], "big") % self.m
    def add(self, x):
        for i in range(self.k):
            p = self._pos(x, i); self.bits[p // 8] |= 1 << (p % 8)
    def might_contain(self, x):
        return all(self.bits[p // 8] & (1 << (p % 8)) for p in map(lambda i: self._pos(x, i), range(self.k)))

4.1. Quicksort : partition in place et analyse

def quicksort(a, lo=0, hi=None):
    if hi is None: hi = len(a) - 1
    if lo >= hi: return a
    p = partition(a, lo, hi)          # pivot a sa place definitive
    quicksort(a, lo, p - 1)           # tout a gauche < pivot
    quicksort(a, p + 1, hi)           # tout a droite >= pivot
    return a

def partition(a, lo, hi):
    """Partition de Lomuto : pivot = a[hi], en place, O(hi-lo)."""
    pivot, i = a[hi], lo
    for j in range(lo, hi):
        if a[j] < pivot:              # maintenir l'invariant :
            a[i], a[j] = a[j], a[i]   # a[lo..i-1] < pivot
            i += 1                    # a[i..j-1] >= pivot
    a[i], a[hi] = a[hi], a[i]         # placer le pivot entre les deux
    return i
Proposition 4.1 — Complexité moyenne \(\Theta(n \log n)\), pire cas \(\Theta(n^2)\) Pire cas (pivot toujours extrémal, ex. tableau déjà trié avec pivot en dernière position) : récurrence \(T(n) = T(n-1) + \mathcal{O}(n) = \Theta(n^2)\). En moyenne (pivot uniforme) : récurrence aléatoire $$T(n) = n - 1 + \frac{1}{n}\sum_{k=0}^{n-1}\big(T(k) + T(n-1-k)\big),$$ car le rang du pivot est uniforme. En multipliant par \(n\) puis en soustrayant les équations pour \(n\) et \(n-1\) (technique de télescopage), on obtient \(\frac{T(n)}{n+1} = \frac{T(n-1)}{n} + \frac{2}{n+1}\), d'où \(T(n) = 2(n+1)H_n - 4n \approx 1{,}39\, n \log_2 n\) : optimal à 39 % près (la constante du tri fusion est \(n\log_2 n\), la borne informationnelle \(\log_2 n! \approx n\log_2 n - 1{,}44 n\)).
Mitigations du pire cas (i) Pivot aléatoire : le pire cas devient un événement de probabilité négligeable — l'analyse passe du « adversaire choisit l'entrée » au « l'algorithme choisit le pivot ». (ii) Médiane de trois (lo/milieu/hi). (iii) Introsort (C++ std::sort) : quicksort, bascule en heapsort si la profondeur dépasse \(2\log n\) — garantit \(\mathcal{O}(n\log n)\) et garde la vitesse pratique. Python utilise Timsort (hybride fusion/insertion, exploite les runs triés, stable) : \(\Theta(n)\) sur les données presque triées.

4.2. Tri fusion et comptage d'inversions

Proposition 4.2 — Mergesort Diviser au milieu, trier chaque moitié, fusionner en \(\Theta(n)\) : récurrence \(2T(n/2) + n\), donc \(\Theta(n \log n)\) garanti (théorème 2.2). Stable (l'ordre relatif des éléments égaux est préservé — indispensable pour les tris multi-critères : trier par score puis par date laisse les scores groupés par date). Coût : \(\Theta(n)\) mémoire auxiliaire.
Exemple 4.3 — Bonus : compter les inversions en \(\Theta(n\log n)\) Une inversion est un couple \((i,j)\), \(i \lt j\), avec \(a_i > a_j\) — mesure de désordre (corrélation de Kendall entre deux classements : utile pour comparer des rankings de modèles ou de moteurs de recherche). La force brute compte en \(\mathcal{O}(n^2)\) ; le tri fusion instrumenté fait mieux : 
def count_inversions(a):
    if len(a) <= 1: return a, 0
    mid = len(a) // 2
    left,  cl = count_inversions(a[:mid])
    right, cr = count_inversions(a[mid:])
    merged, cross = [], 0
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            merged.append(left[i]); i += 1
        else:                              # left[i] > right[j] :
            merged.append(right[j]); j += 1
            cross += len(left) - i          # tous ces elements forment une inversion
    return merged + left[i:] + right[j:], cl + cr + cross

count_inversions([5, 4, 3, 2, 1])   # -> 10 = C(5,2) : ordre totalement inverse
Chaque fois qu'un élément droit passe devant des éléments gauches restants, cela compte exactement les inversions inter-blocs ; les inversions intra-blocs sont comptées par la récursion.

4.3. Radix sort : trier sans comparer

Proposition 4.4 — Tri par base (LSD) Pour \(n\) entiers de \(k\) chiffres en base \(b\) : \(k\) passes de tri stable par chiffre (bucket par valeur de chiffre), chacune \(\Theta(n + b)\) : $$T = \Theta\big(k\,(n + b)\big) \;\approx\; \Theta(n \cdot k).$$ Sans comparaison — la borne inférieure \(\Omega(n\log n)\) des tris par comparaisons (arbre de décision à \(n!\) feuilles) ne s'applique pas. Pour des clés 64 bits (\(k = 8\) octets), c'est \(\Theta(8n)\), linéaire en pratique. Usage : trier des identifiants de tokens, des adresses IP, des couples (cluster, distance) dans les k-means accélérés. Inconvénient : mémoire \(\Theta(n+b)\) et efficacité qui s'effondre si \(k\) grandit (clés longues, flottants).

4.4. Sélection : la médiane en \(\Theta(n)\) attendu

Proposition 4.5 — Quickselect Pour trouver le \(k\)-ième plus petit élément : partitionner comme quicksort, mais ne récursiver que du côté où se trouve le rang \(k\). Récurrence moyenne \(T(n) = T(\text{fraction de } n) + \mathcal{O}(n)\), avec fractions espérées \(\to\) \(T(n) = \Theta(n)\) (chaque niveau divise au moins par ~2 en moyenne, et les tailles somment géométriquement). C'est la médiane du k-médianoïde, le quantile rapide des statistiques d'ordre (module Statistics, chapitre 3) ; la variante déterministe « médiane des médianes » garantit le pire cas \(\Theta(n)\) au prix de constantes lourdes.

4.5. Dichotomie : invariant de boucle et dérivés

def binary_search(a, x):           # a trie croissant
    lo, hi = 0, len(a)             # recherche dans [lo, hi)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] == x: return mid
        elif a[mid] < x: lo = mid + 1
        else:            hi = mid
    return -1
Correction par invariant. Invariant : « si \(x\) est dans \(a\), alors \(x\) se trouve dans \(a[lo..hi)\) ». Initialisation : \(lo=0, hi=n\), la tranche est tout le tableau — vrai. Conservation : si \(a[mid] < x\), le tableau étant trié, tous les \(a[lo..mid]\) sont \(< x\), donc \(x \notin a[lo..mid]\) et l'invariant tient pour \([mid+1, hi)\) ; symétriquement si \(a[mid] > x\). Terminaison : \(hi - lo\) décroît strictement à chaque itération (au moins 1). À la sortie, la tranche est vide : soit on a trouvé \(x\) plus tôt, soit \(x\) est absent. Complexité : la taille est au moins divisée par 2 à chaque pas, d'où \(\Theta(\log n)\). ∎
Exemple 4.6 — Binary search sur la réponse Pattern transverse : quand la propriété « \(\leq c\) » est monotone en \(c\), on cherche le seuil par dichotomie au lieu de le calculer. Exemple : \(n\) tâches de durées \(d_i\), \(k\) machines, minimiser le makespan (charge max). 
def feasible(d, k, cap):                 # glouton : peut-on tout placer
    load, machines = 0, 1                # avec chaque machine <= cap ?
    for t in d:
        if t > cap: return False
        if load + t > cap: machines += 1; load = t
        else: load += t
    return machines <= k

def min_makespan(d, k):
    lo, hi = max(d), sum(d)              # bornes triviales
    while lo < hi:                       # meme squelette que binary_search
        mid = (lo + hi) // 2
        if feasible(d, k, mid): hi = mid
        else: lo = mid + 1
    return lo                            # plus petite capacite faisable
L'invariant devient « \([lo, hi]\) contient la plus petite capacité faisable ». Même schéma : racine \(k\)-ième par encadrement, recherche du \(\varepsilon\) de régularisation optimal, apprentissage du seuil de coupure optimal d'un classifieur — et, en RL/module Optimal Transport, la recherche du multiplicateur de Lagrange dans les projections entropiques.

  • Réduction mémoire : la table \(m \times n\) de Levenshtein se réduit à deux lignes (\(\mathcal{O}(\min(m,n))\)) car chaque cellule ne dépend que de la ligne précédente.
Exemple 4.7 — Distance d'édition (DP) 
def levenshtein(a, b):
    m, n = len(a), len(b)
    dp = [[0]*(n+1) for _ in range(m+1)]
    for i in range(m+1): dp[i][0] = i
    for j in range(n+1): dp[0][j] = j
    for i in range(1, m+1):
        for j in range(1, n+1):
            cost = 0 if a[i-1] == b[j-1] else 1
            dp[i][j] = min(dp[i-1][j] + 1,        # suppression
                           dp[i][j-1] + 1,        # insertion
                           dp[i-1][j-1] + cost)   # substitution
    return dp[m][n]          # O(m n) temps et mémoire (réductible à O(min(m,n)))

5. Algorithmes de graphes

Le module le plus important de ce refresher : le master s'appelle Large Language Models, Graphs and Applications. On réutilise l'objet « graphe » pendant deux ans ; il faut être à l'aise avec ses représentations et ses algorithmes classiques — et avec leurs preuves, car les GNN du module Graph ML héritent directement de cette combinatoire.

Définition 5.1 — Graphe Un graphe \(G = (V, E)\) est un ensemble de sommets \(V\) et un ensemble d'arêtes \(E \subseteq V \times V\). Il est non orienté si les arêtes sont symétriques, orienté sinon ; pondéré si chaque arête porte un poids \(w : E \to \mathbb{R}\). Le voisinage de \(v\) est \(\mathcal{N}(v) = \{u : (v,u) \in E\}\), son degré est \(|\mathcal{N}(v)|\).

5.2. Parcours en largeur et en profondeur

from collections import deque

def bfs(adj, s):
    """Parcours en largeur : distances (non pondérées) et parents depuis s. O(|V|+|E|)"""
    dist, parent = {s: 0}, {s: None}
    q = deque([s])
    while q:
        u = q.popleft()
        for v in adj[u]:
            if v not in dist:
                dist[v], parent[v] = dist[u] + 1, u
                q.append(v)
    return dist, parent

def dfs(adj, u, visited=None):
    """Parcours en profondeur (récursif) : composantes connexes, cycles, tri topologique."""
    visited = visited if visited is not None else set()
    visited.add(u)
    for v in adj[u]:
        if v not in visited:
            dfs(adj, v, visited)
    return visited
BFS calcule les distances exactes. Par récurrence forte sur \(d\) : tous les sommets à distance \(d\) sont découverts à la profondeur \(d\) de la file, et aucun plus tôt. Initialisation : \(s\), distance 0, découvert à la profondeur 0. Hérédité : un sommet \(v\) à distance \(d+1\) a un prédécesseur \(u\) à distance \(d\) sur un plus court chemin ; par hypothèse de récurrence \(u\) est découvert à la profondeur \(d\) avec \(\mathrm{dist}[u] = d\), et \(v\) (pas encore découvert, sinon il serait plus proche) reçoit \(\mathrm{dist}[v] = d+1\). La file sortant par ordre de découverte, les profondeurs sont croissantes : cohérence totale. De plus, l'arbre des parents \(\{v \to \mathrm{parent}[v]\}\) contient un plus court chemin de \(s\) à chaque sommet atteint. ∎
DFS énumère les composantes connexes. Le DFS depuis \(s\) visite exactement l'ensemble des sommets reliés à \(s\) (toute arête traversée maintient la connexité ; réciproquement un sommet non visité après l'appel n'a aucun chemin vers \(s\), sinon l'arête « de sortie » de sa composante aurait été proposée au parcours). En relançant dfs sur chaque sommet non visité, on partitionne \(V\) : \(\mathcal{O}(|V|+|E|)\) au total. ∎

5.3. Tri topologique d'un DAG (algorithme de Kahn)

from collections import deque

def topo_sort(adj, n):
    """adj oriente sans cycle ; renvoie un ordre tel que u -> v implique u avant v."""
    indeg = [0] * n
    for u in adj:
        for v in adj[u]: indeg[v] += 1
    q = deque(u for u in range(n) if indeg[u] == 0)
    order = []
    while q:
        u = q.popleft(); order.append(u)
        for v in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0: q.append(v)
    return order if len(order) == n else None   # None => il y a un cycle

# Workflow d'agents ( orchestration de LLMs ) :
dag = {0: [1, 2], 1: [3], 2: [3], 3: []}        # fetch -> {chunk, enrich} -> index
print(topo_sort(dag, 4))                        # [0, 1, 2, 3] ou [0, 2, 1, 3]
Correction. Invariant : tout sommet entre dans la file seulement quand tous ses prédécesseurs ont été émis ; donc chaque émission respecte les arêtes déjà traitées, et par induction sur l'ordre d'émission, l'ordre final est topologique. Complétude. Un DAG a toujours un sommet de degré entrant nul (sinon, en remontant les arêtes entrantes indéfiniment, on revisiterait un sommet : cycle). Si l'algorithme bloque avec \(\mathrm{len}(\mathrm{order}) \lt; n\), les sommets restants forment un sous-graphe de degrés entrants tous \(> 0\) dans ce sous-graphe : il contient un cycle. L'algorithme est donc aussi un détecteur de cycles. ∎

5.4. Plus courts chemins

Théorème 5.2 — Dijkstra (poids \(\geq 0\)), avec tas La version « paresseuse » ci-dessous calcule toutes les distances depuis \(s\) en \(\mathcal{O}((|V|+|E|)\log |V|)\). 
import heapq

def dijkstra(adj_w, s):           # adj_w[u] = [(v, w_uv), ...]
    dist = {s: 0.0}; pq = [(0.0, s)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist.get(u, float("inf")):
            continue               # entrée périmée
        for v, w in adj_w[u]:
            nd = d + w
            if nd < dist.get(v, float("inf")):
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist                    # dist[v] = plus courte distance s -> v
Invariant de correction. On prouve que tout sommet \(u\) extrait du tas avec \(d = \mathrm{dist}[u]\) est définitif : \(\mathrm{dist}[u] = \delta(s,u)\) (distance optimale). Supposons le contraire et prenons le premier sommet \(u\) extrait avec \(\mathrm{dist}[u] > \delta(s,u)\) ; soit \(P\) un plus court chemin \(s \to u\), et \(x\) le premier sommet de \(P\) non définitif, de prédécesseur \(y \in P\) définitif. Au moment où \(y\) est devenu définitif, la relaxation de \((y,x)\) a posé \(\mathrm{dist}[x] \leq \delta(s,y) + w(y,x) = \delta(s,x)\) ; or \(x\) est sur un plus court chemin vers \(u\), et les préfixes de plus courts chemins sont optimaux, donc \(\delta(s,x) \leq \delta(s,u)\). En chaînant : \(\mathrm{dist}[x] \leq \delta(s,u) < \mathrm{dist}[u]\). Mais alors \(x\), de clé plus petite, aurait été extrait avant \(u\) : contradiction. Les entrées périmées du tas sont simplement ignorées (test d > dist[u]). ∎
A* : Dijkstra guidé A* oriente la recherche vers la cible en extrayant selon \(f(v) = \mathrm{dist}[v] + h(v)\), où \(h\) est une heuristique (estimation du coût restant). Si \(h\) est admissible (\(h(v) \leq \delta(v, t)\), ne surestime jamais) et cohérente (\(h(u) \leq w(u,v) + h(v)\)), A* est optimal et développe moins de sommets que Dijkstra ; avec \(h = 0\) on retrouve Dijkstra exactement. Usage : jeux, routage, planification de mouvement robotique, recherche beam des LLMs décodage (l'esprit « guider la recherche », cf. module LLMs M2).
Théorème 5.3 — Bellman-Ford : poids négatifs, cycles négatifs \(n - 1\) passes de relaxation de toutes les arêtes suffisent à converger vers les distances exactes (si aucun cycle négatif atteignable), en \(\mathcal{O}(|V| \, |E|)\). Une \(n\)-ième passe qui améliore encore quelque distance révèle un cycle négatif atteignable.
Esquisse. Par récurrence sur \(i\) : après la \(i\)-ième passe, tout plus court chemin à \(\leq i\) arêtes est correct (la passe \(i\) relaxe la dernière arête d'un chemin à \(i\) arêtes dont le préfixe est déjà correct). Un plus court chemin simple a au plus \(|V| - 1\) arêtes : \(|V|-1\) passes suffisent. Si la passe \(|V|\) améliore encore, c'est qu'un chemin améliorant a \(\geq |V|\) arêtes : il répète un sommet, et le cycle ainsi fermé est de poids strictement négatif — on peut alors le parcourir indéfiniment, aucune distance finie n'est optimale. La relaxation répétée \(V(s) = \max_a [r + V(s')]\) annonce la programmation dynamique de Bellman en RL (module RL), où les « passes » s'appellent des itérations de valeur. ∎ 
def bellman_ford(n, edges, s):          # edges = [(u, v, w), ...]
    dist = [float("inf")] * n; dist[s] = 0.0
    for _ in range(n - 1):
        changed = False
        for u, v, w in edges:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w; changed = True
        if not changed: break            # convergence anticipee
    for u, v, w in edges:                # detection de cycle negatif
        if dist[u] + w < dist[v]:
            return None                  # atteignable depuis s
    return dist
Proposition 5.4 — Cas particuliers et généralisations
  • DAG : tri topologique + une passe de relaxation dans l'ordre — \(\mathcal{O}(|V|+|E|)\), poids négatifs inclus (pas de cycle, donc aucun problème). C'est l'algorithme de l'ordonnancement de tâches au plus tôt (chemin critique).
  • Floyd-Warshall : toutes les paires par DP sur les sommets intermédiaires — \(d^{(k)}_{ij} = \min(d^{(k-1)}_{ij}, d^{(k-1)}_{ik} + d^{(k-1)}_{kj})\), \(\mathcal{O}(n^3)\) temps / \(\mathcal{O}(n^2)\) mémoire. Pour \(n \leq\) ~1000, c'est souvent le plus simple ; matriciel, il se vectorise en NumPy (min-plus produit — module Optimal Transport, structure de distance).

5.5. Arbres couvrants minimaux (MST)

Proposition 5.5 — Kruskal et Prim
  • Kruskal : trier les arêtes, ajouter celle qui ne crée pas de cycle (union-find), \(\mathcal{O}(|E|\log|E|)\).
  • Prim : faire croître une composante par extractions de tas, \(\mathcal{O}((|V|+|E|)\log|V|)\) — Dijkstra sur poids = arêtes.
  • Correction (propriété de coupe) : pour toute coupe \((S, V \setminus S)\), l'arête de poids minimum traversant la coupe appartient à un MST. Preuve : sinon, l'ajouter à un MST crée un cycle, qui traverse la coupe une autre fois par une arête plus lourde qu'on échange contre elle — MST plus léger : contradiction. Kruskal applique cette propriété coupe par coupe (chaque ajout isole un nouveau sommet ou fusionne deux composantes par leur arête légère).
Applications : réseaux (électricité, fibre) au coût minimal, clustering single-link (couper les \(k-1\) plus grosses arêtes du MST — approche historique du clustering de graphes, cf. module Graph ML), approximation du TSP factor 2 (doublement du MST + marche eulérienne).

5.6. Flux max et coupes

Ford-Fulkerson, en intuition Un réseau : capacités \(c(u,v) \geq 0\), une source \(s\), un puits \(t\). Un flot respecte capacités et conservation ; l'algorithme de Ford-Fulkerson répète : trouver un chemin augmentant (dans le graphe résiduel : arêtes avant de capacité restante + arêtes arrière de flot annulable), pousser le maximum le long, jusqu'à blocage. Au blocage, les sommets atteignables dans le résiduel forment une coupe dont la capacité — égale au flot courant — borne tout flot : flot max = coupe min (théorème max-flow min-cut). Avec DFS : \(\mathcal{O}(|f| \cdot |E|)\) ; avec BFS (Edmonds-Karp) : \(\mathcal{O}(|V||E|^2)\) ; Dinic : meilleur encore. Applications : couverture minimale d'images (GrabCut), appariement, fiabilité de réseaux, et le matching biparti : relier gauche et droite avec capacité 1 — un flot maximal de valeur \(k\) est un matching de taille \(k\).
Matching biparti : Hopcroft-Karp Le problème d'affectation (étudiants/projets, workers/tâches, utilisateurs/objets) est un matching dans un graphe biparti. L'algorithme de Hopcroft-Karp trouve le matching maximal en \(\mathcal{O}(|E|\sqrt{|V|})\) par vagues de chemins augmentants disjoints. En pratique : scipy.sparse.csgraph.maximum_bipartite_matching ou la forme hongroise (affectation pondérée, \(\mathcal{O}(n^3)\)) — qu'on retrouvera comme sous-produit du transport optimal discret (module Optimal Transport, où le couplage optimal pondéré généralise le matching).

5.7. Détection de communautés : label propagation

import random

def label_propagation(adj, n, rounds=20, seed=0):
    """Chaque sommet adopte le label majoritaire de ses voisins ; consensus = communaute."""
    rng = random.Random(seed)
    labels = list(range(n))                        # initialisation distincte
    for _ in range(rounds):
        order = list(range(n)); rng.shuffle(order) # mise a jour asynchrone
        for u in order:
            if adj[u]:
                counts = {}
                for v in adj[u]:
                    counts[labels[v]] = counts.get(labels[v], 0) + 1
                labels[u] = max(counts, key=counts.get)
    return labels
# Simple, quasi lineaire, sans parametre — baseline des methodes de communautes ;
# le module Graph ML montera en gamme : modulaire de Louvain, spectral, GNN.

8.1. Primitives : orientation par produit vectoriel

Définition 8.1 — Test d'orientation Pour trois points \(A, B, C\) du plan, le signe du déterminant $$\mathrm{orient}(A,B,C) \;=\; \operatorname{signe}\det\begin{pmatrix} B_x - A_x & C_x - A_x \\ B_y - A_y & C_y - A_y \end{pmatrix}$$ dit si le chemin \(A \to B \to C\) tourne à gauche (positif), à droite (négatif), ou est aligné (nul) : c'est le produit vectoriel \((B-A) \times (C-A)\) projeté sur l'axe sortant. Coût : trois soustractions, deux multiplications, une comparaison — la brique de tous les algorithmes de ce chapitre. 
def orient(a, b, c):
    """> 0 : contre-montre (gauche) ; < 0 : droite ; = 0 : aligne."""
    return (b[0]-a[0])*(c[1]-a[1]) - (b[1]-a[1])*(c[0]-a[0])
Précision Le calcul flottant de l'orientation peut mentir pour des points quasi alignés : les implémentations robustes (CGAL) utilisent des prédicats exacts en arithmétique rationnelle pour les cas limites — au master, float64 + marge \(\varepsilon\) suffisent aux TP, mais sachez que le sujet existe (cf. module Geometric DL M2 pour les géométries non euclidiennes).

8.2. Enveloppe convexe : Jarvis puis Graham

Proposition 8.2 — Gift wrapping (marche de Jarvis), \(\mathcal{O}(nh)\) Partir du point le plus à gauche ; à chaque étape, choisir parmi tous les points celui qui est « le plus à droite » vu du point courant (minimiser l'angle polaire relativement à la direction précédente) : c'est le prochain sommet de l'enveloppe. S'arrête au retour au départ. \(h\) = nombre de sommets de l'enveloppe : linéaire par sommet produit.
Théorème 8.3 — Graham scan, \(\mathcal{O}(n \log n) Trier les points par angle autour d'un pivot (le plus bas), puis parcourir en maintenant une pile : si le trio (avant-dernier, dernier, nouveau) tourne à droite, dépiler. À la fin, la pile contient l'enveloppe convexe.
Invariant : après le traitement du \(k\)-ième point, la pile contient exactement l'enveloppe convexe des \(k\) premiers points (triés angulairement). Initialisation : les deux premiers points. Conservation : le nouveau point \(p\) est à l'extérieur de l'angle formé au sommet de la pile ; si \(\mathrm{orient}(q_{m-1}, q_m, p) \leq 0\) (tour à droite ou alignement), alors \(q_m\) est à l'intérieur du triangle \((q_{m-1}, p_{\text{suivant eventual}}, p)\) — plus précisément dans le demi-plan convexe balayé — et ne peut pas être un sommet de l'enveloppe de \(\{p_1,\dots,p_k\}\) : le dépiler restaure la convexité ; on répète tant que la pile « tourne à droite ». L'alignement (\(=0\)) doit dépiler aussi (point cocyclique sur une arête : garder un seul représentant). Terminaison : chaque point est empilé une fois, dépilé au plus une fois : \(\mathcal{O}(n)\) après le tri \(\mathcal{O}(n\log n)\). ∎ 
import math

def graham_scan(points):
    pts = sorted(set(points), key=lambda p: (p[1], p[0]))   # pivot le plus bas
    pivot = pts[0]
    rest = sorted(pts[1:],
                  key=lambda p: math.atan2(p[1]-pivot[1], p[0]-pivot[0]))  # par angle
    hull = [pivot]
    for p in rest:
        while len(hull) >= 2 and orient(hull[-2], hull[-1], p) <= 0:
            hull.pop()                       # tourne a droite ou aligne : evict
        hull.append(p)
    return hull

8.3. Paire de points la plus proche

Proposition 8.4 — Diviser pour régner en \(\mathcal{O}(n\log n)\) Tri par abscisse, coupe médiane, récursion sur les deux moitiés (\(d\) = meilleur des deux), puis examen de la bande verticale de largeur \(2d\) autour de la médiane : triée par ordonnée, chaque point n'a à être comparé qu'aux \(\leq 7\) suivants (sinon des points de la même moitié seraient plus proches que \(d\), contradiction dans un carré de côté \(d\)). 8.4. Triangulations et Delaunay

Définition 8.5 — Triangulation de Delaunay Une triangulation d'un ensemble de points est de Delaunay si pour chaque triangle, son cercle circonscrit est vide : aucun autre point du nuage n'est à son intérieur. Le dual de la construction est le diagramme de Voronoi (cellules des points plus proches d'un site que de tout autre) : les sites dont les cellules de Voronoi partagent une arête sont reliés dans Delaunay.
Pourquoi Delaunay ? Propriétés et algorithme par flips
  • Qualité des triangles : parmi toutes les triangulations, Delaunay maximise le plus petit angle (évite les triangles « ficelle ») — d'où son rôle central en éléments finis : des triangles bien conditionnés stabilisent les simulations numériques.
  • Algorithme par flips : toute arête partagée par deux triangles formant un quadrilatère non convexe-vide peut être flippée (remplacée par l'autre diagonale) pour restaurer la propriété de cercle vide ; l'énergie (somme des angles opposés) augmente strictement à chaque flip, donc le processus converge en un nombre fini de flips — la structure locale dicte la géométrie globale, exactement comme les relaxations locales des chapitres 5 (flux) et du label propagation.
  • Raffinement de Delaunay (Ruppert, Chew) : insérer itérativement le centre des cercles circonscrits « trop gros » produit des maillages de qualité garantie — la base de la mesh generation industrielle (voir les travaux ci-dessous).
  • En Python : scipy.spatial.Delaunay (Qhull) ; le graphe de Delaunay d'un nuage de points est un graphe — et l'on retombe sur le chapitre 5 : c'est un candidat naturel de « graphe de proximité » pour un GNN sur données géométriques.

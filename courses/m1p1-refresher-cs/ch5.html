5. Algorithmes de graphes

Le module le plus important de ce refresher : le master s'appelle Large Language Models, Graphs and Applications. On réutilise l'objet « graphe » pendant deux ans ; il faut être à l'aise avec ses représentations et ses algorithmes classiques — et avec leurs preuves, car les GNN du module Graph ML héritent directement de cette combinatoire.

Définition 5.1 — Graphe Un graphe \(G = (V, E)\) est un ensemble de sommets \(V\) et un ensemble d'arêtes \(E \subseteq V \times V\). Il est non orienté si les arêtes sont symétriques, orienté sinon ; pondéré si chaque arête porte un poids \(w : E \to \mathbb{R}\). Le voisinage de \(v\) est \(\mathcal{N}(v) = \{u : (v,u) \in E\}\), son degré est \(|\mathcal{N}(v)|\).

5.1. Représentations : listes, matrice, CSR

import numpy as np
from scipy import sparse

# 1) Listes d'adjacence (référence en pratique — networkx, PyG)
adj = {0: [1, 2], 1: [0, 2], 2: [0, 1, 3], 3: [2]}

# 2) Matrice d'adjacence (dense O(|V|^2) mémoire, mais algèbre !)
A = np.array([[0, 1, 1, 0],
              [1, 0, 1, 0],
              [1, 1, 0, 1],
              [0, 0, 1, 0]])
print((A @ A)[0, 3] > 0)   # True : il existe un chemin de longueur 2 entre 0 et 3

# 3) CSR (Compressed Sparse Row) : trois tableaux, le format des vrais graphes
#    indptr[i] .. indptr[i+1] = plage des voisins de i dans indices[]
rows  = np.array([0, 0, 1, 1, 2, 2, 2, 3], dtype=np.int32)   # COO : par arête
cols  = np.array([1, 2, 0, 2, 0, 1, 3, 2], dtype=np.int32)
A_csr = sparse.coo_matrix((np.ones(8), (rows, cols))).tocsr()
print(A_csr.indptr, A_csr.indices)   # [0 2 4 7 8] [1 2 0 2 0 1 3 2]
# Cora (reseau de citations) : ~5k sommets, ~20k arêtes :
#   dense = 270 Mo de zeros ; CSR = quelques centaines de Ko.
Pourquoi trois représentations ? Listes d'adjacence → parcours efficaces en \(\mathcal{O}(|V|+|E|)\) ; matrice dense → propriétés spectrales (\(A^k\) compte les chemins, base du module Graph ML) ; CSR/sparse → passage à l'échelle et format natif de PyTorch Geometric (les messages d'un GNN se propagent exactement comme un produit matriciel sparse). Savoir passer de l'une à l'autre est un réflexe du master.

5.2. Parcours en largeur et en profondeur

from collections import deque

def bfs(adj, s):
    """Parcours en largeur : distances (non pondérées) et parents depuis s. O(|V|+|E|)"""
    dist, parent = {s: 0}, {s: None}
    q = deque([s])
    while q:
        u = q.popleft()
        for v in adj[u]:
            if v not in dist:
                dist[v], parent[v] = dist[u] + 1, u
                q.append(v)
    return dist, parent

def dfs(adj, u, visited=None):
    """Parcours en profondeur (récursif) : composantes connexes, cycles, tri topologique."""
    visited = visited if visited is not None else set()
    visited.add(u)
    for v in adj[u]:
        if v not in visited:
            dfs(adj, v, visited)
    return visited
BFS calcule les distances exactes. Par récurrence forte sur \(d\) : tous les sommets à distance \(d\) sont découverts à la profondeur \(d\) de la file, et aucun plus tôt. Initialisation : \(s\), distance 0, découvert à la profondeur 0. Hérédité : un sommet \(v\) à distance \(d+1\) a un prédécesseur \(u\) à distance \(d\) sur un plus court chemin ; par hypothèse de récurrence \(u\) est découvert à la profondeur \(d\) avec \(\mathrm{dist}[u] = d\), et \(v\) (pas encore découvert, sinon il serait plus proche) reçoit \(\mathrm{dist}[v] = d+1\). La file sortant par ordre de découverte, les profondeurs sont croissantes : cohérence totale. De plus, l'arbre des parents \(\{v \to \mathrm{parent}[v]\}\) contient un plus court chemin de \(s\) à chaque sommet atteint. ∎
DFS énumère les composantes connexes. Le DFS depuis \(s\) visite exactement l'ensemble des sommets reliés à \(s\) (toute arête traversée maintient la connexité ; réciproquement un sommet non visité après l'appel n'a aucun chemin vers \(s\), sinon l'arête « de sortie » de sa composante aurait été proposée au parcours). En relançant dfs sur chaque sommet non visité, on partitionne \(V\) : \(\mathcal{O}(|V|+|E|)\) au total. ∎

5.3. Tri topologique d'un DAG (algorithme de Kahn)

from collections import deque

def topo_sort(adj, n):
    """adj oriente sans cycle ; renvoie un ordre tel que u -> v implique u avant v."""
    indeg = [0] * n
    for u in adj:
        for v in adj[u]: indeg[v] += 1
    q = deque(u for u in range(n) if indeg[u] == 0)
    order = []
    while q:
        u = q.popleft(); order.append(u)
        for v in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0: q.append(v)
    return order if len(order) == n else None   # None => il y a un cycle

# Workflow d'agents ( orchestration de LLMs ) :
dag = {0: [1, 2], 1: [3], 2: [3], 3: []}        # fetch -> {chunk, enrich} -> index
print(topo_sort(dag, 4))                        # [0, 1, 2, 3] ou [0, 2, 1, 3]
Correction. Invariant : tout sommet entre dans la file seulement quand tous ses prédécesseurs ont été émis ; donc chaque émission respecte les arêtes déjà traitées, et par induction sur l'ordre d'émission, l'ordre final est topologique. Complétude. Un DAG a toujours un sommet de degré entrant nul (sinon, en remontant les arêtes entrantes indéfiniment, on revisiterait un sommet : cycle). Si l'algorithme bloque avec \(\mathrm{len}(\mathrm{order}) \lt; n\), les sommets restants forment un sous-graphe de degrés entrants tous \(> 0\) dans ce sous-graphe : il contient un cycle. L'algorithme est donc aussi un détecteur de cycles. ∎

5.4. Plus courts chemins

Théorème 5.2 — Dijkstra (poids \(\geq 0\)), avec tas La version « paresseuse » ci-dessous calcule toutes les distances depuis \(s\) en \(\mathcal{O}((|V|+|E|)\log |V|)\). 
import heapq

def dijkstra(adj_w, s):           # adj_w[u] = [(v, w_uv), ...]
    dist = {s: 0.0}; pq = [(0.0, s)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist.get(u, float("inf")):
            continue               # entrée périmée
        for v, w in adj_w[u]:
            nd = d + w
            if nd < dist.get(v, float("inf")):
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist                    # dist[v] = plus courte distance s -> v
Invariant de correction. On prouve que tout sommet \(u\) extrait du tas avec \(d = \mathrm{dist}[u]\) est définitif : \(\mathrm{dist}[u] = \delta(s,u)\) (distance optimale). Supposons le contraire et prenons le premier sommet \(u\) extrait avec \(\mathrm{dist}[u] > \delta(s,u)\) ; soit \(P\) un plus court chemin \(s \to u\), et \(x\) le premier sommet de \(P\) non définitif, de prédécesseur \(y \in P\) définitif. Au moment où \(y\) est devenu définitif, la relaxation de \((y,x)\) a posé \(\mathrm{dist}[x] \leq \delta(s,y) + w(y,x) = \delta(s,x)\) ; or \(x\) est sur un plus court chemin vers \(u\), et les préfixes de plus courts chemins sont optimaux, donc \(\delta(s,x) \leq \delta(s,u)\). En chaînant : \(\mathrm{dist}[x] \leq \delta(s,u) < \mathrm{dist}[u]\). Mais alors \(x\), de clé plus petite, aurait été extrait avant \(u\) : contradiction. Les entrées périmées du tas sont simplement ignorées (test d > dist[u]). ∎
A* : Dijkstra guidé A* oriente la recherche vers la cible en extrayant selon \(f(v) = \mathrm{dist}[v] + h(v)\), où \(h\) est une heuristique (estimation du coût restant). Si \(h\) est admissible (\(h(v) \leq \delta(v, t)\), ne surestime jamais) et cohérente (\(h(u) \leq w(u,v) + h(v)\)), A* est optimal et développe moins de sommets que Dijkstra ; avec \(h = 0\) on retrouve Dijkstra exactement. Usage : jeux, routage, planification de mouvement robotique, recherche beam des LLMs décodage (l'esprit « guider la recherche », cf. module LLMs M2).
Théorème 5.3 — Bellman-Ford : poids négatifs, cycles négatifs \(n - 1\) passes de relaxation de toutes les arêtes suffisent à converger vers les distances exactes (si aucun cycle négatif atteignable), en \(\mathcal{O}(|V| \, |E|)\). Une \(n\)-ième passe qui améliore encore quelque distance révèle un cycle négatif atteignable.
Esquisse. Par récurrence sur \(i\) : après la \(i\)-ième passe, tout plus court chemin à \(\leq i\) arêtes est correct (la passe \(i\) relaxe la dernière arête d'un chemin à \(i\) arêtes dont le préfixe est déjà correct). Un plus court chemin simple a au plus \(|V| - 1\) arêtes : \(|V|-1\) passes suffisent. Si la passe \(|V|\) améliore encore, c'est qu'un chemin améliorant a \(\geq |V|\) arêtes : il répète un sommet, et le cycle ainsi fermé est de poids strictement négatif — on peut alors le parcourir indéfiniment, aucune distance finie n'est optimale. La relaxation répétée \(V(s) = \max_a [r + V(s')]\) annonce la programmation dynamique de Bellman en RL (module RL), où les « passes » s'appellent des itérations de valeur. ∎ 
def bellman_ford(n, edges, s):          # edges = [(u, v, w), ...]
    dist = [float("inf")] * n; dist[s] = 0.0
    for _ in range(n - 1):
        changed = False
        for u, v, w in edges:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w; changed = True
        if not changed: break            # convergence anticipee
    for u, v, w in edges:                # detection de cycle negatif
        if dist[u] + w < dist[v]:
            return None                  # atteignable depuis s
    return dist
Proposition 5.4 — Cas particuliers et généralisations
  • DAG : tri topologique + une passe de relaxation dans l'ordre — \(\mathcal{O}(|V|+|E|)\), poids négatifs inclus (pas de cycle, donc aucun problème). C'est l'algorithme de l'ordonnancement de tâches au plus tôt (chemin critique).
  • Floyd-Warshall : toutes les paires par DP sur les sommets intermédiaires — \(d^{(k)}_{ij} = \min(d^{(k-1)}_{ij}, d^{(k-1)}_{ik} + d^{(k-1)}_{kj})\), \(\mathcal{O}(n^3)\) temps / \(\mathcal{O}(n^2)\) mémoire. Pour \(n \leq\) ~1000, c'est souvent le plus simple ; matriciel, il se vectorise en NumPy (min-plus produit — module Optimal Transport, structure de distance).

5.5. Arbres couvrants minimaux (MST)

Proposition 5.5 — Kruskal et Prim
  • Kruskal : trier les arêtes, ajouter celle qui ne crée pas de cycle (union-find), \(\mathcal{O}(|E|\log|E|)\).
  • Prim : faire croître une composante par extractions de tas, \(\mathcal{O}((|V|+|E|)\log|V|)\) — Dijkstra sur poids = arêtes.
  • Correction (propriété de coupe) : pour toute coupe \((S, V \setminus S)\), l'arête de poids minimum traversant la coupe appartient à un MST. Preuve : sinon, l'ajouter à un MST crée un cycle, qui traverse la coupe une autre fois par une arête plus lourde qu'on échange contre elle — MST plus léger : contradiction. Kruskal applique cette propriété coupe par coupe (chaque ajout isole un nouveau sommet ou fusionne deux composantes par leur arête légère).
Applications : réseaux (électricité, fibre) au coût minimal, clustering single-link (couper les \(k-1\) plus grosses arêtes du MST — approche historique du clustering de graphes, cf. module Graph ML), approximation du TSP factor 2 (doublement du MST + marche eulérienne).

5.6. Flux max et coupes

Ford-Fulkerson, en intuition Un réseau : capacités \(c(u,v) \geq 0\), une source \(s\), un puits \(t\). Un flot respecte capacités et conservation ; l'algorithme de Ford-Fulkerson répète : trouver un chemin augmentant (dans le graphe résiduel : arêtes avant de capacité restante + arêtes arrière de flot annulable), pousser le maximum le long, jusqu'à blocage. Au blocage, les sommets atteignables dans le résiduel forment une coupe dont la capacité — égale au flot courant — borne tout flot : flot max = coupe min (théorème max-flow min-cut). Avec DFS : \(\mathcal{O}(|f| \cdot |E|)\) ; avec BFS (Edmonds-Karp) : \(\mathcal{O}(|V||E|^2)\) ; Dinic : meilleur encore. Applications : couverture minimale d'images (GrabCut), appariement, fiabilité de réseaux, et le matching biparti : relier gauche et droite avec capacité 1 — un flot maximal de valeur \(k\) est un matching de taille \(k\).
Matching biparti : Hopcroft-Karp Le problème d'affectation (étudiants/projets, workers/tâches, utilisateurs/objets) est un matching dans un graphe biparti. L'algorithme de Hopcroft-Karp trouve le matching maximal en \(\mathcal{O}(|E|\sqrt{|V|})\) par vagues de chemins augmentants disjoints. En pratique : scipy.sparse.csgraph.maximum_bipartite_matching ou la forme hongroise (affectation pondérée, \(\mathcal{O}(n^3)\)) — qu'on retrouvera comme sous-produit du transport optimal discret (module Optimal Transport, où le couplage optimal pondéré généralise le matching).

5.7. Détection de communautés : label propagation

import random

def label_propagation(adj, n, rounds=20, seed=0):
    """Chaque sommet adopte le label majoritaire de ses voisins ; consensus = communaute."""
    rng = random.Random(seed)
    labels = list(range(n))                        # initialisation distincte
    for _ in range(rounds):
        order = list(range(n)); rng.shuffle(order) # mise a jour asynchrone
        for u in order:
            if adj[u]:
                counts = {}
                for v in adj[u]:
                    counts[labels[v]] = counts.get(labels[v], 0) + 1
                labels[u] = max(counts, key=counts.get)
    return labels
# Simple, quasi lineaire, sans parametre — baseline des methodes de communautes ;
# le module Graph ML montera en gamme : modulaire de Louvain, spectral, GNN.

À retenir — chapitre 5

  • Trois représentations (listes / dense / CSR) et leur coût ; CSR = format PyG.
  • BFS = distances (preuve par induction) ; DFS = composantes ; Kahn = tri topologique + détection de cycles (invariant de degrés).
  • Dijkstra : invariant « extrait = définitif » (preuve par premier contre-exemple) ; A* = heuristique admissible ; Bellman-Ford = relaxation, cycles négatifs ; DAG = topo + une passe ; Floyd-Warshall O(n³).
  • MST : propriété de coupe ; flux max = coupe min ; matching biparti = flux ; label propagation = baseline communautés.

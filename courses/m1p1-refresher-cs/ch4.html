4. Tri, recherche, récursion

4.1 Quicksort : partition in place et analyse

def quicksort(a, lo=0, hi=None):
    if hi is None: hi = len(a) - 1
    if lo >= hi: return a
    p = partition(a, lo, hi)          # pivot a sa place definitive
    quicksort(a, lo, p - 1)           # tout a gauche < pivot
    quicksort(a, p + 1, hi)           # tout a droite >= pivot
    return a

def partition(a, lo, hi):
    """Partition de Lomuto : pivot = a[hi], en place, O(hi-lo)."""
    pivot, i = a[hi], lo
    for j in range(lo, hi):
        if a[j] < pivot:              # maintenir l'invariant :
            a[i], a[j] = a[j], a[i]   # a[lo..i-1] < pivot
            i += 1                    # a[i..j-1] >= pivot
    a[i], a[hi] = a[hi], a[i]         # placer le pivot entre les deux
    return i
Proposition 4.1 — Complexité moyenne \(\Theta(n \log n)\), pire cas \(\Theta(n^2)\) Pire cas (pivot toujours extrémal, ex. tableau déjà trié avec pivot en dernière position) : récurrence \(T(n) = T(n-1) + \mathcal{O}(n) = \Theta(n^2)\). En moyenne (pivot uniforme) : récurrence aléatoire $$T(n) = n - 1 + \frac{1}{n}\sum_{k=0}^{n-1}\big(T(k) + T(n-1-k)\big),$$ car le rang du pivot est uniforme. En multipliant par \(n\) puis en soustrayant les équations pour \(n\) et \(n-1\) (technique de télescopage), on obtient \(\frac{T(n)}{n+1} = \frac{T(n-1)}{n} + \frac{2}{n+1}\), d'où \(T(n) = 2(n+1)H_n - 4n \approx 1{,}39\, n \log_2 n\) : optimal à 39 % près (la constante du tri fusion est \(n\log_2 n\), la borne informationnelle \(\log_2 n! \approx n\log_2 n - 1{,}44 n\)).
Mitigations du pire cas (i) Pivot aléatoire : le pire cas devient un événement de probabilité négligeable — l'analyse passe du « adversaire choisit l'entrée » au « l'algorithme choisit le pivot ». (ii) Médiane de trois (lo/milieu/hi). (iii) Introsort (C++ std::sort) : quicksort, bascule en heapsort si la profondeur dépasse \(2\log n\) — garantit \(\mathcal{O}(n\log n)\) et garde la vitesse pratique. Python utilise Timsort (hybride fusion/insertion, exploite les runs triés, stable) : \(\Theta(n)\) sur les données presque triées.

4.2 Tri fusion et comptage d'inversions

Proposition 4.2 — Mergesort Diviser au milieu, trier chaque moitié, fusionner en \(\Theta(n)\) : récurrence \(2T(n/2) + n\), donc \(\Theta(n \log n)\) garanti (théorème 2.2). Stable (l'ordre relatif des éléments égaux est préservé — indispensable pour les tris multi-critères : trier par score puis par date laisse les scores groupés par date). Coût : \(\Theta(n)\) mémoire auxiliaire.
Exemple 4.3 — Bonus : compter les inversions en \(\Theta(n\log n)\) Une inversion est un couple \((i,j)\), \(i \lt j\), avec \(a_i > a_j\) — mesure de désordre (corrélation de Kendall entre deux classements : utile pour comparer des rankings de modèles ou de moteurs de recherche). La force brute compte en \(\mathcal{O}(n^2)\) ; le tri fusion instrumenté fait mieux : 
def count_inversions(a):
    if len(a) <= 1: return a, 0
    mid = len(a) // 2
    left,  cl = count_inversions(a[:mid])
    right, cr = count_inversions(a[mid:])
    merged, cross = [], 0
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            merged.append(left[i]); i += 1
        else:                              # left[i] > right[j] :
            merged.append(right[j]); j += 1
            cross += len(left) - i          # tous ces elements forment une inversion
    return merged + left[i:] + right[j:], cl + cr + cross

count_inversions([5, 4, 3, 2, 1])   # -> 10 = C(5,2) : ordre totalement inverse
Chaque fois qu'un élément droit passe devant des éléments gauches restants, cela compte exactement les inversions inter-blocs ; les inversions intra-blocs sont comptées par la récursion.

4.3 Radix sort : trier sans comparer

Proposition 4.4 — Tri par base (LSD) Pour \(n\) entiers de \(k\) chiffres en base \(b\) : \(k\) passes de tri stable par chiffre (bucket par valeur de chiffre), chacune \(\Theta(n + b)\) : $$T = \Theta\big(k\,(n + b)\big) \;\approx\; \Theta(n \cdot k).$$ Sans comparaison — la borne inférieure \(\Omega(n\log n)\) des tris par comparaisons (arbre de décision à \(n!\) feuilles) ne s'applique pas. Pour des clés 64 bits (\(k = 8\) octets), c'est \(\Theta(8n)\), linéaire en pratique. Usage : trier des identifiants de tokens, des adresses IP, des couples (cluster, distance) dans les k-means accélérés. Inconvénient : mémoire \(\Theta(n+b)\) et efficacité qui s'effondre si \(k\) grandit (clés longues, flottants).

4.4 Sélection : la médiane en \(\Theta(n)\) attendu

Proposition 4.5 — Quickselect Pour trouver le \(k\)-ième plus petit élément : partitionner comme quicksort, mais ne récursiver que du côté où se trouve le rang \(k\). Récurrence moyenne \(T(n) = T(\text{fraction de } n) + \mathcal{O}(n)\), avec fractions espérées \(\to\) \(T(n) = \Theta(n)\) (chaque niveau divise au moins par ~2 en moyenne, et les tailles somment géométriquement). C'est la médiane du k-médianoïde, le quantile rapide des statistiques d'ordre (module Statistics, chapitre 3) ; la variante déterministe « médiane des médianes » garantit le pire cas \(\Theta(n)\) au prix de constantes lourdes.

4.5 Dichotomie : invariant de boucle et dérivés

def binary_search(a, x):           # a trie croissant
    lo, hi = 0, len(a)             # recherche dans [lo, hi)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] == x: return mid
        elif a[mid] < x: lo = mid + 1
        else:            hi = mid
    return -1
Correction par invariant. Invariant : « si \(x\) est dans \(a\), alors \(x\) se trouve dans \(a[lo..hi)\) ». Initialisation : \(lo=0, hi=n\), la tranche est tout le tableau — vrai. Conservation : si \(a[mid] < x\), le tableau étant trié, tous les \(a[lo..mid]\) sont \(< x\), donc \(x \notin a[lo..mid]\) et l'invariant tient pour \([mid+1, hi)\) ; symétriquement si \(a[mid] > x\). Terminaison : \(hi - lo\) décroît strictement à chaque itération (au moins 1). À la sortie, la tranche est vide : soit on a trouvé \(x\) plus tôt, soit \(x\) est absent. Complexité : la taille est au moins divisée par 2 à chaque pas, d'où \(\Theta(\log n)\). ∎
Exemple 4.6 — Binary search sur la réponse Pattern transverse : quand la propriété « \(\leq c\) » est monotone en \(c\), on cherche le seuil par dichotomie au lieu de le calculer. Exemple : \(n\) tâches de durées \(d_i\), \(k\) machines, minimiser le makespan (charge max). 
def feasible(d, k, cap):                 # glouton : peut-on tout placer
    load, machines = 0, 1                # avec chaque machine <= cap ?
    for t in d:
        if t > cap: return False
        if load + t > cap: machines += 1; load = t
        else: load += t
    return machines <= k

def min_makespan(d, k):
    lo, hi = max(d), sum(d)              # bornes triviales
    while lo < hi:                       # meme squelette que binary_search
        mid = (lo + hi) // 2
        if feasible(d, k, mid): hi = mid
        else: lo = mid + 1
    return lo                            # plus petite capacite faisable
L'invariant devient « \([lo, hi]\) contient la plus petite capacité faisable ». Même schéma : racine \(k\)-ième par encadrement, recherche du \(\varepsilon\) de régularisation optimal, apprentissage du seuil de coupure optimal d'un classifieur — et, en RL/module Optimal Transport, la recherche du multiplicateur de Lagrange dans les projections entropiques.

4.6 Récursion et programmation dynamique

  • Mémoïser les sous-problèmes : transformer une récurrence exponentielle en résolution de sous-problèmes partagés. Exemples qui reviendront : distance d'édition (Levenshtein) en NLP, Viterbi pour les HMM, équations de Bellman en RL — tous des DP déguisés.
  • Réduction mémoire : la table \(m \times n\) de Levenshtein se réduit à deux lignes (\(\mathcal{O}(\min(m,n))\)) car chaque cellule ne dépend que de la ligne précédente.
Exemple 4.7 — Distance d'édition (DP) 
def levenshtein(a, b):
    m, n = len(a), len(b)
    dp = [[0]*(n+1) for _ in range(m+1)]
    for i in range(m+1): dp[i][0] = i
    for j in range(n+1): dp[0][j] = j
    for i in range(1, m+1):
        for j in range(1, n+1):
            cost = 0 if a[i-1] == b[j-1] else 1
            dp[i][j] = min(dp[i-1][j] + 1,        # suppression
                           dp[i][j-1] + 1,        # insertion
                           dp[i-1][j-1] + cost)   # substitution
    return dp[m][n]          # O(m n) temps et mémoire (réductible à O(min(m,n)))

print(levenshtein("graph", "giraffe"))  # 4

À retenir — chapitre 4

  • Quicksort : partition in-place, \(\approx 1{,}39 n\log_2 n\) en moyenne (télescopage de la récurrence), pire cas évité par pivot aléatoire/médiane.
  • Mergesort : stable et garanti \(\Theta(n\log n)\) ; le même schéma compte les inversions.
  • Radix : linéaire hors du modèle par comparaisons ; quickselect : médiane en \(\Theta(n)\) attendu.
  • Dichotomie : invariant de boucle (preuve), \(\Theta(\log n)\), et le pattern « recherche binaire sur la réponse » chaque fois qu'une faisabilité est monotone.

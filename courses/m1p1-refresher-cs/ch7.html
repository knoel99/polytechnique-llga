7. Génie logiciel minimal (OOP, tests, git)

7.1 Héritage contre composition

Deux relations, un choix Héritage (« est un ») : la sous-classe réutilise et spécialise. Composition (« a un ») : l'objet contient d'autres objets et délègue. Règle professionnelle : préférer la composition, l'héritage pour les interfaces (frameworks). PyTorch illustre les deux : MLP(nn.Module) hérite (le framework appelle vos forward) mais compose ses couches (self.net = nn.Sequential(...)). L'héritage profond (> 3 niveaux) est un marqueur de design fragile ; les GNN de PyG illustrent la bonne hybridation — hériter de MessagePassing, composer des convolutions. 
# Le squelette que l'on réécrira 50 fois pendant le master
import torch, torch.nn as nn

class MLP(nn.Module):
    def __init__(self, d_in, d_hidden, d_out):
        super().__init__()                    # herite : parameters(), to(), train()
        self.net = nn.Sequential(             # compose : les couches
            nn.Linear(d_in, d_hidden), nn.ReLU(),
            nn.Linear(d_hidden, d_out))
    def forward(self, x):          # appelé par model(x)
        return self.net(x)

model = MLP(10, 64, 2)
x = torch.randn(4, 10)
assert model(x).shape == (4, 2)    # un test, même minimal, vaut mieux que rien

7.2 Dunder methods : rendre un objet « natif »

class Vec:
    """Vecteur R^2 minimal illustant les dunder methods."""
    __slots__ = ("x", "y")
    def __init__(self, x, y): self.x, self.y = x, y
    def __repr__(self): return f"Vec({self.x}, {self.y})"     # affichage debug
    def __eq__(self, o): return (self.x, self.y) == (o.x, o.y)
    def __hash__(self): return hash((self.x, self.y))          # requis si __eq__
    def __add__(self, o): return Vec(self.x + o.x, self.y + o.y)
    def __mul__(self, s): return Vec(self.x * s, self.y * s)
    def __len__(self): return 2
    def __getitem__(self, i): return (self.x, self.y)[i]

v = Vec(1, 2); v + Vec(3, 4) * 2      # Vec(7, 10) — Python appelle les dunder
# PyTorch/TensorFlow reposent entièrement là-dessus : a + b, x @ W, loss.backward()

7.3 Exceptions : hiérarchie et bonnes pratiques

# Hiérarchie (extraits) : BaseException > SystemExit, KeyboardInterrupt
#                            Exception > ArithmeticError > ZeroDivisionError
#                                        > ValueError, TypeError, KeyError, OSError...
class DataValidationError(Exception):
    """Erreur metier : les donnees ne respectent pas le contrat."""

def load_batch(path):
    try:
        with open(path, "rb") as f:
            data = pickle.load(f)
    except FileNotFoundError as e:
        raise DataValidationError(f"batch absent : {path}") from e   # chainage
    except (KeyError, ValueError) as e:
        raise DataValidationError(f"batch corrompu : {path}") from e
    return data

# Bonnes pratiques :
# - attraper le PLUS SPECIFIQUE possible ; jamais "except:" nu (avale Ctrl-C)
# - "errors should never pass silently... unless explicitly silenced" (Zen)
# - EAFP : demander pardon (try) plutot que la permission (if) — pythonique

7.5 Git avancé et revue

  • Branches : une branche par fonctionnalité (feat/tokenizer), fusion par pull request — jamais de travail direct sur main.
  • Merge vs rebase : merge conserve l'historique réel (arbre de merges) ; git rebase main rejoue vos commits au sommet — historique linéaire, mais réécrit : ne jamais rebaser une branche partagée. Le rebase interactif (git rebase -i main) nettoie avant partage : squasher les commits de WIP, reworder les messages (feat: ..., fix: ...).
  • Revue de code : PR courtes, description structurée (quoi/pourquoi/ comment tester), relecteur qui vérifie tests et invariants ; le projet transverse M2 s'organise ainsi (binômes, protection de branche, CI).
  • Debug historique : git bisect — dichotomie (chapitre 4 !) sur les commits pour trouver celui qui a cassé les tests.

À retenir — chapitre 7

  • Composition par défaut, héritage pour les interfaces (le duo nn.Module) ; dunder methods = interopérabilité Python.
  • Exceptions : spécifiques, chaînées (raise ... from), jamais except: nu ; logging à la place de print.
  • Docstrings NumPy + pré-commit + PR + revue = le contrat d'équipe ; git bisect = dichotomie sur l'historique.
  • Docker minimal : image slim, requirements, utilisateur non root — reproductibilité des TP.

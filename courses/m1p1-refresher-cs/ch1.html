1. Python pour la science des données

Python est la langue véhiculaire du master : tous les TP (PyTorch, PyG, HuggingFace, POT, networkx, scikit-learn) s'écrivent en Python. On suppose les bases (boucles, fonctions, types) acquises ; on consolide ici les idiomes que les TP utilisent massivement. Ce chapitre est long parce qu'il est opératoire : chaque section doit vous rendre capable de lire et d'écrire le code des modules suivants sans friction.

1.2. Décorateurs

Un décorateur est une fonction qui prend une fonction et renvoie une fonction — du sucre syntaxique pour « emballer » un comportement. Ils sont partout dans l'écosystème (PyTorch torch.no_grad, pytest @pytest.fixture, Flask routes, @functools.lru_cache). En comprendre la mécanique n'est pas optionnel.

import functools, time

def timing(fn):
    """Mesure et affiche le temps d'exécution — outil de TP indispensable."""
    @functools.wraps(fn)                     # conserve le nom/docstring de fn
    def wrapper(*args, **kwargs):
        t0 = time.perf_counter()
        out = fn(*args, **kwargs)
        dt = (time.perf_counter() - t0) * 1e3
        print(f"[{fn.__name__}] {dt:.2f} ms")
        return out
    return wrapper

@timing                                     # equivaut a train = timing(train)
def train_one_epoch(model, loader):
    ...

# @property : accesseur calcule a la volee, acces sans parentheses
class Dataset:
    def __init__(self, x, y):
        self.x, self.y = x, y
    @property
    def n(self):                            # ds.n (pas ds.n())
        return len(self.x)

# Decorateur parametre (usine a decorateurs) : memoisation LRU
@functools.lru_cache(maxsize=None)          # cles = arguments hashables
def fib(n):
    return n if n < 2 else fib(n-1) + fib(n-2)
# fibonacci exponentiel -> lineaire : la memoisation transforme la recurrence
# en programmation dynamique (cf. chapitre 4)

1.3. Générateurs : le protocole et les pipelines

Un générateur produit ses valeurs paresseusement : rien n'est calculé avant l'itération, et la mémoire reste \(\mathcal{O}(1)\) par élément traité. C'est la seule façon de parcourir des corpus qui ne tiennent pas en RAM (Wikipedia, Common Crawl, grands logs).

def stream_tokens(path):
    """Generateur : yield suspend la fonction et conserve son etat."""
    with open(path, encoding="utf-8") as f:
        for line in f:
            yield from line.lower().split()   # yield from : sous-genérateur

def up_to(it, n):
    for i, x in enumerate(it):
        if i >= n: return
        yield x

# Pipeline : chaque etape est un générateur, les données coulent element par element
tokens = up_to(stream_tokens("corpus.txt"), 1_000_000)
long_words = (t for t in tokens if len(t) >= 6)   # expression génératrice
first100 = list(zip(range(100), long_words))

# Protocole complet : next() / Send / close ; en pratique on boucle :
# for tok in stream_tokens(path): ...   # <- 99 % des usages
Générateur ≠ liste : le piège de l'épuisement Un générateur se consomme une seule fois : après une boucle, il est vide. Pour deux passes, soit matérialiser (list(gen)), soit régénérer. Seconde différence clé : len() et l'indexation échouent sur un générateur — les DataLoader de PyTorch résolvent ce problème avec des itérables dédiés (cf. module Deep Learning).

# Le protocole : __enter__ / __exit__
import contextlib, numpy as np

@contextlib.contextmanager
def seed_context(rng, seed):
    state = rng.bit_generator.state         # sauver
    rng = np.random.default_rng(seed)       # substituer
    try:
        yield rng                           # corps du with
    finally:
        rng = None                          # restaurer/nettoyer

# Usage standard en TP : etat d'erreur numpy, device PyTorch

1.5. Typage : Generic et Protocol

from typing import Generic, TypeVar, Protocol, Iterator

T = TypeVar("T")

class Stack(Generic[T]):                    # pile typée : Stack[int], Stack[str]
    def __init__(self) -> None:
        self._items: list[T] = []
    def push(self, x: T) -> None:
        self._items.append(x)
    def pop(self) -> T:
        return self._items.pop()

class SupportsFit(Protocol):                # typage structurel (canard typé)
    def fit(self, x: np.ndarray, y: np.ndarray) -> "SupportsFit": ...
    def predict(self, x: np.ndarray) -> np.ndarray: ...

def train_and_score(model: SupportsFit, x, y) -> float:
    """Accepte tout objet avec fit/predict, sans héritage commun :
    LinearRegression de sklearn OU un modèle maison — typage duck."""
    model.fit(x, y)
    return float((model.predict(x) == y).mean())
Pourquoi typer en Python ? Les annotations ne sont pas vérifiées à l'exécution (sauf avec pydantic ou beartype) mais : (i) elles documentent ; (ii) les IDE complètent et refactorent sûrement ; (iii) mypy/pyright attrapent les bugs avant exécution — précieux sur les pipeline longs d'entraînement où un crash au 40e epoch coûte une nuit. Le code des bibliothèques du master (PyTorch, PyG) est massivement typé.

Réflexe professionnel Un pipeline lent a presque toujours un goulot (data loading, conversion CPU-GPU, boucle Python là où une primitive vectorisée existe). cProfile le localise en trente secondes ; l'intuition, elle, se trompe régulièrement. 1.11. Tests avec pytest

# test_softmax.py — les tests du master ressemblent tous a ceci
import pytest, math
import numpy as np

def softmax(v):
    m = max(v)
    e = [math.exp(x - m) for x in v]
    Z = sum(e)
    return [x / Z for x in e]

def test_softmax_sums_to_one():
    out = softmax([1.0, 2.0, 3.0])
    assert abs(sum(out) - 1.0) < 1e-12          # invariant fondamental

def test_softmax_stable_under_shift():
    # invariance par translation : la propriete qui justifie le -max
    assert np.allclose(softmax([1000.0, 1001.0]), softmax([0.0, 1.0]))

def test_softmax_empty_raises():
    with pytest.raises(ValueError):
        softmax([])

@pytest.mark.parametrize("n", [1, 5, 100])       # meme test, 3 tailles
def test_softmax_output_length(n):
    assert len(softmax(list(range(n)))) == n

@pytest.fixture                                    # donnee reutilisable, isolee
def toy_dataset():
    rng = np.random.default_rng(0)
    return rng.normal(size=(50, 3)), rng.integers(0, 2, 50)

def test_model_overfits_toy(model, toy_dataset):  # un modele qui n'apprend
    X, y = toy_dataset                             # pas ce toy echoue
    model.fit(X, y, epochs=500)
    assert model.score(X, y) > 0.95
Vectorialisation En Python scientifique, on évite les boucles quand une opération vectorisée existe : np.dot(A, x) est ~100× plus rapide qu'une triple boucle, car il délègue à du code BLAS compilé. Réflexe à acquérir dès maintenant — il conditionne la lisibilité et la performance de tous les TP de deep learning.

3.1 Tables de hachage : sous le capot de dict et set

Définition 3.1 — Table de hachage Un grand tableau de \(m\) alvéoles ; la clé \(k\) est placée à l'indice \(h(k) \bmod m\) où \(h\) est une fonction de hachage (uniformisante, déterministe). Recherche/insertion/suppression en \(\mathcal{O}(1)\) en moyenne (sous hachage uniforme), \(\mathcal{O}(n)\) au pire (toutes les clés en collision).
Collisions : deux stratégies
  • Chaînage : chaque alvéole est une petite liste ; les clés en collision s'y empilent. Simple, mais pointeurs = cache-unfriendly.
  • Adressage ouvert (variante Python) : en cas de collision, sonder une autre alvéole (sondage pseudo-aléatoire). Toutes les données vivent dans un seul tableau contigu — excellent pour le cache.
  • Facteur de charge \(\alpha = n/m\) : Python redimensionne (rehash complet) dès que \(\alpha \gtrsim 2/3\) ; c'est ce rehash qui rend l'insertion amortie \(\mathcal{O}(1)\) — même mécanisme que le théorème 2.4. Clé : les objets mutables sont interdits comme clés (un list haché puis modifié serait introuvable) ; les frozenset/tuple d'immuables, oui.
Exemple 3.2 — Vocabulaire NLP en une passe 
vocab = {}                                # token -> id
def tokenize_id(text):
    out = []
    for tok in text.lower().split():
        if tok not in vocab:              # O(1) moyen
            vocab[tok] = len(vocab)       # prochain id libre
        out.append(vocab[tok])
    return out
# 10^9 tokens, vocabulaire 10^5 : O(n) au lieu de O(n * V) avec une liste.
# Le meme principe indexe les arêtes d'un graphe (chapitre 5) ou les couples
# (user, item) des systemes de recommandation.

3.2 Arbres équilibrés : AVL et rouge-noir

Esquisse Un arbre binaire de recherche (ABR) stocke les clés ordonnées : gauche < racine < droite ; toutes les opérations coûtent \(\Theta(\text{hauteur})\), entre \(\log n\) (équilibré) et \(n\) (dégénéré en liste). Les ABR auto-équilibrés maintiennent la hauteur en \(\mathcal{O}(\log n)\) par des rotations (réarrangements locaux qui préservent l'ordre) : AVL (hauteurs des fils différant d'au plus 1, rotations à l'insertion), rouge-noir (hauteur \(\leq 2\log n\), rotations moins fréquentes — implémentation des map de C++ et des index de bases de données). En Python pur on n'en écrit presque jamais (dict suffit pour 95 % des usages), mais leur invariant — toute branche a des longueurs comparables — est le même que celui des arbres de segmentation et des hiérarchies de clustering (module Graph ML).

3.3 Tas binaire : heapify est linéaire

Théorème 3.3 — Construction en \(\mathcal{O}(n)\) Un tas binaire (tableau où chaque parent \(\leq\) ses fils) se construit à partir d'un tableau quelconque en temps \(\Theta(n)\) — et non \(\Theta(n \log n)\).
La construction « bas-haut » tamise (sift-down) chaque nœud interne ; un nœud à hauteur \(h\) coûte \(\mathcal{O}(h)\), et il y a au plus \(\lceil n/2^{h+1} \rceil\) nœuds à hauteur \(h\). Somme : $$\sum_{h=0}^{\lfloor \log n \rfloor} \frac{n}{2^{h+1}}\,\mathcal{O}(h) \;=\; \mathcal{O}\Big(n \sum_{h \geq 0} \frac{h}{2^{h}}\Big) \;=\; \mathcal{O}(2n) = \mathcal{O}(n),$$ en utilisant \(\sum_{h\geq0} h/2^h = 2\) (dérivée d'une série géométrique). La moitié des nœuds sont des feuilles (coût nul), le quart à hauteur 1 coûte 1 pas... : la masse est en bas, où c'est bon marché. ∎
Exemple 3.4 — Top-k avec un tas 
import heapq

def top_k(items, scores, k):
    """Renvoie les k items de plus haut score en O(n log k)."""
    heap = []                                  # min-tas de taille <= k
    for it, s in zip(items, scores):
        if len(heap) < k:
            heapq.heappush(heap, (s, it))
        elif s > heap[0][0]:
            heapq.heapreplace(heap, (s, it))   # évict le plus petit
    return sorted(heap, reverse=True)

# En NLP : les k tokens les plus probables d'un LLM (échantillonnage top-k).
# heapify préalable (O(n)) puis nsmallest/nlargest de heapq font la même chose.

3.5 Tries : la recherche par préfixe

Définition 3.5 — Trie (arbre de préfixes) Arbre dont les arêtes portent des caractères ; chaque nœud matérialise un préfixe commun. Insérer ou chercher un mot de longueur \(L\) coûte \(\Theta(L)\) — indépendant du nombre de mots stockés, contre \(\mathcal{O}(\log n)\) par comparaisons pour un ABR (et \(\mathcal{O}(n)\) en moyenne pour une liste triée de mots par recherche binaire sur des chaînes). 
class TrieNode:
    __slots__ = ("children", "is_word")
    def __init__(self):
        self.children = {}            # char -> TrieNode (table de hachage)
        self.is_word = False

class Trie:
    def __init__(self):
        self.root = TrieNode()
    def insert(self, word):
        node = self.root
        for ch in word:
            node = node.children.setdefault(ch, TrieNode())
        node.is_word = True
    def search(self, word):
        node = self._walk(word)
        return node is not None and node.is_word
    def starts_with(self, prefix):           # autocomplétion
        return self._walk(prefix) is not None
    def completions(self, prefix, limit=10):
        node = self._walk(prefix)
        out, stack = [], [(node, prefix)] if node else []
        while stack and len(out) < limit:    # DFS lexicographique
            n, s = stack.pop()
            if n.is_word: out.append(s)
            stack.extend((c, s + ch) for ch, c in reversed(list(n.children.items())))
        return out
    def _walk(self, s):
        node = self.root
        for ch in s:
            node = node.children.get(ch)
            if node is None: return None
        return node

t = Trie()
for w in ["graph", "graphe", "graine", "gradient"]:
    t.insert(w)
assert t.starts_with("grad") and not t.starts_with("grapx")
print(t.completions("gra"))     # ['graine', 'gradient', 'graph', 'graphe']
Tries et NLP Recherche de préfixe (autocomplétion, suggestions), tokenizers par sous-mots (l'arbre des pièces BPE vit dans un trie), stockage de grands lexiques avec partage de préfixes, routage de règles par masque (module NLP). Variante compressée (radix tree) utilisée par les routeurs IP.

3.6 File de priorité double bout

Médiane d'un flux, en ligne Le problème type : recevoir des nombres un par un et pouvoir interroger la médiane à tout instant. Solution classique par deux tas : un max-tas \(L\) pour la moitié basse, un min-tas \(U\) pour la moitié haute, avec l'invariant \(|L| - |U| \in \{0, 1\}\) et \(\max L \leq \min U\). Insertion \(\mathcal{O}(\log n)\) (placer, puis rééquilibrer en déplaçant la racine d'un tas vers l'autre) ; médiane \(\mathcal{O}(1)\) (racine de \(L\), ou moyenne des deux racines). Cette structure sert au contrôle de dérive des distributions (monitoring de modèles en production) et aux algorithmes médians de k-means.

3.7 Filtres de Bloom

Définition 3.6 — Filtre de Bloom Un tableau de \(m\) bits et \(k\) fonctions de hachage indépendantes. Insertion de \(x\) : mettre à 1 les bits \(h_1(x), \dots, h_k(x)\). Requête « \(x\) a-t-il été inséré ? » : répondre oui si tous ces bits valent 1, non sinon. Réponse non : certaine. Réponse oui : probabiliste (faux positifs possibles, jamais de faux négatifs). Mémoire : \(\mathcal{O}(m)\) bits, indépendamment de la taille des clés.
Taux de faux positifs. Après \(n\) insertions, la probabilité qu'un bit donné soit resté à 0 : \((1 - 1/m)^{kn} \approx e^{-kn/m}\). Un élément absent est déclaré présent si ses \(k\) bits sont à 1 : $$p \;=\; \big(1 - e^{-kn/m}\big)^k.$$ À \(m/n\) fixé (bits par élément), on minimise en dérivant en \(k\) : optimum pour \(k^\star = \frac mn \ln 2\), donnant \(p^\star \approx (0{,}6185)^{m/n}\) — exponentiellement petit en le nombre de bits par élément : avec 10 bits/élément et \(k = 7\), \(p \approx 0{,}008\). C'est la même arithmétique que les probabilités d'indépendance approximative du cours de statistiques (chapitre 1 du module Statistics) — appliquée aux bits. ∎
Exemple 3.7 — Déduplication de crawling 
import hashlib
class Bloom:
    def __init__(self, m_bits, k):
        self.m, self.k, self.bits = m_bits, k, bytearray(m_bits // 8 + 1)
    def _pos(self, x, i):
        h = hashlib.sha256(f"{i}:{x}".encode()).digest()
        return int.from_bytes(h[:8], "big") % self.m
    def add(self, x):
        for i in range(self.k):
            p = self._pos(x, i); self.bits[p // 8] |= 1 << (p % 8)
    def might_contain(self, x):
        return all(self.bits[p // 8] & (1 << (p % 8)) for p in map(lambda i: self._pos(x, i), range(self.k)))

b = Bloom(m_bits=8_000_000, k=7)      # ~1 Mo pour ~1 M d'url, p ~ 0.008
b.add("https://polytechnique.edu")
assert b.might_contain("https://polytechnique.edu")
# Usage : crawler (deja vu ?), cache negatif de disque, blocage d'URLs,
# jointure approximative de gros datasets avant verification exacte.
Représentation sparse Un vocabulaire de 100 k mots dans une matrice dense \(10^5 \times 10^5\) est impossible ; la matrice de co-occurrence réelle est creuse (sparse). On utilise scipy.sparse / dictionnaires — idée que l'on retrouvera pour les matrices d'adjacence de graphes (chapitre 5) et les filtres de Bloom ci-dessus : ne stocker que l'information présente.

À retenir — chapitre 3

  • Hash : collisions par chaînage ou adressage ouvert, rehash à \(\alpha \approx 2/3\), \(\mathcal{O}(1)\) moyen amorti — le nerf de dict/set.
  • heapify linéaire (preuve \(\sum h/2^h = 2\)) ; top-k en \(\mathcal{O}(n\log k)\).
  • Trie : opérations \(\Theta(L)\), indépendantes du nombre de mots — autocomplétion et tokenizers.
  • Bloom : pas de faux négatifs ; faux positifs \((1-e^{-kn/m})^k\), optimum \(k = \frac mn \ln 2\) — dédup massive à mémoire bornée.

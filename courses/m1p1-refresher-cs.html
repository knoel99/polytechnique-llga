2. Analyse de complexité

Définition 2.1 — Notation \(\mathcal{O}\) \(f(n) = \mathcal{O}(g(n))\) s'il existe \(C > 0\) et \(n_0\) tels que \(f(n) \leq C\, g(n)\) pour tout \(n \geq n_0\). On note \(\Theta(g)\) si \(f\) est à la fois \(\mathcal{O}(g)\) et \(\Omega(g)\) (encadrement exact à constantes près).

La complexité se mesure en temps et en mémoire, dans le pire cas par défaut. L'échelle pratique à avoir en tête :

ComplexitéExemple canoniqueOrdre de grandeur à \(n = 10^6\)
\(\mathcal{O}(\log n)\)dichotomie~20 opérations
\(\mathcal{O}(n)\)parcours de liste, BFS/DFS10⁶
\(\mathcal{O}(n \log n)\)tri fusion, tri par tas~2·10⁷
\(\mathcal{O}(n^2)\)double boucle, matrices denses naïves10¹² — déjà trop
\(\mathcal{O}(n^3)\)produit matriciel naïf, inversionhors de portée
Exemple 2.2 — Deux boucles imbriquées 
def all_pairs_dist(V, E):
    d = {}
    for u in V:              # n itérations
        for v in V:          # n itérations  -> O(n^2)
            d[u, v] = dist(u, v)

Sur un graphe de \(10^5\) nœuds, \(\mathcal{O}(n^2)\) = 10¹⁰ paires stockées : intenable. C'est exactement pourquoi le module Graph ML n'apprend pas toutes les distances mais des embeddings (chapitre 8 du module Graph ML) : réduire une complexité structurelle par apprentissage.

Exemple 3.1 — Top-k avec un tas 
import heapq

def top_k(items, scores, k):
    """Renvoie les k items de plus haut score en O(n log k)."""
    heap = []                                  # min-tas de taille <= k
    for it, s in zip(items, scores):
        if len(heap) < k:
            heapq.heappush(heap, (s, it))
        elif s > heap[0][0]:
            heapq.heapreplace(heap, (s, it))   # évict le plus petit
    return sorted(heap, reverse=True)

# En NLP : les k tokens les plus probables d'un LLM (échantillonnage top-k)
Représentation sparse Un vocabulaire de 100 k mots dans une matrice dense \(10^5 \times 10^5\) est impossible ; la matrice de co-occurrence réelle est creuse (sparse). On utilise scipy.sparse / dictionnaires — idée que l'on retrouvera pour les matrices d'adjacence de graphes (chapitre 5).

4. Tri, recherche, récursion

  • Tri fusion : diviser pour régner, \(\mathcal{O}(n \log n)\) garanti, stable ; quicksort : \(\mathcal{O}(n \log n)\) attendu, \(\mathcal{O}(n^2)\) pire cas, en place. trier par base (radix) : \(\mathcal{O}(n k)\) pour des clés entières de taille bornée — utilisé pour trier des tokens.
  • Dichotomie : recherche en tableau trié en \(\mathcal{O}(\log n)\) — même principe que la recherche bin­aire d'hyperparamètres et la discrétisation de grille en transport optimal (recherche de \(\varepsilon\) de Sinkhorn).
  • Récursion & programmation dynamique : mémoïser les sous-problèmes. Exemples qui reviendront : distance d'édition (Levenshtein) en NLP, Viterbi pour les HMM, équations de Bellman en RL — tous des DP déguisés.
Exemple 4.1 — Distance d'édition (DP) 
def levenshtein(a, b):
    m, n = len(a), len(b)
    dp = [[0]*(n+1) for _ in range(m+1)]
    for i in range(m+1): dp[i][0] = i
    for j in range(n+1): dp[0][j] = j
    for i in range(1, m+1):
        for j in range(1, n+1):
            cost = 0 if a[i-1] == b[j-1] else 1
            dp[i][j] = min(dp[i-1][j] + 1,        # suppression
                           dp[i][j-1] + 1,        # insertion
                           dp[i-1][j-1] + cost)   # substitution
    return dp[m][n]          # O(m n) temps et mémoire (réductible à O(min(m,n)))

print(levenshtein("graph", "giraffe"))  # 4

5. Algorithmes de graphes

Le module le plus important de ce refresher : le master s'appelle Large Language Models, Graphs and Applications. On réutilise l'objet « graphe » pendant deux ans ; il faut être à l'aise avec ses représentations et ses algorithmes classiques.

Définition 5.1 — Graphe Un graphe \(G = (V, E)\) est un ensemble de sommets \(V\) et un ensemble d'arêtes \(E \subseteq V \times V\). Il est non orienté si les arêtes sont symétriques, orienté sinon ; pondéré si chaque arête porte un poids \(w : E \to \mathbb{R}\). Le voisinage de \(v\) est \(\mathcal{N}(v) = \{u : (v,u) \in E\}\), son degré est \(|\mathcal{N}(v)|\).

5.1 Représentations

import numpy as np
from scipy import sparse

# 1) Listes d'adjacence (référence en pratique — networkx, PyG)
adj = {0: [1, 2], 1: [0, 2], 2: [0, 1, 3], 3: [2]}

# 2) Matrice d'adjacence (dense O(|V|^2) mémoire, mais algèbre !)
A = np.array([[0, 1, 1, 0],
              [1, 0, 1, 0],
              [1, 1, 0, 1],
              [0, 0, 1, 0]])
print((A @ A)[0, 3] > 0)   # True : il existe un chemin de longueur 2 entre 0 et 3

# 3) Sparse COO/CSR : le format des vrais jeux de données (Cora ~ 10k arêtes)
A_sp = sparse.coo_matrix(A)
Pourquoi trois représentations ? Listes d'adjacence → parcours efficaces ; matrice dense → propriétés spectrales (\(A^k\) compte les chemins, base du module Graph ML) ; sparse → passage à l'échelle. Savoir passer de l'une à l'autre est un réflexe du master.

5.2 Parcours en largeur et en profondeur

from collections import deque

def bfs(adj, s):
    """Parcours en largeur : distances (non pondérées) et parents depuis s. O(|V|+|E|)"""
    dist, parent = {s: 0}, {s: None}
    q = deque([s])
    while q:
        u = q.popleft()
        for v in adj[u]:
            if v not in dist:
                dist[v], parent[v] = dist[u] + 1, u
                q.append(v)
    return dist, parent

def dfs(adj, u, visited=None):
    """Parcours en profondeur (récursif) : composantes connexes, cycles, tri topologique."""
    visited = visited if visited is not None else set()
    visited.add(u)
    for v in adj[u]:
        if v not in visited:
            dfs(adj, v, visited)
    return visited

5.3 Plus courts chemins et composantes

  • Dijkstra (poids \(\geq 0\)) : \(\mathcal{O}((|V|+|E|)\log |V|)\) avec un tas — le cœur des itinéraires (OSM), des dépendances de tâches et du routing d'agents ;
  • Bellman-Ford : gère les poids négatifs, détecte les cycles négatifs, \(\mathcal{O}(|V||E|)\) — la relaxation répétée annonce la programmation dynamique de Bellman en RL ;
  • Composantes connexes : DFS/BFS (non orienté) ou Kosaraju/Tarjan (fortement connexes, orienté) — utilisé pour partitionner des graphes de connaissances ;
  • Détection de cycles / tri topologique d'un DAG (Kahn) — les workflows d'agents (orchestration de LLMs) sont des DAG précisément pour ça.
Exemple 5.2 — Dijkstra avec heapq 
import heapq

def dijkstra(adj_w, s):           # adj_w[u] = [(v, w_uv), ...]
    dist = {s: 0.0}; pq = [(0.0, s)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist.get(u, float("inf")):
            continue               # entrée périmée
        for v, w in adj_w[u]:
            nd = d + w
            if nd < dist.get(v, float("inf")):
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist                    # dist[v] = plus courte distance s -> v

6. NumPy : algèbre linéaire numérique

Tout le deep learning est de l'algèbre linéaire batchée. Rappels des opérations et de leurs coûts :

import numpy as np

A = np.random.randn(1000, 500)
x = np.random.randn(500)

A @ x               # produit matrice-vecteur : O(n^2)
A.T @ A             # produit matrice-matrice : O(n^3) — via BLAS, très optimisé

np.linalg.norm(x)                       # norme euclidienne
np.linalg.solve(A.T @ A, A.T @ x)       # résolution (mieux que inv() @ b !)
w, V = np.linalg.eigh(np.array([[2,1],[1,2]]))   # valeurs/vecteurs propres (symétrique)
Rappels essentiels
  • \(\langle u, v\rangle = u^\top v\), \(\|u\| = \sqrt{u^\top u}\) ; \(u \perp v \iff u^\top v = 0\) ;
  • matrices symétriques : diagonalisables en base orthonormée, valeurs propres réelles — le socle spectral du module Graph ML ;
  • décomposition en valeurs singulières \(M = U \Sigma V^\top\) : base de l'ACP et des embeddings ;
  • diffusion : \((I - \alpha A)^{-1}\), séries de Neumann \(\sum_k \alpha^k A^k\) — c'est PageRank et les marches aléatoires ;
  • stabilité numérique : ne jamais inverser une matrice (np.linalg.solve), soustraire le max avant exp (softmax), travailler en float64 pour le calcul scientifique et float32 pour l'apprentissage profond.

5. La DP dans l'industrie et les attaques

Exemple 5.1 — Trois déploiements réels (a) Recensement américain 2020 (Abowd, KDD 2018). Toutes les tables statistiques publiées passent par l'algorithme TopDown (optimisation + bruit gaussien, mécanisme exponentiel pour les invariants) ; motivation directe : attaques de reconstruction sur les tabulations du recensement 2010 — une attaque interne a reconstitué exactement une fraction substantielle des enregistrements individuels (de l'ordre de la moitié) ; budget ε par domaine public, débats publics intenses avec les démographes. (b) Apple (2017–). « Learning with Privacy at Scale » : télémétrie clavier/emoji/QuickType en DP locale (count-mean sketch + Hadamard) ; millions d'appareils, ε journalier de l'ordre de 4–8 par domaine — illustration du « budget » qui se consomme chaque jour. (c) Google RAPPOR (Erlingsson et al., CCS 2014). Première grande production académique-entreprise de DP locale ; chaîne : signal (registre de Bloom) → permanent randomized response → instantaneous RR → cohortes ; découvertes réelles (paramètres Chrome dominant).
Repère 5.2 — Deux familles d'attaques qui motivent les garanties Membership inference (Shokri et al., IEEE S&P 2017). L'adversaire interroge le modèle (confidences) et classe « était dans le train ? » ; AUC typiquement bien au-dessus de 0,5 sur les points rares/atypiques — le risque croît avec la surconfiance du modèle : la calibration (ch. 7) est aussi une défense. Mémorisation involontaire (Carlini et al., 2019 — « The Secret Sharer »). Insérer un canari (« clé secrète ») dans le train d'un générateur ; exposition mesurée par la perplexité relative du canari : les LLMs mémorisent et exfiltrent verbatim des séquences vues une seule fois — résultat fondateur pour la privacy des LLMs (ch. 11) ; suite : extraction d'entraînement sur GPT-2 par le même groupe (2021). La DP est la défense avec garantie : un mécanisme \(\varepsilon\)-DP borne le rapport de vraisemblance du membership à \(e^{\varepsilon}\) (donc l'AUC de tout adversaire) ; le modèle d'entraînement privé reste utile (ch. 4) à condition de payer en précision.
Réglementation GDPR (anonymisation « raisonnablement impossible à réidentifier ») : la DP est la lecture formelle la plus acceptée de ce critère ; référentiels sectoriels (santé, banque) et normes émergentes (NIST, ISO/IEC 27559). Pour l'ingénieur : tenir un registre de budget (quelle requête, quel ε dépensé, quelle composition) comme on tient un registre d'incidents — les frameworks (OpenDP, Google DP library) imposent cette discipline.

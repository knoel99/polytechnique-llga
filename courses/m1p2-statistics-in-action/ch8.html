8. A/B testing : séquentiel et effets ciblés

Définition 8.1 — Test A/B et OEC Expérience randomisée en ligne : chaque unité (utilisateur, requête, session — l'unité de randomisation doit être l'unité d'analyse) reçoit la variante A (contrôle) ou B (traitement). L'OEC (Overall Evaluation Criterion) est la métrique de décision unique, définie avant l'expérience ; les métriques secondaires (garde-fous : latence, taux d'erreur, désabonnement) se testent en correction de tests multiples (ch. 6). Discipline : pas d'OEC, pas de test.
Théorème 8.2 — Le coût du « peeking » (regarder avant la fin) Un test à horizon fixe de niveau \(\alpha\) examiné \(K\) fois avec arrêt dès qu'une p-value passe sous \(\alpha\) a un taux de faux positifs $$\mathbb{P}(\exists k \leq K : p_k \leq \alpha) \;\geq\; \alpha \quad \text{et} \quad \leq\; 1 - (1 - \alpha)^K \ \text{(si indépendants).}$$ Pour \(K = 5\) regards et \(\alpha = 5\,\%\) déjà \(1 - 0{,}95^5 = 22{,}6\,\% ;\) en monitoring continu quotidien pendant des semaines, Johari, Pekelis, Walsh et Ye (KDD 2017) mesurent des taux atteignant environ trois fois le niveau nominal.
La borne inférieure est claire (le premier regard est un test de niveau \(\alpha\)). La borne supérieure : union bound sur les \(K\) événements \(\{p_k \leq \alpha\}\), dont chacun a probabilité \(\leq \alpha\) sous \(H_0\) — avec égalité \(\times\) indépendance quand les regards sont des tests indépendants (approximation grossière : en pratique les p-values successives sont très corrélées, ce qui rend le vrai taux plus petit que la borne mais très supérieur à \(\alpha\)). D'où la simulation de l'exercice 7. ∎
Définition 8.3 — p-values toujours valides et mSPRT (Johari et al., 2017) Une p-value séquentielle \(p_t\) est toujours valide si \(\mathbb{P}(\exists t : p_t \leq \alpha) \leq \alpha\) pour tout temps d'arrêt — on peut alors regarder aussi souvent qu'on veut. Construction : mélange de tests séquentiels du rapport de vraisemblance (mSPRT) ; la version bayésienne miroir : monter le posterior de \(d = p_B - p_A\) et son intervalle crédible à chaque instant (code ci-dessous), avec a priori Beta non informatif ; les deux familles se correspondent asymptotiquement (mêmes frontières en \(t\), cf. module Reinforcement Learning ch. 6 pour les bandits, l'autre réponse au problème). 
import numpy as np
rng = np.random.default_rng(52)

# ---- A/B test bayesien : posteriors Beta, decision par esperance de perte ----
conv = np.array([1274, 1378])          # conversions
n    = np.array([12000, 12000])        # visites
a, b = 1.0, 1.0                        # a priori Beta(1, 1)
post = [rng.beta(conv[i] + a, n[i] - conv[i] + b, size=200_000) for i in range(2)]

d = post[1] - post[0]                  # gain absolu tire a posteriori
loss_if_B = np.where(d < 0, -d, 0.0)   # perte si l'on deploie B et que A etait mieux

print(f"P(B > A)            : {(d > 0).mean():.3f}")
print(f"gain median         : {np.median(d):.5f}")
print(f"IC 95 % du gain     : {np.quantile(d, [0.025, 0.975])}")
print(f"E[perte | deploi B] : {loss_if_B.mean():.2e}")
# Sorties typiques : P(B>A) = 0.984 ; gain median = 0.0087 ;
# IC = [0.0007, 0.0166] ; E[perte] = 2.2e-05.
# Decision : le cout d'un choix de B errone (2 conversions sur 10^5) est negligeable
# devant le gain attendu (+0.87 point) -- on deploye B.
Définition 8.4 — Effets ciblés (hétérogènes) et erreurs associées L'effet moyen cache l'hétérogénéité : B gagne sur mobile, perd sur desktop. Deux écueils symétriques : (i) spinning sous-groupes : 20 segments ⇒ attendez-vous à un « gain significatif » dans l'un d'eux par pur bruit (ch. 6, Bonferroni/BH obligatoires) ; (ii) effets d'interaction réels ignorés : l'OEC agrégé peut annuler des effets opposés (Simpson, ch. 3). Cadre sain : spécifier les segments a priori, tester l'interaction segment × traitement, corriger les tests multiples. Du côté variance : CUPED (Deng et al., 2013) réutilise la métrique mesurée avant expérience comme covariable — réduction de variance typique de 30–50 % « gratuite », statistiquement équivalente aux blocs du ch. 2.
Interférences et validité Marché biface (Uber : plus de chauffeurs ⇒ délai baisse pour tous, y compris le contrôle), caches CDN, effets de réseau social : SUTVA (ch. 4) violé. Réponses : randomiser par grappes (villes, clusters d'IP — perte de puissance via le design effect \(1 + (m-1)\rho\)), ou isoler (switchback). Voir Kohavi, Tang & Xu (2020) pour le catalogue complet des pièges de production ; le module Reinforcement Learning (bandits ch. 6) traite l'alternative « exploiter pendant l'expérience ».

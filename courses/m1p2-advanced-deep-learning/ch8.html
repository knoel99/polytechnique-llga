8. Recherche reproductible : protocole expérimental

Définition 8.1 — Protocole expérimental minimal Toute expérience rapportée : (1) une question précise ; (2) une hypothèse falsifiable ; (3) un protocole : jeu de données fixé et versionné, découpage train/val/test unique, métrique principale déclarée avant l'expérience ; (4) une baseline re-entraînée dans les mêmes conditions ; (5) \(n \geq 3\) graines avec moyenne ± écart-type ; (6) les ablations ; (7) budget de calcul rapporté ; (8) code (et idéalement données) publié.

8.1 Les graines comptent (vraiment)

Picard (2021) — « torch.manual_seed(3407) is all you need » — entraîne des classifieurs identiques sur 10 000 graines : la gap d'accuracy entre graines atteint plusieurs points ; le choix de la graine peut inverser un classement de méthodes. Bouthillier et al. (2021) généralisent : la variance due aux graines (init, ordre des données, augmentations) doit être estimée et rapportée ; comparer deux moyennes sans variabilité, c'est comparer du bruit. Outils : intervalles de confiance à \(t\) de Student sur \(n\) runs ; tests appariés quand les graines sont couplées ; correction pour tests multiples (cf. module Refresher in Statistics pour les tests, module Machine Learning pour la sélection de modèles).

Exemple 8.2 — Un « gain » qui n'en est pas un Méthode A : 79,4 % ± 0,6 (5 graines) ; baseline B : 78,9 % ± 0,5 (5 graines). Différence des moyennes 0,5 ; écart-type de la différence \(\approx \sqrt{0{,}6^2/5 + 0{,}5^2/5} \approx 0{,}35\) → statistic \(t \approx 1{,}4\), à comparer à \(t_{0{,}975}(8) \approx 2{,}3\) : non significatif. La bonne conclusion : « comparable à la baseline », pas « +0,5 % state of the art ». Dans le projet (ch. 11), tout tableau de résultats comporte moyenne ± écart-type et la mention du test employé.

8.2 Réplication : la méthode du module

  1. choisir un chiffre : une ligne, un tableau du papier pivot ;
  2. réduire : même tâche, modèle ×0,2 (µP, ch. 7, aide à transposer les hyperparamètres) ; budget déclarable en heures-GPU ;
  3. instrumenter : suivi d'expériences (config + graines + courbes versionnées — W&B/tensorboard ; déterminisme des loaders ; pas de fuite : le test n'est regardé qu'à la fin) ;
  4. rapporter : tableau papier vs réplication ± écart-type ; analyser l'écart (données ? recette ? matériel ?) — c'est là qu'on apprend.
Note — Fuites et pièges fréquents Découpage par image sur des données vidéo (voisines quasi identiques) ; normalisation calculée sur tout le jeu ; sélection du meilleur checkpoint sur le test ; « dev set = test set » implicite après 50 éditions de config ; comparaison à budgets d'entraînement inégaux (cf. DeiT vs ViT, ch. 1 ; ConvNeXt, ch. 2). Chaque chapitre du module relit son papier pivot avec cette grille : quelle est la baseline ? les graines ? le budget ? la métrique déclarée a priori ?

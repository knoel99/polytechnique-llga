4. Homologie persistante : l'algorithme

Revenons aux données. À quelle échelle \(\varepsilon\) construire le Rips ? Trop petit : poussière de points. Trop grand : une boule contractile. La réponse de la persistance : toutes les échelles à la fois, avec un livre de comptes qui note, pour chaque feature topologique, sa naissance et sa mort. Les features qui vivent longtemps sont les candidats « vrais trous » ; les éphémères sont du bruit.

Définition 4.1 — Filtration et module de persistance Une filtration d'un complexe \(K\) est une famille croissante $$\emptyset = K_{-1} \subseteq K_0 \subseteq K_1 \subseteq \dots \subseteq K_m = K$$ (chaque \(K_i\) est un sous-complexe de \(K_{i+1}\)). En pratique : on ordonne les simplexes \(\sigma_1 < \sigma_2 < \dots < \sigma_m\) par valeur croissante d'une fonction \(\varphi\) (distance d'apparition dans le Rips, niveau de gris d'une image, altitude d'un terrain), faces avant cofaces, et \(K_i = K_{i-1} \cup \{\sigma_i\}\). Le module de persistance est la famille d'espaces et d'applications linéaires $$H_k(K_0) \to H_k(K_1) \to \dots \to H_k(K_m)$$ induites par les inclusions. Il est tamé si ces espaces sont de dimension finie — ce que garantit la finitude de \(K\).
Théorème 4.2 (décomposition en intervalles) Tout module de persistance tamé sur un corps se décompose de façon unique (à l'isomorphisme et à l'ordre des facteurs près) en somme directe de modules intervalle \(\mathbb{I}[b, d)\) : copies du corps placées aux indices \(b \leq i < d\), reliées par identités, nulles ailleurs. Le barcode est le multi-ensemble de ces intervalles \([b, d)\) ; chaque barre est une classe d'homologie qui naît à \(b\) et meurt à \(d\) (avec \(d = \infty\) pour les classes essentielles).
(Structure, hors programme : c'est le théorème de Gabriel pour les carquois de type \(\mathbb{A}\) — le module est une représentation du carquois linéaire \(0 \to 1 \to \dots \to m\), toutes ses représentations indécomposables sont les \(\mathbb{I}[b, d)\), et la décomposition est unique car le carquois est de type fini. Le livre d'Oudot, ch. 9, en donne une preuve autonome — cf. ch. 9 du présent module. ∎
Définition 4.3 — Matrice de bord d'une filtration et indice bas Numérotons les simplexes \(\sigma_1, \dots, \sigma_m\) dans l'ordre de la filtration. La matrice de bord \(M \in \mathbb{F}_2^{m \times m}\) est définie par \(M[i, j] = 1\) si \(\sigma_i\) est une face propre de \(\sigma_j\), et 0 sinon (matrice triangulaire supérieure stricte : une face précède toujours son coface). Pour une colonne non nulle, l'indice bas est $$\mathrm{low}(j) = \max \{ i : M[i, j] = 1 \}.$$
Théorème 4.4 (algorithme standard de persistance) Soit \(R\) la matrice obtenue en réduisant \(M\) colonne par colonne, de gauche à droite : tant que \(\mathrm{low}(j)\) est défini et déjà occupé par une colonne antérieure \(j' < j\) (i.e. \(\mathrm{low}(j') = \mathrm{low}(j)\)), remplacer \(R_{:, j} \leftarrow R_{:, j} + R_{:, j'}\). Alors :
  1. chaque colonne \(j\) avec \(\mathrm{low}(j) = i\) associe la paire \((i, j)\) : une classe née à l'indice \(i\) (le simplexe \(\sigma_i\)) meurt à l'indice \(j\) — barre \([i, j)\) ;
  2. chaque colonne nulle \(j\) (réduite) code une classe essentielle née en \(j\) — barre \([j, \infty)\) ;
  3. le complexité totale est \(O(m^3)\) dans le pire cas, \(O(m^2)\) en pratique sur données réelles (colonnes déjà presque réduites).
Cohérence dimensionnelle. Si \(\sigma_j\) est un \(k\)-simplexe, sa colonne vit dans les lignes des \((k-1)\)-simplexes : une paire \((i, j)\) relie toujours deux dimensions consécutives (\(\sigma_i\) est un \((k-1)\)-simplexe).

Une paire \((i, j)\) est une naissance-then-mort. À l'étape \(i\), le simplexe \(\sigma_i\) crée soit une classe (s'il complète un cycle indépendant), soit il tue (s'il complète une chaîne dont le bord devient cycle trivial). L'algorithme reproduit cette alternative : \(\sigma_i\) tue une classe exactement quand la colonne réduite de \(\sigma_j\) a \(\mathrm{low}(j) = i\), c'est-à-dire quand \(\partial \sigma_j\) contient \(\sigma_i\) comme dernière face non appariée — la classe portée par le cycle \(\partial \sigma_j + (\text{bords déjà appariés})\) naissait avec \(\sigma_i\).

Colonnes nulles = naissances essentielles. Si la colonne réduite de \(\sigma_j\) est nulle, \(\sigma_j\) complète un cycle \(z = \sigma_j + \dots\) dont aucune face n'est « disponible » pour le tuer plus tard : aucun futur coface n'aura \(\sigma_j\) pour indice bas dans sa réduction (les réductions n'éliminent jamais les pivots déjà utilisés). La classe vit jusqu'à la fin : barre \([j, \infty)\).

Unicité. Le choix des pivots est forcé : à chaque étape, il existe au plus une colonne antérieure de même indice bas (invariant maintenu par l'algorithme), donc l'appariement ne dépend d'aucun choix arbitraire — il coïncide avec la décomposition en intervalles du théorème 4.2. ∎ 
# Algorithme standard de persistance (Edelsbrunner-Letscher-Zomorodian,
# Zomorodian-Carlsson), sur F2. low[j] = ligne du dernier 1 de la colonne j.
def persistence(M):                        # M : matrice de bord m x m (bits)
    m = M.shape[1]
    R = M.copy()
    pairs = []
    for j in range(m):
        while True:
            nz = np.nonzero(R[:, j])[0]
            if len(nz) == 0:
                pairs.append(None)         # colonne nulle : barre [j, inf)
                break
            low = nz[-1]
            prev = [jj for jj in range(j)
                    if pairs[jj] == low]   # pivot deja utilise
            if not prev:
                pairs.append(low)          # paire (low, j) : barre [low, j)
                break
            R[:, j] ^= R[:, prev[0]]       # addition de colonne (XOR en F2)
    return [(i, j) for j, i in enumerate(pairs) if i is not None]

Réduction, colonne par colonne.
  • Colonne 5 : \(\{1, 2\}\), \(\mathrm{low} = 2\). Aucun pivot antérieur : paire \((2, 5)\). La composante née avec \(v_2\) meurt quand l'arête \([v_1v_2]\) la fusionne.
  • Colonne 6 : \(\{2, 3\}\), \(\mathrm{low} = 3\) — paire \((3, 6)\). Idem pour \(v_3\).
  • Colonne 7 : \(\{3, 4\}\), \(\mathrm{low} = 4\) — paire \((4, 7)\). Idem pour \(v_4\).
  • Colonne 8 : \(\{1, 3\}\), \(\mathrm{low} = 3\) : conflit avec la colonne 6. On additionne : \(\{1,3\} \oplus \{2,3\} = \{1,2\}\), \(\mathrm{low} = 2\) : conflit avec la colonne 5. On additionne : \(\{1,2\} \oplus \{1,2\} = \emptyset\) : colonne nulle — une classe de \(H_1\) naît à l'indice 8 (la boucle \(v_1 \to v_2 \to v_3 \to v_1\)). Aucun pivot n'est détruit : l'appariement existant est inchangé.
  • Colonne 9 : \(\{5, 6, 8\}\), \(\mathrm{low} = 8\). Le pivot 8 est-il occupé ? La colonne 8 est maintenant nulle — elle n'occupe rien : pas de conflit, paire \((8, 9)\). La boucle née à 8 est tuée par le triangle \([v_1v_2v_3]\).
  • Colonne 10 : \(\{1, 4\}\), \(\mathrm{low} = 4\) : conflit avec la colonne 7 → \(\{1,4\} \oplus \{3,4\} = \{1,3\}\), \(\mathrm{low} = 3\) : conflit avec la colonne 6 → \(\{1,3\} \oplus \{2,3\} = \{1,2\}\), \(\mathrm{low} = 2\) : conflit avec la colonne 5 → \(\{1,2\} \oplus \{1,2\} = \emptyset\) — colonne nulle : une classe de \(H_1\) naît à 10 (la boucle \(v_1 \to v_3 \to v_4 \to v_1\)) et ne meurt jamais.
Barcode final. $$H_0 : [1, \infty),\; [2, 5),\; [3, 6),\; [4, 7) \qquad H_1 : [8, 9),\; [10, \infty).$$ Contrôles. (i) À la fin, \(\beta_0 = 1\) et \(\beta_1 = 1\), cohérents avec le graphe final (connexe, deux cycles indépendants — formule 3.4 : \(m - n + c = 5 - 4 + 1 = 2\) dont un tué par le triangle). (ii) Caractéristique d'Euler du complexe final : \(4 - 5 + 1 = 0 = \beta_0 - \beta_1\) (théorème 3.7). (iii) Comptage des barres : 4 naissances H0 (4 sommets), 3 morts H0 (3 arêtes fusionnantes — la 4ᵉ arête \([v_1v_3]\) crée une boucle au lieu de fusionner), 2 naissances H1, 1 mort H1 (le triangle). Tout se raccorde.
D'Euler aux barcodes, et retour La caractéristique d'Euler–Poincaré se relit à travers l'algorithme : au niveau de filtration \(i\), \(\chi(K_i)\) est le nombre de barres H0 actives moins le nombre de barres H1 actives, etc. La courbe de Betti \(\beta_k(i)\) — nombre de barres actives — est un résumé discret du barcode, strictement moins fin mais parfois suffisant (et directement lié aux fonctions de comptage du ch. 5). Retenir : le barcode est la version dynamique de l'homologie ; l'homologie simple du ch. 3 en est la tranche à \(i = m\) figée.
Variantes et limites (culture générale) La contrainte « faces avant cofaces » rend la filtration croissante ; pour s'en affranchir, on utilise la persistance en zigzag (Carlsson, de Silva, Morozov) : les flèches alternent gauche-droite, et l'algorithme se réécrit avec des colonnes « in-out ». Pour les fonctions à valeurs vectorielles, on entre dans la persistance multi-dimensionnelle — où le théorème 4.2 échoue : plus de barcode discret complet (théorème de structure négatif de Carlsson–Zomorodian).

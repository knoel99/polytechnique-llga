5. Évaluation en production : drift et monitoring

5.1 Drift de données, drift de concept

Définition 5.1 — Dérives (drift) Dérive de données : la distribution des entrées change (\(P(X)\) bouge — nouveaux topics, nouvelle population d'utilisateurs, nouvelle source documentaire). Dérive de concept : la relation entrée → réponse juste change (\(P(Y\mid X)\) bouge — la « bonne » réponse d'hier devient fausse : réglementation, fusion d'entreprises, vocabulaire). Pour un RAG, une troisième dérive : le corpus change (ch. 6).
Proposition 5.2 — PSI = divergence de Jeffreys L'indice de stabilité de population (PSI), somme sur les bacs \(i\) d'un histogramme : $$\mathrm{PSI}(p, q) \;=\; \sum_i \bigl(p_i - q_i\bigr)\, \ln\frac{p_i}{q_i} \;=\; \mathrm{KL}(p \,\|\, q) + \mathrm{KL}(q \,\|\, p),$$ est exactement la divergence de Jeffreys : symétrique, nulle ssi \(p = q\). Seuils usuels en risque de crédit : PSI < 0,1 stable ; 0,1-0,25 à surveiller ; > 0,25 alerte.
Développons : \(\mathrm{KL}(p\|q) = \sum_i p_i \ln(p_i/q_i)\) et \(\mathrm{KL}(q\|p) = \sum_i q_i \ln(q_i/p_i)\). La somme vaut \(\sum_i (p_i - q_i)\ln(p_i/q_i)\) — précisément le PSI. Chaque terme est positif (les deux facteurs \(p_i - q_i\) et \(\ln(p_i/q_i)\) ont le même signe) ; nul si et seulement si \(p_i = q_i\) pour tout \(i\). La symétrie est évidente par la forme somme. ∎

Les détecteurs classiques : PSI/KL par feature (interprétable, bac par bac), test de Kolmogorov-Smirnov (comparaison de distributions continues, cf. Refresher Statistics), distance MMD (module ML), et détecteurs de flux (ADWIN) pour les signes en ligne. Pour un LLM, les « features » à surveiller sont : longueur de prompt, langue, topics (classifieur léger), présence de documents injectés, taux de troncature — et des proxy de sortie : taux de refus, taux de « je ne sais pas », longueur médiane de réponse, taux d'échec de parse JSON. Sans labels en ligne, on surveille des symptômes ; les vraies métriques viennent du feedback et de l'échantillonnage.

Documenter cette boucle fait partie de l'audit (ch. 9 ; module Emerging ML ch. 6 sur l'équité).

5.3 Le LLM-judge en CI et en production

Juge : comment, et avec quels biais Un modèle juge évalue des paires (question, réponse) selon une grille (fidélité au contexte, complétude, ton) ; Zheng et al. (MT-Bench, NeurIPS 2023) montrent un accord avec les humains > 80 % sur des tâches de conversation — mais avec des biais documentés : préférence pour la première position, pour les réponses longues, et auto-préférence (le juge favorise son propre style). Bonnes pratiques : ordre alterné, rubrique explicite, référence fournie, golden set humain pour étalonner le juge, version du juge figée en CI (ch. 1). Le juge est un capteur bruité — on l'utilise pour détecter les régressions, pas pour certifier. 
# Mini-judge de regression en CI : compare prod vs candidate sur le golden set
def judge_pair(question, ref, ans_prod, ans_cand, judge):
    rub = "Reponse attendue (reference) : {ref}\nA : {a}\nB : {b}\n" \
          "Laquelle est la plus fidele a la reference ? Reponds A, B ou EGAL."
    out = judge(f"Q: {question}\n" + rub.format(ref=ref, a=ans_prod, b=ans_cand))
    out_sw = judge(f"Q: {question}\n" + rub.format(ref=ref, a=ans_cand, b=ans_prod))
    pair = {out.strip()[:4], out_sw.strip()[:4]}      # ordre alterne anti-biais
    return "cand" if pair == {"A", "B"} else ("prod" if pair == {"B", "A"} else "egal")

# gate : pas de regression significative (cf. prop. 2.2 pour la marge minimale)
wins = sum(judge_pair(**ex) == "cand" for ex in golden)
assert wins >= 0.45 * len(golden), f"regression juge : {wins}/{len(golden)}"

1. Relire votre MLP MNIST — ce qui marche déjà

Point de départ assumé : un réseau entièrement connecté entraîné sur des digits 28×28 aplatis, en NumPy, du type de MNIST_from_scratch.ipynb (poids ReLU / sigmoid sauvegardés, boucle train/test). On ne réécrit pas le notebook ; on le lit comme un ingénieur.

1.1. Le modèle en une ligne

Pour une image \(x \in \mathbb{R}^{784}\) et des classes \(y \in \{0,\dots,9\}\) :

$$z^{(1)} = W^{(1)} x + b^{(1)}, \quad h = \sigma\!\big(z^{(1)}\big), \quad z^{(2)} = W^{(2)} h + b^{(2)}, \quad \hat p = \mathrm{softmax}(z^{(2)}).$$

Deux couches linéaires, une non-linéarité \(\sigma\) (souvent sigmoid ou ReLU), une sortie en probabilités. C'est déjà un réseau de neurones profond au sens minimal : la profondeur commence dès qu'il y a composition non linéaire.

Définition 1.1 — Perceptron multicouche (MLP) Un MLP de profondeur \(L\) compose des applications affines et des activations élément-par-élément : \(h^{(\ell)} = \sigma\!\big(W^{(\ell)} h^{(\ell-1)} + b^{(\ell)}\big)\), avec \(h^{(0)}=x\). La dernière couche est souvent linéaire + softmax (classification) ou linéaire (régression).

1.2. Ce que votre notebook a déjà validé

  • Forward vectorisé : batches \((B, 784)\), pas de boucle pixel à pixel.
  • Une fonction de coût : cross-entropy \(-\sum_k y_k \log \hat p_k\) (souvent via log-softmax pour la stabilité).
  • Une règle de mise à jour : \(W \leftarrow W - \eta \nabla_W \mathcal{L}\) sur mini-batches.
  • Un critère empirique : accuracy test ~97 %+ sur MNIST avec un MLP raisonnable — assez pour croire que le gradient « marche ».
Diagnostic rapide Si votre MLP stagne ~10 % (hasard sur 10 classes) : learning rate absurde, soft-max/numérique, ou labels mal encodés. S'il atteint ~90 % train et ~70 % test : capacité OK, régularisation / données à revoir. S'il atteint 99 % train et test sur MNIST : le benchmark est trop facile pour juger la généralisation — d'où Fashion-MNIST ou CIFAR plus tard en Deep Learning. 
import numpy as np

def softmax(z):
    z = z - z.max(axis=1, keepdims=True)          # stabilité
    e = np.exp(z)
    return e / e.sum(axis=1, keepdims=True)

def forward(x, W1, b1, W2, b2, kind="relu"):
    z1 = x @ W1 + b1
    h = np.maximum(z1, 0.0) if kind == "relu" else 1.0 / (1.0 + np.exp(-z1))
    logits = h @ W2 + b2
    return softmax(logits), h, z1

def cross_entropy(p, y_idx):
    return -np.log(p[np.arange(len(y_idx)), y_idx] + 1e-12).mean()

2. Forward, perte, boucle d'entraînement — ce qui casse

Un MLP MNIST qui converge masque les modes de panne que Deep Learning rencontrera immédiatement (images plus dures, profondeur, séquences). On les provoque volontairement sur le même code.

Définition 2.1 — Risque empirique Pour un échantillon \(\{(x_i,y_i)\}_{i=1}^n\) et une perte ponctuelle \(\ell\), $$\hat{\mathcal{R}}(\theta) = \frac1n \sum_{i=1}^n \ell\big(f_\theta(x_i), y_i\big).$$ L'entraînement minimise \(\hat{\mathcal{R}}\) (souvent en mini-batches). La généralisation concerne \(\mathcal{R}(\theta)=\mathbb{E}[\ell(f_\theta(x),y)]\), inaccessible — d'où train/val/test.

Pour la classification multiclasse, la perte canonique est la cross-entropy entre le one-hot \(y\) et \(\hat p = \mathrm{softmax}(z)\). Combinée au softmax, son gradient en \(z\) se simplifie en \(\hat p - y\).

2.2. Quatre pannes classiques (à provoquer sur MNIST)

  1. Learning rate trop grand : loss → NaN en quelques steps. Trop petit : plateau pendant des epochs.
  2. Saturation sigmoid : \(|z|\) grand ⇒ \(\sigma'(z)\approx 0\) ⇒ gradients nuls sur les premières couches.
  3. Batch size extrême : \(B=1\) bruyant mais parfois régularisant ; full-batch lisse mais peut coller à un mauvais bassin.
  4. Fuite de test : tuner \(\eta\), largeur, epochs sur le test set — toujours une validation séparée.
def sgd_step(params, grads, lr):
    return [p - lr * g for p, g in zip(params, grads)]
# Astuce : logger loss train et ||grad||_2 ; une norme qui x10 chaque step annonce l'explosion.

3. Gradients et rétropropagation, sans magie

Autograd (PyTorch) automatise ce que votre notebook NumPy faisait à la main. Comprendre la rétropropagation reste non négociable : c'est le même mécanisme sous les CNN, l'attention et les GNN.

Proposition 3.1 — Règle de la chaîne sur un graphe Si \(\mathcal{L}\) dépend de \(z\) via \(h=\phi(z)\), $$\frac{\partial\mathcal{L}}{\partial z} = \frac{\partial\mathcal{L}}{\partial h}\cdot \phi'(z)$$ (élément-par-élément si \(\phi\) est une activation). Pour \(z=Wh\), \(\nabla_W \mathcal{L} = (\nabla_z \mathcal{L})\, h^\top\) (selon conventions ligne/colonne).

3.1. Sur votre MLP à deux couches

Soit \(\delta^{(2)} = \hat p - y\) (gradient des logits). Alors :

$$\nabla_{W^{(2)}}\mathcal{L} = h^\top \delta^{(2)}, \quad \delta^{(1)} = \big(\delta^{(2)} (W^{(2)})^\top\big) \odot \sigma'(z^{(1)}), \quad \nabla_{W^{(1)}}\mathcal{L} = x^\top \delta^{(1)}.$$

C'est exactement le « backward » de votre from-scratch : on pousse \(\delta\) vers l'entrée en multipliant par les \(W^\top\) et les dérivées d'activation.

# Backward NumPy (batch) — ReLU
delta2 = (p - y_onehot) / B
dW2 = h.T @ delta2
db2 = delta2.sum(axis=0)
delta1 = (delta2 @ W2.T) * (z1 > 0)
dW1 = x.T @ delta1
db1 = delta1.sum(axis=0)
Lien doctoral, formulation ingénieur Le graphe de calcul est un DAG ; backprop est un parcours en ordre topologique inverse qui applique la règle de la chaîne (VJP). Quand vous déboguerez un transformer, vous chercherez encore « quelle arête multiplie mon gradient par ~0 ? ».

4. Activations, initialisation, profondeur

Définition 4.1 — Activations usuelles \(\mathrm{ReLU}(z)=\max(z,0)\), \(\sigma(z)=(1+e^{-z})^{-1}\), \(\tanh(z)\). ReLU évite la saturation positive ; sigmoid/tanh saturent en \(\pm\infty\).

4.1. Initialisation : pourquoi le tirage compte

Si \(W_{ij} \sim \mathcal{N}(0,1)\) en grande largeur, les pré-activations explosent (variance \(\propto\) fan-in). Les schémas Xavier/Glorot (tanh) et He (ReLU) calibrent \(\mathrm{Var}(W)\) pour garder des variances stables au forward (et approximativement au backward).

rng = np.random.default_rng(0)
# He pour ReLU : Var = 2 / fan_in
W1 = rng.normal(0, np.sqrt(2 / 784), size=(784, 128))
W2 = rng.normal(0, np.sqrt(2 / 128), size=(128, 10))

4.2. Quand la profondeur fait mal

Empiler des sigmoids sans soin ⇒ vanishing gradients. ReLU soigne une partie du problème mais introduit des neurones « morts ». En Deep Learning vous verrez BatchNorm, connexions résiduelles et LayerNorm comme réponses structurelles — ici, retenez le symptôme : \(\|\delta^{(\ell)}\|\) qui s'écroule vers l'entrée.

5. Optimisation en pratique (SGD → Adam)

Définition 5.1 — SGD mini-batch $$\theta_{t+1} = \theta_t - \eta \nabla_\theta \hat{\mathcal{R}}_{B_t}(\theta_t),$$ où \(B_t\) est un mini-batch. Le bruit d'échantillonnage peut aider en non-convexe.

Momentum accumule une vitesse : \(v \leftarrow \mu v + \nabla\), \(\theta \leftarrow \theta - \eta v\). Adam combine moments d'ordre 1 et 2 avec biais corrigé — défaut raisonnable en DL, pas une excuse pour ignorer \(\eta\).

def adam(param, grad, m, v, t, lr=1e-3, beta1=0.9, beta2=0.999, eps=1e-8):
    m = beta1 * m + (1 - beta1) * grad
    v = beta2 * v + (1 - beta2) * (grad * grad)
    mhat = m / (1 - beta1 ** t)
    vhat = v / (1 - beta2 ** t)
    param = param - lr * mhat / (np.sqrt(vhat) + eps)
    return param, m, v
Réflexes d'ingénieur Logger train/val loss et accuracy ; commencer par \(\eta\) trop grand puis diviser par 3 ; décroître \(\eta\) quand la val stagne ; fixer les graines pour reproduire un bug. PyTorch est bienvenu dès que les shapes deviennent pénibles — un backward NumPy sur MLP reste l'exercice de vérité.

6. Du MLP au toy-transformer — intuition LLM

Objectif : pas entraîner un LLM. Juste voir que l'attention est une combinaison bilinéaire de vecteurs, implémentable en quelques lignes NumPy, et que le bloc transformer enchaîne attention + MLP — deux ingrédients que vous connaissez déjà.

Définition 6.1 — Attention (une tête, version pédagogique) Pour des requêtes \(Q\), clés \(K\), valeurs \(V\) (matrices \(T\times d\)) : $$\mathrm{Attention}(Q,K,V) = \mathrm{softmax}\!\Big(\frac{QK^\top}{\sqrt{d}}\Big) V.$$ Chaque position agrège les valeurs des autres positions avec des poids dépendant du contenu — message passing sur un graphe complet de tokens (lecture Graph ML). 
def attention(Q, K, V):
    # Q,K,V: (T, d)
    d = Q.shape[1]
    scores = (Q @ K.T) / np.sqrt(d)
    weights = softmax(scores[None, :, :])[0]
    return weights @ V, weights

rng = np.random.default_rng(1)
X = rng.normal(size=(4, 8))
Wq, Wk, Wv = (rng.normal(size=(8, 8)) * 0.1 for _ in range(3))
out, w = attention(X @ Wq, X @ Wk, X @ Wv)
print(out.shape, w.round(2))

Un bloc transformer (esquisse) : LayerNorm → attention → résidu → LayerNorm → MLP position-wise → résidu. Les LLMs empilent ces blocs et entraînent en prédiction du prochain token (cross-entropy, comme MNIST mais sur un vocabulaire). Votre MLP digits = même famille de perte ; l'attention ajoute le routage entre positions.

Expérience 6.2 — sans GPU Construisez \(T=5\), \(d=16\). Calculez les poids d'attention. Forcez une clé \(K_2\) très alignée avec \(Q_0\) et vérifiez que la ligne 0 de \(w\) se concentre sur la colonne 2.

Exercices

  1. Shapes MNIST. Pour un batch \(B=64\), largeur cachée \(H=256\), écrire les shapes de \(x, W^{(1)}, z^{(1)}, h, W^{(2)}, \hat p\). Quelle est la complexité FLOPs d'un forward (ordre de grandeur) ?
    \(x:(64,784)\), \(W^{(1)}:(784,256)\), \(z^{(1)},h:(64,256)\), \(W^{(2)}:(256,10)\), \(\hat p:(64,10)\). Dominant : \(64\cdot784\cdot256 + 64\cdot256\cdot10 \approx 1{,}3\cdot10^7\) mul-add.
  2. Gradient softmax-CE. Montrer que si \(\ell=-\sum_k y_k\log p_k\) et \(p=\mathrm{softmax}(z)\), alors \(\nabla_z \ell = p-y\). Vérifier numériquement par différences finies sur \(z\in\mathbb{R}^{10}\).
    Calcul direct : \(\partial\log p_k/\partial z_j = \mathbf{1}_{kj}-p_j\). D'où \(\partial\ell/\partial z_j=p_j-y_j\).
  3. Saturation. MLP 784-128-10 avec \(W\sim\mathcal{N}(0,2)\), sigmoid, \(\eta=0{,}1\). Observer loss et \(\|W^{(1)}\|_{\mathrm{F}}\) sur 20 steps. Corriger (init ou activation) et retester.
    Variance trop grande ⇒ saturations ⇒ gradients ~0. He/Xavier ou ReLU + \(\eta\) plus petit restaure l'apprentissage.
  4. Backprop à la main. Réseau scalaire \(y=\sigma(w_2\sigma(w_1 x))\), perte \(\frac12(y-t)^2\). Calculer \(\partial\mathcal{L}/\partial w_1\) pour \(x=1,t=0,w_1=w_2=1\).
    Remonter \(\delta\) via \(\sigma'\). Valeur numérique de l'ordre de \(0{,}03\).
  5. Adam vs SGD. Sur votre MLP MNIST (2–3 epochs), comparer SGD \(\eta=0{,}1\) et Adam \(\eta=10^{-3}\) à seed fixée. Dans quel régime Adam aide-t-il vraiment ici ?
    Sur un petit MLP MNIST, SGD bien réglé suffit souvent ; Adam aide surtout si \(\eta\) SGD est mal choisi. L'exercice vise le protocole de comparaison.
  6. Attention toy. Implémenter attention(Q,K,V). Ajouter un masque causal et vérifier que les poids sont triangulaires inférieurs.
    Avant softmax : scores[i,j]=-1e9 si j>i. Après softmax, \(w_{ij}=0\) pour \(j>i\).
  7. Pont Graph ML. En une demi-page, expliquer pourquoi \(\mathrm{softmax}(QK^\top)V\) ressemble à un message passing sur le graphe complet à \(T\) nœuds. Différence avec un GCN 1-hop ?
    Poids d'attention = coefficients sur toutes les arêtes contenu-dépendantes ; GCN 1-hop restreint aux voisins structurels.
  8. (Optionnel PyTorch) Recoder le MLP MNIST en nn.Linear + Adam. Vérifier qu'un backward NumPy et autograd coïncident à \(10^{-5}\) près sur un batch.
    Copier les tenseurs NumPy → torch, comparer .grad aux matrices dW.

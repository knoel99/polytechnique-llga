0. Rappels : théorie des graphes

Rappels L3 — l'objet « graphe » (cf. Refresher CS, ch. 5)
  • Définitions : \(G = (V, E)\) ; orienté/non orienté, pondéré ; degré \(d_v\), voisins \(\mathcal{N}(v)\), matrice d'adjacence \(A\), matrice de degrés \(D = \mathrm{diag}(d_v)\). Chemins, connexité, composantes, cycles, DAG.
  • Euler et Königsberg (1736) : la traversée des 7 ponts est impossible car plus de deux sommets sont de degré impair — premier théorème de la théorie des graphes ; l'abstraction (nœuds + arêtes) a fondé la discipline.
  • Algèbre linéaire : \((A^k)_{ij}\) compte les chemins de longueur \(k\) ; valeurs propres de \(A\) = spectre du graphe ; matrices symétriques diagonalisables en base orthonormée (rappel d'algèbre).
  • Matrices stochastiques : \(P = D^{-1}A\) = marche aléatoire ; distribution stationnaire, PageRank \(\pi \propto (I - \alpha P)^{-1}\mathbf{1}\).
Définition 0.1 — Le laplacien d'un graphe $$L = D - A, \qquad \text{ou normalisé : } L_{\mathrm{sym}} = I - D^{-1/2} A\, D^{-1/2}.$$ Pour tout vecteur \(x \in \mathbb{R}^n\) (\(n = |V|\)) : $$x^\top L x = \sum_{(u,v) \in E} (x_u - x_v)^2 \ \geq\ 0$$ — \(L\) est positive semi-définie ; ses valeurs propres \(0 = \lambda_1 \leq \lambda_2 \leq \dots \leq \lambda_n\) encodent la connectivité ; \(\lambda_2\) (trou spectral de Fiedler) mesure la difficulté à couper le graphe, et le nombre de valeurs propres nulles = nombre de composantes connexes.
Exemple 0.2 — Le spectre raconte l'histoire Chemin de \(n\) sommets : \(\lambda_k = 2(1 - \cos\frac{k\pi}{n})\) ; graphe complet : \(0\) puis \(n\) (multiplicité \(n-1\)) ; cycle : valeurs propres de \(2\cos\). Un graphe « deux communautés » a un petit \(\lambda_2\) ; le vecteur propre de Fiedler sépare les communautés — c'est le spectral clustering : k-means sur les \(k\) premiers vecteurs propres de \(L\) (pont direct avec l'ACP du module Machine Learning).

1. Pourquoi les graphes ?

Les données du monde réel sont relationnelles : la structure porte une information que les méthodes iid ignorent. Les réseaux sociaux (amitiés), les molécules (liaisons), les réseaux de transactions (fraude !), les graphes de connaissances d'entreprise (clients, produits, processus), les réseaux informatiques, les grappes de citations, les ontologies juridiques… Tous sont naturellement des graphes, souvent hétérogènes (nœuds/arrêtes typés) et dynamiques.

Le positionnement LLGA Les LLMs excellent sur le texte mais peinent sur : les relations structurées, la fidélité factuelle (hallucinations), et les données non textuelles. Les graphes comblent exactement ces manques :
  • GraphRAG : connecter le LLM à des données propriétaires structurées — l'approche la plus efficace aujourd'hui pour fiabiliser un LLM en entreprise ;
  • GNN + LLM : IA générative sur données structurées (générer des molécules, des plans, des recommandations) ;
  • Applications industrielles : pharma/biotech (molécules = graphes), finance (réseaux de transactions, risque systémique), recommandation, supply chain, systèmes multi-agents (les workflows d'agents sont des DAG — module RL, ch. 7).

La difficulté fondamentale Un graphe n'a ni taille fixe, ni ordre canonique des nœuds. Toute architecture doit être permutation-invariante (prédiction de graphe) ou permutation-équivariante (prédiction par nœud) : \(f(P X, P A P^\top) = P f(X, A)\) pour toute permutation \(P\). Les CNN/RNN ne satisfont pas cela — d'où des architectures dédiées.

3. Node embeddings

Objectif Apprendre \(z_v \in \mathbb{R}^d\) tel que la similarité des embeddings reflète la proximité dans le graphe : \(\mathrm{sim}(z_u, z_v) \approx P(\text{\(u\) voisin de \(v\)})\).
DeepWalk (Perozzi et al., 2014) et node2vec (Grover & Leskovec, 2016)
  1. générer des marches aléatoires depuis chaque nœud (node2vec : paramètres \(p\) (retour) et \(q\) (exploration BFS vs DFS) qui biaisent la marche) ;
  2. appliquer word2vec skip-gram aux marches : les « phrases » sont des suites de nœuds ; maximiser \(\sum \log P(v \mid u)\) avec \(P(v\mid u) \propto \exp(z_u^\top z_v)\) ;
  3. ensuite : n'importe quelle méthode vectorielle (k-means, classification…).
La marche aléatoire définit la proximité : deux nœuds co-visités souvent obtiennent des embeddings proches — la k-alors que factorisation de \(P = D^{-1}A\) (NetMF) explique rétroactivement pourquoi ça marche.
L'intuition « word2vec sur le graphe » C'est le pont historique NLP ↔ graphes : un corpus de marches ≈ un corpus de phrases. Le même Vazirgiannis a poussé l'idée inverse — Graph of Words : représenter un document par un graphe de termes co-occurrents, et classifier le document avec des outils de graphes. Les deux directions convergent aujourd'hui dans les LLMs sur graphes (ch. 8). 
from gensim.models import Word2Vec
import networkx as nx

G = nx.karate_club_graph()
walks = []
for _ in range(80):
    for v in G.nodes():
        walk, cur = [v], v
        for _ in range(30):
            cur = np.random.choice(list(G.neighbors(cur)))
            walk.append(cur)
        walks.append([str(n) for n in walk])

model = Word2Vec(walks, vector_size=64, window=5, min_count=0, sg=1, epochs=5)
Z = np.array([model.wv[str(v)] for v in G.nodes()])   # embeddings (34, 64)

4. Filtres spectraux

Définition 4.1 — Transformée de Fourier sur graphe Soit \(L = U \Lambda U^\top\) (décomposition spectrale, \(U\) orthogonale). Pour un signal \(x \in \mathbb{R}^n\) porté par les nœuds : $$\hat x = U^\top x \quad (\text{analyse}), \qquad x = U \hat x \quad (\text{synthèse}).$$ Les « fréquences » sont les valeurs propres \(\lambda_k\) — petites = variations lentes sur le graphe (basses fréquences), grandes = alternances locales (hautes fréquences). C'est la convolution du module Signal Processing, avec le laplacien pour opérateur !
Convolution spectrale et ChebNet (Defferrard et al., 2016) Filtrer : \(y = U\, g_\theta(\Lambda)\, U^\top x\) — coûteux (décomposition complète, dépend du graphe). Astuce : prendre \(g_\theta\) polynomial de degré \(K\), \(g_\theta(\Lambda) = \sum_{k=0}^{K} \theta_k T_k(\tilde\Lambda)\) (polynômes de Tchebychev de \(\tilde\Lambda\) renormalisé) ; alors $$y = \sum_{k=0}^K \theta_k\, T_k(\tilde L)\, x,$$ sans vecteurs propres : un filtre \(K\)-localisé (chaque nœud ne voit que ses \(K\)-voisins) et des poids \(\theta\) partagés par tous les graphes.

5. GNN et message passing

Définition 5.1 — La couche de message passing (MPNN, Gilmer et al., 2017) $$h_v^{(\ell+1)} = \phi\Big(h_v^{(\ell)},\ \underset{u \in \mathcal{N}(v)}{\mathrm{AGG}}\ \big\{\psi\big(h_v^{(\ell)}, h_u^{(\ell)}\big)\big\}\Big)$$ message \(\psi\) (calculé par le voisin), agrégation \(\mathrm{AGG}\) (permutation-invariante : somme, moyenne, max, attention), update \(\phi\). Une couche = un tour de message passing = une convolution = un pas de diffusion sur le graphe.
Les trois architectures canoniques
  • GCN (Kipf & Welling, 2017) : simplification du ChebNet à \(K=1\) ; $$H^{(\ell+1)} = \sigma\Big(\tilde D^{-1/2} \tilde A \tilde D^{-1/2}\, H^{(\ell)} W^{(\ell)}\Big), \qquad \tilde A = A + I$$ (auto-boucles ; renormalisation spectrale). Moyenne pondérée des voisins transformés ; \(L\) couches = réceptive field de \(L\) sauts.
  • GraphSAGE (Hamilton et al., 2017) : agrégateurs au choix (mean/lstm/pool) + concaténation avec \(h_v\) ; s'entraîne par échantillonnage de minibatchs de voisinage ⇒ induction à des nœuds/graphes non vus (indispensable en production : prédire pour un nouvel client).
  • GAT (Veličković et al., 2018) : poids d'arête appris par attention ; $$\alpha_{uv} = \frac{\exp\big(\mathrm{LeakyReLU}(a^\top[W h_u \| W h_v])\big)}{\sum_{u' \in \mathcal{N}(v)} \exp\big(\dots\big)}, \qquad h_v^{(\ell+1)} = \sigma\Big(\sum_{u \in \mathcal{N}(v)} \alpha_{uv}\, W h_u^{(\ell)}\Big)$$ — structurellement identique à l'attention des transformers (module Deep Learning, ch. 6) : ici le graphe est donné, là il est calculé.
Over-smoothing Empiler beaucoup de couches GCN fait converger tous les embeddings vers le même vecteur (la moyenne répétée lisse) ; en pratique 2-4 couches suffisent, et les deep GNN (ResGCN, APPNP, GCNII) contournent par résidus/propagation initiale. Autres limites structurelles : over-squashing (goulots d'étranglement — « bottlenecks ») et l'expressivité limitée au test de Weisfeiler-Lehman (module M2 Advanced GNN). 
import torch
from torch_geometric.nn import GCNConv, GATConv
from torch_geometric.datasets import Planetoid

dataset = Planetoid(root="/tmp/Cora", name="Cora")   # 2708 noeuds, 5429 aretes, 7 classes
data = dataset[0]

class GCN(torch.nn.Module):
    def __init__(self, d_in, d_hid, n_classes):
        super().__init__()
        self.c1, self.c2 = GCNConv(d_in, d_hid), GCNConv(d_hid, n_classes)
    def forward(self, x, edge_index):
        return self.c2(torch.relu(self.c1(x, edge_index)), edge_index)

model = GCN(dataset.num_features, 64, dataset.num_classes)
opt = torch.optim.Adam(model.parameters(), lr=0.01, weight_decay=5e-4)
for epoch in range(200):
    opt.zero_grad()
    out = model(data.x, data.edge_index)
    loss = torch.nn.functional.cross_entropy(out[data.train_mask], data.y[data.train_mask])
    loss.backward(); opt.step()
acc = (model(data.x, data.edge_index).argmax(1)[data.test_mask]
       == data.y[data.test_mask]).float().mean()
print(f"Cora test accuracy : {acc:.3f}")   # ~0.81 avec ce reglage simple

6. Applications et mise en œuvre

  • Recommandation : graphe utilisateur-item, link prediction ; PinSage (Pinterest, milliards d'arêtes) = GraphSAGE à l'échelle industrielle ;
  • Détection de fraude : classification de nœuds sur le graphe de transactions ; les flux financiers sont des graphes — l'un des débouchés LLGA ;
  • Chimie / biotech : molécule = graphe (atomes = nœuds, liaisons = arêtes) ; classification de graphes pour prédire des propriétés (toxicité, solubilité) ; benchmarks : ZINC, QM9, ogbg-mol*
  • Complétion de graphes de connaissances : link prediction sur KG hétérogènes (R-GCN, TransE) ; base du RAG « entreprise » ;
  • Passage à l'échelle : mini-batching par sous-graphes (NeighborLoader), échantillonnage de voisinage, GPU multi-nœuds — benchmarks ouverts : Open Graph Benchmark (OGB).

7. Génération de graphes

Problème Échantillonner \(G \sim p_\theta(G)\) où \(p\) est appris sur une famille de graphes (molécules actives, réseaux routiers…) — éventuellement conditionné par une propriété cible (« génère une molécule avec cette activité ») ou par du texte (text-to-graph). C'est le versant « Generative AI » du titre du master.
  • Autorégressifs par nœuds/arêtes : DeepGMG, GraphRNN — générer séquentiellement (ajouter un nœud ? une arête ?) ;
  • VAE de graphes : GraphVAE (adjacence générée d'un bloc), NeVAE (Vazirgiannis et al., 2019) : VAE pour molécules avec contraintes de valence ;
  • Normalizing flows : GraphAF (autorégressif par flow) ;
  • Diffusion : EDT / DiGress (diffusion discrète sur types de nœuds et d'arêtes) — l'état de l'art 2024-2026, cousin direct des modèles de diffusion du module Multimodal GenAI ;
  • Évaluation : validité chimique, unicité, Fréchet ChemNet, MMD de degrés/motifs — mesurer la « fidélité distributionnelle » des graphes générés (les distances entre distributions de graphes utilisent… le transport optimal, module suivant ; Gromov-Wasserstein compare des graphes sans correspondance de nœuds).

8. Graphes × LLMs : GraphRAG et l'hybride

  • Knowledge graphs d'entreprise : extraire automatiquement un graphe (entités, relations) de documents non structurés — extraction par LLM (NER + relation extraction, cf. module NLP) ou par modèles dédiés ;
  • GraphRAG : au lieu d'indexer des morceaux de texte (RAG vectoriel classique), requêter le graphe de connaissances — parcours multi-sauts, raisonnement relationnel, réponses sourcées et traçables ; hybride : graphe + recherche vectorielle (GraphRAG par communautés, resp. Microsoft) ;
  • Faire raisonner le LLM sur le graphe : sérialiser le graphe en texte (prompting) ; pseudo-code prompting pour le raisonnement graphique ; GNN comme encodeur structurel + LLM comme reasoner ; projeter des embeddings de GNN dans l'espace du LLM ;
  • Agents sur graphes : le plan d'un système multi-agents est un graphe (DAG d'orchestration) ; le « graph engineering » (2026) = programmer la topologie des agents — la boucle master : le graphe dans le modèle (attention), le graphe pour le modèle (RAG), le graphe entre les modèles (agents).
TP final Construire un mini-GraphRAG : 1) extraire d'un corpus d'entreprise (rapports, e-mails simulés) un graphe d'entités avec un LLM ; 2) répondre à des questions relationnelles (« qui travaille avec qui sur X ? ») par parcours de graphe vs. par RAG vectoriel ; 3) comparer fidélité et coût.

Exercices

  1. Laplacien. Montrer \(x^\top L x = \sum_{(u,v) \in E}(x_u - x_v)^2\), puis que \(\lambda_2 > 0 \iff\) connexe. Calculer le spectre du chemin et du cycle.
  2. Permutation-équivariance. Vérifier que la couche GCN satisfait \(f(PX, PAP^\top) = P f(X, A)\) et interpréter ; montrer qu'une couche dense classique (MLP sur features concaténées) ne la satisfait pas.
  3. node2vec. Simuler des marches avec \((p, q) = (1, 1)\), \((0{,}25, 0{,}25)\), \((4, 1)\) sur le graphe du club de karaté ; projeter les embeddings en 2D (t-SNE) et relier \(p, q\) aux stratégies BFS/DFS.
  4. GCN à la main. Implémenter une couche GCN sans PyG (calculer \(\tilde A\), \(\tilde D\)), vérifier l'égalité des sorties avec GCNConv à poids fixés, puis mesurer l'over-smoothing : similarité cosinus moyenne des embeddings en fonction du nombre de couches (1 à 10).
  5. Link prediction. Sur Cora : masquer 10 % des arêtes, encoder avec un GCN, scorer les paires par \(\sigma(z_u^\top z_v)\) ; évaluer AUC contre des négatifs échantillonnés ; discuter l'usage pour la recommandation.
  6. Génération. Entraîner un petit modèle autorégressif (ajout séquentiel de nœuds/arêtes, MLP + softmax) sur des molécules de ZINC ; mesurer validité (valence chimique) et unicité des graphes générés ; comparer à un échantillonneur Erdős–Rényi de même densité.

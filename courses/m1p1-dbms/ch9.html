9. Au-delà du relationnel : NoSQL, graphes, vecteurs

Le relationnel domine les charges transactionnelles, mais trois évolutions des années 2000-2020 ont essaimé de nouveaux modèles : l'échelle horizontale (NoSQL), la donnée en graphe (knowledge graphs), et la recherche par similarité sur vecteurs — le carburant des systèmes d'apprentissage et du RAG (cf. module Large Language Models, chapitre 7).

Théorème 9.1 — CAP (Brewer, 2000 ; Gilbert-Lynch, 2002) Dans un système distribué soumis à des pannes réseau (partitions), on ne peut garantir simultanément cohérence forte (C) et disponibilité (A) : il faut choisir, au moins pendant la partition.
Esquisse. Partitionnez le réseau en deux composants \(\Gamma_1, \Gamma_2\). Un client écrit dans \(\Gamma_1\), un autre lit dans \(\Gamma_2\). Si les deux opérations aboutissent (A), la lecture ne peut pas voir l'écriture : incohérence (non-C). Pour rester cohérent, \(\Gamma_2\) doit refuser ou bloquer (non-A). ∎
Les systèmes NoSQL revendiquent donc AP avec cohérence éventuelle (BASE) ; les systèmes dits CP sacrifient la disponibilité pendant les partitions. Le compromis se pilote par requête (niveaux de cohérence lisibles / écrites, quorum \(r + w > n\)).
Définition 9.2 — Familles NoSQL
  • clé-valeur (Redis, DynamoDB) : une table de hachage distribuée (ch. 5 à l'échelle d'un cluster, consistent hashing) ;
  • documents (MongoDB) : des arbres JSON identifiés, interrogation par champs — la 1NF est délibérément abandonnée pour regrouper ce qui se lit ensemble ; 
    { "_id": "cmd1043", "client": { "nom": "Anna", "ville": "Palaiseau" },
  "lignes": [ { "article": "DB", "qte": 2 }, { "article": "DL", "qte": 1 } ],
  "statut": "expédiée" }
  • colonnes (Cassandra, Bigtable) : lignes clairsemées regroupées physiquement par famille de colonnes et triées par clé de regroupement — les SSTables et le log-structured merge tree (memtable → niveaux de fichiers triés, lectures majorées par des filtres de Bloom) remplacent le B+ ;
  • graphes : voir ci-dessous — le seul modèle où la jointure récursive est de première classe.
Définition 9.3 — Property graphs et RDF Un property graph (Neo4j ; standard GQL) est un graphe multi-relations dont nœuds et arêtes portent des propriétés clé-valeur. Le langage Cypher interroge par motifs : 
MATCH (a:Personne {nom: "Anna"})-[:INSCRIT_A*1..3]->(c:Cours)
WHERE c.credits >= 3
RETURN DISTINCT c.code;
Le modèle RDF (W3C) représente tout par des triplets (sujet, prédicat, objet) formant un graphe orienté étiqueté global, avec des IRI (identifiants universels) et des ontologies (RDFS, OWL) pour raisonner. SPARQL reprend le SQL (SELECT/WHERE) sur des motifs de graphe : 
SELECT DISTINCT ?code WHERE {
  :Anna :inscritA+ ?c .            # chemin de longueur ≥ 1 (SPARQL 1.1)
  ?c :credits ?cr . FILTER(?cr >= 3)
  ?c :code ?code . }

Pour l'apprentissage sur graphes (plongements de nœuds, GNN, message passing), les deux modèles se projettent en matrices creuses — cf. module Graph ML, chapitres 1 (pourquoi les graphes ?) et 5 (GNN).
Définition 9.4 — Bases vectorielles et recherche ANN Un magasin de vecteurs indexe des plongements \(x_i \in \mathbb{R}^d\) (produits par des encodeurs — cf. modules NLP, ch. 3, et Multimodal GenAI, ch. 5) avec une distance (cosinus, \(L^2\)) et répond « les \(k\) plus proches voisins de \(q\) ». La recherche exacte coûte \(O(nd)\) : pour \(n = 10^7\), \(d = 768\), soit \(7{,}7\times10^{10}\) multiplications par requête — prohibitif en service. La recherche approchée (ANN) échange un peu de rappel contre des ordres de grandeur de vitesse :
  • IVF (inverted file) : partitionner l'espace en \(n_{list}\) cellules par k-moyennes (cf. module Machine Learning, ch. 6) ; n'explorer que les \(n_{probe}\) cellules les plus proches. \(n_{list} = 4096\), \(n_{probe} = 16\) sur \(10^7\) vecteurs : ~ \(39\,000\) distances au lieu de \(10^7\) — 250× moins de travail, rappel typique > 95 % ;
  • HNSW (Malkov-Yashunin) : graphe hiérarchique « navigable small-world ». La couche 0 contient tous les vecteurs, les couches supérieures des sommets de plus en plus clairsemés (un nœud apparaît à la couche \(\ell\) avec probabilité \(p^{-\ell}\)). La recherche part du sommet de la couche haute et fait du greedy routing (passer au voisin qui rapproche le plus de \(q\)) en descendant couche par couche ; l'insertion relie le nouveau nœud à ses \(M\) plus proches voisins ainsi trouvés. Les liens longs des couches hautes (choisis par une heuristique de diversité) donnent le raccourci quasi logarithmique ; coût pratique ~\(O(\log n)\), rappel réglable, au prix d'une construction coûteuse et d'un graphe en mémoire ;
  • quantification (PQ) : découper \(x \in \mathbb{R}^d\) en \(m\) sous-vecteurs quantifiés chacun sur \(2^8\) centroïdes ; la distance devient une somme de termes lus dans des tables — mémoire divisée par ~\(d\), au prix d'une distance approximée.
Exemple 9.5 — Recherche vectorielle en Python (parcours complet + IVF) 
import numpy as np
from sklearn.cluster import MiniBatchKMeans

rng  = np.random.default_rng(0)
X    = rng.normal(size=(100_000, 64)).astype("float32")   # "base" de vecteurs
q    = rng.normal(size=(64,)).astype("float32")

def normalize(A): return A / np.linalg.norm(A, axis=1, keepdims=True)
Xn, qn = normalize(X), q / np.linalg.norm(q)

# --- 1. recherche exacte (brute force) : O(n d)
d_all = Xn @ qn
top10_exact = set(np.argsort(d_all)[-10:])

# --- 2. IVF : nlist cellules par k-means, on sonde nprobe cellules
nlist, nprobe = 256, 8
km = MiniBatchKMeans(n_clusters=nlist, n_init=3, random_state=0).fit(Xn)
cell_of_X = km.labels_
d_centro  = np.linalg.norm(km.cluster_centers_ - qn, axis=1)
probes    = np.argsort(d_centro)[:nprobe]
cand      = np.where(np.isin(cell_of_X, probes))[0]
top10_ivf = set(cand[np.argsort(Xn[cand] @ qn)[-10:]])

print(len(top10_exact & top10_ivf) / 10, "rappel@10")     # typiquement 0.9-1.0
print(f"exact : {len(Xn)} distances ; IVF : {len(cand) + nlist} distances")
Le rappel @k se monnaie contre le coût : c'est le même compromis que celui des index B+ (exact, logarithmique, contraint par les préfixes) — mais avec une tolérance probabiliste assumée. Les SGBD relationnels intègrent aujourd'hui ces index en extension (pgvector ; le module Large Language Models, ch. 7, montre le pipeline RAG complet qui les consomme).

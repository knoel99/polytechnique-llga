0. Rappels : de word2vec aux transformers

Prérequis (modules M1)
  • Embeddings (NLP ch. 3) : word2vec/GloVe — un mot = un vecteur statique ;
  • Attention & transformers (Deep Learning ch. 6) : \(\mathrm{softmax}(QK^\top/\sqrt{d_k})V\), multi-tête, résidus, LayerNorm ; lecture « graphe de tokens » ;
  • RL (module RL) : politiques, gradients de politique, PPO, bandits — le moteur de l'alignement ;
  • Cross-entropy (ML ch. 3) : la perte de pré-entraînement est exactement la maximisation de vraisemblance du token suivant.

La trajectoire : n-grammes → embeddings statiques → réseaux récurrents (LSTM) → attention (Bahdanau 2014) → transformer (Vaswani 2017) → BERT/GPT (2018-2019) → scaling (GPT-3, 2020) → alignement (InstructGPT 2022, RLHF) → LLMs généralistes multimodaux et agents (2023-2026). Ce module couvre chaque étage technique de cette pile.

1. Tokenisation

Définition 1.1 — BPE (Byte Pair Encoding) Vocabulaire initial : octets ; itérer : fusionner la paire adjacente la plus fréquente du corpus ; jusqu'à \(|V|\) (32k-128k) tokens. WordPiece (BERT : fusion maximisant la vraisemblance), Unigram (Segment Anything… non — modèle unigramme + algorithme de Viterbi pour segmenter), SentencePiece (indépendant de la langue, gère les espaces). Tout texte est une séquence de tokens ; les nombres, le code, les langues rares se décomposent parfois en 1 token = 1 caractère (coût ×4-10 !).
Pourquoi ça compte La tokenisation gouverne le coût (longueur en tokens), les biais (arithmétique floue car « 123 + 456 » se tokenise mal), le multilingue (le français coûte plus cher que l'anglais), et même des vulnérabilités de sécurité (tokens spéciaux). Diagnostic systématique en TP avec tiktoken / tokenizers. 
import tiktoken
enc = tiktoken.encoding_for_model("gpt-4o")
for s in ["Les graphes pour les LLMs", "1234 + 5678 = ?", "こんにちは世界"]:
    print(len(enc.encode(s)), enc.encode(s)[:8])

2. L'architecture en profondeur

Définition 2.1 — Le bloc décodeur Un LLM empile \(N\) blocs : $$x \leftarrow x + \mathrm{MHA}(\mathrm{LN}(x)), \qquad x \leftarrow x + \mathrm{MLP}(\mathrm{LN}(x)),$$ avec attention causale (masque triangulaire : le token \(i\) ne voit que \(j \leq i\)), têtes groupées (grouped-query attention pour l'inférence), MLP en grille (SwiGLU, expansion ~4×), et embeddings de position RoPE (rotations ; généralisation relative aux longues contextes).
  • Paramètres : où sont-ils ? embedding (\(|V| \times d\)), attention (\(4d^2\)/bloc), MLP (\(8d^2\)/bloc) — la règle \(\#\text{params} \approx 12 N d^2\) et le coût mémoire d'entraînement (paramètres + Adam + activations + gradients : ~20 octets/paramètre en fp16/mixed) ;
  • Loi de Chinchilla : à compute fixé, \(D \approx 20\,P\) tokens pour \(P\) paramètres (GPT-3 était « sous-entraîné ») ; aujourd'hui on sur-entraîne volontairement (Llama 3 : 15T tokens) pour l'inférence ;
  • Mixture of Experts : activer \(k\) experts MLP sur \(E\) — décorrige capacité et coût d'inférence ;
  • Variantes d'attention efficaces : FlashAttention (exact, IO-aware), sparse/sliding window (Mistral), linéaires (Mamba/SSM = alternative aux transformers — « architectures alternatives » du programme officiel).

3. Pré-entraînement

Objectifs de pré-entraînement (programme officiel)
  • Modélisation causale (CLM) — GPT : $$\mathcal{L} = -\sum_t \log p_\theta(x_t \mid x_{<t})$$ — prédire le token suivant ; génératif par construction ;
  • Modélisation masquée / débruitage (MLM) — BERT : masquer ~15 % des tokens et les prédire (bidirectionnel) ; excellent pour l'encodage (classification, retrieval), ne génère pas ;
  • Span corruption / text-to-text — T5 : masquer des fragments et générer ; tout se formule en séquence→séquence.
Données : web (filtrage qualité, déduplication MinHash), code, ouvrages, données synthétiques ; curriculum ; multi-lingue. Compute : des semaines sur des milliers de GPU — jamais fait en TP ; on étudie des checkpoints et des courbes d'entraînement publiées (loss, scaling).
Lab : entraîner un mini-GPT Sur un corpus type Shakespeare (~1 Mo), entraîner un transformer ~10M params (nanoGPT) : 30 min de GPU suffisent pour générer du texte crédible. Observer : la courbe de loss, l'effet du contexte, la température d'échantillonnage.

4. Post-training : SFT et alignement

Étape 1 — Supervised Fine-Tuning (instruction tuning) Fine-tuner le modèle de base sur des paires (instruction, réponse) de qualité — quelques dizaines/centaines de milliers d'exemples suffisent à transformer un autocomplete en assistant. Détails d'ingénierie : masque de perte (on ne calcule la loss que sur la réponse), templates de chat, données « distillées » d'un gros modèle.
Étape 2 — Pourquoi l'alignement au-delà du SFT ? Le SFT imite des démonstrations ; il n'optimise pas directement « la meilleure réponse » et n'apprend pas à éviter les réponses nocives. L'idée centrale de InstructGPT/ChatGPT : apprendre une récompense humaine, puis optimiser la politique contre cette récompense (RL) — c'est ici que le module M1 RL devient l'outil central du M2. 
# SFT avec masque de perte (pseudo-code HF TRL)
from trl import SFTTrainer

trainer.train()

5. RLHF, DPO, GRPO

RLHF — pipeline classique (Ouyang et al., 2022)
  1. Modèle de récompense : entraîner \(r_\phi(x, y)\) sur des préférences humaines (paires de réponses) ; perte Bradley-Terry : $$\mathcal{L} = -\log \sigma\big(r_\phi(x, y^+) - r_\phi(x, y^-)\big).$$
  2. Optimisation de la politique par PPO (module RL, ch. 4) : $$\max_\theta\ \mathbb{E}\big[r_\phi(x, y)\big] - \beta\, \mathrm{KL}\big(\pi_\theta \| \pi_{\mathrm{SFT}}\big)$$ — le terme KL empêche le reward hacking et la dérive hors distribution.
DPO (Rafailov et al., 2023) — le RL sans RL La solution optimale du problème RLHF a une forme fermée \(\pi^\star(y\mid x) \propto \pi_{\mathrm{SFT}}(y \mid x)\,e^{r(x,y)/\beta}\) ; en réinjectant dans Bradley-Terry, on obtient une perte directe sur la politique : $$\mathcal{L}_{\mathrm{DPO}} = -\log \sigma\Big(\beta \log\tfrac{\pi_\theta(y^+ \mid x)}{\pi_{\mathrm{SFT}}(y^+\mid x)} - \beta \log\tfrac{\pi_\theta(y^- \mid x)}{\pi_{\mathrm{SFT}}(y^-\mid x)}\Big).$$ Pas de modèle de récompense, pas de rollouts — c'est le cheval de bataille de l'open-source.
RLVR et GRPO (DeepSeek, 2024) Quand la qualité est vérifiable (test unitaire qui passe, réponse mathématique exacte), la récompense n'a plus besoin d'être apprise. GRPO : générer un groupe de \(G\) réponses par prompt, estimer l'avantage dans le groupe \(A_i = \big(r_i - \mathrm{mean}(r)\big)/\mathrm{std}(r)\), et faire un pas de gradient de politique : $$\nabla J = \mathbb{E}\big[\nabla\log\pi_\theta(y_i\mid x)\, A_i\big] - \beta\nabla\mathrm{KL}.$$ — c'est le moteur des modèles de raisonnement (chaînes de pensée longues, auto-vérification) ; explorer (bandits, module RL ch. 6) devient central.
Vue d'ensemble SFT (imiter) → RLHF (optimiser des préférences) → DPO (préférences sans RL) → RLVR/GRPO (optimiser la vérité vérifiable). Un LLM « moderne » enchaîne : base → SFT → rejection sampling → DPO/GRPO ; c'est exactement le plan du cours officiel (« post-training methods »).

6. Faire tourner un LLM : inférence

  • Décodage : greedy, température, top-k / top-p (nucleus), pénalités de répétition — rappel : les bandits explorent/expliquent ;
  • KV-cache : attention = cache des clés/valeurs des tokens passés ; mémoire \(\mathcal{O}(n \cdot d)\) — pourquoi le contexte long coûte cher ; speculative decoding (petit modèle propose, gros modèle vérifie) ;
  • Quantification : fp16 → int8/int4 (GPTQ, AWQ) ; scaling laws de quantification ;
  • Serving : batching continu, vLLM ; coût/token ; contraintes on-prem vs API — l'angle « ML Ops » est approfondi au module M2 dédié.

7. RAG et agents

Définition 7.1 — RAG (Retrieval-Augmented Generation) $$p(y \mid q) \approx p_\theta\big(y \mid q, \mathrm{top}_k\, \mathrm{sim}(e_q, e_d)\big)$$ indexer des documents par embeddings, récupérer les plus proches du prompt, les injecter dans le contexte. Réduit les hallucinations, actualise les connaissances, gère des données propriétaires sans ré-entraînement. Variantes avancées : chunking sémantique, re-ranking (cross-encoder), requêtes HyDE, et surtout GraphRAG (module Graph ML, ch. 8) : le retrieval traverse un graphe de connaissances — le cœur LLGA.
Définition 7.2 — Agents LLM Boucle perception-action (module RL, ch. 7) : le LLM décide d'appeler des outils (function calling), observe les résultats, itère ; ReAct, réflexion, planification ; multi-agents : orchestration en graphes (DAG d'agents spécialisés — scoping, recherche, vérification, synthèse), frameworks type LangGraph. L'évaluation des agents (tâches, coûts, sûreté) est un sujet de recherche ouvert — et un débouché majeur du master. 
# RAG minimal (pseudocode avec sentence-transformers + FAISS)
from sentence_transformers import SentenceTransformer

8. Multimodalité et perspectives

  • LLMs multimodaux : vision (ViT-encodeur → projecteur → tokens dans le contexte) ; audio ; vidéo ; l'espace latent commun rappelle CLIP (module Multimodal GenAI, ch. 5) ;
  • Architectures alternatives : SSM/Mamba (complexité linéaire), hybrides attention+SSM, xLSTM — le transformer n'a pas le monopole ;
  • Small Language Models & distillation : le compromis qualité/coût/latence gouverne le déploiement entreprise ;
  • Sûreté : jailbreaks, injections de prompt, fuites de données d'entraînement ; watermarking ; le module M2 « Explainability, Security, Privacy of LLMs » y est consacré ;
  • Recherche ouverte : raisonnement (o1-style), mémoire longue durée, LLMs sur graphes (représentation textuelle vs embeddings structurés — travaux du master), évaluation (benchmarks, LLM-as-judge et ses biais).
Lab final Construire un assistant documentaliste : corpus technique → pipeline RAG (chunks, embeddings, reranking) ; mesure de la fidélité (citations vérifiables) contre le RAG vectoriel vs une version GraphRAG ; rapport coûts (tokens, latence).

Exercices / Labs

  1. Tokenisation. Comparer BPE vs Unigram vs SentencePiece sur un corpus multilingue : compression (caractères/token), couverture des nombres ; mesurer le « surcoût » du français sur l'anglais pour un même texte.
  2. Scaling. À partir des données publiées (LLaMA 1/2/3, Chinchilla), vérifier la loi \(\mathcal{L} \approx A N^{-\alpha} + B D^{-\beta} + E\) par régression ; situer chaque modèle par rapport à l'optimum compute.
  3. Attention causale. Implémenter le masque triangulaire, vérifier la propriété de causalité (perturber le token \(t+1\) ne change pas les logits ≤ \(t\)), et mesurer le coût mémoire du KV-cache en fonction de la longueur de contexte.
  4. DPO papier. Dériver la forme fermée \(\pi^\star\) du problème KL-pénalisé (variation classique), puis la perte DPO en réinjectant dans Bradley-Terry ; vérifier le gradient : il augmente la marge log-ratio des réponses préférées.
  5. GRPO jouet. Sur une tâche vérifiable (arithmétique binaire), entraîner un mini-modèle avec GRPO (groupe de 8 réponses) ; tracer accuracy et longueur des réponses — observer l'émergence de « raisonnement » plus long.
  6. RAG vs longueur de contexte. Questionner un LLM avec 4k/32k/128k de contexte sur un corpus : le « lost in the middle » apparaît-il ? Comparer avec RAG ; discuter les compromis.
  7. Projet agent. Étendre le lab final : un agent qui choisit entre retrieval vectoriel et requête de graphe selon le type de question (relationnelle ou factuelle) — mesure de l'amélioration et du surcoût.

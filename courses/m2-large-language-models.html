1. Tokenisation

Définition 1.1 — BPE byte-level : la construction exacte Le BPE (démontré pas à pas au NLP ch. 1) démarre ici de l'alphabet des 256 octets : toute chaîne Unicode est représentable sans symbole « inconnu ». Boucle d'apprentissage : $$\mathrm{fusion}^{(k)} = \arg\max_{(a,b)}\; f(a,b),\qquad f(a,b)=\sum_{w}\mathrm{freq}(w)\,n_{(a,b)}(w),$$ où \(n_{(a,b)}(w)\) compte les occurrences de la paire adjacente \((a,b)\) dans le mot \(w\) (comptage pondéré par la fréquence du mot) ; on applique la fusion partout et on recommence jusqu'à \(|V|\) (32k-128k). L'encodage d'un texte nouveau rejoue les fusions dans l'ordre appris (GPT-2/4, Llama) ; WordPiece (BERT) maximise \(\frac{f(x,y)}{f(x)f(y)}\), Unigram (T5) apprend un modèle génératif par EM puis segmente par Viterbi (NLP ch. 1.2).
Vocabulaire, compression, coûts multilingues Le taux de compression (caractères/token) dépend du vocabulaire et de la langue : les vocabulaires entraînés sur l'anglais compressent bien l'anglais (~4 caractères/token) mais dégradent les autres langues. Ordres de grandeur mesurés en TP : avec les tokenizers type GPT/Llama, un même texte français coûte typiquement 15 à 25 % de tokens de plus qu'en anglais ; pour des écritures non latines mal représentées, le facteur peut atteindre 3× ou plus (chaque caractère rarement vu se décompose en octets). Conséquences directes : coût API (facturé au token), longueur de contexte consommée, et inégalité de qualité. Llama 3 a porté le vocabulaire à 128k tokens — une grande partie du gain sert aux langues non anglaises ; GPT-4o (o200k) revendique jusqu'à ~1,4× à ~4× moins de tokens selon la langue par rapport à la génération précédente. L'exercice 1 mesure tout cela sur vos propres textes.
Tokens spéciaux et sécurité Les tokens spéciaux (<|endoftext|>, <|im_start|>, rôles de template) délimitent les tours et les documents. Si le décodeur les accepte dans une entrée utilisateur, un attaquant peut injecter un faux tour de dialogue ou terminer prématurément un document (confusion de frontières) — défense : ré-encoder systématiquement l'entrée et neutraliser les tokens spéciaux (encode_ordinary, flag allowed_special de tiktoken), jamais de concaténation de chaînes brute autour du prompt. On retrouve cette classe d'attaques au ch. 9 (injections de prompt). 
import tiktoken
enc = tiktoken.encoding_for_model("gpt-4o")
okapi = tiktoken.encoding_for_model("gpt-3.5-turbo")   # vocabulaire cl100k

fr = "Les graphes pour les LLMs : une révolution pour la recherche d'information."
de = "Donaudampfschifffahrtsgesellschaftskapitän"
for s in (fr, de, "1234 + 5678 = ?"):
    print(len(okapi.encode(s)), "vs", len(enc.encode(s)), "->", s[:40])

# tokenisation "sure" : les tokens speciaux ne sont PAS decodes par defaut
b = enc.encode("fin <|endoftext|> suite", allowed_special=set())
print("ids :", b, "| decode rond-trip ok :", enc.decode(b))
Pourquoi ça compte (rappel M1) La tokenisation gouverne le coût (longueur en tokens), les biais (arithmétique floue car « 123 + 456 » se tokenise mal), le multilingue (surcoût mesuré ci-dessus) et des vulnérabilités réelles (tokens spéciaux). Diagnostic systématique en TP avec tiktoken / tokenizers. Pour l'adaptation d'un LLM à une langue peu dotée — vocabulaire, template, données — le ch. 10 présente les travaux de l'enseignant (Atlas-Chat, Nile-Chat).

2. L'architecture en profondeur

Définition 2.1 — Le bloc décodeur Un LLM empile \(N\) blocs : $$x \leftarrow x + \mathrm{MHA}(\mathrm{LN}(x)), \qquad x \leftarrow x + \mathrm{MLP}(\mathrm{LN}(x)),$$ avec attention causale (masque triangulaire : le token \(i\) ne voit que \(j \leq i\)), têtes groupées (grouped-query attention pour l'inférence), MLP en grille (SwiGLU, expansion ~4×), et embeddings de position RoPE (rotations ; généralisation relative aux longues contextes), et une LN finale.
Proposition 2.2 — Pre-norm vs post-norm : le flux de gradient Post-LN (transformer original) : \(x_{l+1}=\mathrm{LN}(x_l+F(x_l))\) — chaque bloc renormalise le résidu lui-même ; le gradient de \(x_L\) vers \(x_0\) traverse \(L\) Jacobennes de LN dont le produit décroît/explode exponentiellement avec \(L\) : warmup obligatoire, profondeur fragile. Pre-LN (GPT-2+, tous les LLMs modernes) : \(x_{l+1}=x_l+F(\mathrm{LN}(x_l))\) — le chemin résiduel est l'identité : $$\frac{\partial x_L}{\partial x_l} = I + \sum_{l'\,>\,l}\frac{\partial F_{l'}}{\partial x_l}$$ → gradient qui atteint chaque couche sans atténuation produit : entraînement stable sans warmup fin. Prix : la norme \(\|x_l\|\) croît avec la profondeur (contributions additives), d'où la LN finale. (Xiong et al., ICML 2020.)
Théorème 2.3 — RoPE dérivé (Su et al., 2021) La position est injectée par rotation : le vecteur de dimension \(d\) est vu comme \(d/2\) paires 2D ; la paire \(i\) du token en position \(m\) subit \(R(m\theta_i)\) avec \(\theta_i = 10000^{-2i/d}\) : $$R(\varphi)=\begin{pmatrix}\cos\varphi & -\sin\varphi\\ \sin\varphi & \cos\varphi\end{pmatrix}, \qquad q^{(i)}_m = R(m\theta_i)\,q^{(i)},\quad k^{(i)}_n = R(n\theta_i)\,k^{(i)}.$$
Propriété relative : le produit scalaire d'une paire ne dépend que de la différence de positions : \(\langle q^{(i)}_m,k^{(i)}_n\rangle = q^{(i)\top} R(m\theta_i)^\top R(n\theta_i)\, k^{(i)} = q^{(i)\top} R\big((n-m)\theta_i\big)\,k^{(i)}\), car les rotations 2D commutent et \(R(a)^\top R(b)=R(b-a)\). Somme sur les paires = un score d'attention fonction de \((n-m)\) et des contenus — une généralisation « soft » des embeddings relatifs. Bonus pratique : pour étendre le contexte, on interpole les angles (\(m\to m/L\)) au lieu de réapprendre. ∎
Proposition 2.4 — MQA/GQA : l'arithmétique mémoire du KV-cache Le cache stocke clés et valeurs de tous les tokens passés : $$\text{octets/token} = 2\ (\text{K et V}) \times N_{\text{couches}} \times n_{\text{têtes KV}} \times d_{\text{tête}} \times \text{octets/élément}.$$ Multi-Query Attention (Shazeer, 2019) : une seule tête KV partagée ; Grouped-Query (Ainslie et al., 2023) : \(n_{\text{KV}} < n_{\text{têtes}}\) — ex. Llama-3-8B : 32 têtes, 8 têtes KV, 32 couches, \(d_{\text{tête}}=128\), fp16 → \(2\times32\times8\times128\times2 = 128\,\text{Kio/token}\) ; un contexte de 100k tokens ≈ 12,8 Go de cache (contre ~51 Go en attention pleine — réduction 4×, qualité quasi identique). C'est LE levier du contexte long (ch. 6).
Mixture-of-Experts (MoE) : routage et équilibrage Chaque bloc MLP est remplacé par \(E\) experts \(\{E_i\}\) ; un routeur \(g(x)=\mathrm{softmax}(W_g x)\) n'active que le top-\(k\) : $$y = \sum_{i\in \mathrm{top}\text{-}k} g_i(x)\,E_i(x), \qquad \#\text{params actifs} \ll \#\text{params totaux}.$$ Capacité décorrelée du coût d'inférence (Switch Transformer : Fedus et al. 2021 ; DeepSeek-V3 : 671B totaux, ~37B actifs). Piège : effondrement du routage — les experts gagnants attirent tout. Perte auxiliaire d'équilibrage (Switch) : $$\mathcal{L}_{\text{aux}} = \alpha\, E \sum_{i=1}^{E} f_i\,P_i,$$ \(f_i\) = fraction de tokens routés vers \(i\), \(P_i=\frac{1}{T}\sum_t g_i(x_t)\) = probabilité moyenne du routeur ; minimum atteint à la distribution uniforme (\(f_i=P_i=1/E\)) — pénalité nulle ssi routeur équilibré et confiant. Variantes modernes : experts fins + experts partagés, équilibrage sans perte auxiliaire (biais ajusté dynamiquement, DeepSeek-V3).
Attention efficace : FlashAttention et la complexité IO L'attention exacte coûte \(\mathcal{O}(n^2)\) en calcul mais dominé en pratique par les entrées/sorties : l'implémentation naïve écrit la matrice \(n\times n\) en HBM (grande mémoire, lente). FlashAttention (Dao et al., 2022) : calcul exact par tuiles qui tiennent en SRAM, softmax « en ligne » avec accumulateur (running max \(m\) et somme \(\ell\) mis à jour par tuile : \(m_{\text{new}}=\max(m,x)\), \(\ell_{\text{new}}=e^{m-m_{\text{new}}}\ell+e^{x-m_{\text{new}}}\)) — la matrice \(n^2\) n'est jamais matérialisée ; lecture HBM réduite de \(\Theta(n^2)\) à \(\Theta(n^2d^2/M)\) (\(M\) = taille SRAM). La leçon générale : optimiser les accès mémoire, pas seulement les FLOPs (cf. module Signal Processing pour la hiérarchie mémoire).
Au-delà : SSM/Mamba (esquisse d'équation d'état) Un modèle à espace d'état discretise un système linéaire \(x'(t)=Ax(t)+Bu(t),\ y=Cx\) : $$x_k = \bar A x_{k-1} + \bar B u_k,\qquad y_k = C x_k,\qquad \bar A = e^{\Delta A},\ \bar B \approx \Delta B,$$ calculable en \(\mathcal{O}(n)\) par scan (pas de matrice \(n^2\)). La sélectivité de Mamba (Gu & Dao, 2023) : \(\bar B, C, \Delta\) dépendent de l'entrée → contenu-dépendant (oubli sélectif), ce qui donne la qualité d'attention au coût linéaire. Dualité SSD (Mamba-2, 2024) : le même calcul se réécrit \(y_k=\sum_{s\le k} C_k^\top\big(\prod_{s<k'}\bar A\big)\bar B_s\,u_s\) — une « attention » à noyau causal ; d'où les architectures hybrides attention+SSM. Prolongement au ch. 8.
  • Paramètres : où sont-ils ? embedding (\(|V| \times d\)), attention (\(4d^2\)/bloc), MLP (\(8d^2\)/bloc, ~\(12d^2\)/bloc en SwiGLU) — la règle \(\#\text{params} \approx 12 N d^2\) et le coût mémoire d'entraînement (paramètres + Adam + activations + gradients : ~20 octets/paramètre en mixed précision ; cf. ch. 3 pour les compute réels) ;
  • Pont LLGA : l'attention est un message passing sur un graphe de tokens (module Graph ML ch. 2, Advanced GNN) ; les transformers de graphes en héritent.

3. Pré-entraînement

Objectifs de pré-entraînement
  • Modélisation causale (CLM) — GPT : $$\mathcal{L} = -\sum_t \log p_\theta(x_t \mid x_{<t})$$ — prédire le token suivant ; génératif par construction ;
  • Modélisation masquée / débruitage (MLM) — BERT (NLP ch. 7) : masquer ~15 % et prédire (bidirectionnel) ; excellent pour l'encodage (classification, retrieval), ne génère pas ;
  • Span corruption / text-to-text — T5 : masquer des fragments et les régénérer ; tout se formule en séquence→séquence.

3.1 Le pipeline de données : qualité, filtrage, déduplication

  • Curation : web → filtrage par règles (longueur, ratio code/ponctuation, langues), puis filtrage par modèle (classifieurs de qualité entraînés sur pages de référence — p. ex. juges distillés) ; mélange contrôlé (web, code, ouvrages, articles, mathématiques, données synthétiques générées puis filtrées) ;
  • Déduplication MinHash-LSH (démontrée au NLP ch. 8.3) : shingles k-grammes → signatures MinHash (la collision d'un min-hash a pour probabilité la similarité de Jaccard) → bandes/rangs LSH avec \(\mathbb{P}_{\text{détecter}}(J)=1-(1-J^r)^b\) → on retire les quasi-doublons jusqu'à un seuil. À l'échelle : des dizaines de To de texte, clustering approximately linéaire ; effet mesuré : moins de mémorisation, meilleur benchmark (dédupliquer, c'est régulariser — les LLMs apprennent « deux fois » les doublons) ;
  • Mixtures et curriculum : proportions par domaine (annealing : monter la qualité/descendre le web en fin d'entraînement) ; l'ordonnancement facile→difficile (par perplexité) améliore l'efficacité compute — démontré à grande échelle par l'enseignant (ch. 10, « Beyond Random Sampling ») ;
  • Multilingue : équilibrage par langue (sinon le tokenizer et le modèle dérivent vers l'anglais — cf. ch. 1 et 10).

3.2 Scaling laws : décomposition et optimum Chinchilla

Loi combinée (Hoffmann et al. 2022, « Chinchilla ») La perte d'un modèle à \(N\) paramètres entraîné sur \(D\) tokens suit, sur des décades de scale : $$L(N,D) = E + \frac{A}{N^{\alpha}} + \frac{B}{D^{\beta}},$$ \(E\) = entropie irréducible du texte naturel ; les deux autres termes = sous-capacité et données épuisées (ajustés sur ~400 entraînements ; Kaplan et al. 2020 pour la version \(L(N)\) seule). Lecture : il faut croître N et D ensemble.
Théorème 3.1 — L'optimum compute \(D^\star \approx 20\,N\), dérivé À budget \(C\) fixé, avec \(\mathrm{FLOPs}(C) \approx 6ND\) (2 par paramètre × forward + backward, × D tokens) : $$(N^\star, D^\star) = \arg\min_{N,D}\; L(N,D)\quad \text{s.c.}\quad 6ND = C.$$
Lagrangien \(\mathcal{J}=E+AN^{-\alpha}+BD^{-\beta}-\lambda(6ND-C)\) : $$\frac{\partial\mathcal{J}}{\partial N}= -\alpha A N^{-\alpha-1}-6\lambda D=0, \qquad \frac{\partial\mathcal{J}}{\partial D}= -\beta B D^{-\beta-1}-6\lambda N=0.$$ En divisant membre à membre, \(\lambda\) s'élimine : $$\frac{\alpha A}{\beta B}\cdot\frac{D^{\beta}}{N^{\alpha}} = \frac{D}{N} \Big/\frac{D}{N}\quad\Longrightarrow\quad \frac{N^{\alpha}}{D^{\beta}} = \frac{\alpha A}{\beta B}.$$ Avec les constantes ajustées de Chinchilla (\(\alpha\approx0{,}34\), \(\beta\approx0{,}28\), \(A\approx406\), \(B\approx411\)) : le membre droit vaut \(\approx 1{,}2\), et la condition avec \(6ND=C\) donne \(N^\star\propto C^{0{,}46}\), \(D^\star\propto C^{0{,}54}\) — les deux croissent comme \(\sqrt{C}\), et numériquement \(D^\star/N^\star\approx 20\) tokens par paramètre. GPT-3 (300B tokens pour 175B params, ratio 1,7) était donc « sous-entraîné » à son budget. ∎
Compute et coûts réels (Llama 3, 2024) Ordres de grandeur du rapport technique Llama 3 (entraînements H100) : 8B / 15T tokens ≈ 1,5 M heures-GPU ; 70B ≈ 7 M ; 405B / 15,6T tokens ≈ 30,8 M heures-GPU (≈ 3,5 ans d'un seul H100 × 10⁴). À ~2-3 $/h-GPU, le 405B coûte ~80-90 M$ de compute — pourquoi on « suite » des checkpoints plutôt qu'on ne ré-entraîne (ch. 6 : distillation, LoRA) ; et pourquoi le ratio post-Chinchilla a monté : l'inférence coûtant au quotidien, on sur-entraîne délibérément des petits modèles (Llama-3-8B : 15T tokens ≈ 1900 tokens/paramètre, ~100× Chinchilla) — l'optimum dépend de ce qu'on optimise : le coût d'entraînement (Chinchilla) ou le coût total incluant l'inférence.

4. Post-training : SFT et alignement

Étape 1 — Supervised Fine-Tuning (instruction tuning) Fine-tuner le modèle de base sur des paires (instruction, réponse) de qualité — quelques dizaines/centaines de milliers d'exemples suffisent à transformer un autocomplete en assistant. Détails d'ingénierie : masque de perte (on ne calcule la loss que sur la réponse), templates de chat, données « distillées » d'un gros modèle.
Templates et masque de perte — le détail qui compte Le template sérialise les tours : <|system|>…<|user|>…<|assistant|>. La loss masque les tokens du prompt (rôles système/user) et ne garde que la completion — sinon le modèle apprend à imiter l'utilisateur et le logging de prompt devient du bruit : $$\mathcal{L}_{\text{SFT}} = -\sum_{t\,\in\,\text{completion}} \log p_\theta(y_t\mid y_{<t}, x).$$ 
# SFT avec masque de perte (pseudo-code HF TRL)
from trl import SFTTrainer

def format(example):                    # template de chat + labels masques
    prompt  = f"<|user|>\n{example['question']}\n<|assistant|>\n"
    completion = example["answer"]
    return {"prompt": prompt, "completion": completion}
# - la loss est calculee UNIQUEMENT sur les tokens de completion (TRL SFTTrainer
#   fait le masquage automatiquement ; en PyTorch pur : labels = -100 sur le prompt)

trainer = SFTTrainer(model="meta-llama/Llama-3.1-8B",
                     train_dataset=dataset.map(format), ...)
trainer.train()

# pieges vus en TP : template != template d'inference -> chute de performance ;
# padding token confondu avec eos ; reponses trop longues -> troncature silencieuse
Étape 2 — Pourquoi l'alignement au-delà du SFT ? Le SFT imite des démonstrations ; il n'optimise pas directement « la meilleure réponse » et n'apprend pas à éviter les réponses nocives. L'idée centrale de InstructGPT/ChatGPT : apprendre une récompense humaine, puis optimiser la politique contre cette récompense (RL) — c'est ici que le module M1 RL devient l'outil central du M2.
Rejection sampling (best-of-n) Étape intermédiaire et increvable : générer \(n\) réponses, garder celles qui passent un filtre (modèle de récompense, tests, heuristiques), re-fine-tuner dessus — la recette de Llama 2 entre les tours de RLHF (Touvron et al., 2023). C'est exactement « exploiter le meilleur des \(n\) », sans gradient de politique ; le lien avec les bandits (module RL ch. 6) est direct : chaque tirage informe la politique pour le tour suivant.

5. RLHF, DPO, GRPO

RLHF — pipeline classique (Ouyang et al., 2022)
  1. Modèle de récompense : entraîner \(r_\phi(x, y)\) sur des préférences humaines (paires de réponses) ; perte Bradley-Terry : $$\mathcal{L} = -\log \sigma\big(r_\phi(x, y^+) - r_\phi(x, y^-)\big).$$
  2. Optimisation de la politique par PPO (module RL, ch. 4) : $$\max_\theta\ \mathbb{E}\big[r_\phi(x, y)\big] - \beta\, \mathrm{KL}\big(\pi_\theta \| \pi_{\mathrm{SFT}}\big)$$ — le terme KL empêche le reward hacking et la dérive hors distribution.
Proposition 5.1 — Bradley-Terry, dérivé Si les humains comparent des paires \((y^+,y^-)\) avec une probabilité de préférer \(y^+\) croissante en la « force » différence, l'axiomatique (choix binaire transitif, invariance) impose un modèle logistique sur la différence de scores latents : $$\mathbb{P}(y^+ \succ y^- \mid x) = \sigma\big(r(x,y^+)-r(x,y^-)\big),$$ et la log-vraisemblance des préférences observées donne la perte ci-dessus — seule la différence de récompense est identifiable (ajouter une fonction de \(x\) ne change rien) ; d'où le besoin de la pénalité KL pour fixer le zéro.
Dérivée en \(r^+\) : \(-\big(1-\sigma(r^+-r^-)\big)\) — la pénalité est maximale quand la paire est mal classée, nulle quand la marge est largement positive ; c'est une régression logistique sur les différences de récompenses. ∎
PPO pour LLMs — le protocole concret Quatre modèles en mémoire : politique \(\pi_\theta\), référence \(\pi_{\mathrm{SFT}}\) (gelée, pour le KL), récompense \(r_\phi\) (gelée), critique (value head). Hyperparamètres sensibles : \(\beta\in[0{,}01\,;\,0{,}2]\) ; learning rate faible (≈ 10× plus petit qu'en SFT) ; clip PPO \(\epsilon\sim0{,}2\) ; batch de prompts > celui des complétions. Symptômes classiques : KL explose (β trop petit) ; réponses dégénérées (récompense hackée) ; longueur qui dérive (biais de verbosité du RM). C'est le chapitre 4 du module RL appliqué mot à mot — la lecture préalable.
Théorème 5.2 — DPO (Rafailov et al., 2023) : dérivation complète La perte $$\mathcal{L}_{\mathrm{DPO}} = -\log \sigma\Big(\beta \log\tfrac{\pi_\theta(y^+ \mid x)}{\pi_{\mathrm{SFT}}(y^+\mid x)} - \beta \log\tfrac{\pi_\theta(y^- \mid x)}{\pi_{\mathrm{SFT}}(y^-\mid x)}\Big)$$ optimise directement la politique sur les préférences — sans modèle de récompense ni rollouts.
Étape 1 (solution close du problème KL-pénalisé). Pour \(x\) fixé, maximiser \(\mathbb{E}_{y\sim\pi}[r(y)] - \beta\,\mathrm{KL}(\pi\|\pi_{\mathrm{SFT}})\) s'écrit $$\max_\pi \int \pi(y)\Big[r(y) - \beta\log\frac{\pi(y)}{\pi_{\mathrm{SFT}}(y)}\Big]dy = -\beta\int \pi\log\frac{\pi(y)}{\pi_{\mathrm{SFT}}(y)e^{r(y)/\beta}}\,dy,$$ qui est \(-\beta\,\mathrm{KL}\big(\pi\,\big\|\,\tfrac{1}{Z}\pi_{\mathrm{SFT}}e^{r/\beta}\big)+\beta\log Z\) ; le KL est minimal en zéro, donc \(\;\pi^\star(y\mid x) = \frac{1}{Z(x)}\,\pi_{\mathrm{SFT}}(y\mid x)\,e^{r(x,y)/\beta}\). Étape 2 (récompense implicite). En inversant : \(r(x,y) = \beta\log\frac{\pi^\star(y|x)}{\pi_{\mathrm{SFT}}(y|x)} + \beta\log Z(x)\). Étape 3 (injection dans Bradley-Terry). Dans \(\sigma(r^+-r^-)\), le terme \(Z(x)\) — le même pour \(y^+\) et \(y^-\) — s'annule : seule compte la différence des log-ratios ; maximiser la vraisemblance des préférences donne \(\mathcal{L}_{\mathrm{DPO}}\) ci-dessus (avec \(\theta\) à la place de \(\pi^\star\)). Gradient : \(-\beta\,\sigma(-\hat r)\,\nabla_\theta\big[\log\pi(y^+|x)-\log\pi(y^-|x)\big]\) avec récompense implicite \(\hat r = \beta\log\frac{\pi_\theta(y^+)}{\pi_{\mathrm{SFT}}(y^+)} -\beta\log\frac{\pi_\theta(y^-)}{\pi_{\mathrm{SFT}}(y^-)}\) : la marge log-ratio des préférées est augmentée, d'autant plus fort que la paire est mal classée. ∎
Théorème 5.3 — GRPO (Shao et al., DeepSeekMath 2024) : dérivation Générer un groupe de \(G\) réponses \(\{y_i\}\) par prompt ; récompenses \(\{r_i\}\) ; avantages dans le groupe : $$A_i = \frac{r_i - \mathrm{mean}(r_{1..G})}{\mathrm{std}(r_{1..G})},\qquad \nabla_\theta J = \mathbb{E}\Big[\frac{1}{G}\sum_i \frac{1}{|y_i|}\sum_t \nabla_\theta\log\pi_\theta(y_{i,t}\mid x)\,A_i\Big] - \beta\,\nabla_\theta \widehat{\mathrm{KL}},$$ avec \(\widehat{\mathrm{KL}}\) estimateur sans biais et basse variance \(\;\mathbb{E}\big[\frac{\pi_{\mathrm{ref}}}{\pi_\theta}-\log\frac{\pi_{\mathrm{ref}}}{\pi_\theta}-1\big]\).
Variance. REINFORCE : \(\nabla\mathbb{E}[r]=\mathbb{E}[r\,\nabla\log\pi]\) est sans biais pour toute baseline indépendante de l'action : \(\mathbb{E}[b\,\nabla\log\pi]=b\,\nabla\!\int\pi=0\) ; soustraire \(b=\mathrm{mean}(r)\) divise la variance (mieux que \(b=0\) ou qu'une baseline apprise) ; normaliser par l'écart-type rend l'échelle du gradient invariante entre prompts (faciles : petits écarts → amplifiés ; durs : amortis). Plus de critique. Contrairement à PPO, la baseline vient du groupe lui-même — le réseau de valeur (et sa mémoire/son entraînement) disparaît ; c'est l'estimation Monte-Carlo de \(A(s,a)=Q(s,a)-V(s)\) par échantillonnage multiple. ∎
RLVR et raisonnement (2024-2026) Quand la qualité est vérifiable (test unitaire qui passe, réponse mathématique exacte), la récompense n'a plus besoin d'être apprise : RL with Verifiable Rewards. GRPO est le moteur de DeepSeek-R1 : en optimisant la justesse vérifiable, émergent des chaînes de pensée longues (auto-vérification, retours en arrière, « aha ») — le style « o1 ». Self-consistency à l'inférence (Wang et al., 2023) : échantillonner \(n\) raisonnements, répondre par vote majoritaire — précision qui grimpe en \(\Theta(\sqrt n)\)-ish tant que les erreurs sont peu corrélées. Coûts : 10× plus de tokens ; des travaux récents régularisent la longueur (ch. 10 : « Shorter but not Worse »). Explorer (bandits, module RL ch. 6) devient central : le groupe de GRPO est une exploration structurée.
Vue d'ensemble SFT (imiter) → RLHF (optimiser des préférences) → DPO (préférences sans RL) → RLVR/GRPO (optimiser la vérité vérifiable). Un LLM « moderne » enchaîne : base → SFT → rejection sampling → DPO/GRPO ; c'est exactement le plan du cours officiel (« post-training methods »). 6.1 Décodage : formules et effets

Définition 6.1 — Du greedy au nucleus À chaque pas, logits \(z\) sur \(|V|\) ;
  • Température : \(p_i = \dfrac{\exp(z_i/T)}{\sum_j \exp(z_j/T)}\) — \(T\to0\) : argmax (greedy) ; \(T\) grand : uniformisation ;

  • Pénalité de répétition : diviser le logit des tokens déjà émis (facteur 1,1-1,3) ; min-p : seuil relatif au meilleur token.

6.2 KV-cache : l'arithmétique mémoire

Proposition 6.2 — Mémoire du cache = \(\mathcal{O}(n\cdot d)\), chiffrée En autorégression, chaque token nouveau doit assister aux clés/valeurs de tout le passé — on les met en cache (prop. 2.4) : octets/token \(= 2\,N_{\text{couches}}\,n_{\text{KV}}\,d_{\text{tête}}\times\) précision. Llama-3-8B (32 couches, 8 têtes KV, 128 dim, fp16) → 128 Kio/token : contexte 8k ≈ 1 Go, 100k ≈ 12,8 Go, 1M ≈ 128 Go (hors poids !). Trois portes de sortie : GQA (÷4 ici), quantification du cache int8 (÷2), et eviction/re computation (sliding window). Règle d'ingénieur : la longueur de contexte est d'abord un problème de bande passante mémoire, pas de FLOPs — d'où le ch. suivant.

6.3 Decoding spéculatif : la correction démontrée

Théorème 6.3 — Speculative decoding (Leviathan et al., 2023) Un petit modèle \(q\) propose \(\gamma\) tokens ; le gros modèle \(p\) calcule les \(\gamma\) distributions en un seul forward ; chaque proposition \(y\) est acceptée avec probabilité \(\min(1, p(y)/q(y))\) ; à la première rejection, on rééchantillonne depuis le résidu normalisé \(\mathrm{norm}\big(\max(0,\,p-q)\big)\). Alors la distribution marginale de chaque token produit est exactement \(p\) — qualité inchangée, latence divisée par ~2-3 quand \(q\approx p\).
Pour un token : contribution d'acceptation \(q(y)\min(1,p(y)/q(y)) = \min(q(y),p(y))\) ; contribution de rejet : la masse rejetée totale vaut \(\sum_x q(x)\big(1-\min(1,p(x)/q(x))\big) = \sum_x \max(0,q(x)-p(x)) = R\), et le résidu rééchantillonné ajoute \(R\cdot\frac{\max(0,p(y)-q(y))}{R} = \max(0,p(y)-q(y))\). Total : \(\min(q,p)+\max(0,p-q)=p\). ∎

6.4 Quantification : principes et erreurs

  • Post-training int8 : quasi sans perte (calibration par lot, scales par canal) ; int4 : le standard compromis ;
  • GPTQ (Frantar et al., 2022) : couche par couche, minimiser \(\|Wx-\hat W x\|_2^2\) sur un jeu de calibration — quantification colonne par colonne avec compensation d'erreur sur les colonnes restantes (via l'inverse de la Hessienne \(\mathbf{H}=2\mathbf{X}\mathbf{X}^\top\)) ;
  • AWQ (Lin et al., 2023) : protéger les canaux « saliens » (activations élevées) par une mise à l'échelle par canal avant quantification — l'erreur est déplacée vers les canaux peu actifs ;
  • Erreurs typiques : int8 ≈ +0,0-0,1 PPL ; int4 bien calibré ≈ +0,1-0,5 PPL (souvent imperceptible) ; en dessous de 4 bits, la dégradation s'accélère (quanti 2-3 bits = recherche) ; en production, toujours re-valider sur vos benchmarks, pas la PPL seule.

6.5 Serving : batching continu, PagedAttention, coûts

  • Batching continu (vLLM, Orca) : ordonnancer au pas de décodage — les séquences finies sortent, les nouvelles entrent dans le même batch ; débit multiplié par ~10-20× vs batching statique ;
  • PagedAttention (Kwon et al., 2023) : le KV-cache découpé en pages (comme la mémoire virtuelle) — plus de fragmentation ; partage des préfixes communs (system prompt) ; gain mémoire ~2-4× → batchs plus grands ;
  • Coûts : deux régimes — API (de l'ordre du $/M tokens, décroissant régulièrement) vs on-prem (heure-GPU amortie : un H100 à ~3$/h qui débite ~2-5k tokens/s sur un 8B quantifié int4 → quelques $/M tokens à forte charge) ; le coût réel d'un agent = tokens d'entrée répétés × longueur d'historique (ch. 8) ; l'angle « ML Ops » est approfondi au module M2 dédié.

7. RAG approfondi

Définition 7.1 — RAG (Retrieval-Augmented Generation) $$p(y \mid q) \approx p_\theta\big(y \mid q, \mathrm{top}_k\, \mathrm{sim}(e_q, e_d)\big)$$ indexer des documents par embeddings, récupérer les plus proches du prompt, les injecter dans le contexte. Réduit les hallucinations, actualise les connaissances, gère des données propriétaires sans ré-entraînement.

7.1 Chunking

  • Fixe avec recouvrement : 256-1024 tokens, stride 10-20 % ; découpe structurelle (sections, paragraphes) > découpe aveugle (les phrases coupées détruisent le repêchage) ;
  • Chunking sémantique : couper là où la similarité d'embeddings entre fenêtres successives chute (changement de topic) ;
  • Multi-granularité : indexer par passages, mais renvoyer la section parente au LLM (small-to-big) ; pour les documents structurés, garder titres/métadonnées dans le chunk (filtres de pré-repêchage).

Gain typique : +3 à +5 points de NDCG@10. Le «  lost in the middle » (Liu et al., 2023) : même avec les bons passages, le LLM exploite mieux ceux en début/fin de contexte → réordonner les meilleurs aux extrémités.

7.3 Évaluation du RAG

Métriques type RAGAS (Es et al., 2023)
  • Faithfulness (fidélité) : décomposer la réponse en affirmations atomiques (par un LLM-juge) ; fidélité = fraction soutenues par le contexte repêché ;
  • Answer relevance : le LLM génère des questions candidates depuis la réponse — similarité moyenne avec la vraie question ;
  • Context precision / recall : les chunks utiles sont-ils là et bien rangés ? / le corpus contient-il ce qui manquait ?
Protocole TP : jeu QA avec contexte de référence (golden context), comparer fidélité avec/sans reranking, mesurer le coût (tokens, latence) de chaque étage.

7.4 GraphRAG et variantes

  • HyDE (Gao et al., 2022) : générer une réponse hypothétique à la question et chercher avec son embedding — la réponse imaginaire est plus proche des documents que la question ;
  • GraphRAG : le retrieval traverse un graphe de connaissances (entités-relations extraites par NER/RE — NLP ch. 6 ; communautés-résumés ; requêtes multi-sauts) ; détaillé au module Graph ML ch. 8 — le cœur LLGA ; les travaux Buscaldi (AI-KG/CS-KG, NLP ch. 9) construisent exactement de tels graphes à partir de corpus scientifiques ;
  • Requêtes structurées : texte → requête de graphe (linéarisation, ch. 10.3) ou SQL (text-to-SQL) : le LLM écrit la requête, la base répond — auditabilité maximale.

9. Évaluation et sûreté des LLMs

9.1 Benchmarks : construction et contamination

Définition 9.1 — Benchmark de type MMLU (Hendrycks et al., 2020) Questions à choix multiples (57 matières pour MMLU ; variantes : MMLU-Pro, GPQA, HELM pour l'évaluation multi-facettes). Deux modes de scoring : log-vraisemblance des options (déterministe, mais biaisé par la longueur/fréquence des réponses) vs génération puis extraction (réaliste, mais dépend du prompt et du parsing). Règle : toujours préciser le protocole — les classements changent selon le mode.
Contamination : la mesure qui fausse tout Si le benchmark est dans le pré-entraînement (web !), le score mesure la mémorisation, pas la compétence. Détection : recouvrement de n-grammes (8-13 grammes) questions/données d'entraînement, canary strings (marqueurs cachés), tests de rappel à trous. Remèdes : évaluations privées/rotatives, génération dynamique de questions, re-splits temporels (questions post-cutoff). Travaux récents en la matière : la mémorisation en fine-tuning et les hallucinations multilingues — ch. 10 du module M1 NLP (travaux Buscaldi : MUCH, prédiction de mémorisation).

9.2 LLM-as-judge : commode, mais biaisé

  • Biais positionnel : le juge préfère la première (ou seconde) réponse selon l'ordre — mitigation : évaluer dans les deux ordres et moyenner ;
  • Biais de verbosité / style : les réponses longues et bien formatées sont surestimées — mitigation : rubriques (critères explicites), format contraint ;
  • Auto-préférence : un juge favorise les réponses de sa propre famille de modèles — mitigation : ensembles de juges, juges entraînés à la calibration (référence : MT-Bench, G-Eval) ;
  • Calibration : un score de juge n'est pas une probabilité — vérifier sur un jeu où la vérité existe (fraction de jugements conformes à l'humain) ; les métriques distillées bon marché (FrugalScore, ch. 10) sont exactement nées de ce besoin.

9.3 Hallucinations

Taxonomie 9.2 Intrinsèques : la réponse contredit la source/le contexte (RAG : citation erronée) ; extrinsèques : affirmations invérifiables (inventées) ; fidélité au prompt : désobéissance silencieuse aux consignes. Causes : échantillonnage (température), coupure des connaissances, biais de l'entraînement à « toujours répondre » (pas d'abstention apprise), sycophancie (dire oui à l'utilisateur). Mitigations : RAG + citations vérifiables (ch. 7), self-consistency (ch. 5), température basse pour le factuel, entraînement à l'abstention, vérification post-hoc par décomposition en affirmations (le cœur de la « faithfulness » RAGAS).

9.4 Attaques : jailbreaks et injections de prompt

  • Jailbreaks directs : role-play (« DAN »), cadrage hypothétique, encodage (base64, unicode), multi-tours en crescendo — contourner les consignes de sécurité ;
  • Injections indirectes : le contenu repêché (page web, PDF, résultat d'outil) contient des instructions malveillantes — l'attaque n°1 des systèmes RAG/agents (ch. 7-8) ;
  • Défenses en profondeur : classifieurs d'entrée/sortie (type Llama Guard), spotlighting (délimiter et marquer le contenu non fiable), moindres privilèges sur les outils (le retriever n'écrit pas dans la base !), séparation prompt/données (ch. 1 — tokens spéciaux : la même hygiène), humain dans la boucle pour les actions irréversibles. Aucune défense n'est complète — on réduit la surface.

9.5 Watermarking

Théorème 9.3 — Filigrane statistique (Kirchenbauer et al., 2023) Avant chaque token, hacher le préfixe → graine pseudo-aléatoire qui partitionne le vocabulaire en « verte »/« rouge » (fraction \(\gamma\), p. ex. 1/2) ; la génération pénalise les rouges. Sur un texte de \(T\) tokens contenant \(s_G\) verts : $$z = \frac{s_G - \gamma T}{\sqrt{T\,\gamma(1-\gamma)}} \;\xrightarrow{T\ \text{grand}}\; \mathcal{N}(0,1)\ \text{sous H}_0,$$ rejet de « texte humain » si \(z\) dépasse le seuil (p-value) — sous H1 (marqué), \(z\) croît comme \(\sqrt T\) fois le biais introduit.
Sous H₀ (texte non marqué), chaque token est vert avec probabilité \(\gamma\) indépendamment → \(s_G\sim\mathrm{Bin}(T,\gamma)\), centré-réduit tend vers la normale (TCL) d'où le z-score ; la partition dépend du préfixe : impossible à retirer sans la graine. Limites (papier de suivi, Kirchenbauer et al. 2023) : paraphrase, troncation, et faux positifs sur textes courts — le test est statistique, pas déterministe. ∎

Problème : les métriques neuronales de génération (BERTScore, MoverScore…) coûtent un forward de gros modèle par paire — rédhibitoire en boucle d'apprentissage ou d'évaluation d'un LLM-juge. Méthode : distiller la métrique de référence (les scores, pas les textes !) dans un étudiant minuscule (T5-small), avec re-présentation des entrées compatible avec la métrique mère. Résultat : corrélation quasi préservée pour un coût réduit d'un facteur jusqu'à ~700× (et des variantes V2 pré-entraînées). Position : le chaînon « évaluation à prix industrialisable » du ch. 9 — évaluer souvent, à bas coût, avant d'évaluer bien (juges lourds) sur un sous-échantillon.
Axe 2 — Curriculum au pré-entraînement : Beyond Random Sampling (EACL 2026) Zhang, Mohamed, Abdine, Shang & Vazirgiannis, Beyond Random Sampling: Efficient Language Model Pretraining via Curriculum Learning — arXiv:2506.11300. Question : l'ordre des données au pré-entraînement (ch. 3) compte-t-il, à compute constant ? Méthode : première étude systématique à grande échelle (plusieurs centaines de modèles, de 50M à 1M paramètres) : curriculum par difficulté (perplexité, qualité) faciles→difficiles vs mélanges aléatoires. Résultat : le curriculum améliore la perte à budget fixé (meilleure efficience compute), avec des choix de granularité qui comptent. Position : le contenu « curriculum & annealing » du ch. 3 s'appuie sur ce papier — un exemple de question d'ingénierie (dans quel ordre nourrir le modèle ?) devenue science mesurable.
Axe 3 — LLMs pour langues peu dotées : Atlas-Chat & Nile-Chat (2024-2025) Shang et al., Atlas-Chat: Adapting Large Language Models for Low-Resource Moroccan Arabic Dialect — arXiv:2409.17912 (modèles 1B/2B/3B sur 223B tokens de dialecte ; templates, SFT + DPO) ; Nile-Chat: Egyptian Language Models for Arabic and Latin Scripts — arXiv:2507.04569 (traiter l'arabizi — arabe en écriture latine — au niveau du tokenizer et du pré-entraînement). Position : le ch. 1 (coûts multilingues, vocabulaire) et le ch. 4 (SFT/DPO) appliqués à un vrai problème : adapter l'écosystème LLM à des langues/écritures que les vocabulaires dominants pénalisent — la suite logique des mesures de surcoût faites en TP.

Exercices / Labs

  1. Tokenisation multilingue. Comparer BPE vs Unigram vs SentencePiece sur un corpus multilingue : compression (caractères/token), couverture des nombres ; mesurer le « surcoût » du français sur l'anglais pour un même texte.
    Guidage (résultats attendus) : traductions professionnelles alignées (fr/en/de) → tokens/mot ; typiquement fr ≈ 1,15-1,25× en ; l'allemand avec composés encore plus — jusqu'à ce que les composés fréquents deviennent des tokens ; vérifier que o200k (GPT-4o) resserre l'écart vs cl100k. Conclure sur le coût réel (contexte, prix API) d'une même application selon la langue. ∎
  2. RoPE. Démontrer la propriété relative du thm 2.3 (\(R(a)^\top R(b) = R(b-a)\)), puis vérifier numériquement que le score d'attention est invariant par translation commune des positions ; implémenter l'interpolation de contexte \(m\to m/L\) et mesurer la perplexité au-delà de la longueur d'entraînement.
    Guidage : rotations 2D = nombres complexes — commutativité et \(e^{-ia}e^{ib}=e^{i(b-a)}\) ; l'invariance par translation découle du théorème ; en pratique l'extrapolation naïve dégrade la PPL, l'interpolation la préserve largement (c'est la base des contextes étendus 32k→128k sans ré-entraînement complet). ∎
  3. Arithmétique du KV-cache. Pour Llama-3-8B (32 couches, 8 têtes KV, 128 dim) et un contexte de 128k tokens : calculer la mémoire du cache en fp16, puis en int8, puis avec MQA ; quel batch maximal tient sur un GPU de 80 Go (poids int4 ≈ 5 Go) ?
    Guidage : 128 Kio/token (prop. 2.4) → 128k tokens = 16 Gio ; int8 → 8 Gio ; MQA (1 tête KV) → 2 Gio ; budget disponible ≈ 80−5 = 75 Gio → batch de ~4 (fp16) à ~37 (MQA int8) : le GQA/MQA et la quantification du cache déterminent le débit servi. ∎
  4. Scaling. À partir des données publiées (LLaMA 1/2/3, Chinchilla), vérifier la loi \(\mathcal{L} \approx A N^{-\alpha} + B D^{-\beta} + E\) par régression ; situer chaque modèle par rapport à l'optimum compute (thm 3.1).
  5. MoE. Dériver le minimum de la perte auxiliaire \(\alpha E\sum_i f_iP_i\) sous contrainte \(\sum_i f_i=1\) et montrer qu'il correspond au routage uniforme ; simuler l'effondrement (routeur initialisé biaisé) sans puis avec la perte.
    Guidage : à l'équilibre du routeur, \(P_i=f_i\) ; minimiser \(E\sum f_i^2\) sous \(\sum f_i=1\) → Lagrange → \(f_i=1/E\) uniforme ; sans perte, l'expert gagnant attire les tokens (retour sur expérience renforcé) et la spécialisation dégénère. ∎
  6. SFT guidé. Fine-tuner un petit modèle instructé (1-3B) sur 500 paires (question, réponse) de votre domaine : template strict, labels masqués (code du ch. 4), 2-3 epochs ; mesurer l'effet d'un template faux au moment du test (chute spectaculaire à constater une fois pour toutes).
  7. DPO papier. Dériver la forme fermée \(\pi^\star\) du problème KL-pénalisé (variation classique), puis la perte DPO en réinjectant dans Bradley-Terry ; vérifier le gradient : il augmente la marge log-ratio des réponses préférées.
    Guidage : suivre la preuve du thm 5.2 étape par étape — l'argument clé est que \(\mathcal{J}=-\beta\,\mathrm{KL}(\pi\|\pi_{\mathrm{ref}}e^{r/\beta}/Z)+\beta\log Z\) ; puis \(Z(x)\) disparaît dans la différence \(r^+-r^-\). Le gradient pousse \(\log\pi(y^+)-\log\pi_{\mathrm{ref}}(y^+)\) vers le haut et le \(y^-\) vers le bas, modulé par \(\sigma(-\hat r)\) (paires difficiles d'abord). ∎
  8. GRPO jouet. Sur une tâche vérifiable (arithmétique binaire), entraîner un mini-modèle avec GRPO (groupe de 8 réponses) ; tracer accuracy et longueur des réponses — observer l'émergence de « raisonnement » plus long ; comparer variance du gradient avec/sans normalisation par l'écart-type du groupe.
  9. Spéculatif, sur le papier. Rédiger complètement la preuve du thm 6.3 dans le cas \(\gamma=2\), puis estimer le gain de latence attendu si \(q=p\) sur 80 % de la masse mais diverge sur le reste.
    Guidage : accepter le token 1 (proba \(\sum_y\min(q,p)\)), puis le second conditionnellement ; l'espérance de tokens acceptés par tour est \(\frac{1}{1-\alpha}\) (géométrique) avec \(\alpha\approx0{,}8\) → ~5 tokens/forward ; gain borné par \(\gamma\) et par le rapport de coût petit/gros modèle. ∎
  10. RAG vs longueur de contexte. Questionner un LLM avec 4k/32k/128k de contexte sur un corpus : le « lost in the middle » apparaît-il ? Comparer avec RAG ; discuter les compromis (coût, fidélité, frais d'indexation).
  11. Filigrane. Avec \(\gamma=0{,}5\) et \(T=400\) tokens, calculer \(z\) pour un texte portant 230 tokens verts ; seuil à 5 % ; combien de tokens faut-il pour détecter un biais de +5 % de verts ?
    Guidage : \(z=(230-200)/10 = 3\) → p ≈ 0,1 % : rejeté (marqué) ; pour un biais \(\varepsilon\) petit, l'espérance de \(z\) croît comme \(\varepsilon\sqrt{T/\gamma(1-\gamma)}\) → il faut \(T\sim (1{,}96/\varepsilon)^2\gamma(1-\gamma)\) ; avec \(\varepsilon=0{,}05\), ~770 tokens — d'où la difficulté sur les textes courts. ∎
  12. Projet agent. Étendre le lab final : un agent qui choisit entre retrieval vectoriel et requête de graphe selon le type de question (relationnelle ou factuelle) — mesure de l'amélioration et du surcoût.

Rappels L3 — ce qu'on suppose acquis

  • Réseaux convolutifs : champs réceptifs, partage de poids, pooling, architecture ResNet (connexions résiduelles) — cf. module Deep Learning, chapitre 4 ; attention et transformers — cf. module Deep Learning, chapitre 6.
  • Apprentissage supervisé : descente de gradient, SGD/Adam, surapprentissage, régularisation, transfer learning et fine-tuning — cf. module Deep Learning, chapitres 3 et 8 ; validation croisée, courbes ROC — cf. module Machine Learning.

Le présent module adopte l'orientation systèmes et applications : on y construit le pipeline complet d'un produit de vision — de la donnée annotée au modèle déployé sur un matériel contraint — et on étudie les briques que l'industrie utilise réellement (détecteurs, segmenteurs, trackers, capteurs 3D, runtime d'inférence).

Définition 0.1 — Boîte englobante et IoU Une boîte englobante (bounding box) est un rectangle axis-aligné \(b = (x_1, y_1, x_2, y_2)\) avec \(x_1 < x_2\), \(y_1 < y_2\), codant les coins haut-gauche et bas-droit. Pour deux boîtes \(a\) et \(b\), on note \(A(a)\) l'aire du rectangle. L'intersection-sur-union est $$\mathrm{IoU}(a, b) \;=\; \frac{|a \cap b|}{|a \cup b|} \;=\; \frac{|a \cap b|}{A(a) + A(b) - |a \cap b|},$$ où \(|\cdot|\) désigne l'aire. La boîte d'intersection a pour coins \((\max(x_1^a, x_1^b), \max(y_1^a, y_1^b))\) et \((\min(x_2^a, x_2^b), \min(y_2^a, y_2^b))\) si ces coordonnées sont cohérentes, sinon l'intersection est vide et \(\mathrm{IoU} = 0\).
Proposition 0.2 — Propriétés de l'IoU Pour toutes boîtes \(a, b\) axis-alignées : (i) \(\mathrm{IoU}(a,b) \in [0, 1]\) ; (ii) \(\mathrm{IoU}(a,b) = \mathrm{IoU}(b,a)\) ; (iii) \(\mathrm{IoU}(a,b) = 1\) si et seulement si \(a = b\) (à égalité d'ensemble de pixels) ; (iv) \(\mathrm{IoU}(a,b) = 0\) si et seulement si l'intérieur des deux rectangles est disjoint.
(i) L'aire d'intersection est une aire de rectangle, positive et majorée par chacune des aires, donc \(0 \leq |a \cap b| \leq \min(A(a), A(b)) \leq |a \cup b|\). (ii) Les opérations d'intersection et d'union sont symétriques. (iii) Si \(\mathrm{IoU} = 1\) alors \(|a \cap b| = |a \cup b|\), donc \(|a \setminus b| = |b \setminus a| = 0\) et les rectangles coïncident ; la réciproque est immédiate. (iv) Si l'intersection est vide, le numérateur est nul ; réciproquement un rectangle d'intersection non vide a une aire strictement positive, donc \(\mathrm{IoU} > 0\). ∎
Exemple 0.3 — Un calcul d'IoU Soit la vérité terrain \(g = (0, 0, 10, 10)\) (aire 100) et la prédiction \(p = (5, 5, 15, 15)\) (aire 100). L'intersection est le carré \((5,5,10,10)\) d'aire 25, l'union vaut \(100 + 100 - 25 = 175\), donc \(\mathrm{IoU}(g, p) = 25/175 \approx 0{,}143\) : la prédiction est rejetée au seuil usuel \(\tau = 0{,}5\). Une prédiction décalée de 2 pixels seulement, \(p' = (2, 2, 12, 12)\), donne une intersection de 64 et une union de 136, soit \(\mathrm{IoU} \approx 0{,}47\) — encore sous le seuil : sur de petits objets, la métrique est intraitable, ce qui justifiera les seuils multiples du chapitre 2.

1. Détection d'objets : les deux paradigmes

Définition 1.1 — Tâche de détection Étant donné une image \(x\), produire un ensemble \(\{(b_i, c_i, s_i)\}_{i=1}^{N}\) où \(b_i\) est une boîte englobante, \(c_i\) une classe parmi \(K\) classes et \(s_i \in [0,1]\) un score de confiance. Contrairement à la classification (cf. module Deep Learning, chapitre 1), la sortie est de cardinal variable : le nombre d'objets est inconnu et dépend du contenu de l'image.

1.1. La famille two-stage : proposer puis affiner

Les détecteurs dits à deux étapes (two-stage) séparent la génération de candidates et leur classification :

  • R-CNN (2014) : ~2000 régions candidates extraites par segmentation par grappes (selective search), chaque recadrement passe dans un CNN ; lent (des dizaines de secondes par image), mais la preuve de concept du CNN en détection ;
  • Fast R-CNN (2015) : l'image entière passe une fois dans le CNN, les candidates sont projetées dans l'espace des caractéristiques (RoI pooling) ; seul un classifieur léger est appliqué par candidate ;
  • Faster R-CNN (2015) : les candidates sont produites par un Region Proposal Network (RPN) intégré, appris de bout en bout — le schéma canonique ;
  • FPN (2017) : pyramide de caractéristiques ; les objets petits sont détectés sur les cartes de haute résolution, les grands sur les basses.
Définition 1.2 — Ancres (anchors) Pour chaque cellule d'une carte de caractéristiques, le RPN prédit des décalages par rapport à un ensemble fixe de \(A\) rectangles de référence — les ancres — produits par le produit cartésien de \(S\) échelles et \(R\) ratios d'aspect (typiquement \(S = 5\), \(R = 3\), donc \(A = 15\) ancrages par position). La régression de boîte encode $$t_x = \frac{x - x_a}{w_a}, \quad t_y = \frac{y - y_a}{h_a}, \quad t_w = \log\frac{w}{w_a}, \quad t_h = \log\frac{h}{h_a},$$ où \((x_a, y_a, w_a, h_a)\) sont centre et taille de l'ancre.
Proposition 1.3 — Pourquoi le logarithme pour les tailles La paramétrisation logarithmique rend la régression invariante d'échelle : un même décalage \(t_w\) correspond à un même rapport de tailles. Une erreur \(|t_w| = \varepsilon\) signifie \(w = w_a e^{\pm\varepsilon}\), soit un taux d'erreur relatif constant ; avec une paramétrisation linéaire, la même erreur absolue serait négligeable pour un camion (600 px) et fatale pour un piéton lointain (10 px).
Avec \(t_w = \log(w / w_a)\), on a \(w = w_a e^{t_w}\), donc l'erreur relative vaut \(|e^{t_w} - 1| \approx |t_w|\) au premier ordre — indépendante de \(w_a\). En paramétrisation directe \(\tilde t_w = w - w_a\), l'erreur relative \(|\tilde t_w| / w_a\) dépend de \(w_a\) ; fixer une échelle de bruit homogène pour toutes les tailles d'objets exigerait une pondération par classe de taille, et la loss serait dominée par les grands objets. ∎

1.2. La famille single-stage : tout en une passe

Les détecteurs monostades (single-stage) prédisent directement boîtes et classes sur une grille dense, en une seule passe :

  • YOLO (2015) : l'image est découpée en une grille \(7 \times 7\) ; chaque cellule prédit 2 boîtes + probabilités de classes ; vitesse remarquable (45 images/s à l'époque), au prix d'une localisation plus grossière ;
  • SSD (2016) : prédictions multi-échelles via des cartes de caractéristiques de résolutions décroissantes, ancres par cellule ;
  • RetinaNet (2017) : introduit la focal loss pour corriger le déséquilibre avant/arrière-plan (des centaines de milliers d'ancres faciles contre quelques objets), réconciliant précision monostade et précision bistade.
Définition 1.4 — Focal loss Pour la classification binaire par ancre avec logit \(z\), probabilité prédite \(p = \sigma(z)\) et étiquette \(y \in \{0, 1\}\) : $$\mathrm{FL}(p) \;=\; -\alpha\,(1 - p_t)^{\gamma}\,\log(p_t), \qquad p_t = y\,p + (1 - y)(1 - p),$$ avec facteur d'équilibrage \(\alpha \in [0,1]\) et focalisation \(\gamma > 0\) (typiquement \(\gamma = 2\)). Quand \(\gamma = 0\) et \(\alpha = 0{,}5\), on retrouve l'entropie croisée.

L'effet du facteur \((1 - p_t)^{\gamma}\) est de diviser la contribution des exemples faciles : une ancre d'arrière-plan classée à \(p_t = 0{,}9\) voit son loss réduit d'un facteur \(0{,}1^2 = 0{,}01\) ; les rares exemples difficiles (\(p_t\) petit) gardent un gradient quasi intact. Le gradient devient \(\frac{\partial \mathrm{FL}}{\partial z} = -\alpha\,(1-p_t)^{\gamma}\big(\gamma\, p_t \log p_t + 1 - p_t\big)\,\frac{\partial p_t}{\partial z}\) : le module se concentre sur la frontière de décision.

1.3. Suppression des non-maxima (NMS)

Les détecteurs denses émettent de nombreuses boîtes redondantes autour d'un même objet. La NMS garde la boîte de score maximal et supprime celles qui la recouvrent trop :

  1. trier les \(N\) détections par score décroissant ;
  2. prendre la première boîte \(b\), l'ajouter aux conservées ;
  3. supprimer toute boîte \(b'\) telle que \(\mathrm{IoU}(b, b') > \tau\) (typiquement \(\tau = 0{,}5\)) ;
  4. reprendre en 2 avec les boîtes restantes, jusqu'à épuisement.
import numpy as np

def nms(boxes, scores, tau=0.5):
    """boxes: (N,4) [x1,y1,x2,y2] ; scores: (N,) ; retourne les indices conserves."""
    x1, y1, x2, y2 = boxes[:, 0], boxes[:, 1], boxes[:, 2], boxes[:, 3]
    areas = np.maximum(0, x2 - x1) * np.maximum(0, y2 - y1)
    order = scores.argsort()[::-1]          # tri par score decroissant
    keep = []
    while order.size > 0:
        i = order[0]
        keep.append(i)
        xx1 = np.maximum(x1[i], x1[order[1:]])
        yy1 = np.maximum(y1[i], y1[order[1:]])
        xx2 = np.minimum(x2[i], x2[order[1:]])
        yy2 = np.minimum(y2[i], y2[order[1:]])
        inter = np.maximum(0, xx2 - xx1) * np.maximum(0, yy2 - yy1)
        iou = inter / (areas[i] + areas[order[1:]] - inter)
        order = order[1:][iou <= tau]       # on supprime les recouvrements
    return np.array(keep)
Note — Limites de la NMS gloutonne La NMS est greedy : en \(O(N^2)\) au pire, elle peut supprimer une vraie détection qui chevauche un objet distinct (deux personnes se touchant, wagons alignés). Soft-NMS (Bodla et al., 2017) remplace la suppression binaire par une décroissance du score \(s_i \mapsto s_i \cdot f(\mathrm{IoU})\) — linéaire ou gaussienne — ce qui laisse une seconde chance aux boîtes recouvrantes ; la NMS par classe doit être appliquée classe par classe, sauf variantes « class-agnostic ». Les détecteurs à prédiction d'ensemble du chapitre 2 remplacent la NMS par un appariement global, différentiable.

2. Évaluation (mAP) et détecteurs modernes

2.1. Précision, rappel et AP — calculé sur un exemple

Définition 2.1 — Précision, rappel, AP et mAP Pour une classe donnée, une détection est un vrai positif (VP) si \(\mathrm{IoU}(\text{prédiction}, \text{vérité terrain}) \geq \tau\) (et si cette vérité terrain n'est pas déjà associée) ; sinon faux positif (FP) ; une vérité terrain non détectée est un faux négatif (FN). Alors $$\text{précision} = \frac{VP}{VP + FP}, \qquad \text{rappel} = \frac{VP}{VP + FN} = \frac{VP}{|\text{vérités terrain}|}.$$ L'average precision (AP) est l'aire sous la courbe précision-rappel obtenue en balayant le seuil de score ; le mAP de COCO moyenne les AP sur 80 classes et sur 10 seuils IoU \(\tau \in \{0{,}5,\, 0{,}55,\, \dots,\, 0{,}95\}\) — noté \(\mathrm{mAP}@[0{,}5{:}0{,}95]\).
Exemple 2.2 — AP d'une classe à la main Une classe (« chat ») avec 3 vérités terrain et 5 détections triées par score décroissant, évaluées au seuil \(\tau = 0{,}5\) :
RangScoreVerdictVP cumulésPrécisionRappel

En interpolation « tous points » (précision écrêtée par le maximum à droite), les points retenus sont \((0{,}33; 1{,}00)\), \((0{,}67; 0{,}67)\) et \((1{,}00; 0{,}60)\), d'où $$\mathrm{AP} \approx 0{,}33 \times 1{,}00 + 0{,}34 \times 0{,}67 + 0{,}33 \times 0{,}60 \approx 0{,}75.$$ L'AP récompense à la fois le classement des scores (un FP à score élevé coûte cher) et la complétude ; c'est pourquoi elle est plus informative qu'un simple taux de bonnes réponses à seuil fixe.
Note — Pourquoi des seuils multiples À \(\tau = 0{,}5\), un détecteur peut avoir raison « grossièrement » : la moyenne sur \([0{,}5{:}0{,}95]\) pénalise les localisations médiocres. COCO publie aussi \(\mathrm{mAP}_S, \mathrm{mAP}_M, \mathrm{mAP}_L\) par taille d'objet — un modèle industriel « global » peut être très mauvais sur les petits objets, point crucial pour la vidéo-surveillance ou la microscopie.

2.2. Sans ancres : les détecteurs anchor-free

Les ancrages imposent une grille d'hypothèses arbitraire. Les détecteurs sans ancre prédisent directement, par pixel de la carte de caractéristiques : (i) une probabilité de centre d'objet (centerness / heatmap de centre, cf. FCOS et CenterNet) et (ii) des régressions de distances aux quatre bords. Le décodage devient : $$b = (x_c - l, \; y_c - t, \; x_c + r, \; y_c + b'),$$ où \((x_c, y_c)\) est la position du pixel central et \(l, t, r, b'\) les distances régressées — le tout sans boîte de référence. Bénéfices : moins d'hyperparamètres (échelles/ratios), pas de déséquilibre ancre/objet, meilleur sur les formes atypiques ; coût : il faut encore une NMS, et l'affectation centre-à-vérité-terrain demande des règles de zone (assignation par zone de caractéristiques).

2.3. Détection comme prédiction d'ensemble : DETR

Définition 2.3 — DETR (DEtection TRansformer) DETR traite la détection comme un problème de prédiction d'ensemble : un CNN extrait des caractéristiques, un encodeur-décodeur transformer (cf. module Deep Learning, chapitre 6) produit \(N\) requêtes d'objet décodées en \(N\) paires (boîte, classe) ; l'entraînement apparie prédiction et vérité terrain par couplage biparti à coût minimal (algorithme hongrois) : $$\hat\sigma = \arg\min_{\sigma \in \mathfrak{S}_N} \sum_{i=1}^{N} \Big( \mathcal{L}_{\mathrm{box}}(b_i, g_{\sigma(i)}) + \mathcal{L}_{\mathrm{cls}}(c_i, y_{\sigma(i)}) \Big),$$ puis applique une perte de type « set prediction » (hungarian loss) sur l'appariement optimal. La sortie étant un ensemble sans redondance apprise, DETR supprime la NMS et les ancrages.
Note — Pourquoi DETR converge lentement, et le fix L'attention globale a du mal à localiser précisément les petites boîtes (l'attention se distribue sur toute l'image) : DETR demandait ~500 époques. Deformable DETR remplace l'attention dense par une attention déformable qui n'échantillonne qu'un petit ensemble de points pertinents par requête, accélérant la convergence d'un ordre de grandeur. L'appariement hongrois est un couplage affectation-coût minimal — exactement le transport discret vu au module Computational Optimal Transport, chapitres 1–2 (là résolu par la méthode hongroise plutôt que par Sinkhorn).

3.1. Trois granularités

3.2. Segmentation sémantique : de FCN à U-Net et DeepLab

  • FCN (2015) : classifier pleinement convolutionnelle — les couches fully-connected deviennent des convolutions 1×1, et des couches de upsampling (transposées) restaurent la résolution ; sortie dense, entraînement de bout en bout ;
  • U-Net (2015) : encodeur-décodeur symétrique avec connexions de saut (skip connections) qui réinjectent les détails haute résolution de l'encodeur dans le décodeur ; conçu pour l'imagerie médicale avec peu d'images annotées, resté la référence du domaine ;
  • DeepLab (v1→v3+) : convolutions dilatées (trous) : un noyau \(3 \times 3\) de dilatation \(d\) voit un voisinage de taille \(2d+1\), agrandissant le champ réceptif sans perdre de résolution ; le module ASPP (Atrous Spatial Pyramid Pooling) combine plusieurs dilatations en parallèle pour capturer plusieurs échelles ; v3+ ajoute un décodeur léger.
Exemple 3.1 — Dice et IoU de masques Pour un masque binaire prédit \(p\) et une vérité terrain \(g\) (ensembles de pixels), l'IoU est \(|p \cap g| / |p \cup g|\) et le Dice \(2|p \cap g| / (|p| + |g|)\). Avec \(|p| = 1200\), \(|g| = 1000\) et \(|p \cap g| = 900\) : IoU \(= 900/1300 \approx 0{,}69\) et Dice \(= 1800/2200 \approx 0{,}82\). On vérifie l'identité \(\mathrm{Dice} = 2\,\mathrm{IoU} / (1 + \mathrm{IoU})\) : \(2 \times 0{,}692 / 1{,}692 = 0{,}818\) — les deux métriques sont interchangeables en tant que classement, mais le Dice paraît « plus gentil » : toujours préciser la métrique dans un rapport.

3.3. Segmentation d'instances : Mask R-CNN

Mask R-CNN (2017) étend Faster R-CNN : en parallèle des têtes classification et régression de boîte, chaque région d'intérêt reçoit une tête de segmentation qui prédit un masque binaire à résolution \(28 \times 28\) (par classe). Le détail décisif est RoI Align : le RoI pooling original quantifiait les coordonnées des cellules (arrondis), décalant les caractéristiques de quelques dixièmes de pixel — négligeable pour classer, désastreux pour aligner un masque. RoI Align échantillonne par interpolation bilinéaire aux coordonnées réelles, sans arrondi : ~2 points de mask AP gagnés pour une simple correction de précision numérique — une belle leçon d'ingénierie.

3.4. Panoptique : une métrique unique

Définition 3.2 — Panoptic Quality (PQ) On apparie segments prédits et vérités terrain par classe avec \(\mathrm{IoU} > 0{,}5\) (couplage au plus un-à-un) . Avec VP l'ensemble des appariements, FP les prédits non appariés et FN les vérités non appariées : $$\mathrm{PQ} \;=\; \underbrace{\frac{1}{|\mathrm{VP}|}\sum_{(p,g) \in \mathrm{VP}} \mathrm{IoU}(p, g)}_{\text{qualité de segmentation (SQ)}} \;\times\; \underbrace{\frac{|\mathrm{VP}|}{|\mathrm{VP}| + \tfrac12|\mathrm{FP}| + \tfrac12|\mathrm{FN}|}}_{\text{qualité de reconnaissance (RQ = score F1)}},$$ puis moyenné sur les classes. PQ découple proprement « les frontières sont-elles justes ?» (SQ) et « ai-je trouvé les bons objets ?» (RQ).

3.5. SAM : la segmentation invite-able (promptable)

Le Segment Anything Model (Meta, 2023) change de paradigme : au lieu d'entraîner un modèle par tâche, SAM apprend une tâche générale — produire un masque valide pour toute invite (point, boîte, masque grossier, texte à venir) :

  • architecture : encodeur d'image lourd (ViT, cf. module Advanced Deep Learning (P2), chapitre 1) calculable une fois par image ; encodeur d'invite léger ; décodeur de masque léger, relançable en temps réel (~50 ms) pour chaque invite — la séparation coûteux-une-fois / léger-plusieurs-fois est le pattern de déploiement « interactif » ;
  • moteur de données : boucle d'annotation assistée (modèle suggère, humain corrige) dans un premier temps, puis annotation semi-automatique puis automatique — aboutissant à SA-1B : 11 millions d'images sous licence, 1,1 milliard de masques, 99 % automatiques ;
  • usage : zéro-coup pour extraire des masques, servir de base à du fine-tuning (medical, satellite), ou d'assistant d'annotation — SAM y retourne la boucle : le modèle fabrique ses données.

4. Suivi multi-objets (tracking)

Définition 4.1 — Suivi multi-objets (MOT) Étant donné un flux vidéo, associer à travers les images des détections du même objet physique sous un identifiant de trajectoire (track) stable, tout en gérant apparitions, disparitions, occlusions et croisements. Le paradigme dominant est tracking-by-detection : un détecteur (chapitres 1–2) tourne à chaque image ; le tracker se réduit au problème d'association entre détections courantes et trajectoires existantes.

4.1. SORT : Kalman + appariement hongrois

SORT (2016) est le tracker minimal :

  1. chaque trajectoire porte un filtre de Kalman à vitesse constante (état \([x, y, s, \dot x, \dot y, \dot s]\) ; le filtre de Kalman est rappelé ci-dessous) ;
  2. prédiction : les boîtes sont extrapolées à l'image courante ;
  3. association : on résout le couplage biparti entre prédictions et détections avec pour coût \(1 - \mathrm{IoU}\) (algorithme hongrois) ;
  4. les paires formées mettent à jour les filtres (correction) ; les trajectoires non appariées \(T_{\text{max}}\) images de suite sont détruites ; les détections orphelines créent des trajectoires.
Rappel — le filtre de Kalman en deux équations
Modèle linéaire-gaussien d'état \(x_t = F x_{t-1} + w\), d'observation \(z_t = H x_t + v\), bruits blancs de covariances \(Q, R\) : $$\hat x_{t|t-1} = F \hat x_{t-1|t-1}, \quad P_{t|t-1} = F P_{t-1|t-1} F^\top + Q \quad (\text{prédiction}),$$ $$K_t = P_{t|t-1} H^\top (H P_{t|t-1} H^\top + R)^{-1}, \quad \hat x_{t|t} = \hat x_{t|t-1} + K_t (z_t - H \hat x_{t|t-1}) \quad (\text{correction}).$$ Le gain \(K_t\) pondère prédiction (mouvement) et observation (détection) selon leurs incertitudes — cf. module Signal Processing pour l'interprétation bayésienne.

4.2. DeepSORT : ajouter l'apparence

En foule, deux piétons qui se croisent échangent leurs boîtes : l'IoU seul ré-associe mal. DeepSORT (2017) associe en deux étages : (i) cascade matching privilégiant les trajectoires récemment vues, avec un coût combinant IoU et distance d'embedding d'apparence — un petit réseau RéID (ré-identification) apprend un descripteur \(e_i \in \mathbb{R}^{128}\) invariant aux pose/échelle ; (ii) appariement IoU (comme SORT) pour le reste. La « mémoire d'apparence » (galerie des derniers descripteurs par trajectoire) résiste aux occlusions longues.

4.3. ByteTrack : ne pas jeter les détections à bas score

ByteTrack (2022) part d'une observation simple : pendant une occlusion partielle, le détecteur émet souvent une détection correcte mais peu confiante — que les pipelines classiques jettent au seuil. L'algorithme esquisse :

  1. scinder les détections en haut score (\(\geq \tau_{\mathrm{haute}}\), ex. 0,5) et bas score (\(\tau_{\mathrm{basse}} \leq s < \tau_{\mathrm{haute}}\)) ;
  2. premier appariement : trajectoires actives vs détections haut score, couplage hongrois sur une distance combinée (IoU + apparence) ;
  3. second appariement : trajectoires restées orphelines vs détections bas score, couplage sur l'IoU seul — les boîtes peu confiantes « portent » la trajectoire à travers l'occlusion ;
  4. les trajectoires encore orphelines sont mises en attente puis détruites ; les détections haut score orphelines créent des trajectoires (jamais les bas score).

Résultat : des gains notables de MOTA/IDF1 sans détecteur nouveau — l'association est un levier aussi rentable que la perception.

4.4. Mesurer un tracker

Définition 4.2 — MOTA et IDF1 $$\mathrm{MOTA} = 1 - \frac{|\mathrm{FN}| + |\mathrm{FP}| + |\mathrm{changements\ d'ID}|} {\sum_t |\text{vérités terrain}_t|}, \qquad \mathrm{IDF1} = \frac{2\,\mathrm{IDTP}}{2\,\mathrm{IDTP} + \mathrm{IDFP} + \mathrm{IDFN}},$$ où les changements d'ID comptent les bascules d'identité (un tracker qui « échange » deux personnes perd en IDF1 même si sa MOTA est bonne). MOTA mesure surtout la détection ; IDF1 mesure surtout l'identité ; HOTA (2020) rééquilibre détection et association.
Note — En production Le suivi pose des contraintes systèmes fortes : latence par image (le tracker doit tenir dans le budget, cf. chapitre 8) ; robustesse aux sauts de détecteur (une frame ratée) ; ré-identification après sortie-champ de vue ; et, en multi-caméras, l'association inter-caméras (RéID pur, sans IoU disponible). Les deux briques clés — couplage hongrois et filtre de Kalman — sont des classiques L3 : le modernité est dans les descripteurs appris.

5. Vision 3D appliquée : stéréo et LiDAR

5.1. Le modèle sténopé (rappel)

Rappel L3 — projection perspective
Une caméra pinhole projette un point 3D \(X = (X, Y, Z)\) (repère caméra, \(Z\) vers l'avant) en \((u, v)\) dans l'image : $$\lambda \begin{pmatrix} u \\ v \\ 1 \end{pmatrix} = K \,[\,R \mid t\,] \begin{pmatrix} X \\ Y \\ Z \\ 1 \end{pmatrix}, \qquad K = \begin{pmatrix} f_x & 0 & c_x \\ 0 & f_y & c_y \\ 0 & 0 & 1 \end{pmatrix},$$ avec \(K\) les paramètres intrinsèques (focales en pixels, centre optique), \([R|t]\) les extrinsèques (pose caméra) ; \(\lambda = Z\). La calibration (OpenCV) estime \(K\) et la distorsion (modèle radial-tangentiel) — cf. cours P1 pour la géométrie complète (Hartley & Zisserman).

5.2. Stéréo : la disparité comme mesure de profondeur

Définition 5.1 — Disparité Pour un couple stéréo rectifié (images coplanaires, lignes épipolaires horizontales, focale commune \(f\), base \(B\)), un point 3D se projette en \((u_L, v)\) à gauche et \((u_R, v)\) à droite ; la disparité est \(d = u_L - u_R \geq 0\), mesurée en pixels.
Proposition 5.2 — Profondeur depuis la disparité Dans le cadre rectifié, la profondeur du point est $$Z = \frac{f \, B}{d}.$$
Le point 3D \((X, Y, Z)\) se projette à gauche en \(u_L = fX/Z\) et à droite (centre optique décalé de \(B\) le long de \(x\)) en \(u_R = f(X - B)/Z\). Par différence, \(u_L - u_R = fB/Z\), soit \(d = fB / Z\) et donc \(Z = fB / d\). ∎
Conséquence pratique : l'incertitude de profondeur \(\partial Z / \partial d = -fB/d^2 = -Z^2/(fB)\) croît quadratiquement avec la distance — la stéréo est précise de près, grossière de loin ; augmenter \(B\) ou \(f\) améliore la portée au prix du champ visible et des appariements difficiles.

Le pipeline stéréo classique : (i) rectification ; (ii) cost volume — pour chaque pixel gauche et chaque disparité candidate \(d\), coût d'appariement (census, SSD de descripteurs) — c'est un volume \(H \times W \times D_{\max}\) ; (iii) agrégation et régularisation : SGM (Hirschmüller, 2008) agrège les coûts le long de plusieurs directions (programmation dynamique par chemin) avec pénalités de discontinuité — le standard industriel (lithographie des GPU !) ; (iv) carte de disparité. Les méthodes profondes (PSM-Net et successeurs) apprennent le cost volume : convolutions 3D sur les descripteurs empilés par disparité — exactement la même construction de volume que le module Multimodal GenAI, chapitre 3, exploite pour d'autres données.

5.3. LiDAR : nuages de points

Le LiDAR émet des impulsions et mesure le temps de vol : sortie = nuage de points 3D (\(x, y, z\), réflectivité), ~100k–2M points/s, précis en distance (~2 cm), éparse et irrégulier — unstructuralisé : les convolutions sur grille ne s'appliquent pas directement. Familles de méthodes :

  • PointNet (2017) : par point, un MLP partagé ; agrégation par max global ; puis MLP. L'invariance par permutation vient du max : le descripteur global ne dépend pas de l'ordre des points — cf. proposition ci-dessous ;
  • Voxels / pillars : discrétiser l'espace (VoxelNet) ou seulement le plan sol (PointPillars : colonnes verticales), y agréger les caractéristiques de points, puis CNN 2D/3D sur la grille obtenue ;
  • Détection centre : CenterPoint projette tout en vue oiseau (BEV — bird's eye view) et détecte les objets par leur centre (heatmap + régression de taille/rotation) — la formulation anchor-free du chapitre 2, transposée en 2D « vue de dessus ».
Proposition 5.3 — Le max global est invariant par permutation Soit \(h(X) = \mathrm{max}_{i=1..n} \mathrm{MLP}(x_i)\) le descripteur global de PointNet. Pour toute permutation \(\pi\) de \(\{1, \dots, n\}\) : \(h(x_{\pi(1)}, \dots, x_{\pi(n)}) = h(x_1, \dots, x_n)\).
Le MLP est appliqué point à point : l'ensemble \(\{\mathrm{MLP}(x_i)\}\) est inchangé par permutation (seul l'ordre d'énumération change). Le maximum par coordonnée d'un ensemble ne dépend pas de l'ordre d'énumération, d'où l'égalité. Noter qu'une somme ou une moyenne auraient la même propriété ; le max est préféré car il sélectionne un « témoin » par coordonnée et évite le lissage d'information des moyennes. ∎

5.4. Fusion multi-capteurs en vue oiseau

Les caméras donnent la sémantique (classes, feux, panneaux) mais une profondeur indirecte ; le LiDAR donne la géométrie mais une sémantique pauvre. Les architectures modernes fusionnent en BEV : chaque capteur est amené dans un repère commun vue-de-dessus où détection, suivi et prédiction de trajectoire se combinent. BEVFormer (2022) : les caractéristiques image sont « requêtées » dans l'espace BEV par attention croisée spatiale (chaque cellule BEV interroge les pixels le long de son pilier de vue), avec attention temporelle vers la carte BEV précédente — le tracking devient implicite. Note — Les trois pièges classiques (1) Fuite de données : images quasi-dupliquées entre train et test (séquences vidéo) ; toujours découper par vidéo/scene, pas par image. (2) Déséquilibre longue traîne : le mAP global masque les classes rares — regarder les AP par classe ; les données d'entraînement doivent être ré-échantillonnées ou re-pondérées (cf. focal loss, chapitre 1). (3) Décalage de domaine : un modèle COCO s'écroule sur vos caméras de production (angle, compression, météo) ; prévoir dès le protocole un jeu « shadow » de données réelles non vues, et un suivi de dérive en exploitation (chapitre 8).

7. Études de cas industrielles

7.1. Inspection industrielle (control quality)

Contrôler des pièces (rayures, fissures, contaminations) sur ligne de production : éclairage maîtrisé (strobo, fond obscur), cadence imposée (des décisions par seconde), et — spécificité majeure — très peu d'exemples de défauts. D'où le passage au non supervisé : apprendre la normalité (auto-encodeurs, distances de caractéristiques ; cf. module Deep Learning, chapitre 7, pour les auto-encodeurs) et lever l'alerte sur écart ; le jeu MVTec AD est le benchmark de référence (15 catégories : vis, textiles, bois, bouteilles…, avec masques de défauts au pixel). Métriques : détection image-niveau (AUROC) et segmentation du défaut (pixel AUROC, PRO). Contraintes : une erreur coûte asymétriquement (faux rejet = perte de rendement ; défaut manqué = rappel produit) ; le seuil se règle sur le coût métier, pas sur 0,5.

Exemple 7.1 — Régler un seuil sur les coûts Soit un score d'anomalie \(s \in [0,1]\) ; faux rejet coût 1 € (ré-inspection manuelle), défaut manqué coût 100 € (rappel produit). Au point de fonctionnement (FP rate \(= 4\,\%\) sur pièces saines, FN rate \(= 2\,\%\) sur pièces défectueuses, taux de défauts réel 0,5 %) : coût attendu pour 10 000 pièces $$10\,000 \times \big[0{,}995 \times 0{,}04 \times 1 + 0{,}005 \times 0{,}02 \times 100\big] = 10\,000 \times (0{,}0398 + 0{,}01) \approx 498\ \text{€}.$$ Baisser le seuil (plus sensible) augmente les FP mais réduit les FN : refaire le calcul et choisir le seuil au minimum du coût — la bonne métrique d'ingénierie est un coût, pas une accuracy.

7.2. Conduite autonome

Le pipeline perception typique d'un véhicule de niveau SAE 2+ à 4 :

  1. détection/segmentation multi-caméras (chapitres 1–3) ;
  2. fusion caméra/LiDAR/radar en BEV (chapitre 5) ;
  3. suivi et prédiction des agents (chapitre 4 + modèles de trajectoires) ;
  4. planification (hors périmètre — cf. module Reinforcement Learning pour la formalisation en MDP) ;
  5. surveillance système : redondance, diagnostics, mode dégradé.

Leçons d'ingénierie : les corner cases dominent le coût (travaux, gyrophares, remorques renversées) ; les benchmarks fermés (nuScenes) sont saturés et mal corrélés aux kilomètres réels ; la sécurité impose des garanties de latence (chapitre 8) et de traçabilité (version du modèle, du jeu de données, du seuil).

7.3. Imagerie médicale

Segmentation d'organes/lésions (U-Net reste la colonne vertébrale, chapitre 3), comptage cellulaire, détection de fractures. Spécificités : données rares et coûteuses (cliniciens), formats DICOM (métadonnées, fenêtrage), validation clinique stricte, réglementation (marquage CE médical) ; la métrique est le Dice par structure et la cohérence inter-observateurs est le plafond atteignable — un Dice supérieur à l'accord humain est suspect ; les modèles sont des outils d'aide (CAD — computer-aided diagnosis), pas des décideurs.

7.4. Autres domaines (synthèse)

  • retail : planogrammes (produits en rayon), flux clients (comptage anonyme) ;
  • agriculture : détection de mauvaises herbes pour pulvérisation ciblée (drone, embedded) ;
  • sport : tracking joueurs/ballon (chapitre 4 à l'échelle), statistiques tactiques ;
  • satellite : détection de bâtiments/routes, masques de déforestation — domain randomization et multispectral en bonus.

8. Déploiement : ONNX, quantification, edge

8.1. Le pipeline de déploiement

Du notebook au produit, les étapes canoniques :

  1. export : le modèle entraîné (PyTorch) est exporté en graphe figé — ONNX (Open Neural Network Exchange), format commun accepté par la plupart des runtimes ;
  2. optimisation de graphe : fusion d'opérations (conv + batchnorm → conv unique ; conv + activation), élimination de couches mortes, choix des noyaux ;
  3. compilation ciblée : TensorRT (NVIDIA), Core ML (Apple), TF Lite / LiteRT (mobile), OpenVINO (Intel) — générent des moteurs spécialisés au matériel ;
  4. calibration/quantification : passer en INT8 (ci-dessous) ;

8.2. Quantification INT8

Définition 8.1 — Schéma affine de quantification À un tenseur flottant \(x\) on associe un entier signé sur 8 bits par $$Q(x) = \mathrm{clip}\!\left(\mathrm{round}\!\left(\frac{x}{s}\right) + z,\; -128,\; 127\right), \qquad x \approx s\,(Q(x) - z),$$ avec l'échelle \(s > 0\) et le point zéro \(z\) choisis par calibration (min-max des activations sur un échantillon représentatif, ou percentile pour limiter l'effet des valeurs extrêmes). Les poids sont quantifiés une fois pour toutes ; les activations le sont à l'exécution.
Note — PTQ vs QAT Post-training quantization (PTQ) : rapide, sans réentraînement, suffisant pour beaucoup de CNN ; quantization-aware training (QAT, Jacob et al. 2018) : pendant l'entraînement on simule la quantification par de fausses opérations (arrondi par passe avant, gradients exacts par passe arrière — straight-through estimator), le modèle apprend à être robuste à l'arrondi ; c'est la solution quand la PTQ dégrade trop (architectures sensibles, petits modèles). Bénéfice typique : mémoire ÷4 (FP32→INT8) et débit ×2–4 sur les cibles à noyaux INT8 — au prix de quelques dixièmes de point de mAP à surveiller.

8.3. Comprimer : élagage et distillation

  • élagage (pruning) : mettre à zéro les poids de plus faible module (élagage non structuré — pas de gain sans bibliothèque creuse) ou des canaux entiers (structuré — accélère réellement) ; suivre la courbe précision/taille ;
  • distillation des connaissances (Hinton et al., 2015) : un petit élève imite la distribution de sorties d'un grand professeur — la loss combine la vérité terrain et la divergence KL avec les logits du professeur « ramollis » par une température \(T\) : $$\mathcal{L} = \alpha\, \mathrm{CE}(y, z_é) + (1 - \alpha)\, T^2\, \mathrm{KL}\!\big(\mathrm{softmax}(z_p / T)\,\|\,\mathrm{softmax}(z_é / T)\big)$$ (traitée en détail au module Advanced Deep Learning (P2), chapitre 6).

8.4. Budgets de latence et profilage

Exemple 8.2 — Budget d'une application « détection temps réel » Caméra 30 fps → budget image 33,3 ms. Décomposition type sur module embarqué (Jetson classe Orin) : acquisition + décodage 3 ms ; prétraitement (redimensionnement, normalisation, NV12→RVB) 4 ms ; inférence INT8 18 ms ; post-traitement (NMS + rendu) 3 ms ; marge 5 ms. Trois leçons : (i) le pré/post-traitement est non négligeable — le coller au GPU (pipeline DALI/TensorRT-PLUGIN) si possible ; (ii) viser la latence P99 (image la plus défavorable, lots de détections nombreux), pas la moyenne ; (iii) si le budget crève, les leviers dans l'ordre industriel : résolution d'entrée ↓, modèle plus petit (distillation), INT8, skip-frame + interpolation (détection à 15 Hz, tracking à 30 Hz — le chapitre 4 sert précisément à ça).

8.5. Exploitation, dérive et vie privée

  • monitoring : journaliser distributions de scores, taux de détections, alertes « monde » (caméra sale, nuit) ; détecter la dérive de domaine et planifier le ré-entraînement (boucle de données du chapitre 6) ;
  • vie privée : traitement on-device autant que possible (aucune image ne quitte le capteur) ; si flux envoyé : floutage/ anonymisation des visages et plaques (…détectés par… les modèles du chapitre 3 !), rétention minimale ;
  • versionnement : modèle + code + données + seuils = un artefact reproductible — la méthodologie du module Advanced Deep Learning (P2), chapitre 8 s'applique mutatis mutandis.

9. Éthique, robustesse et limites

9.1. Exemples adverses

De petites perturbations imperceptibles changent la prédiction. L'attaque la plus simple — FGSM — déplace l'entrée d'un pas dans la direction du gradient de la loss : $$x_{\mathrm{adv}} = x + \varepsilon\, \mathrm{sign}\!\left(\nabla_x \mathcal{L}(\theta, x, y)\right),$$ avec \(\varepsilon\) de l'ordre de 2–8/255. En détection, des pastilles collées sur un panneau peuvent faire disparaître un objet de la sortie ; les défenses vont de l'entraînement adversarial (min-max sur les perturbations) à la certification par bornes — un panorama est donné au module Machine Learning ; l'ingénieur retient surtout : le modèle intégré dans un produit peut être ciblé, et la robustesse se teste (boîtes à outils d'attaques) avant déploiement.

9.2. Biais et équité des systèmes de vision

  • biais de représentation : jeux majoritairement nord-américains/européens → chute de performance sur d'autres contextes (rues, vêtements, objets) ; le rapport « Gender Shades » a documenté des écarts d'accuracy de détection selon le phototype ; en pratique : découper l'évaluation par sous-groupes (cf. module Machine Learning) ;
  • surveillance et biométrie : la reconnaissance faciale de masse est encadrée/interdite dans plusieurs juridictions ; le règlement européen sur l'IA (AI Act, 2024) classe l'identification biométrique à distance parmi les usages à haut risque ou interdits ; anonymisation avant stockage ;
  • consentement : données scrappées (LAION etc.) et droit à l'image ; préférer les jeux sous licence claire et documenter la provenance (data cards).

9.3. Limites fondamentales à connaître

Note — Ce que les modèles ne « comprennent » pas Compositionnalité : un détecteur peut voir « une personne » et « un vélo » sans inférer « une personne sur un vélo » — les relations exigent d'autres formalismes (graphes de scène ; cf. module Graph ML). Hallucination multimodale : les légendeurs décrivent des objets absents (cf. module Multimodal GenAI, chapitre 8). Hors distribution : neige, nuit, capteur nouveau — la confiance affichée n'est pas calibrée hors distribution d'entraînement. Causalité : la vision corrèle, n'explique pas — un système de décision doit séparer perception et décision (conduite autonome, chapitre 7).

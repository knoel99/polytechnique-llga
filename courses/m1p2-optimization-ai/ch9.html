9. Optimisation des hyperparamètres

Le pas \(t\), la pénalité \(\lambda\), la taille du batch, le learning rate schedule : autant d'hyperparamètres que le module a jusqu'ici traités comme donnés. Or l'expérience montre qu'ils valent souvent plus de points de performance que le choix d'algorithme lui-même. Optimiser l'optimiseur.

Définition 9.1 — Le problème (et pourquoi il est dur) $$\max_{h \in \mathcal{H}}\; v(h), \qquad v(h) = \text{score de validation d'un modèle entraîné avec } h,$$ fonction chère (chaque évaluation = un entraînement), bruitée, non convexe, sans gradient disponible. Typiquement 5 à 50 dimensions, budget 10 à 1 000 évaluations. C'est le domaine de l'optimisation sans dérivées bayésienne.
Proposition 9.2 — Grid vs random (Bergstra–Bengio, argument) À budget de \(B\) essais et \(p\) hyperparamètres « importants » parmi \(d\) : la grille explore \(B^{1/d}\) valeurs par dimension, le tirage aléatoire en explore \(B\) par dimension (mais une seule fois par tirage). Si seuls \(p \ll d\) paramètres comptent vraiment, l'essai aléatoire atteint une bonne combinaison sur ces \(p\) avec probabilité bien plus grande : en grille, toute case « bonne » sur les \(p\) axes utiles est dupliquée sur les \(d-p\) axes inutiles — budget gâché.
Modèle : une cellule est « bonne » si ses coordonnées sur les \(p\) axes utiles sont bonnes, probabilité \(q^p\) par tirage aléatoire (\(q\) = fraction de valeurs bonnes par axe) — après \(B\) tirages, probabilité de n'en toucher aucune : \((1-q^p)^B\). En grille régulière \(m = B^{1/d}\) valeurs par axe : le nombre de combinaisons explorées sur les axes utiles est \(m^p = B^{p/d} \ll B\). Dès que \(p < d\), \(B^{p/d} < B\) : la grille visite moins de régions utiles à budget égal. ∎
Définition 9.3 — Optimisation bayésienne (GP-EI) (1) Modèle : \(v \sim \mathrm{GP}(0, k)\) sur \(\mathcal{H}\) ; après \(k\) évaluations, prédictions gaussiennes \((\mu_k(h), \sigma_k(h))\) en tout point. (2) Acquisition expected improvement : avec \(v_k^\star = \max_j v(h_j)\), $$\mathrm{EI}_k(h) = \mathbb{E}\big[(v(h) - v_k^\star)_+\big] = (\mu_k(h) - v_k^\star)\,\Phi(z_k(h)) + \sigma_k(h)\,\varphi(z_k(h)), \quad z_k = \frac{\mu_k - v_k^\star}{\sigma_k}.$$ (3) Boucle : évaluer \(h_{k+1} = \arg\max_h \mathrm{EI}_k(h)\), mettre à jour le GP. La formule fermée montre la mécanique exploitation/exploration : \(\mathrm{EI}\) grandit quand \(\mu\) dépasse le record (exploiter) et quand \(\sigma\) est grand (explorer).
Multi-fidélité : Hyperband, le pragmatisme Quand l'évaluation a un « réglage de qualité » (epochs, sous-échantillon de données), lancer beaucoup de configurations à bas prix puis ne poursuivre que les prometteuses domine souvent le GP pur : c'est Successive Halving et Hyperband (Li et al., 2017), omniprésent en pratique (optuna, ray tune). Le trio de référence du praticien : random pour dégrossir, Hyperband pour creuser, GP-EI pour les 5–10 paramètres vraiment sensibles. 
import numpy as np
rng = np.random.default_rng(0)
def train_score(lr, lam, epochs=30):          # proxy : modele lineaire reg
    # ... entrainement reel remplace par une fonction rugueuse
    peak = 0.92 - 0.4*np.abs(np.log10(lr) + 1.5) - 0.15*np.log10(1+lam)
    return peak + 0.02*np.sin(10*lr) + 0.01*rng.standard_normal()

best_grid = max(train_score(10**e, 10**-l)
                for e in np.linspace(-4, -1, 8) for l in np.linspace(0, 3, 8))
best_rand = max(train_score(10**rng.uniform(-4, -1), 10**-rng.uniform(0, 3))
                for _ in range(64))           # meme budget : 64 essais
print("grid:", round(best_grid, 4), "random:", round(best_rand, 4))
# sur ce type de paysage (rares parametres sensibles), random gagne presque toujours

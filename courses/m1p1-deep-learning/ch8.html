8. Transfer learning et fine-tuning

Entraîner « from scratch » est devenu l'exception : la pratique dominante consiste à partir d'un modèle pré-entraîné sur d'immenses corpus (ImageNet pour la vision, des téraoctets de texte pour les LLMs) et à l'adapter. Ce chapitre donne le cadre et le vocabulaire ; le module LLMs (M2) l'applique à grande échelle.

8.1 Les trois régimes d'adaptation

  • Frozen features / linear probing : geler tout le backbone, entraîner un classifieur linéaire (ou une petite tête) sur les représentations pré-entraînées. Diagnostic précieux : la qualité des features se mesure par la performance d'un simple softmax dessus (cf. exercice 12).
  • Fine-tuning complet : ré-entraîner tous les poids avec un pas plus petit (typiquement 10 à 100× plus petit que le pré-entraînement) — le risque de catastrophic forgetting (oubli des connaissances pré-entraînées) se gère par un pas décroissant et peu d'époques.
  • Fine-tuning paramètre-efficace (PEFT) : n'entraîner qu'une petite fraction de nouveaux paramètres, le reste restant figé — d'autant plus pertinent que les modèles grossissent.
Pourquoi ça marche Les couches basses apprennent des features quasi universelles (chapitre 4 : bords, textures ; chapitre 9 : morphologie de graphes) ; la spécificité de la tâche vit dans les couches hautes. La courbe performance / nombre d'exemples étiquetés du domaine se décale massivement vers la gauche — c'est le bénéfice pratique le plus mesurable du deep learning moderne.

8.2 Adaptation de domaine, en deux mots

Quand la cible n'a aucune étiquette (domaine source étiqueté → domaine cible non étiqueté), l'adaptation de domaine aligne les distributions : adversariale (un discriminateur essaye de deviner le domaine sur les features : elles doivent devenir non discriminantes), ou par distances de distributions (MMD, distances de Wasserstein — cf. module Optimal Transport). L'idée directrice : apprendre des représentations invariantes au domaine mais discriminantes pour la tâche.

8.3 LoRA : esquisse mathématique

Définition 8.1 — LoRA (Hu et al., 2021) Pour une matrice pré-entraînée \(W_0 \in \mathbb{R}^{d_{\mathrm{out}} \times d_{\mathrm{in}}}\), on fige \(W_0\) et l'on apprend un update de bas rang : $$W = W_0 + \Delta W = W_0 + \frac{\alpha}{r}\, B A, \qquad B \in \mathbb{R}^{d_{\mathrm{out}} \times r},\ A \in \mathbb{R}^{r \times d_{\mathrm{in}}},\ r \ll \min(d_{\mathrm{in}}, d_{\mathrm{out}}),$$ avec \(B\) initialisée à zéro et \(A\) gaussienne : \(\Delta W = 0\) au départ, l'entraînement part exactement du modèle pré-entraîné. \(\alpha/r\) fixe l'échelle effective de la mise à jour.
Pourquoi un bas rang suffit L'hypothèse de travail, étayée par Aghajanyan et al. (2020), est que les mises à jour de poids lors de l'adaptation ont un « rang intrinsèque » faible : \(\Delta W\) est bien approximé par un produit \(BA\) de rang \(r\) petit (4 à 64 en pratique). Comptons : adapter une couche \(d \times d\) avec \(r = 8\) coûte \(2dr = 16d\) paramètres au lieu de \(d^2\) — pour \(d = 4096\), un facteur 1000. Autres bénéfices : un seul \(W_0\) figé en mémoire + des paires \((A, B)\) interchangeables par tâche (swap instantané) ; et pour la latence d'inférence, on peut fusionner \(W = W_0 + BA\) sans surcoût. Les généralisations (QLoRA : backbone quantifié + LoRA) sont traitées au module LLMs (M2). 
import torch, torch.nn as nn

class LoRALinear(nn.Module):
    def __init__(self, base: nn.Linear, r=8, alpha=16):
        super().__init__()
        self.base = base                       # W0 gele
        for p in self.base.parameters(): p.requires_grad = False
        self.A = nn.Parameter(torch.randn(r, base.in_features) * 0.01)
        self.B = nn.Parameter(torch.zeros(base.out_features, r))
        self.scale = alpha / r
    def forward(self, x):
        return self.base(x) + self.scale * (x @ self.A.T @ self.B.T)
# parametres entrales : r*(in+out) au lieu de in*out

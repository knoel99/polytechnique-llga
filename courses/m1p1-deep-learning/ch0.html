0. Rappels : calcul différentiel matriciel et stabilité numérique

Le deep learning est, à 90 %, du calcul différentiel appliqué à des fonctions à des milliards de paramètres. Ce chapitre consolide les outils du L3 dont nous aurons besoin chaque semaine : différentiation de fonctions matricielles, théorème central limite (pour comprendre pourquoi la SGD fonctionne) et un peu de stabilité numérique (pour comprendre pourquoi les implémentations naïves produisent des NaN).

Rappels L3 — la mécanique de base
  • Règle de la chaîne : \((g \circ f)'(x) = g'(f(x))\, f'(x)\) ; en dimension : \(\nabla (g \circ f)(x) = J_f(x)^\top \nabla g(f(x))\), où \(J_f\) est la matrice jacobienne \((J_f)_{ij} = \partial f_i / \partial x_j\).
  • Gradient de formes quadratiques : \(\nabla_x \tfrac12\|Ax - b\|^2 = A^\top(Ax - b)\) et \(\nabla_x x^\top A x = (A + A^\top)x\).
  • Dérivées des activations usuelles : \(\sigma' = \sigma(1-\sigma)\), \(\tanh' = 1 - \tanh^2\), \(\mathrm{ReLU}' = \mathbf{1}_{x>0}\), et pour le softmax \(\hat y = \mathrm{softmax}(z)\) : \(\partial \hat y_k / \partial z_j = \hat y_k(\delta_{kj} - \hat y_j)\).
  • TCL : la moyenne de \(m\) variables iid de variance \(\sigma^2\) fluctue autour de son espérance avec un écart-type en \(\sigma/\sqrt m\) (cf. module Refresher Statistics).

0.1. Différentiation de fonctions matricielles

Les paramètres d'un réseau sont des matrices ; il faut savoir dériver par rapport à une matrice. La convention la plus commode : le gradient d'une fonction \(f : \mathbb{R}^{m \times n} \to \mathbb{R}\) est la matrice \(G\) telle que \(f(X + H) = f(X) + \langle G, H\rangle + o(\|H\|)\) avec le produit scalaire de Frobenius \(\langle G, H \rangle = \mathrm{tr}(G^\top H)\). Trois identités suffisent pour tout ce cours.

Proposition 0.1 — Identités différentielles utiles Pour \(X \in \mathbb{R}^{m \times n}\), \(a \in \mathbb{R}^m\), \(b \in \mathbb{R}^n\), \(A\) de taille compatible : $$\frac{\partial}{\partial X}\,\mathrm{tr}(A^\top X) = A, \qquad \frac{\partial}{\partial X}\, a^\top X b = a\, b^\top, \qquad \frac{\partial}{\partial X}\, \tfrac12\|X A - B\|_F^2 = (XA - B)A^\top.$$
On démontre la seconde (les autres sont identiques). Écrivons \(a^\top X b = \sum_{i,j} a_i X_{ij} b_j = \mathrm{tr}(b a^\top X)\). La différentielle est \(d(a^\top X b) = a^\top H b = \langle a b^\top, H\rangle\) pour toute perturbation \(H\), donc le gradient (au sens de Frobenius) est \(ab^\top\). Pour la troisième : \(f(X) = \tfrac12\|XA - B\|_F^2\), \(df = \langle XA - B,\; HA\rangle = \langle (XA-B)A^\top,\; H\rangle\), en utilisant la cyclicité de la trace \(\mathrm{tr}(M^\top H A) = \mathrm{tr}((M A^\top)^\top H)\) avec \(M = XA - B\). ∎
Règle pratique Dans un réseau, « le gradient remonte par les transposées » : si la passe avant contient \(z = Wx\), la passe arrière contient \(\nabla_x = W^\top \nabla_z\) et \(\nabla_W = \nabla_z\, x^\top\). Vérifiez toujours les dimensions : \(\nabla_W\) a la taille de \(W\), \(\nabla_x\) celle de \(x\). C'est le contrôle qualité le plus efficace contre les bugs de backprop.

0.2. TCL et bruit du mini-batch

Pourquoi optimiser sur des mini-batchs plutôt que sur tout le jeu de données ? Soit \(\mathcal{D} = (\xi_1, \dots, \xi_N)\) iid et la perte empirique \(L(\theta) = \frac1N \sum_i \ell(\theta; \xi_i)\). Le gradient du mini-batch \(B = (\xi_{i_1}, \dots, \xi_{i_m})\) est \(\hat g(\theta) = \frac1m \sum_{j=1}^m \nabla_\theta \ell(\theta; \xi_{i_j})\).

Proposition 0.2 — Le gradient stochastique est un estimateur sans biais de bruit \(1/\sqrt m\) \(\mathbb{E}[\hat g] = \nabla L\) et, si les gradients individuels ont une covariance finie \(\Sigma = \mathrm{Cov}(\nabla \ell(\theta; \xi))\), alors $$\mathrm{Cov}(\hat g) = \frac{1}{m}\,\Sigma.$$
Linéarité de l'espérance et tirage uniforme : \(\mathbb{E}[\nabla \ell(\theta;\xi_i)] = \nabla L\). Pour la covariance, les tirages sont indépendants : \(\mathrm{Cov}(\tfrac1m\sum_j G_j) = \tfrac{1}{m^2}\sum_j \mathrm{Cov}(G_j) = \tfrac1m \Sigma\), où \(G_j = \nabla \ell(\theta; \xi_{i_j})\). L'écart-type de l'estimation décroît donc en \(\|\Sigma\|^{1/2}/\sqrt m\) : multiplier la taille du batch par 100 ne divise le bruit que par 10 — argument économique pour les petits batchs, complété au chapitre 3 (le bruit a aussi un effet bénéfique d'exploration). ∎

0.3. Stabilité numérique : softmax et l'astuce log-sum-exp

Le softmax \(\hat y_i = e^{z_i} / \sum_j e^{z_j}\) apparaît dans toutes les pertes d'classification et dans l'attention. En précision flottante (float32, max \(\approx 3{,}4 \times 10^{38}\)), l'implémentation naïve déborde : \(e^{1000} = \infty\), et \(\infty/\infty = \mathrm{NaN}\). L'astuce universelle consiste à soustraire le maximum avant d'exponentier.

Proposition 0.3 — Identité log-sum-exp et softmax stable Posons \(\mathrm{LSE}(z) = \log \sum_{j=1}^n e^{z_j}\) et \(m = \max_j z_j\). Alors : $$\mathrm{LSE}(z) = m + \log \sum_{j=1}^n e^{z_j - m}, \qquad m \;\le\; \mathrm{LSE}(z) \;\le\; m + \log n,$$ $$\mathrm{softmax}(z)_i = \frac{e^{z_i - m}}{\sum_j e^{z_j - m}},$$ et cette dernière forme ne déborde jamais.
Factorisation : \(\sum_j e^{z_j} = e^{m} \sum_j e^{z_j - m}\), donc \(\mathrm{LSE}(z) = m + \log \sum_j e^{z_j - m}\). Comme \(0 < e^{z_j - m} \le e^0 = 1\) et qu'au moins un terme vaut exactement 1 (celui du maximum), la somme vit dans \([1, n]\), d'où l'encadrement. Pour le softmax, diviser numérateur et dénominateur par \(e^m > 0\) ne change pas la valeur. Stabilité : tous les exposants \(z_i - m \le 0\), donc chaque \(e^{z_i - m} \in (0, 1]\) : aucun débordement, et le terme dominant du dénominateur vaut exactement 1, si bien que le résultat reste précis même quand les autres termes sous-débordent vers 0 (ce qui est inoffensif : le softmax tend simplement vers un one-hot). ∎ 
import torch

z = torch.tensor([1000., 1001., 999.])
# print(torch.softmax(z, 0))          # NaN avec une implementation naive
print(torch.logsumexp(z, 0))          # 1001.4076 : stable (PyTorch l'applique toujours)
print(torch.softmax(z - z.max(), 0))  # forme stable : [0.2447, 0.6652, 0.0900]
Culture numérique Cette section prépare aussi le chapitre 10 : la plupart des NaN en entraînement viennent d'un softmax/exposant non protégé, d'un log d'une probabilité nulle (on minimise \(-\log p\) via log-softmax, jamais \(-\log(\mathrm{softmax})\)), ou d'un taux d'apprentissage trop grand. La règle : quand un NaN apparaît, remontez la passe avant couche par couche jusqu'à trouver la première activation infinie.

6. Attention et transformers

6.1 Scaled dot-product : pourquoi \(\sqrt{d_k}\)

Définition 6.1 — Scaled dot-product attention (Vaswani et al., 2017) Pour des tokens \(i = 1..n\) d'embeddings \(x_i\), on calcule $$q_i = W_q x_i,\quad k_i = W_k x_i,\quad v_i = W_v x_i,$$ $$\mathrm{Attention}(Q, K, V) = \mathrm{softmax}\!\Big(\frac{Q K^\top}{\sqrt{d_k}}\Big) V, \qquad \alpha_{ij} = \frac{\exp(q_i^\top k_j / \sqrt{d_k})}{\sum_{j'} \exp(q_i^\top k_{j'} / \sqrt{d_k})}.$$ Multi-head : \(h\) têtes d'attention en parallèle (projections \(W^q_m, W^k_m, W^v_m\), dimensions \(d_k = d/h\)), concaténées puis projetées — plusieurs « canaux de communication » indépendants.
Proposition 6.2 — La variance des scores croît comme \(d_k\) Si les composantes de \(q\) et \(k\) sont iid, centrées, de variance 1, alors \(q^\top k = \sum_{\ell=1}^{d_k} q_\ell k_\ell\) est centré et de variance exactement \(d_k\). Sans normalisation, l'écart-type des scores est \(\sqrt{d_k}\) (32 pour \(d_k = 1024\)) : le softmax devient un argmax one-hot, ses gradients s'évanouissent — saturation, cf. chapitre 0, proposition 0.3. Diviser par \(\sqrt{d_k}\) ramène la variance à 1, indépendamment de la dimension.
Centrage : \(\mathbb{E}[q_\ell k_\ell] = \mathbb{E}[q_\ell]\,\mathbb{E}[k_\ell] = 0\) (indépendance). Variance : les termes \(q_\ell k_\ell\) sont iid entre eux, donc \(\mathrm{Var}(\sum_\ell q_\ell k_\ell) = \sum_\ell \mathrm{Var}(q_\ell k_\ell) = d_k\, \mathbb{E}[q_\ell^2]\mathbb{E}[k_\ell^2] = d_k\). Après division par \(\sqrt{d_k}\), la variance du score normalisé vaut \(1\). Conséquence sur la saturation : les écarts typiques entre scores normalisés sont \(\mathcal{O}(1)\), les ratios d'exponentielles \(\exp(s_i - s_j)\) restent dans une gamme raisonnable et le softmax garde un gradient non nul ; sans scaling, des écarts d'ordre \(\sqrt{d_k} \gg 1\) produisent une distribution proche du one-hot, dont le gradient (\(\hat y_k(\delta_{kj} - \hat y_j)\)) tend vers 0. ∎

6.2 Architecture du bloc : pre-norm, RoPE

  • Post-norm (Vaswani et al., original) : \(y = \mathrm{LN}(x + \mathrm{Att}(x))\) — la connexion résiduelle passe à travers la normalisation. Pre-norm (GPT-2 et suivants) : \(y = x + \mathrm{Att}(\mathrm{LN}(x))\) — le chemin identité est intact (proposition 4.6) : le gradient atteint l'entrée sans atténuation, ce qui rend l'entraînement stable à grande profondeur et réduit le besoin de warmup ; une LayerNorm finale compense l'absence de normalisation en sortie. Standard actuel.
  • RoPE (rotary position embedding, Su et al., 2021) : au lieu d'ajouter un code positionnel, on fait tourner chaque paire de coordonnées \((q_{2i}, q_{2i+1})\) d'un angle \(m\,\theta_i\) dépendant de la position \(m\) du token (et de \(i\)), avec \(\theta_i = b^{-2i/d}\). Preuve du caractère « relatif » : les rotations planes commutent et \(R(m)^\top R(n) = R(n - m)\), donc $$\langle R(m)\, q,\; R(n)\, k \rangle = q^\top R(m)^\top R(n)\, k = q^\top R(n-m)\, k,$$ le score ne dépend que de l'écart \(n - m\) : la position est encodée dans l'interaction, avec un support longueur non borné — c'est l'encodage des LLMs modernes (cf. module LLMs, M2).

6.3 Coûts et attention efficace

  • Complexité : \(\mathcal{O}(n^2 d)\) temps et \(\mathcal{O}(n^2)\) mémoire (matrice \(QK^\top\) de taille \(n \times n\) par tête) — le goulot des LLMs. Le MLP est \(\mathcal{O}(n d^2)\) : l'attention domine dès que \(n \gtrsim d\).
  • FlashAttention (Dao et al., 2022) : exacte, mais IO-aware — elle tile le calcul de softmax(QK^T)V en blocs chargés en SRAM (mémoire rapide du GPU) et n'écrit jamais la matrice \(n \times n\) en HBM, en maintenant des statistiques de log-sum-exp en ligne (la proposition 0.3 rend le softmax incrémental : on fusionne les blocs avec \(m\) et la somme partielle). Résultat : même Flops, mémoire \(\mathcal{O}(n)\), vitesse ×2 à ×4 en pratique.
  • Approximations : sparse, linéaires, sliding window (cf. module LLMs, M2).
Lecture « graphe » (Karpathy, 2025-2026) — le pont vers le module Graph ML Un transformer est un réseau de neurones sur graphe dynamique :
  • chaque token = un nœud qui porte un vecteur ;
  • l'attention calcule des arêtes pondérées \(\alpha_{ij}\) à partir des données (graphe dynamique, contrairement aux GNN) ;
  • \(\sum_j \alpha_{ij} v_j\) est un message passing : les nœuds s'échangent leurs « values » ;
  • le bloc MLP = la computation locale de chaque nœud ; residual + LayerNorm = plomberie pour que le « graphe » reste entraînable ;
  • une couche transformer = communication (attention) puis computation (MLP), exactement l'alternance d'un GNN.
Le master LLGA exploite cette double lecture : le même objet mathématique vu « de l'intérieur du LLM » (module M2) et « sur les données structurées » (module Graph ML).

6.4 Un bloc complet en PyTorch

import torch, torch.nn as nn, torch.nn.functional as F

class Block(nn.Module):
    """Un bloc transformer pre-norm : attention causale multi-tete + MLP."""
    def __init__(self, d, n_heads, p_drop=0.1):
        super().__init__()
        self.ln1, self.ln2 = nn.LayerNorm(d), nn.LayerNorm(d)
        self.n_heads, self.d_head = n_heads, d // n_heads
        self.qkv = nn.Linear(d, 3 * d)
        self.proj = nn.Linear(d, d)
        self.mlp = nn.Sequential(nn.Linear(d, 4 * d), nn.GELU(), nn.Linear(4 * d, d))
        self.drop = nn.Dropout(p_drop)

    def forward(self, x):                          # x : (B, n, d)
        B, n, d = x.shape
        q, k, v = self.qkv(self.ln1(x)).chunk(3, -1)
        # multi-tete : (B, n, d) -> (B, n, h, d_head) -> (B, h, n, d_head)
        def split(t): return t.view(B, n, self.n_heads, self.d_head).transpose(1, 2)
        q, k, v = split(q), split(k), split(v)
        mask = torch.tril(torch.ones(n, n, device=x.device))     # masque causal
        att = F.scaled_dot_product_attention(q, k, v,            # softmax(QK^T/sqrt(d_head))V
                                             attn_mask=mask, dropout_p=0.0)
        att = att.transpose(1, 2).reshape(B, n, d)               # refusion des tetes
        x = x + self.drop(self.proj(att))                        # residual 1 (pre-norm)
        x = x + self.drop(self.mlp(self.ln2(x)))                 # residual 2
        return x

torch.manual_seed(0)
x = torch.randn(2, 16, 128)
model = nn.Sequential(*[Block(128, 4) for _ in range(4)])
print(model(x).shape)                              # [2, 16, 128]

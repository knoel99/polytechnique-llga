7. Robustesse et privacy sur graphes

7.1 — Nettack (Zügner et al., 2018) : attaque par gradient, en détail Le scénario : evasion (l'attaquant modifie le graphe au moment du test) sur une cible \(u\) et sa classe \(y_u\) ; budget : \(\Delta\) modifications (ajout/retrait d'arêtes, changements de features). Le dilemme de l'attaquant : le modèle n'est pas différentiable en la structure discrète. La solution Nettack :
  1. entraîner un surrogate linéarisé (GCN à une couche, softmax) ; sa sortie \(Z_u(A)\) est alors polynomiale en \(A\) — continue, différentiable ;
  2. score de première ordre : pour chaque modification candidate \(\delta\) (flip d'une arête \((a,b)\) ou d'une feature), $$\mathrm{score}(\delta) = -\nabla_{A}\, \mathcal{L}_{att}\big(Z_u(A)\big)\big|_{(a,b)} \cdot \big(\delta_{ab} - A_{ab}\big),$$ l'approximation de Taylor du changement de perte (produit du gradient avec la direction du changement) ; on retient la modification au score maximal ;
  3. itérer (modifier, re-score) jusqu'au budget ; contraintes de « discrétion » : n'ajouter que des arêtes plausibles (degrés, features communes).
Résultat historique : quelques flips suffisent à retourner la prédiction — et les attaques transfert au vrai GCN (le surrogate suffit). La leçon LLGA : en détection de fraude, l'attaquant connaît le modèle (ou son ombre) ; la robustesse est une exigence de conception, pas une option.
7.2 — Empoisonnement : Meta-Self (Zügner & Günnemann, 2019) Attaque à l'entraînement (poisoning) : le graphe est corrompu avant l'apprentissage. Bilevel : $$\min_{\delta}\ \mathcal{L}_{att}\big(f_{\theta^*}(A + \delta)\big) \quad \text{s.c.} \quad \theta^* = \arg\min_\theta \mathcal{L}_{train}\big(f_\theta(A + \delta)\big),$$ résolu par méta-gradient : quelques pas de gradient interne sont déroulés (differentiable), le gradient extérieur remonte à \(\delta\) — la même machinerie que le MAML du module RL/Deep Learning. Variante « self-labeled » (Meta-Self) : l'attaquant contrôle aussi quelques étiquettes. Défenses structurelles : le pruning (les arêtes d'attaque sont souvent « suspectes » — grandes distances features) ; la purification (Pro-GNN : apprendre un graphe propre \(A'\) régularisé proche de \(A\) tout en entraînant le GNN) ; le robust GCN (RGCN, Zhu et al., 2019) : couches gaussiennes dont la variance absorbe l'attaque + attention sur les voisins fiables.
7.3 — Certification : esquisse Garantir qu'aucune attaque de budget \(\Delta\) ne change la prédiction : par randomized smoothing appliqué aux graphes (majorité sur des graphes bruités par flips aléatoires) ou par bornes spectrales (certificats liés à \(\lambda_{\max}\) du ch. 2 — même monnaie) ; l'état de l'art certifie de petits budgets sur des GCN modérés : en pratique, on combine certification partielle + défenses ci-dessus + monitoring (détecter les anomalies d'ajout d'arêtes).
7.4 — Privacy : node-DP, edge-DP, réidentification
  • edge-DP : le mécanisme de base est la randomized response — retourner chaque arête avec probabilité \(p\), calibrée pour \((\varepsilon, 0)\)-DP ; les requêtes de comptage (combien d'arêtes entre deux groupes ?) reçoivent du bruit Laplace sensibilité 1 ;
  • node-DP : beaucoup plus dur — la sensibilité explose avec le degré (retirer un nœud retire \(d\) arêtes) ; recette : projeter le graphe sur un graphe de degré borné \(k\) (garder les \(k\) voisins « les plus importants »), puis appliquer les mécanismes bord ; le prix : biais sur les hubs ;
  • réidentification : les embeddings de graphe (M1, ch. 3) sont des empreintes — re-router un nœud « anonymisé » dans un graphe public par comparaison de voisinages (attaques par degrés, par sous-graphes — l'attaque de Narayanan-Shmatikov transposée) ; GraphRAG (M1, ch. 11) agrège des faits dispersés : le risque de réidentification croît avec la qualité du graphe ;
  • évaluation : mesurer trade-off utilité-privacy (AUC vs \(\varepsilon\)) ; croisement avec le module sécurité des LLMs M2 (injection de prompt sur le KG, fuite par génération).
7.5 — Équité structurelle Biais de degré : les nœuds à faible degré (minorités dans les réseaux sociaux, nouveaux clients) sont moins bien prédits — moins de messages = moins de signal ; remèdes : features structurelles (RWSE, ch. 3), arêtes virtuelles, ré-échantillonnage par degré, pertes repondérées ; question ouverte : l'équité structurelle (communautés) vs individuelle (nœuds) peut entrer en conflit — le pendant exact des tensions fairness du module Optimal Transport (transporter des distributions de nœuds ; biais homophilie : un GNN homophile propage les biais des étiquettes).

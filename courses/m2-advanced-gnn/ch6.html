6. Échelle : sampling, systèmes

Ce qui est supposé acquis (M1, ch. 7)
NeighborSampler (fanouts, voisinage expansif \(1 + s_L(1 + s_{L-1}(\dots))\)), Cluster-GCN (partition METIS, biais de partition), GraphSAINT (sous-graphes + normalisation par couverture sans biais), et le triangle biais/variance/mémoire. Ici : la couche systèmes et l'hygiène expérimentale.
  • Multi-GPU et partitionnement : au-delà d'un GPU, partitionner le graphe (METIS/vertex-cut) sur plusieurs machines ; les arêtes frontalières sont dupliquées (shadow nodes) — l'entraînement distribué du module Emerging ML s'applique presque tel quel (parameter server vs all-reduce) ; PinSage (M1, ch. 6) est la référence industrielle ;
  • Caching et pipelining : l'échantillonnage voisinage est un problème de système (I/O, réutilisation des sous-graphes entre batchs — d'où l'échantillon par importance de PinSage qui fige les portes d'entrée) ; les frameworks : DGL, PyG + torch_geometric.sampler, Quiver ;
  • Complexités récapitulatives :
    MéthodeMémoire/batchBiaisNotes
    full-batch\(\mathcal{O}(|V| + |E|)\)aucuncasse au-delà d'~1M nœuds
    NeighborSampler\(\mathcal{O}(\prod s_l)\)varianceinductif, standard
    Cluster-GCN\(\mathcal{O}(|E|/k)\)partitionprofond possible
    GraphSAINT\(\mathcal{O}(|\mathcal{G}_s|)\)corrigébatchs denses
  • Benchmarks et hygiène : OGB (ogbn-arxiv 169k ; ogbn-products 2,4M ; PCQM4M 3,7M molécules), leaderboards publics ; le papier « Benchmarking Graph Neural Networks » (Dwivedi et al., 2020/2023) fixe le protocole : mêmes budgets de paramètres, mêmes splits, seeds multiples avec intervalles de confiance — beaucoup de « SOTA » meurent à cette aune ; la recherche d'hyperparamètres bayésienne est la règle (les gains < 0,5 point exigeant un protocole strict) ;
  • Bonne pratique recherche : toujours publier la variance, tester la significativité (tests appariés sur seeds), et vérifier la fuite (splits temporels pour les graphes dynamiques — ch. 5).

9. Agrégation d'estimateurs

Définition 9.1 — Le problème d'agrégation On dispose d'un dictionnaire \(f_1, \dots, f_M\) d'estimateurs (hyperparamètres, modèles, features) ; on veut construire un agrégat \(\tilde f\) dont le risque approche celui du meilleur d'entre eux (ou d'une combinaison). Trois cadres : (MS) sélection de modèle \(\tilde f = f_{\hat j}\) ; (C) combinaison convexe \(\tilde f = \sum_j \pi_j f_j\), \(\pi\) dans le simplexe ; (L) combinaison linéaire (agrégation « convexe au sens \(L^2\) », pour la perte quadratique). Objectif quantitatif : un excès de risque oracle $$L(\tilde f) - \min_{j \leq M} L(f_j) \;\leq\; \text{prix}(M, n)$$ avec un prix qui soit petit devant le risque lui-même — typiquement \(\sqrt{\log M/n}\) ou même \(\log M/n\) (perte quadratique, cf. thm 9.3).
Définition 9.2 — Poids exponentiels Avec une température \(\eta > 0\) (et un prior \(\rho\) sur le dictionnaire) : $$\pi_j = \frac{\rho_j\, e^{-\eta n \hat L(f_j)}}{\sum_{k} \rho_k\, e^{-\eta n \hat L(f_k)}}, \qquad \tilde f = \sum_j \pi_j f_j \quad (\text{perte convexe}).$$ Les poids récompensent exponentiellement les bonnes performances empiriques ; \(\rho\) pénalise la complexité (prior uniforme : \(\log M\) dans la borne ; prior sparse : reconstruction des résultats type Lasso, ch. 10).
Théorème 9.3 — Oracle d'agrégation convexe (démontré pour (i)) Pertes convexes \(\ell\) en la prédiction, \(\ell \in [0,1]\), prior uniforme.
  • (i) Avec probabilité \(\geq 1 - \delta\) : \(L(\tilde f) - \min_j L(f_j) \leq \sqrt{\frac{2\log(2M/\delta)}{n}}\) ;
  • (ii) pour la perte quadratique, l'argument de la « progression » améliore le prix en \(\frac{2\log M}{n} + \sqrt{\ldots}\) (ordre \(\log M/n\)) — forme sharp due à Catoni, Tsybakov ; c'est le régime atteint par le mirror averaging (ch. 10, Lounici 2007).
(i), preuve complète en trois pas. Convexité : \(\ell\) convexe en la prédiction et les \(\pi_j\) somment à 1, donc (Jensen conditionnellement aux poids) : $$L(\tilde f) \;\leq\; \sum_j \pi_j \hat L(f_j) + \max_j \big|L(f_j) - \hat L(f_j)\big| \;\leq\; \min_j \hat L(f_j) + \max_j \big|L(f_j) - \hat L(f_j)\big|.$$ Uniformisation : chaque \(\hat L(f_j)\) est une moyenne de v.a. bornées i.i.d. ; Hoeffding (thm 2.3) + union bound (prop. 0.1) sur \(j \leq M\) donnent, avec probabilité \(1-\delta\), \(\max_j |L - \hat L| \leq \sqrt{\log(2M/\delta)/(2n)}\). Retour au vrai risque : sur cet événement, \(L(\tilde f) \leq \min_j \hat L(f_j) + \sqrt{\frac{\log(2M/\delta)}{2n}} \leq \min_j L(f_j) + 2\sqrt{\frac{\log(2M/\delta)}{2n}}\), et \(2\) fois la racine est exactement \(\sqrt{2\log(2M/\delta)/n}\).∎
Proposition 9.4 — Validation croisée comme agrégation (énoncé) La validation croisée \(K\)-fold (module Machine Learning, chapitre 9) est une agrégation (MS) robuste : le risque du modèle sélectionné \(\hat j_{\mathrm{CV}}\) satisfait des inégalités oracle de même type, avec \(M\) remplacé par le nombre de candidats et une correction du biais de validation (l'échantillon d'apprentissage est de taille \(n(1-1/K)\)) ; la règle « une erreur standard » (prendre le modèle le plus parcimonieux dans la barre d'erreur du minimum CV) est l'analogue empirique du compromis d'approximation/estimation de la prop. 1.2. Bornes de type thm 9.3 pour la CV : la sélection par validation croisée hérite d'inégalités oracle du même type — littérature de l'agrégation et de la prédiction séquentielle (Cesa-Bianchi et Lugosi, 2006). 
import numpy as np
rng = np.random.default_rng(8)

n, M = 400, 12
x = rng.uniform(-2, 2, n); y = np.sin(2*x) + 0.3*rng.standard_normal(n)
cible = lambda z: np.sin(2*z)

dico = [lambda z, d=d: np.polyval(np.polyfit(x, y, d), z) for d in range(1, M+1)]
pertes = np.array([np.mean((f(x) - y)**2) for f in dico])   # risque empirique

eta = 20.0
pi = np.exp(-eta*n*(pertes - pertes.min())); pi /= pi.sum()
agg = lambda z: sum(w*f(z) for w, f in zip(pi, dico))

z = np.linspace(-2, 2, 400)
risque = lambda f: np.mean((f(z) - cible(z))**2)
print("meilleur modele :", int(np.argmin(pertes))+1,
      f"risque {risque(dico[int(np.argmin(pertes))]):.4f}")
print(f"agrege exponentiel : risque {risque(agg):.4f}")
print("poids (3 premiers) :", np.round(pi[:3], 3))
PAC-bayésien : le pont Les poids exponentiels sont une loi a posteriori ; les bornes PAC-baysiennes controlent directement \(L(\tilde f)\) contre la moyenne pondérée des risques, avec un terme de divergence KL(poids, prior) au lieu de \(\log M\) — d'où des priors structurés (sparce : reconstruction de vitesses \(\log p\) sans condition de design) : c'est l'axe d'Alquier et Lounici (ch. 10). Cette littérature relie le choix de modèle bayésien et l'agrégation fréquentiste en une seule inégalité.

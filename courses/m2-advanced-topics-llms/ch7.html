7.1 Le LLM « nu » face aux graphes sérialisés

Résultat pivot — NLGraph (Wang et al., 2023) 29 370 problèmes en langage naturel couvrant 8 tâches (connectivité, plus court chemin, plus grand ensemble indépendant… jusqu'au chemin hamiltonien et au flux max), difficulté croissante (taille de graphe, nombre d'étapes). GPT-3/GPT-4 dépassent nettement le hasard sur les tâches faciles… et s'effondrent sur les dures ; les auteurs proposent Build-a-Graph (expliciter le graphe dans le prompt) et un graph translator (convertir la sortie en structure), qui améliorent — sans combler l'écart avec des algorithmes de quelques lignes. Conclusion mesurée : les LLMs ont une intuition graphique préliminaire, pas une compétence algorithmique.
Proposition 7.1 — L'encodage est une variable première (Fatemi et al., 2024) « Talk like a Graph » étudie systématiquement comment sérialiser un graphe : listes d'arêtes, matrice, relations incidentes, ordonnancement par degré, etc. Résultats : (i) le choix d'encodage déplace la précision de dizaines de points — plus que le choix du modèle dans certaines tranches ; (ii) l'ordre par degré aide globalement ; (iii) la performance décroît avec la taille du graphe bien plus vite qu'avec la longueur du texte — c'est la structure, pas la longueur, qui coûte. Bilan pratique : sérialiser un graphe est un acte de conception d'ingénierie (et de recherche), pas une formalité.

7.2 Hybrider : GNN-encodeur + LLM-décodeur

Définition 7.2 — G-Retriever (He et al., NeurIPS 2024) Pour répondre sur un grand graphe textuel (scènes, cartes de connaissances) : (1) retrouver le sous-graphe pertinent en formulant la récupération comme un arbre de Steiner à collection de prix (PCST — les nœuds « pertinents » ont des prix, les arêtes des coûts : maximiser prix − coût du sous-arbre connecté) ; (2) encoder le sous-graphe par un GNN (message passing — module Graph ML ch. 5) ; (3) injecter les embeddings de nœuds comme soft tokens dans le LLM (adaptateur appris) ; (4) fine-tuning conjoint. Effets rapportés : meilleures réponses et hallucinations réduites sur ExplaGraphs/SceneGraphs/WebQSP, scalable à des graphes de centaines de milliers de nœuds (on n'envoie jamais le graphe entier dans le prompt).

Analyse critique — séance LLGA par excellence (i) Benchmarks : NLGraph et consorts sont petits et synthétiques ; les « graphes d'entreprise » réels sont bruités, attribués, dynamiques — le gouffre est grand. (ii) Coût du prompt : sérialiser \(G=(V,E)\) coûte \(\mathcal{O}(|V| + |E|)\) tokens — un graphe modeste de 105 arêtes sature toute fenêtre (ch. 2) : la compression (résumés, sous-graphes, PCST) n'est pas optionnelle. (iii) Évaluation circulaire : juger les réponses graphiques par LLM-judge (ch. 9) — un LLM est-il juge de ce qu'il sait à peine faire ? (iv) Question ouverte LLGA : quelle part des tâches « LLM × graphe » se réduira à long contexte + bonnes données (ch. 2-3), et quelle part exigera un vrai composant structurel (GNN) ? C'est la question de recherche du master — chacun de vos projets de P3/M2 peut y contribuer. 
# Meme tache, trois encodages : l'experience "talk like a graph" en 10 lignes
def enc_edges(G):     return "\n".join(f"{u} -- {v}" for u, v in G.edges())
def enc_degree(G):    # arêtes triées par degré décroissant des extrémités
    d = dict(G.degree())
    es = sorted(G.edges(), key=lambda e: -(d[e[0]] + d[e[1]]))
    return "\n".join(f"{u} -- {v}" for u, v in es)
def enc_incident(G):
    return "\n".join(f"{u} : " + ", ".join(map(str, G[u])) for u in G)

for enc in (enc_edges, enc_degree, enc_incident):
    acc = run_gpt(enc(G), task="connectivite", n=100)
    print(f"{enc.__name__:14s} acc={acc:.2f}  tokens~{len(enc(G))//4}")

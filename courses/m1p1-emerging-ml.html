0. Rappels : SGD et son analyse

Rappels L3/M1 — le socle stochastique
  • Descente de gradient : \(\theta_{t+1} = \theta_t - \eta \nabla f(\theta_t)\) ; convexe \(L\)-lisse ⇒ décroissance \(\mathcal{O}(1/t)\).
  • SGD : on remplace \(\nabla f\) par un gradient de batch \(g_t = \frac1m \sum_{i \in B_t} \nabla \ell(\theta_t; x_i)\), non biaisé, \(\mathrm{Var}(g_t) = \mathcal{O}(1/m)\) (TCL, cf. Refresher Statistics).
  • Convexité forte : \(f(\lambda x + (1-\lambda)y) \leq \lambda f(x) + (1-\lambda) f(y) - \tfrac{\mu}{2}\lambda(1-\lambda)\|x - y\|^2\) ⇒ convergence linéaire en déterministe, \(\mathcal{O}(1/t)\) en stochastique.
Proposition 0.1 — Taux SGD (convexe, L-lisse, variance \(\sigma^2\)) Avec pas \(\eta_t \propto 1/t\) ou constant bien réglé : $$\mathbb{E}\big[f(\bar\theta_T)\big] - f^\star \;\leq\; \mathcal{O}\Big(\frac{L}{T} + \frac{\sigma}{\sqrt T}\Big).$$ Le terme en \(1/\sqrt T\) est le « plancher statistique » : c'est lui qui dicte les compromis en distribution (chapitre 2).

1. Panorama des sujets émergents

Ce module ouvre sur les questions qui structurent la recherche et l'industrie actuelles, en préparation directe des modules M2 (LLMs, Explainability/Security/Privacy) :

  • Scaling laws : perte en loi de puissance selon données/paramètres/compute (Kaplan 2020, Hoffmann/Chinchilla 2022) ; émergence de capacités ; le compute comme ressource rare ;
  • Entraînement distribué des grands modèles : data/tensor/pipeline parallelism, MoE ;
  • Fine-tuning économe : LoRA et adaptateurs — la « collaboration » entre un gros modèle central et des usages locaux ;
  • Fiable ? Robustesse aux clients malveillants, privacy des données d'entraînement, équité entre participants — les trois fils rouges des chapitres 4-6 ;
  • Agents collaboratifs : orchestration multi-agents = collaboration de modèles (lien direct avec RL & Autonomous Agents et le « graph engineering »).

2. Apprentissage distribué

Définition 2.1 — SGD distribué (workers synchrones) \(K\) workers détiennent des shards de données. À chaque pas : chaque worker \(k\) calcule \(g^{(k)}\) sur son mini-batch, le serveur agrège et diffuse : $$\theta_{t+1} = \theta_t - \eta \, \frac1K \sum_{k=1}^K g_t^{(k)}.$$ La variance de l'agrégat décroît en \(1/(Km)\) : « linear speedup » idéal — \(T\) pas distribués ≈ \(KT\) pas locaux.
  • Le mur de la communication : envoyer un gradient de \(10^9\) paramètres coûte plus cher que de le calculer. Solutions : quantification (1-bit SGD), gradient sparsification (top-k, error feedback), périodes de communication (local SGD) ;
  • Asynchronisme : staleness des gradients, Hogwild!, bornes de convergence dégradées d'un facteur de retard ;
  • Parallélisme de modèle : le modèle ne tient pas sur un GPU — pipeline/tensor parallelism, ZeRO (sharding des états d'optimiseur).
Lien LLM Un entraînement type LLM mobilise des milliers de GPU : les choix data-parallel vs pipeline vs tensor sont des choix d'algèbre et de communication — sujets de TP dans ce module, approfondis en M2 (ML Ops).

3. Apprentissage fédéré

Algorithme 3.1 — FedAvg (McMahan et al., 2017) Clients \(\{1..K\}\) avec données locales \(\mathcal{D}_k\) non iid (chacun ses données, jamais partagées). À chaque round :
  1. le serveur diffuse \(\theta_r\) à un sous-ensemble de clients ;
  2. chaque client \(k\) fait \(E\) époques de SGD local : \(\theta_r^{(k)} \approx \arg\min F_k\) ;
  3. agrégation pondérée : \(\theta_{r+1} = \sum_k \tfrac{n_k}{n}\, \theta_r^{(k)}\).
  • Hétérogénéité (non-iid) : les optima locaux divergent (client drift) ; correctifs : FedProx (pénalité proximale), SCAFFOLD (correction de variance), FedAdam (agrégation adaptative) ;
  • Convergence : sous convexité, taux dégradés d'un facteur d'hétérogénéité \(\Gamma = \sum_k \tfrac{n_k}{n}(F_k^\star - F^\star)\) ;
  • Cas d'usage LLGA : banques/hôpites (données sensibles non centralisables), claviers mobiles, flottes de terminaux ; fédérer des adaptateurs LoRA de LLMs est un sujet de recherche ouvert.

4. Robustesse byzantine

Définition 4.1 — Client byzantin Un client est byzantin s'il renvoie un gradient arbitraire (panne ou attaque : data poisoning, model poisoning, backdoor). Objectif : converger malgré \(f < K/2\) (voire \(f < K/3\)) clients malveillants.
Algorithmes robustes
  • Coordinate-wise median / trimmed mean : médiane (ou moyenne tronquée \(\beta\)) coordonnée par coordonnée — robuste à \(f < K/2\) en dimension modérée ;
  • Krum (Blanchard et al., 2017) : garder le gradient dont la somme des \(K - f - 2\) plus petites distances aux autres est minimale ;
  • GAR géométriques : géomédiane (Weiszfeld), filtrage par angles ;
  • Garanties : borne d'erreur \(\mathcal{O}(\sigma\sqrt{d/K} + \|F\|))\) avec \(\|F\|\) la norme du « bon » gradient — la robustesse a un prix en dimension (fléau de la dimension byzantin).
Expérience TP — attaque et défense 
grads = np.array([...])                 # K gradients honnet
attacker = 10 * np.linalg.norm(grads, axis=1).mean() * rng.standard_normal(d)
all_g = np.vstack([grads, attacker])   # 1 client byzantin

mean_g   = all_g.mean(0)               # CVE : un seul attaquant suffit
median_g = np.median(all_g, axis=0)    # robuste
print(np.linalg.norm(mean_g - grads.mean(0)),
      np.linalg.norm(median_g - grads.mean(0)))
Sans défense, un seul gradient empoisonné déplace la moyenne d'autant qu'on veut ; la médiane reste proche du vrai gradient.

5. Privacy différentielle

Définition 5.1 — \((\varepsilon, \delta)\)-différentielle privacy (Dwork) Un algorithme randomisé \(\mathcal{A}\) est \((\varepsilon,\delta)\)-DP si pour tous jeux de données \(D \sim D'\) differing on one element : $$\mathbb{P}[\mathcal{A}(D) \in S] \;\leq\; e^\varepsilon\, \mathbb{P}[\mathcal{A}(D') \in S] + \delta.$$ \(\varepsilon\) petit ⇒ la sortie change à peine si un individu change — garantie calculable, composable (les DP s'additionnent).
Algorithme 5.2 — DP-SGD (Abadi et al., 2016)
  1. clipper chaque gradient par exemple : \(\tilde g_i = g_i / \max(1, \|g_i\|_2/C)\) ;
  2. bruiter le batch : \(\tilde g = \frac1m\big(\sum_i \tilde g_i + \mathcal{N}(0, \sigma^2 C^2 I)\big)\) ;
  3. faire le pas SGD avec \(\tilde g\). Le privacy budget \(\varepsilon\) se dépense à chaque accès aux données (moments accountant).
Compromis fondamental : utility \(\leftrightarrow\) privacy \(\leftrightarrow\) nombre de données (le bruit est moyenné sur \(n\) grands).
Pourquoi LLGA s'y intéresse Les LLMs mémorisent des fragments d'entraînement (extraction attacks) ; l'entraînement DP est une défense ; la confidentialité des graphes (node-DP, edge-DP) protège les réseaux sociaux ; le module M2 « Explainability, Security, Privacy of LLMs » prolonge exactement ce chapitre.

6. Collaboration, personalisation, équité

  • Personnalisation : un modèle global + des têtes locales (fine-tuning léger par client) ; interprétation bayésienne (mélange de posteriors) ;
  • Apprentissage collaboratif décentralisé : gossip sur graphe de communication (chaque client ne parle qu'à ses voisins — convergence liée au spectre du graphe, lien avec le module Graph ML) ;
  • Équité : performance par sous-groupes (demographic parity, equalized odds) ; en fédéré, l'équité croise les clients ; le module Computational Optimal Transport donne des outils (barycentres, fairness via OT) ;
  • Vers les systèmes multi-agents : quand les « workers » deviennent des agents LLM, la collaboration devient orchestration (rôles, votes, vérification) — la boucle est bouclée avec le module RL & Autonomous Agents.

Exercices

  1. Variance du batch. Montrer que la variance du gradient de batch de taille \(m\) est \(\sigma^2/m\), et en déduire le « linear speedup » de la SGD distribuée (avec \(K\) workers, mêmes pas, mêmes itérations : erreur \(\sigma/\sqrt{Km}\)).
  2. FedAvg = SGD quand \(E = 1\). Vérifier que FedAvg avec une seule époque locale redonne exactement la SGD distribuée, puis simuler le client drift sur des données quadratiques hétérogènes (\(F_k\) de minimiseurs différents) pour \(E \in \{1, 5, 20\}\).
  3. Médiane robuste. Montrer que si \(f < K/2\) gradients sont arbitraires, la médiane coordonnée par coordonnée reste à distance bornée de la médiane des gradients honnêtes, contrairement à la moyenne (donner une attaque explicite sur la moyenne).
  4. DP du counting query. Pour la requête « combien d'individus ont la propriété \(P\) ?», montrer que la release \(q(D) + \mathrm{Lap}(1/\varepsilon)\) est \(\varepsilon\)-DP (sensibilité 1), et calculer l'erreur typique.
  5. Gossip. Simuler l'agrégation gossip \(\theta^{(k)} \leftarrow \theta^{(k)} + \gamma \sum_{j \in \mathcal{N}(k)}(\theta^{(j)} - \theta^{(k)})\) sur un cycle puis sur un graphe complet ; relier la vitesse au second coefficient propre du laplacien (spectre = module Graph ML).

11. Graphes × LLMs : GraphRAG et l'hybride

11.1 — Le pipeline GraphRAG industriel complet (d'après Edge et al., 2024)
  1. ingestion : découpage du corpus en morceaux (chunks) ; extraction par LLM des entités (NER) et relations (extraction de relations typées, cf. module NLP) au format triplet (sujet, relation, objet, passage source) ; résolution d'entités (aliases) ; le graphe se construit incrémentalement — chaque arête garde sa ou ses sources ;
  2. communautés : détection de communautés (Leiden — variante Louvain, ch. 0) sur le graphe d'entités ; pour chaque communauté (à chaque niveau de la hiérarchie), un LLM résume les entités, relations et thèmes ; les résumés s'agrègent de bas en haut ;
  3. index hybride : le graphe plus un index vectoriel des chunks et des résumés (le RAG classique reste utile pour les requêtes locales) ;
  4. requêtes globales (« quels sont les thèmes majeurs du corpus ? ») : map-reduce sur les résumés de communautés — chaque communauté répond partiellement, un LLM synthétise ; requêtes locales (« qui travaille avec qui sur X ? ») : élargissement du voisinage de l'entité X (entités liées, chunks sources) puis réponse ancrée ;
  5. évaluation : comparaison texte vectoriel RAG vs GraphRAG sur la complétude et la diversité des réponses ; coût : l'ingestion LLM est chère — amortie par des milliers de requêtes.
Lecture LLGA : chaque étage est un objet du cours — clustering (ch. 0), link prediction pour la complétion du KG (ch. 6), embeddings pour l'index vectoriel (ch. 3), échangeabilité des résumés (génération, ch. 9).
11.2 — Faire raisonner le LLM sur le graphe : encodage et pseudo-code
  • sérialisation : décrire le (sous-)graphe en texte (listes d'arêtes, adjacence, incidents) ; le benchmark NLGraph (Wang et al., 2023) montre que les LLMs échouent sur des tâches élémentaires (cycles, connexité, plus courts chemins) dès que la taille croît, même en few-shot ; l'étude « Talk like a Graph » (Fatemi et al., 2024) compare les encodages — aucun ne domine partout ;
  • pseudo-code prompting (Skianis, Nikolentzos & Vazirgiannis, 2024 — équipe du master) : fournir au LLM l'algorithme en pseudo-code plutôt qu'une description en langue ; 
    entree : liste d'aretes E, noeud s
visites = {s} ; pile = [s]
tant que pile non vide :
    v = pile.pop()
    pour u in voisins(v) dans E :
        si u non dans visites : visites.ajouter(u) ; pile.push(u)
sortie : visites   # composante connexe de s
    le LLM exécute la trace — gains systématiques par rapport aux instructions naturelles, toutes familles de LLM confondues ; la leçon : sur les structures discrètes, le langage de programmation est un meilleur « prompt » que le langage naturel ;
  • hybrides GNN + LLM : le GNN encode la structure (ch. 5) et injecte : (a) soft tokens dans le prompt (projeter les embeddings de GNN dans l'espace du LLM) ; (b) rappel structurel — le GNN retrouve les passages reliés (comme le KG de 11.1, mais appris) ; (c) distillation croisée — le LLM annoté entraîne le GNN, le GNN filtre les hallucinations du LLM.
11.3 — Limites et hygiène GraphRAG
  • l'extraction hallucine (entités inexistantes) : contrôler par double-passe et ancrage sur chunks ;
  • le graphe est une approximation — les requêtes dépendent de sa qualité ; blinder par KGC (ch. 6) avant de requêter ;
  • le coût d'ingestion vs le gain sur les requêtes relationnelles : pour un FAQ mono-document, le RAG vectoriel suffit ; GraphRAG paie quand les questions sont multi-sauts, agrégatives ou globales ;
  • privacy : le graphe agrège des faits dispersés — risque de réidentification (M2, ch. 7).
  • Agents sur graphes : le plan d'un système multi-agents est un graphe (DAG d'orchestration) ; le « graph engineering » (2026) = programmer la topologie des agents — la boucle master : le graphe dans le modèle (attention), le graphe pour le modèle (RAG), le graphe entre les modèles (agents).
TP final Construire un mini-GraphRAG : 1) extraire d'un corpus d'entreprise (rapports, e-mails simulés) un graphe d'entités avec un LLM ; 2) détecter les communautés (Leiden) et résumer par LLM ; 3) répondre à des questions relationnelles (« qui travaille avec qui sur X ? ») par parcours de graphe vs. par RAG vectoriel vs. par pseudo-code prompting (11.2) ; 4) comparer fidélité, coût en tokens et latence.

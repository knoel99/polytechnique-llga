1. Pourquoi les graphes ?

Les données du monde réel sont relationnelles : la structure porte une information que les méthodes iid ignorent. Les réseaux sociaux (amitiés), les molécules (liaisons), les réseaux de transactions (fraude !), les graphes de connaissances d'entreprise (clients, produits, processus), les réseaux informatiques, les grappes de citations, les ontologies juridiques… Tous sont naturellement des graphes, souvent hétérogènes (nœuds/arêtes typés : « achète », « possède », « travaille avec ») et dynamiques (arêtes horodatées : transactions seconde par seconde). Typiquement aussi : peu d'étiquettes (quelques dizaines de nœuds annotés sur des millions) — le régime semi-supervisé du ch. 5 — et des distributions biaisées par l'échantillonnage (les arêtes observées ne sont pas un échantillon uniforme des interactions).

Le positionnement LLGA Les LLMs excellent sur le texte mais peinent sur : les relations structurées, la fidélité factuelle (hallucinations), et les données non textuelles. Les graphes comblent exactement ces manques :
  • GraphRAG : connecter le LLM à des données propriétaires structurées — l'approche la plus efficace aujourd'hui pour fiabiliser un LLM en entreprise (ch. 11) ;
  • GNN + LLM : IA générative sur données structurées (générer des molécules, des plans, des recommandations) ;
  • Applications industrielles : pharma/biotech (molécules = graphes), finance (réseaux de transactions, risque systémique), recommandation, supply chain, systèmes multi-agents (les workflows d'agents sont des DAG — module RL).
Fil rouge du master Trois places du graphe dans l'IA générative : dans le modèle (l'attention des transformers est un graphe dynamique complet — module Deep Learning), pour le modèle (GraphRAG, encodage structurel — ch. 11), entre les modèles (orchestration d'agents = programmation de DAG). Ce module pose les fondations des trois ; le module M2 « Advanced GNN » prolonge chacune.

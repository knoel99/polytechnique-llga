0. Background: from word2vec to transformers

Prerequisites (M1 modules)

  • Embeddings (NLP ch. 3): word2vec/GloVe — a word = a static vector, derived skip-gram loss and negative sampling;
  • Attention & transformers (Deep Learning ch. 6): \mathrm{softmax}(QK^\top/\sqrt{d_k})V, multi-head, residuals, LayerNorm; the “token graph” reading; BERT/GPT seen as applications (NLP ch. 7);
  • Retrieval (NLP ch. 2): TF-IDF and BM25 — the baselines of this module’s retrieval (ch. 7); SBERT sentence embeddings (NLP ch. 7) for dense search;
  • RL (RL module): policies, policy gradients, PPO (ch. 4 of the RL module — the engine of alignment, ch. 5), bandits (ch. 6);
  • Cross-entropy and perplexity (ML ch. 3, NLP ch. 0): the pre-training loss is exactly maximum likelihood of the next token; \mathrm{PPL}=\exp(\mathcal{L}) in base e.

The trajectory: n-grams → static embeddings → recurrent networks (LSTM) → attention (Bahdanau 2014) → transformer (Vaswani 2017) → BERT/GPT (2018-2019) → scaling (GPT-3, 2020) → alignment (InstructGPT 2022, RLHF) → general-purpose, multimodal, reasoning and agentic LLMs (2023-2026). This module covers every technical stage of this stack, from the tokenizer (ch. 1) to safety (ch. 9), proving results that M1 left as claims.

Module methodology Each chapter alternates proved theory (thm/prop boxes with proofs) and labs (nanoGPT, toy DPO, RAG, agent). The “NLP ch. N” references point to the M1 module Introduction to Text Mining and NLP, of which this course is the direct continuation: tokenization (NLP ch. 1 → ch. 1), BM25 (NLP ch. 2 → ch. 7), sentence embeddings (NLP ch. 7 → ch. 7), transformers (NLP ch. 7 → ch. 2).

1. Tokenization

Concrete scene: the same FR vs EN prompt on a Llama-style tokenizer. French typically costs 15–25% more tokens; your context budget melts, and a rare word splits into 6 subwords — the model “understands” less and bills more. This chapter fixes BPE / WordPiece / Unigram before architecture.

What breaks Mixing train/inference tokenizers; ignoring multilingual cost (latency + $); treating UNK as a detail. All three sabotage a prod RAG as much as a nanoGPT lab.

Definition 1.1 — Byte-level BPE: the exact construction BPE (proved step by step in NLP ch. 1) starts here from the alphabet of 256 bytes: any Unicode string can be represented without an “unknown” symbol. Learning loop: \mathrm{merge}^{(k)} = \arg\max_{(a,b)}\; f(a,b),\qquad f(a,b)=\sum_{w}\mathrm{freq}(w)\,n_{(a,b)}(w), where n\_{(a,b)}(w) counts the occurrences of the adjacent pair (a,b) in word w (counting weighted by word frequency); the merge is applied everywhere and one starts again until \|V\| (32k-128k). Encoding a new text replays the merges in the learned order (GPT-2/4, Llama); WordPiece (BERT) maximizes \\frac{f(x,y)}{f(x)f(y)}, Unigram (T5) learns a generative model by EM then segments with Viterbi (NLP ch. 1.2).

Vocabulary, compression, multilingual costs The compression rate (characters/token) depends on the vocabulary and the language: vocabularies trained on English compress English well (~4 characters/token) but degrade other languages. Orders of magnitude measured in the lab: with GPT/Llama-type tokenizers, the same French text costs typically 15 to 25% more tokens than in English; for poorly represented non-Latin scripts, the factor can reach 3× or more (each rarely seen character decomposes into bytes). Direct consequences: API cost (billed per token), context length consumed, and inequality of quality. Llama 3 raised the vocabulary to 128k tokens — a large part of the gain serves non-English languages; GPT-4o (o200k) claims up to ~1.4× to ~4× fewer tokens depending on the language compared to the previous generation. Exercise 1 measures all this on your own texts.

Special tokens and security Special tokens (<|endoftext|>, <|im_start|>, template roles) delimit turns and documents. If the decoder accepts them in user input, an attacker can inject a fake dialogue turn or prematurely terminate a document (boundary confusion) — defense: systematically re-encode input and neutralize special tokens (encode_ordinary, the allowed_special flag of tiktoken), never raw string concatenation around the prompt. This class of attacks returns in ch. 9 (prompt injections).

import tiktoken
enc = tiktoken.encoding_for_model("gpt-4o")
okapi = tiktoken.encoding_for_model("gpt-3.5-turbo")   # cl100k vocabulary

fr = "Les graphes pour les LLMs : une révolution pour la recherche d'information."
de = "Donaudampfschifffahrtsgesellschaftskapitän"
for s in (fr, de, "1234 + 5678 = ?"):
    print(len(okapi.encode(s)), "vs", len(enc.encode(s)), "->", s[:40])

# "safe" tokenization: special tokens are NOT decoded by default
b = enc.encode("fin <|endoftext|> suite", allowed_special=set())
print("ids :", b, "| decode round-trip ok :", enc.decode(b))

Why it matters (M1 recall) Tokenization governs cost (length in tokens), biases (fuzzy arithmetic because “123 + 456” tokenizes poorly), multilinguality (the extra cost measured above) and real vulnerabilities (special tokens). Systematic diagnosis in the lab with tiktoken / tokenizers. For adapting an LLM to a low-resource language — vocabulary, template, data — ch. 10 presents Shang’s work (Atlas-Chat, Nile-Chat).

2. The architecture in depth

Definition 2.1 — The decoder block An LLM stacks N blocks: x \leftarrow x + \mathrm{MHA}(\mathrm{LN}(x)), \qquad x \leftarrow x + \mathrm{MLP}(\mathrm{LN}(x)), with causal attention (triangular mask: token i sees only j \\leq i), grouped heads (grouped-query attention for inference), a gated MLP (SwiGLU, ~4× expansion), RoPE positional embeddings (rotations; relative generalization to long contexts), and a final LN.

Proposition 2.2 — Pre-norm vs post-norm: the gradient flow Post-LN (original transformer): x\_{l+1}=\\mathrm{LN}(x_l+F(x_l)) — each block renormalizes the residual itself; the gradient of x_L to x_0 crosses L LN Jacobians whose product decays/explodes exponentially with L: warmup mandatory, fragile depth. Pre-LN (GPT-2+, all modern LLMs): x\_{l+1}=x_l+F(\\mathrm{LN}(x_l)) — the residual path is the identity: \frac{\partial x_L}{\partial x_l} = I + \sum_{l'\,\>\,l}\frac{\partial F_{l'}}{\partial x_l} → a gradient that reaches every layer without multiplicative attenuation: stable training without fine warmup. Price: the norm \\\|x_l\\\| grows with depth (additive contributions), hence the final LN. (Xiong et al., ICML 2020.)

Theorem 2.3 — RoPE derived (Su et al., 2021) Position is injected by rotation: the dimension-d vector is viewed as d/2 2D pairs; pair i of the token at position m undergoes R(m\\theta_i) with \\theta_i = 10000\^{-2i/d}: R(\varphi)=\begin{pmatrix}\cos\varphi & -\sin\varphi\ \sin\varphi & \cos\varphi\end{pmatrix}, \qquad q^{(i)}_m = R(m\theta_i)\,q^{(i)},\quad k^{(i)}_n = R(n\theta_i)\,k^{(i)}.

Proof. Relative property: the dot product of a pair depends only on the difference of positions: \\langle q\^{(i)}\_m,k\^{(i)}\_n\\rangle = q\^{(i)\\top} R(m\\theta_i)\^\\top R(n\\theta_i)\\, k\^{(i)} = q\^{(i)\\top} R\\big((n-m)\\theta_i\\big)\\,k\^{(i)}, since 2D rotations commute and R(a)\^\\top R(b)=R(b-a). Summing over pairs = an attention score depending on (n-m) and the contents — a “soft” generalization of relative embeddings. Practical bonus: to extend the context, one interpolates the angles (m\\to m/L) instead of relearning. ∎

Proposition 2.4 — MQA/GQA: the memory arithmetic of the KV-cache The cache stores keys and values of all past tokens: \text{bytes/token} = 2\ (\text{K and V}) \times N_{\text{layers}} \times n_{\text{KV heads}} \times d_{\text{head}} \times \text{bytes/element}. Multi-Query Attention (Shazeer, 2019): a single shared KV head; Grouped-Query (Ainslie et al., 2023): n\_{\\text{KV}} \< n\_{\\text{heads}} — e.g. Llama-3-8B: 32 heads, 8 KV heads, 32 layers, d\_{\\text{head}}=128, fp16 → 2\\times32\\times8\\times128\\times2 = 128\\,\\text{KiB/token}; a 100k-token context ≈ 12.8 GB of cache (versus ~51 GB with full attention — a 4× reduction, nearly identical quality). This is THE lever of long context (ch. 6).

Mixture-of-Experts (MoE): routing and balancing Each MLP block is replaced by E experts \\{E_i\\}; a router g(x)=\\mathrm{softmax}(W_g x) activates only the top-k: y = \sum_{i\in \mathrm{top}\text{-}k} g_i(x)\,E_i(x), \qquad \#\text{active params} \ll \#\text{total params}. Capacity decorrelated from inference cost (Switch Transformer: Fedus et al. 2021; DeepSeek-V3: 671B total, ~37B active). Trap: routing collapse — the winning experts attract everything. Auxiliary balancing loss (Switch): \mathcal{L}_{\text{aux}} = \alpha\, E \sum_{i=1}^{E} f_i\,P_i, f_i = fraction of tokens routed to i, P_i=\\frac{1}{T}\\sum_t g_i(x_t) = mean router probability; minimum reached at the uniform distribution (f_i=P_i=1/E) — zero penalty iff the router is balanced and confident. Modern variants: fine experts + shared experts, balancing without an auxiliary loss (dynamically adjusted bias, DeepSeek-V3).

Efficient attention: FlashAttention and IO complexity Exact attention costs \\mathcal{O}(n\^2) compute but is dominated in practice by input/output: the naive implementation writes the n\\times n matrix to HBM (large, slow memory). FlashAttention (Dao et al., 2022): exact tiled computation that fits in SRAM, “online” softmax with an accumulator (running max m and sum \\ell updated per tile: m\_{\\text{new}}=\\max(m,x), \\ell\_{\\text{new}}=e\^{m-m\_{\\text{new}}}\\ell+e\^{x-m\_{\\text{new}}}) — the n\^2 matrix is never materialized; HBM reads reduced from \\Theta(n\^2) to \\Theta(n\^2d\^2/M) (M = SRAM size). The general lesson: optimize memory access, not just FLOPs (cf. Signal Processing module for the memory hierarchy).

Beyond: SSM/Mamba (state equation sketch) A state-space model discretizes a linear system x'(t)=Ax(t)+Bu(t),\\ y=Cx: x_k = \bar A x_{k-1} + \bar B u_k,\qquad y_k = C x_k,\qquad \bar A = e^{\Delta A},\ \bar B \approx \Delta B, computable in \\mathcal{O}(n) by a scan (no n\^2 matrix). The selectivity of Mamba (Gu & Dao, 2023): \\bar B, C, \\Delta depend on the input → content-dependent (selective forgetting), which yields attention quality at linear cost. SSD duality (Mamba-2, 2024): the same computation rewrites as y_k=\\sum\_{s\\le k} C_k\^\\top\\big(\\prod\_{s\<k'}\\bar A\\big)\\bar B_s\\,u_s — a “attention” with a causal kernel; hence the attention+SSM hybrid architectures. Continued in ch. 8.

  • Parameters: where are they? embedding (\|V\| \\times d), attention (4d\^2/block), MLP (8d\^2/block, ~12d\^2/block with SwiGLU) — the rule \\#\\text{params} \\approx 12 N d\^2 and the training memory cost (parameters + Adam + activations + gradients: ~20 bytes/parameter in mixed precision; cf. ch. 3 for actual compute);
  • LLGA bridge: attention is message passing on a token graph (Graph ML module ch. 2, Advanced GNN); graph transformers inherit from it.

3. Pre-training

Pre-training objectives

  • Causal modeling (CLM) — GPT: \mathcal{L} = -\sum_t \log p_\theta(x_t \mid x_{\<t}) — predict the next token; generative by construction;
  • Masked modeling / denoising (MLM) — BERT (NLP ch. 7): mask ~15% and predict (bidirectional); excellent for encoding (classification, retrieval), does not generate;
  • Span corruption / text-to-text — T5: mask spans and regenerate them; everything is formulated as sequence→sequence.

3.1. The data pipeline: quality, filtering, deduplication

  • Curation: web → rule-based filtering (length, code/punctuation ratio, languages), then model-based filtering (quality classifiers trained on reference pages — e.g. distilled judges); controlled mixture (web, code, books, articles, mathematics, synthetic data generated then filtered);
  • MinHash-LSH deduplication (proved in NLP ch. 8.3): k-gram shingles → MinHash signatures (a min-hash collision has probability equal to the Jaccard similarity) → LSH bands/ranks with \\mathbb{P}\_{\\text{detect}}(J)=1-(1-J\^r)\^b → remove near-duplicates down to a threshold. At scale: tens of TB of text, approximately linear clustering; measured effect: less memorization, better benchmark (deduplicating is regularizing — LLMs learn duplicates “twice”);
  • Mixtures and curriculum: per-domain proportions (annealing: raise quality/lower web at the end of training); easy→hard ordering (by perplexity) improves compute efficiency — demonstrated at scale by Shang (ch. 10, “Beyond Random Sampling”);
  • Multilingual: balancing per language (otherwise the tokenizer and the model drift toward English — cf. ch. 1 and 10).

3.2. Scaling laws: decomposition and the Chinchilla optimum

Combined law (Hoffmann et al. 2022, “Chinchilla”) The loss of a model with N parameters trained on D tokens follows, over decades of scale: L(N,D) = E + \frac{A}{N^{\alpha}} + \frac{B}{D^{\beta}}, E = irreducible entropy of natural text; the other two terms = under-capacity and exhausted data (fitted on ~400 training runs; Kaplan et al. 2020 for the L(N)-only version). Reading: one must grow N and D together.

Theorem 3.1 — The compute optimum D\^\\star \\approx 20\\,N, derived At fixed budget C, with \\mathrm{FLOPs}(C) \\approx 6ND (2 per parameter × forward + backward, × D tokens): (N^\star, D^\star) = \arg\min_{N,D}\; L(N,D)\quad \text{s.t.}\quad 6ND = C.

Proof. Lagrangian \\mathcal{J}=E+AN\^{-\\alpha}+BD\^{-\\beta}-\\lambda(6ND-C): \frac{\partial\mathcal{J}}{\partial N}= -\alpha A N^{-\alpha-1}-6\lambda D=0, \qquad \frac{\partial\mathcal{J}}{\partial D}= -\beta B D^{-\beta-1}-6\lambda N=0. Dividing side by side, \\lambda cancels: \frac{\alpha A\,N^{-\alpha-1}}{\beta B\,D^{-\beta-1}} = \frac{D}{N} \;\Longrightarrow\; \frac{\alpha A}{\beta B}\,D^{\beta} = N^{\alpha} \;\Longrightarrow\; \frac{N^{\alpha}}{D^{\beta}} = \frac{\alpha A}{\beta B}. With Chinchilla’s fitted constants (\\alpha\\approx0.34, \\beta\\approx0.28, A\\approx406, B\\approx411): the right-hand side equals \\approx 1.2, and the condition together with 6ND=C gives N\^\\star\\propto C\^{0.46}, D\^\\star\\propto C\^{0.54} — both grow like \\sqrt{C}, and numerically D\^\\star/N\^\\star\\approx 20 tokens per parameter. GPT-3 (300B tokens for 175B params, ratio 1.7) was therefore “undertrained” at its budget. ∎

Compute and real costs (Llama 3, 2024) Orders of magnitude from the Llama 3 technical report (H100 training): 8B / 15T tokens ≈ 1.5M GPU-hours; 70B ≈ 7M; 405B / 15.6T tokens ≈ 30.8M GPU-hours (≈ 3.5 years of a single H100 × 10⁴). At ~2-3 /GPU-hour, the 405B costs \~80-90M of compute — why one “continues” from checkpoints rather than retraining (ch. 6: distillation, LoRA); and why the post-Chinchilla ratio went up: since inference costs daily, one deliberately overtrains small models (Llama-3-8B: 15T tokens ≈ 1900 tokens per parameter, ~100× Chinchilla) — the optimum depends on what is being optimized: the training cost (Chinchilla) or the total cost including inference.

Lab: training a mini-GPT On a Shakespeare-type corpus (~1 MB), train a ~10M-parameter transformer (nanoGPT): 30 minutes of GPU suffice to generate credible text. Observe: the loss curve, the effect of context, the sampling temperature (ch. 6). Extend: do exercise 4 (check the law L(N,D) by regression on the published points).

4. Post-training: SFT and alignment

Step 1 — Supervised Fine-Tuning (instruction tuning) Fine-tune the base model on quality (instruction, response) pairs — a few tens/hundreds of thousands of examples suffice to turn an autocomplete into an assistant. Engineering details: loss mask (the loss is computed only on the response), chat templates, data “distilled” from a large model.

Templates and loss mask — the detail that matters The template serializes the turns: <|system|>…<|user|>…<|assistant|>. The loss masks the prompt tokens (system/user roles) and keeps only the completion — otherwise the model learns to imitate the user and prompt logging becomes noise: \mathcal{L}_{\text{SFT}} = -\sum_{t\,\in\,\text{completion}} \log p_\theta(y_t\mid y_{\<t}, x).

# SFT with loss masking (HF TRL pseudo-code)
from trl import SFTTrainer

def format(example):                    # chat template + masked labels
    prompt  = f"<|user|>\n{example['question']}\n<|assistant|>\n"
    completion = example["answer"]
    return {"prompt": prompt, "completion": completion}
# - the loss is computed ONLY on the completion tokens (TRL SFTTrainer
#   does the masking automatically; in raw PyTorch: labels = -100 on the prompt)

trainer = SFTTrainer(model="meta-llama/Llama-3.1-8B",
                     train_dataset=dataset.map(format), ...)
trainer.train()

# pitfalls seen in the lab: template != inference template -> performance drop;
# padding token confused with eos; overly long answers -> silent truncation

Step 2 — Why alignment beyond SFT? SFT imitates demonstrations; it does not directly optimize “the best response” and does not learn to avoid harmful responses. The central idea of InstructGPT/ChatGPT: learn a human reward, then optimize the policy against that reward (RL) — this is where the M1 RL module becomes the M2’s central tool.

Rejection sampling (best-of-n) An intermediate and indestructible step: generate n responses, keep those that pass a filter (reward model, tests, heuristics), re-fine-tune on them — the Llama 2 recipe between RLHF rounds (Touvron et al., 2023). This is exactly “exploit the best of n”, without policy gradients; the link with bandits (RL module ch. 6) is direct: each draw informs the policy for the next round.

5. RLHF, DPO, GRPO

RLHF — the classic pipeline (Ouyang et al., 2022)

  1. Reward model: train r\_\\phi(x, y) on human preferences (response pairs); Bradley-Terry loss: \mathcal{L} = -\log \sigma\big(r_\phi(x, y^+) - r_\phi(x, y^-)\big).
  2. Policy optimization with PPO (RL module, ch. 4): \max_\theta\ \mathbb{E}\big[r_\phi(x, y)\big] - \beta\, \mathrm{KL}\big(\pi_\theta \| \pi_{\mathrm{SFT}}\big) — the KL term prevents reward hacking and out-of-distribution drift.

Proposition 5.1 — Bradley-Terry, derived If humans compare pairs (y\^+,y\^-) with a probability of preferring y\^+ increasing in the “strength” difference, the axiomatics (transitive binary choice, invariance) imposes a logistic model on the difference of latent scores: \mathbb{P}(y^+ \succ y^- \mid x) = \sigma\big(r(x,y^+)-r(x,y^-)\big), and the log-likelihood of the observed preferences gives the loss above — only the difference of rewards is identifiable (adding a function of x changes nothing); hence the need for the KL penalty to pin down the zero.

Proof. Derivative in r\^+: -\\big(1-\\sigma(r\^+-r\^-)\\big) — the penalty is maximal when the pair is misclassified, zero when the margin is amply positive; it is a logistic regression on reward differences. ∎

PPO for LLMs — the concrete protocol Four models in memory: policy \\pi\_\\theta, reference \\pi\_{\\mathrm{SFT}} (frozen, for the KL), reward r\_\\phi (frozen), critic (value head). Sensitive hyperparameters: \\beta\\in\[0.01,\\,0.2\]; low learning rate (≈ 10× smaller than in SFT); PPO clip \\epsilon\\sim0.2; prompt batch > completion batch. Classic symptoms: KL explodes (β too small); degenerate responses (hacked reward); drifting length (RM verbosity bias). This is chapter 4 of the RL module applied word for word — the prerequisite reading.

Theorem 5.2 — DPO (Rafailov et al., 2023): complete derivation The loss \mathcal{L}_{\mathrm{DPO}} = -\log \sigma\Big(\beta \log\tfrac{\pi_\theta(y^+ \mid x)}{\pi_{\mathrm{SFT}}(y^+\mid x)} - \beta \log\tfrac{\pi_\theta(y^- \mid x)}{\pi_{\mathrm{SFT}}(y^-\mid x)}\Big) optimizes the policy directly on preferences — without a reward model or rollouts.

Proof. Step 1 (closed-form solution of the KL-penalized problem). For fixed x, maximizing \\mathbb{E}\_{y\\sim\\pi}\[r(y)\] - \\beta\\,\\mathrm{KL}(\\pi\\\|\\pi\_{\\mathrm{SFT}}) rewrites as \max_\pi \int \pi(y)\Big[r(y) - \beta\log\frac{\pi(y)}{\pi_{\mathrm{SFT}}(y)}\Big]dy = -\beta\int \pi\log\frac{\pi(y)}{\pi_{\mathrm{SFT}}(y)e^{r(y)/\beta}}\,dy, which is -\\beta\\,\\mathrm{KL}\\big(\\pi\\,\\big\\\|\\,\\tfrac{1}{Z}\\pi\_{\\mathrm{SFT}}e\^{r/\\beta}\\big)+\\beta\\log Z; the KL is minimal at zero, so \\;\\pi\^\\star(y\\mid x) = \\frac{1}{Z(x)}\\,\\pi\_{\\mathrm{SFT}}(y\\mid x)\\,e\^{r(x,y)/\\beta}. Step 2 (implicit reward). Inverting: r(x,y) = \\beta\\log\\frac{\\pi\^\\star(y\|x)}{\\pi\_{\\mathrm{SFT}}(y\|x)} + \\beta\\log Z(x). Step 3 (injection into Bradley-Terry). In \\sigma(r\^+-r\^-), the term Z(x) — the same for y\^+ and y\^- — cancels: only the difference of log-ratios matters; maximizing the likelihood of the preferences gives \\mathcal{L}\_{\\mathrm{DPO}} above (with \\theta in place of \\pi\^\\star). Gradient: -\\beta\\,\\sigma(-\\hat r)\\,\\nabla\_\\theta\\big\[\\log\\pi(y\^+\|x)-\\log\\pi(y\^-\|x)\\big\] with implicit reward \\hat r = \\beta\\log\\frac{\\pi\_\\theta(y\^+)}{\\pi\_{\\mathrm{SFT}}(y\^+)} -\\beta\\log\\frac{\\pi\_\\theta(y\^-)}{\\pi\_{\\mathrm{SFT}}(y\^-)}: the log-ratio margin of the preferred responses is increased, all the more strongly as the pair is misclassified. ∎

Theorem 5.3 — GRPO (Shao et al., DeepSeekMath 2024): derivation Generate a group of G responses \\{y_i\\} per prompt; rewards \\{r_i\\}; advantages within the group: A_i = \frac{r_i - \mathrm{mean}(r_{1..G})}{\mathrm{std}(r_{1..G})},\qquad \nabla_\theta J = \mathbb{E}\Big[\frac{1}{G}\sum_i \frac{1}{\|y_i\|}\sum_t \nabla_\theta\log\pi_\theta(y_{i,t}\mid x)\,A_i\Big] - \beta\,\nabla_\theta \widehat{\mathrm{KL}}, with \\widehat{\\mathrm{KL}} an unbiased, low-variance estimator \\;\\mathbb{E}\\big\[\\frac{\\pi\_{\\mathrm{ref}}}{\\pi\_\\theta}-\\log\\frac{\\pi\_{\\mathrm{ref}}}{\\pi\_\\theta}-1\\big\].

Proof. Variance. REINFORCE: \\nabla\\mathbb{E}\[r\]=\\mathbb{E}\[r\\,\\nabla\\log\\pi\] is unbiased for any baseline independent of the action: \\mathbb{E}\[b\\,\\nabla\\log\\pi\]=b\\,\\nabla\\!\\int\\pi=0; subtracting b=\\mathrm{mean}(r) divides the variance (better than b=0 or a learned baseline); normalizing by the standard deviation makes the gradient scale invariant across prompts (easy ones: small spreads → amplified; hard ones: damped). No more critic. Unlike PPO, the baseline comes from the group itself — the value network (and its memory/training) disappears; it is the Monte-Carlo estimation of A(s,a)=Q(s,a)-V(s) by multiple sampling. ∎

RLVR and reasoning (2024-2026) When quality is verifiable (a passing unit test, an exact mathematical answer), the reward no longer needs to be learned: RL with Verifiable Rewards. GRPO is the engine of DeepSeek-R1: by optimizing verifiable correctness, long chains of thought emerge (self-verification, backtracking, “aha” moments) — the “o1” style. Self-consistency at inference (Wang et al., 2023): sample n reasonings, answer by majority vote — accuracy climbing at \\Theta(\\sqrt n)-ish as long as errors are weakly correlated. Costs: 10× more tokens; recent works regularize length (ch. 10: “Shorter but not Worse”). Exploration (bandits, RL module ch. 6) becomes central: the GRPO group is structured exploration.

Overview SFT (imitate) → RLHF (optimize preferences) → DPO (preferences without RL) → RLVR/GRPO (optimize verifiable truth). A “modern” LLM chains: base → SFT → rejection sampling → DPO/GRPO; this is exactly the plan of the official course (“post-training methods”). In the lab: toy DPO (exercise 7) then GRPO (exercise 8).

6. Running an LLM: inference

6.1. Decoding: formulas and effects

Definition 6.1 — From greedy to nucleus At each step, logits z over \|V\|;

  • Temperature: p_i = \\dfrac{\\exp(z_i/T)}{\\sum_j \\exp(z_j/T)} — T\\to0: argmax (greedy); large T: uniformization;
  • Top-k: truncate to the k best logits then renormalize;
  • Top-p (nucleus): smallest set of tokens with cumulative probability \\ge p (adaptive size: wide on an uncertain step, narrow on a deterministic step);
  • Repetition penalty: divide the logit of already emitted tokens (factor 1.1-1.3); min-p: threshold relative to the best token.
Setting Effect on quality Effect on diversity Use
T = 0 (greedy) deterministic, possible repetitions none extraction, code, factual RAG
Moderate T (0.7) + top-p 0.9 fluent, controlled moderate general dialogue
High T (1.0+), top-p 0.95 more hallucinations strong brainstorming, synthetic data

6.2. KV-cache: the memory arithmetic

Proposition 6.2 — Cache memory = \\mathcal{O}(n\\cdot d), quantified In autoregression, each new token must attend to the keys/values of the whole past — they are cached (prop. 2.4): bytes/token = 2\\,N\_{\\text{layers}}\\,n\_{\\text{KV}}\\,d\_{\\text{head}}\\times precision. Llama-3-8B (32 layers, 8 KV heads, 128 dim, fp16) → 128 KiB/token: 8k context ≈ 1 GB, 100k ≈ 12.8 GB, 1M ≈ 128 GB (weights excluded!). Three ways out: GQA (÷4 here), int8 cache quantization (÷2), and eviction/recomputation (sliding window). Engineering rule: context length is first a memory bandwidth problem, not a FLOPs problem — hence the next chapter.

6.3. Speculative decoding: the correction proved

Theorem 6.3 — Speculative decoding (Leviathan et al., 2023) A small model q proposes \\gamma tokens; the large model p computes the \\gamma distributions in a single forward; each proposal y is accepted with probability \\min(1, p(y)/q(y)); at the first rejection, one resamples from the normalized residual \\mathrm{norm}\\big(\\max(0,\\,p-q)\\big). Then the marginal distribution of each produced token is exactly p — quality unchanged, latency divided by ~2-3 when q\\approx p.

Proof. For one token: acceptance contribution q(y)\\min(1,p(y)/q(y)) = \\min(q(y),p(y)); rejection contribution: the total rejected mass equals \\sum_x q(x)\\big(1-\\min(1,p(x)/q(x))\\big) = \\sum_x \\max(0,q(x)-p(x)) = R, and the resampled residual adds R\\cdot\\frac{\\max(0,p(y)-q(y))}{R} = \\max(0,p(y)-q(y)). Total: \\min(q,p)+\\max(0,p-q)=p. ∎

6.4. Quantization: principles and errors

  • Post-training int8: nearly lossless (batch calibration, per-channel scales); int4: the standard compromise;
  • GPTQ (Frantar et al., 2022): layer by layer, minimize \\\|Wx-\\hat W x\\\|\_2\^2 on a calibration set — column-by-column quantization with error compensation on the remaining columns (via the inverse of the Hessian \\mathbf{H}=2\\mathbf{X}\\mathbf{X}\^\\top);
  • AWQ (Lin et al., 2023): protect the “salient” channels (high activations) with per-channel scaling before quantization — the error is shifted toward weakly active channels;
  • Typical errors: int8 ≈ +0.0-0.1 PPL; well-calibrated int4 ≈ +0.1-0.5 PPL (often imperceptible); below 4 bits, degradation accelerates (2-3-bit quantization = research); in production, always re-validate on your benchmarks, not PPL alone.

6.5. Serving: continuous batching, PagedAttention, costs

  • Continuous batching (vLLM, Orca): schedule at the decoding step — finished sequences leave, new ones enter the same batch; throughput multiplied by ~10-20× vs static batching;
  • PagedAttention (Kwon et al., 2023): the KV-cache split into pages (like virtual memory) — no more fragmentation; sharing of common prefixes (system prompt); ~2-4× memory gain → larger batches;
  • Costs: two regimes — API (on the order of /M tokens, steadily decreasing) vs on-prem (amortized GPU-hour: an H100 at \~3/h serving ~2-5k tokens/s on an int4-quantized 8B → a few $/M tokens under heavy load); the real cost of an agent = repeated input tokens × history length (ch. 8); the “ML Ops” angle is deepened in the dedicated M2 module.

7. RAG in depth

Definition 7.1 — RAG (Retrieval-Augmented Generation) p(y \mid q) \approx p_\theta\big(y \mid q, \mathrm{top}_k\, \mathrm{sim}(e_q, e_d)\big) index documents by embeddings, retrieve those closest to the prompt, inject them into the context. Reduces hallucinations, updates knowledge, handles proprietary data without retraining.

7.1. Chunking

  • Fixed with overlap: 256-1024 tokens, stride 10-20%; structural splitting (sections, paragraphs) > blind splitting (cut sentences destroy retrieval);
  • Semantic chunking: cut where the embedding similarity between successive windows drops (topic change);
  • Multi-granularity: index by passages, but return the parent section to the LLM (small-to-big); for structured documents, keep titles/metadata in the chunk (pre-retrieval filters).

7.2. Retrieval: BM25, dense, hybrid — with numbers

Retriever Principle BEIR (NDCG@10, ~18 tasks) Strengths / weaknesses
BM25 probabilistic weighting (NLP ch. 2) ≈ 0.44 on average zero training, exact (lexical matches); misses reformulations
Dense (E5/BGE, …) SBERT embeddings + ANN (FAISS/HNSW) ≈ 0.50-0.52 for the best captures paraphrase; errors on jargon/exact refs, must be indexed
Hybrid + reranker fusion (RRF) then cross-encoder ≈ 0.53-0.55 practical state of the art; reranking cost O(top-100)

Cross-encoder rerankers The bi-encoder scores s(q,d)=\cos(e_q,e_d) separately (indexable); the cross-encoder scores s(q,d)=f_\theta([q\,;d]) jointly — it sees the exact term interaction (mini-attention) but must run on every candidate; hence the cascade architecture: dense/BM25 (top-100) → cross-encoder (top-5). Typical gain: +3 to +5 points of NDCG@10. The “lost in the middle” effect (Liu et al., 2023): even with the right passages, the LLM exploits better those at the beginning/end of the context → reorder the best ones at the extremes.

7.3. RAG evaluation

RAGAS-type metrics (Es et al., 2023)

  • Faithfulness: decompose the answer into atomic claims (by an LLM judge); faithfulness = fraction supported by the retrieved context;
  • Answer relevance: the LLM generates candidate questions from the answer — average similarity with the true question;
  • Context precision / recall: are the useful chunks there and well ranked? / does the corpus contain what was missing?

Lab protocol: QA set with reference context (golden context), compare faithfulness with/without reranking, measure the cost (tokens, latency) of each stage.

7.4. GraphRAG and variants

  • HyDE (Gao et al., 2022): generate a hypothetical answer to the question and search with its embedding — the imaginary answer is closer to the documents than the question;
  • GraphRAG: retrieval traverses a knowledge graph (entity-relation extraction by NER/RE — NLP ch. 6; communities-summaries; multi-hop queries); detailed in the Graph ML module ch. 8 — the LLGA heart; Buscaldi’s work (AI-KG/CS-KG, NLP ch. 9) builds exactly such graphs from scientific corpora;
  • Structured queries: text → graph query (linearization, ch. 10.3) or SQL (text-to-SQL): the LLM writes the query, the database answers — maximal auditability.

8.2. Multimodality: how an image enters a context

  • Vision: a ViT encoder cuts the image into 16×16 patches → one token per patch (Deep Learning module ch. 5 for ViT); a projector (MLP or Q-Former) aligns these tokens onto the LLM’s embedding space → the image becomes “text” inside the context (LLaVA scheme); the encoder is often pre-trained contrastively image-text — the common latent space recalls CLIP (Multimodal GenAI module ch. 5);
  • Audio: mel spectrograms → encoder (Whisper-style) → tokens; the “transcription + style” output feeds the LLM (voice assistant = encoder → LLM → synthesis pipeline);
  • Video: sampled images (1-4/s) + temporal pooling — very high token cost: the sampling step choice is a compression choice;
  • Documents: pages = images + interleaved OCR text (the number 1 enterprise use case — contracts, reports).

9. Evaluation and safety of LLMs

9.1. Benchmarks: construction and contamination

Definition 9.1 — MMLU-type benchmark (Hendrycks et al., 2020) Multiple-choice questions (57 subjects for MMLU; variants: MMLU-Pro, GPQA, HELM for multi-faceted evaluation). Two scoring modes: log-likelihood of the options (deterministic, but biased by answer length/frequency) vs generation then extraction (realistic, but prompt- and parsing-dependent). Rule: always specify the protocol — rankings change with the mode.

Contamination: the measurement that skews everything If the benchmark is in the pre-training data (the web!), the score measures memorization, not competence. Detection: n-gram overlap (8-13 grams) between questions/training data, canary strings (hidden markers), cloze recall tests. Remedies: private/rotating evaluations, dynamic question generation, temporal re-splits (post-cutoff questions). Recent work on this: memorization in fine-tuning and multilingual hallucinations — ch. 10 of the M1 NLP module (Buscaldi’s work: MUCH, memorization prediction).

9.2. LLM-as-judge: convenient, but biased

  • Positional bias: the judge prefers the first (or second) answer depending on order — mitigation: evaluate in both orders and average;
  • Verbosity / style bias: long, well-formatted answers are overrated — mitigation: rubrics (explicit criteria), constrained format;
  • Self-preference: a judge favors answers from its own model family — mitigation: judge ensembles, judges trained for calibration (references: MT-Bench, G-Eval);
  • Calibration: a judge score is not a probability — verify on a set where ground truth exists (fraction of judgments matching humans); cheap distilled metrics (FrugalScore, ch. 10) were born exactly from this need.

9.3. Hallucinations

Taxonomy 9.2 Intrinsic: the answer contradicts the source/context (RAG: wrong citation); extrinsic: unverifiable (invented) claims; prompt fidelity: silent disobedience to instructions. Causes: sampling (temperature), knowledge cutoff, the “always answer” training bias (no learned abstention), sycophancy (telling the user yes). Mitigations: RAG + verifiable citations (ch. 7), self-consistency (ch. 5), low temperature for factual tasks, abstention training, post-hoc verification by decomposition into claims (the heart of RAGAS “faithfulness”).

9.4. Attacks: jailbreaks and prompt injections

  • Direct jailbreaks: role-play (“DAN”), hypothetical framing, encoding (base64, unicode), multi-turn crescendo — circumventing safety instructions;
  • Indirect injections: the retrieved content (web page, PDF, tool result) contains malicious instructions — the number 1 attack on RAG/agent systems (ch. 7-8);
  • Defense in depth: input/output classifiers (Llama Guard type), spotlighting (delimiting and marking untrusted content), least privilege on tools (the retriever does not write to the database!), prompt/data separation (ch. 1 — special tokens: the same hygiene), human in the loop for irreversible actions. No defense is complete — one reduces the attack surface.

9.5. Watermarking

Theorem 9.3 — Statistical watermark (Kirchenbauer et al., 2023) Before each token, hash the prefix → a pseudo-random seed that partitions the vocabulary into “green”/“red” (fraction \gamma, e.g. 1/2); generation penalizes reds. On a text of T tokens containing s_G green ones: z = \frac{s_G - \gamma T}{\sqrt{T\,\gamma(1-\gamma)}} \;\xrightarrow{T\ \text{large}}\; \mathcal{N}(0,1)\ \text{under H}_0, reject “human text” if z exceeds the threshold (p-value) — under H1 (marked), z grows like \sqrt T times the introduced bias.

Proof. Under H₀ (unmarked text), each token is green with probability \gamma independently → s_G\sim\mathrm{Bin}(T,\gamma), the standardized variable tends to the normal (CLT), hence the z-score; the partition depends on the prefix: impossible to remove without the seed. Limitations (follow-up paper, Kirchenbauer et al. 2023): paraphrasing, truncation, and false positives on short texts — the test is statistical, not deterministic. ∎

Guokan Shang (lead research scientist, MBZUAI; PhD at the LIX laboratory, École Polytechnique, 2021, under the supervision of M. Vazirgiannis — the LLGA loop) works on the evaluation of generative models, efficient pre-training, multilingual LLMs and dialogue summarization. Three axes presented in detail, then the rest of the filmography, each positioned relative to the chapters.

Axis 1 — Frugal evaluation: FrugalScore (ACL 2022) Kamal Eddine, Shang, Tixier & Vazirgiannis, FrugalScore: Learning Cheaper, Lighter and Faster Evaluation Metrics for Automatic Text Generation — arXiv:2110.08559. Problem: neural generation metrics (BERTScore, MoverScore…) cost one large-model forward per pair — prohibitive in a learning or LLM-judge evaluation loop.   10. RAG vs context length. Query an LLM with 4k/32k/128k of context over a corpus: does the “lost in the middle” effect appear? Compare with RAG; discuss the trade-offs (cost, faithfulness, indexing overhead).

  11. Watermark. With \gamma=0.5 and T=400 tokens, compute z for a text carrying 230 green tokens; threshold at 5%; how many tokens are needed to detect a +5% green bias?

    Proof. Guidance: z=(230-200)/10 = 3 → p ≈ 0.1%: rejected (marked); for a small bias \varepsilon, the expectation of z grows like \varepsilon\sqrt{T/\gamma(1-\gamma)} → one needs T\sim (1.96/\varepsilon)^2\gamma(1-\gamma); with \varepsilon=0.05, ~770 tokens — hence the difficulty on short texts. ∎

  12. Agent project. Extend the final lab: an agent that chooses between vector retrieval and a graph query depending on the question type (relational or factual) — measure the improvement and the extra cost.

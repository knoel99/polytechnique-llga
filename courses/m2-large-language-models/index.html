1. Tokenization

Before a model sees any text, a tokenizer cuts it into units from a fixed vocabulary; this chapter explains how that vocabulary is built and why the choice weighs on cost and quality.

A concrete scene: send the same prompt in French and in English to a Llama-style tokenizer. The French version typically costs 15–25% more tokens, so your context budget shrinks, and a rare word splits into six subwords — the model “understands” less and bills more.

This is why BPE, WordPiece and Unigram come before the architecture.

What breaks Mixing train/inference tokenizers; ignoring multilingual cost (latency + $); treating UNK as a detail. All three sabotage a prod RAG as much as a nanoGPT lab.

Definition 1.1 — Byte-level BPE: the exact construction BPE (proved step by step in NLP ch. 1) starts here from the alphabet of 256 bytes: any Unicode string can be represented without an “unknown” symbol. Learning loop: \mathrm{merge}^{(k)} = \arg\max_{(a,b)}\; f(a,b),\qquad f(a,b)=\sum_{w}\mathrm{freq}(w)\,n_{(a,b)}(w), where n_{(a,b)}(w) counts the occurrences of the adjacent pair (a,b) in word w (counting weighted by word frequency). The merge is applied everywhere and one starts again until |V| (32k-128k).

Encoding a new text replays the merges in the learned order (GPT-2/4, Llama). WordPiece (BERT) maximizes \frac{f(x,y)}{f(x)f(y)}; Unigram (T5) learns a generative model by EM then segments with Viterbi (NLP ch. 1.2).

Vocabulary, compression, multilingual costs The compression rate (characters/token) depends on the vocabulary and the language: vocabularies trained on English compress English well (~4 characters/token) but degrade other languages.

Orders of magnitude measured in the lab: with GPT/Llama-type tokenizers, the same French text costs typically 15 to 25% more tokens than in English; for poorly represented non-Latin scripts, the factor can reach 3× or more (each rarely seen character decomposes into bytes).

Direct consequences: API cost (billed per token), context length consumed, and inequality of quality.

Llama 3 raised the vocabulary to 128k tokens — a large part of the gain serves non-English languages; GPT-4o (o200k) claims up to ~1.4× to ~4× fewer tokens depending on the language compared to the previous generation. Exercise 1 measures all this on your own texts.

Special tokens and security Special tokens (<|endoftext|>, <|im_start|>, template roles) delimit turns and documents. If the decoder accepts them in user input, an attacker can inject a fake dialogue turn or prematurely terminate a document (boundary confusion).

Defense: systematically re-encode input and neutralize special tokens (encode_ordinary, the allowed_special flag of tiktoken), never raw string concatenation around the prompt. This class of attacks returns in ch. 9 (prompt injections).

import tiktoken
enc = tiktoken.encoding_for_model("gpt-4o")
okapi = tiktoken.encoding_for_model("gpt-3.5-turbo")   # cl100k vocabulary

fr = "Les graphes pour les LLMs : une révolution pour la recherche d'information."
de = "Donaudampfschifffahrtsgesellschaftskapitän"
for s in (fr, de, "1234 + 5678 = ?"):
    print(len(okapi.encode(s)), "vs", len(enc.encode(s)), "->", s[:40])

# "safe" tokenization: special tokens are NOT decoded by default
b = enc.encode("end <|endoftext|> next", allowed_special=set())
print("ids :", b, "| decode round-trip ok :", enc.decode(b))

Why it matters (M1 recall) Tokenization governs cost (length in tokens), biases (fuzzy arithmetic because “123 + 456” tokenizes poorly), multilinguality (the extra cost measured above) and real vulnerabilities (special tokens). Systematic diagnosis in the lab with tiktoken / tokenizers. For adapting an LLM to a low-resource language — vocabulary, template, data — ch. 10 presents Shang’s work (Atlas-Chat, Nile-Chat).

2. The architecture in depth

A language model must turn a sequence of token embeddings into a distribution over the next token, at a cost that stays manageable for long sequences. This chapter dissects the decoder-only transformer that does this in every modern LLM, and the design choices (normalization, positions, attention heads, experts) that make it trainable and cheap to run.

Definition 2.1 — The decoder block An LLM stacks N blocks: x \leftarrow x + \mathrm{MHA}(\mathrm{LN}(x)), \qquad x \leftarrow x + \mathrm{MLP}(\mathrm{LN}(x)), with causal attention (triangular mask: token i sees only j \leq i), grouped heads (grouped-query attention for inference), a gated MLP (SwiGLU, ~4× expansion), RoPE positional embeddings (rotations; relative generalization to long contexts), and a final LN.

Proposition 2.2 — Pre-norm vs post-norm: the gradient flow Post-LN (original transformer): x_{l+1}=\mathrm{LN}(x_l+F(x_l)) — each block renormalizes the residual itself. The gradient of x_L to x_0 crosses L LN Jacobians whose product decays/explodes exponentially with L: warmup mandatory, fragile depth.

Pre-LN (GPT-2+, all modern LLMs): x_{l+1}=x_l+F(\mathrm{LN}(x_l)) — the residual path is the identity: \frac{\partial x_L}{\partial x_l} = I + \sum_{l'\,>\,l}\frac{\partial F_{l'}}{\partial x_l} → a gradient that reaches every layer without multiplicative attenuation: stable training without fine warmup.

Price: the norm \|x_l\| grows with depth (additive contributions), hence the final LN. (Xiong et al., ICML 2020.)

Theorem 2.3 — RoPE derived (Su et al., 2021) Position is injected by rotation: the dimension-d vector is viewed as d/2 2D pairs; pair i of the token at position m undergoes R(m\theta_i) with \theta_i = 10000^{-2i/d}: R(\varphi)=\begin{pmatrix}\cos\varphi & -\sin\varphi\\ \sin\varphi & \cos\varphi\end{pmatrix}, \qquad q^{(i)}_m = R(m\theta_i)\,q^{(i)},\quad k^{(i)}_n = R(n\theta_i)\,k^{(i)}.

Proof. Relative property: the dot product of a pair depends only on the difference of positions: \langle q^{(i)}_m,k^{(i)}_n\rangle = q^{(i)\top} R(m\theta_i)^\top R(n\theta_i)\, k^{(i)} = q^{(i)\top} R\big((n-m)\theta_i\big)\,k^{(i)}, since 2D rotations commute and R(a)^\top R(b)=R(b-a).

Summing over pairs = an attention score depending on (n-m) and the contents — a “soft” generalization of relative embeddings.

Practical bonus: to extend the context, one interpolates the angles (m\to m/L) instead of relearning. ∎

Proposition 2.4 — MQA/GQA: the memory arithmetic of the KV-cache The cache stores keys and values of all past tokens: \text{bytes/token} = 2\ (\text{K and V}) \times N_{\text{layers}} \times n_{\text{KV heads}} \times d_{\text{head}} \times \text{bytes/element}.

Multi-Query Attention (Shazeer, 2019): a single shared KV head. Grouped-Query (Ainslie et al., 2023): n_{\text{KV}} < n_{\text{heads}}.

Example — Llama-3-8B: 32 heads, 8 KV heads, 32 layers, d_{\text{head}}=128, fp16: 2\times32\times8\times128\times2 = 128\,\text{KiB/token}. A 100k-token context ≈ 12.8 GB of cache (versus ~51 GB with full attention — a 4× reduction, nearly identical quality).

This is THE lever of long context (ch. 6).

Key result — KV-cache memory \text{bytes/token} = 2 \times N_{\text{layers}} \times n_{\text{KV heads}} \times d_{\text{head}} \times \text{bytes/element}

Mixture-of-Experts (MoE): routing and balancing Each MLP block is replaced by E experts \{E_i\}; a router g(x)=\mathrm{softmax}(W_g x) activates only the top-k: y = \sum_{i\in \mathrm{top}\text{-}k} g_i(x)\,E_i(x), \qquad \#\text{active params} \ll \#\text{total params}. Capacity decorrelated from inference cost (Switch Transformer: Fedus et al. 2021; DeepSeek-V3: 671B total, ~37B active).

Trap: routing collapse — the winning experts attract everything. Auxiliary balancing loss (Switch): \mathcal{L}_{\text{aux}} = \alpha\, E \sum_{i=1}^{E} f_i\,P_i, f_i = fraction of tokens routed to i, P_i=\frac{1}{T}\sum_t g_i(x_t) = mean router probability. At balanced routing (f_i=P_i=1/E) the loss equals \alpha.

This value is the minimum when (f_i) and (P_i) are similarly ordered — the most loaded experts are also the most probable, which is the collapse regime the loss targets. Chebyshev’s sum inequality then gives \sum_{i=1}^{E} f_i P_i \;\ge\; \frac{1}{E}\Big(\sum_i f_i\Big)\Big(\sum_i P_i\Big) = \frac{1}{E}. Without that condition the bound can fail (a counterexample is in Ex. 7). In practice the loss acts through its gradient: f_i is not differentiable, and \frac{\partial\mathcal{L}_{\text{aux}}}{\partial P_i}=\alpha E f_i lowers the probability of the most loaded experts.

Modern variants: fine experts + shared experts, balancing without an auxiliary loss (dynamically adjusted bias, DeepSeek-V3).

Efficient attention: FlashAttention and IO complexity Exact attention costs \mathcal{O}(n^2) compute but is dominated in practice by input/output: the naive implementation writes the n\times n matrix to HBM (large, slow memory).

FlashAttention (Dao et al., 2022): exact tiled computation that fits in SRAM, “online” softmax with an accumulator (running max m and sum \ell updated per tile): m_{\text{new}}=\max(m,x), \qquad \ell_{\text{new}}=e^{m-m_{\text{new}}}\ell+e^{x-m_{\text{new}}}. The n^2 matrix is never materialized; HBM reads are reduced from \Theta(n^2) to \Theta(n^2d^2/M) (M = SRAM size).

The general lesson: optimize memory access, not just FLOPs (the HBM/SRAM hierarchy is in Deep Learning ch. 6, the memory wall in Deep Learning P2 ch. 5).

Beyond: SSM/Mamba (state equation sketch) A state-space model discretizes a linear system x'(t)=Ax(t)+Bu(t),\ y=Cx: x_k = \bar A x_{k-1} + \bar B u_k,\qquad y_k = C x_k,\qquad \bar A = e^{\Delta A},\ \bar B \approx \Delta B, computable in \mathcal{O}(n) by a scan (no n^2 matrix).

The selectivity of Mamba (Gu & Dao, 2023): \bar B, C, \Delta depend on the input → content-dependent (selective forgetting), which yields attention quality at linear cost.

SSD duality (Mamba-2, 2024): the same computation rewrites as y_k=\sum_{s\le k} C_k^\top\big(\prod_{s<k'}\bar A\big)\bar B_s\,u_s — an “attention” with a causal kernel; hence the attention+SSM hybrid architectures. Continued in ch. 8.

  • Parameters: where are they? embedding (|V| \times d), attention (4d^2/block), MLP (8d^2/block, ~12d^2/block with SwiGLU) — the rule \#\text{params} \approx 12 N d^2 and the training memory cost (parameters + Adam + activations + gradients: ~20 bytes/parameter in mixed precision; cf. ch. 3 for actual compute);
  • LLGA bridge: attention is message passing on a token graph (Graph ML module ch. 5, Advanced GNN); graph transformers inherit from it.

3. Pre-training

Pre-training gives the model its knowledge of language by training it on trillions of tokens of raw text. This chapter answers three questions: which objective to optimize, which data to feed, and how to split a fixed compute budget between model size and data size.

Pre-training objectives

  • Causal modeling (CLM) — GPT: \mathcal{L} = -\sum_t \log p_\theta(x_t \mid x_{<t}) — predict the next token; generative by construction;
  • Masked modeling / denoising (MLM) — BERT (NLP ch. 7): mask ~15% and predict (bidirectional); excellent for encoding (classification, retrieval), does not generate;
  • Span corruption / text-to-text — T5: mask spans and regenerate them; everything is formulated as sequence→sequence.

3.1. The data pipeline: quality, filtering, deduplication

  • Curation: web → rule-based filtering (length, code/punctuation ratio, languages), then model-based filtering (quality classifiers trained on reference pages — e.g. distilled judges); controlled mixture (web, code, books, articles, mathematics, synthetic data generated then filtered);
  • MinHash-LSH deduplication (proved in NLP ch. 8.3): k-gram shingles → MinHash signatures (a min-hash collision has probability equal to the Jaccard similarity) → LSH bands/ranks with \mathbb{P}_{\text{detect}}(J)=1-(1-J^r)^b → remove near-duplicates down to a threshold. At scale: tens of TB of text, approximately linear clustering; measured effect: less memorization, better benchmark (deduplicating is regularizing — LLMs learn duplicates “twice”);
  • Mixtures and curriculum: per-domain proportions (annealing: raise quality/lower web at the end of training); easy→hard ordering (by perplexity) improves compute efficiency — demonstrated at scale by Shang (ch. 10, “Beyond Random Sampling”);
  • Multilingual: balancing per language (otherwise the tokenizer and the model drift toward English — cf. ch. 1 and 10).

3.2. Scaling laws: decomposition and the Chinchilla optimum

Combined law (Hoffmann et al. 2022, “Chinchilla”) The loss of a model with N parameters trained on D tokens follows, over decades of scale: L(N,D) = E + \frac{A}{N^{\alpha}} + \frac{B}{D^{\beta}}, E = irreducible entropy of natural text; the other two terms = under-capacity and exhausted data (fitted on ~400 training runs; Kaplan et al. 2020 for the L(N)-only version). Reading: one must grow N and D together.

Theorem 3.1 — The compute optimum D^\star \approx 20\,N, derived At fixed budget C, with \mathrm{FLOPs}(C) \approx 6ND (2 per parameter × forward + backward, × D tokens): (N^\star, D^\star) = \arg\min_{N,D}\; L(N,D)\quad \text{s.t.}\quad 6ND = C.

Proof. Lagrangian: \mathcal{J}=E+AN^{-\alpha}+BD^{-\beta}-\lambda(6ND-C). Stationarity: \frac{\partial\mathcal{J}}{\partial N}= -\alpha A N^{-\alpha-1}-6\lambda D=0, \qquad \frac{\partial\mathcal{J}}{\partial D}= -\beta B D^{-\beta-1}-6\lambda N=0. Dividing side by side, \lambda cancels: \frac{\alpha A\,N^{-\alpha-1}}{\beta B\,D^{-\beta-1}} = \frac{D}{N} \;\Longrightarrow\; \frac{\alpha A}{\beta B}\,D^{\beta} = N^{\alpha} \;\Longrightarrow\; \frac{N^{\alpha}}{D^{\beta}} = \frac{\alpha A}{\beta B}.

With Chinchilla’s fitted constants (\alpha\approx0.34, \beta\approx0.28, A\approx406, B\approx411), the right-hand side equals \approx 1.2. The condition together with 6ND=C gives N^\star\propto C^{0.46}, \qquad D^\star\propto C^{0.54} — both grow like \sqrt{C} — and numerically D^\star/N^\star\approx 20 tokens per parameter.

GPT-3 (300B tokens for 175B params, ratio 1.7) was therefore “undertrained” at its budget. ∎

Key result — the Chinchilla optimum 6ND = C, \qquad D^\star \approx 20\,N^\star

Compute and real costs (Llama 3, 2024) Orders of magnitude from the Llama 3 technical report (H100 training): 8B / 15T tokens ≈ 1.5M GPU-hours; 70B ≈ 7M; 405B / 15.6T tokens ≈ 30.8M GPU-hours (≈ 3.5 years of a single H100 × 10⁴).

At ~2-3 $/GPU-hour, the 405B costs ~80-90M$ of compute. This is why one “continues” from checkpoints rather than retraining (fine-tuning with LoRA, ch. 4; distillation into small models, ch. 8.3).

It is also why the post-Chinchilla ratio went up: since inference costs daily, one deliberately overtrains small models (Llama-3-8B: 15T tokens ≈ 1900 tokens per parameter, ~100× Chinchilla) — the optimum depends on what is being optimized: the training cost (Chinchilla) or the total cost including inference.

Lab: training a mini-GPT On a Shakespeare-type corpus (~1 MB), train a ~10M-parameter transformer (nanoGPT): 30 minutes of GPU suffice to generate credible text. Observe: the loss curve, the effect of context, the sampling temperature (ch. 6). Extend: do exercise 6 (check the law L(N,D) by regression on the published points).

4. Post-training: SFT and alignment

A pre-trained model only continues text; it does not follow instructions or hold a conversation. Post-training turns it into an assistant, and this chapter covers its first stage, supervised fine-tuning, and explains why a second stage based on preferences (chapter 5) is needed.

Step 1 — Supervised Fine-Tuning (instruction tuning) Fine-tune the base model on quality (instruction, response) pairs — a few tens/hundreds of thousands of examples suffice to turn an autocomplete into an assistant. Engineering details: loss mask (the loss is computed only on the response), chat templates, data “distilled” from a large model.

Templates and loss mask — the detail that matters The template serializes the turns: <|system|>…<|user|>…<|assistant|>. The loss masks the prompt tokens (system/user roles) and keeps only the completion — otherwise the model learns to imitate the user and prompt logging becomes noise: \mathcal{L}_{\text{SFT}} = -\sum_{t\,\in\,\text{completion}} \log p_\theta(y_t\mid y_{<t}, x).

# SFT with loss masking (HF TRL pseudo-code)
from trl import SFTTrainer

def format(example):                    # chat template + masked labels
    prompt  = f"<|user|>\n{example['question']}\n<|assistant|>\n"
    completion = example["answer"]
    return {"prompt": prompt, "completion": completion}
# - the loss is computed ONLY on the completion tokens (TRL SFTTrainer
#   does the masking automatically; in raw PyTorch: labels = -100 on the prompt)

trainer = SFTTrainer(model="meta-llama/Llama-3.1-8B",
                     train_dataset=dataset.map(format), ...)
trainer.train()

# pitfalls seen in the lab: template != inference template -> performance drop;
# padding token confused with eos; overly long answers -> silent truncation

Parameter-efficient fine-tuning: LoRA and QLoRA Full fine-tuning updates every weight. LoRA (Hu et al., 2022) freezes each pretrained matrix W_0\in\mathbb{R}^{d\times k} and learns a low-rank correction \Delta W = BA: h = W_0x + \frac{\alpha}{r}\,BAx,\qquad B\in\mathbb{R}^{d\times r},\quad A\in\mathbb{R}^{r\times k},\quad r\ll\min(d,k). A starts random and B=0, so training starts exactly from the base model. After training, BA is merged into W_0: inference costs nothing extra.

Parameters. An adapter has r(d+k) weights instead of dk. For Llama-3-8B (32 blocks, width 4096, KV width 1024, MLP width 14,336) with r=16 on the seven linear maps of every block, that is 1.31M per block, about 42M in total: 0.5 % of the 8.0B weights.

Memory. Full fine-tuning with Adam in mixed precision needs about 16 bytes per parameter (weights, gradients, two moments), so about 128 GB for 8B before activations. LoRA keeps the frozen weights in bf16 (16 GB) and trains 42M parameters (about 0.7 GB of states).

QLoRA (Dettmers et al., 2023) stores the frozen base in 4-bit NF4 (about 4–5 GB for 8B) and backpropagates through it into bf16 adapters. An 8B model then fine-tunes on one 16–24 GB GPU, and a 0.5–1.5B model on a free Colab T4 (Ex. 3).

Step 2 — Why alignment beyond SFT? SFT imitates demonstrations; it does not directly optimize “the best response” and does not learn to avoid harmful responses. The central idea of InstructGPT/ChatGPT: learn a human reward, then optimize the policy against that reward (RL) — this is where the M1 RL module becomes the M2’s central tool.

Rejection sampling (best-of-n) An intermediate and indestructible step: generate n responses, keep those that pass a filter (reward model, tests, heuristics), re-fine-tune on them — the Llama 2 recipe between RLHF rounds (Touvron et al., 2023). This is exactly “exploit the best of n”, without policy gradients; the link with bandits (RL module ch. 4) is direct: each draw informs the policy for the next round.

5. RLHF, DPO, GRPO

This chapter continues chapter 4: once the model imitates good answers, we want it to prefer better answers to worse ones. It derives the three methods that do this — RLHF, which learns a reward and optimizes it with PPO; DPO, which skips the reward model; and GRPO, which uses verifiable rewards and no critic.

RLHF — the classic pipeline (Ouyang et al., 2022)

  1. Reward model: train r_\phi(x, y) on human preferences (response pairs); Bradley-Terry loss: \mathcal{L} = -\log \sigma\big(r_\phi(x, y^+) - r_\phi(x, y^-)\big).
  2. Policy optimization with PPO (RL module, ch. 5): \max_\theta\ \mathbb{E}\big[r_\phi(x, y)\big] - \beta\, \mathrm{KL}\big(\pi_\theta \| \pi_{\mathrm{ref}}\big) — the KL term to the frozen reference policy \pi_{\mathrm{ref}} (in practice the SFT model) prevents reward hacking and out-of-distribution drift.

Notation for the whole chapter: a prompt x, a response y, a reward r(x, y), a policy \pi_\theta(y\mid x) and the reference \pi_{\mathrm{ref}}.

Proposition 5.1 — Bradley-Terry, derived If humans compare pairs (y^+,y^-) with a probability of preferring y^+ increasing in the “strength” difference, the axiomatics (transitive binary choice, invariance) imposes a logistic model on the difference of latent scores: \mathbb{P}(y^+ \succ y^- \mid x) = \sigma\big(r(x,y^+)-r(x,y^-)\big). The log-likelihood of the observed preferences gives the loss above — only the difference of rewards is identifiable (adding a function of x changes nothing); hence the need for the KL penalty to pin down the zero.

Proof. Derivative in r^+: -\big(1-\sigma(r^+-r^-)\big) — the penalty is maximal when the pair is misclassified, zero when the margin is amply positive; it is a logistic regression on reward differences. ∎

PPO for LLMs — the concrete protocol Four models in memory: policy \pi_\theta, reference \pi_{\mathrm{ref}} (the frozen SFT model, for the KL), reward r_\phi (frozen), critic (value head).

Sensitive hyperparameters: \beta\in[0.01,\,0.2]; low learning rate (≈ 10× smaller than in SFT); PPO clip \epsilon\sim0.2; prompt batch > completion batch.

Classic symptoms: KL explodes (β too small); degenerate responses (hacked reward); drifting length (RM verbosity bias). This is chapter 5 of the RL module applied word for word — the prerequisite reading.

Theorem 5.2 — DPO (Rafailov et al., 2023): complete derivation The loss \mathcal{L}_{\mathrm{DPO}} = -\log \sigma\Big(\beta \log\tfrac{\pi_\theta(y^+ \mid x)}{\pi_{\mathrm{ref}}(y^+\mid x)} - \beta \log\tfrac{\pi_\theta(y^- \mid x)}{\pi_{\mathrm{ref}}(y^-\mid x)}\Big) optimizes the policy directly on preferences — without a reward model or rollouts.

Proof. Step 1 (closed-form solution of the KL-penalized problem). For fixed x, maximizing \mathbb{E}_{y\sim\pi}[r(y)] - \beta\,\mathrm{KL}(\pi\|\pi_{\mathrm{ref}}) rewrites as \max_\pi \int \pi(y)\Big[r(y) - \beta\log\frac{\pi(y)}{\pi_{\mathrm{ref}}(y)}\Big]dy = -\beta\int \pi\log\frac{\pi(y)}{\pi_{\mathrm{ref}}(y)e^{r(y)/\beta}}\,dy, which is -\beta\,\mathrm{KL}\big(\pi\,\big\|\,\tfrac{1}{Z}\pi_{\mathrm{ref}}e^{r/\beta}\big)+\beta\log Z . The KL is minimal at zero, so \pi^\star(y\mid x) = \frac{1}{Z(x)}\,\pi_{\mathrm{ref}}(y\mid x)\,e^{r(x,y)/\beta}.

Step 2 (implicit reward). Inverting: r(x,y) = \beta\log\frac{\pi^\star(y|x)}{\pi_{\mathrm{ref}}(y|x)} + \beta\log Z(x).

Step 3 (injection into Bradley-Terry). In \sigma(r^+-r^-), the term Z(x) — the same for y^+ and y^- — cancels: only the difference of log-ratios matters.

Maximizing the likelihood of the preferences gives \mathcal{L}_{\mathrm{DPO}} above (with \theta in place of \pi^\star).

Gradient: -\beta\,\sigma(-\hat r)\,\nabla_\theta\big[\log\pi(y^+|x)-\log\pi(y^-|x)\big] with implicit reward \hat r = \beta\log\frac{\pi_\theta(y^+)}{\pi_{\mathrm{ref}}(y^+)} -\beta\log\frac{\pi_\theta(y^-)}{\pi_{\mathrm{ref}}(y^-)}: the log-ratio margin of the preferred responses is increased, all the more strongly as the pair is misclassified. ∎

Key result — the DPO loss \mathcal{L}_{\mathrm{DPO}} = -\log \sigma\Big(\beta \log\tfrac{\pi_\theta(y^+ \mid x)}{\pi_{\mathrm{ref}}(y^+\mid x)} - \beta \log\tfrac{\pi_\theta(y^- \mid x)}{\pi_{\mathrm{ref}}(y^-\mid x)}\Big)

Theorem 5.3 — GRPO (Shao et al., DeepSeekMath 2024): derivation Generate a group of G responses \{y_i\} per prompt; rewards \{r_i\}; advantages within the group: A_i = \frac{r_i - \mathrm{mean}(r_{1..G})}{\mathrm{std}(r_{1..G})},\qquad \nabla_\theta J = \mathbb{E}\Big[\frac{1}{G}\sum_i \frac{1}{|y_i|}\sum_t \nabla_\theta\log\pi_\theta(y_{i,t}\mid x)\,A_i\Big] - \beta\,\nabla_\theta \widehat{\mathrm{KL}}, with \widehat{\mathrm{KL}} an unbiased, low-variance estimator \mathbb{E}\big[\frac{\pi_{\mathrm{ref}}}{\pi_\theta}-\log\frac{\pi_{\mathrm{ref}}}{\pi_\theta}-1\big].

Proof. Variance. REINFORCE, \nabla\mathbb{E}[r]=\mathbb{E}[r\,\nabla\log\pi], is unbiased for any baseline independent of the action: \mathbb{E}[b\,\nabla\log\pi]=b\,\nabla\!\int\pi=0 . Subtracting b=\mathrm{mean}(r) divides the variance (better than b=0 or a learned baseline). Normalizing by the standard deviation makes the gradient scale invariant across prompts (easy ones: small spreads → amplified; hard ones: damped).

No more critic. Unlike PPO, the baseline comes from the group itself — the value network (and its memory/training) disappears; it is the Monte-Carlo estimation of A(s,a)=Q(s,a)-V(s) by multiple sampling. ∎

RLVR and reasoning (2024-2026) When quality is verifiable (a passing unit test, an exact mathematical answer), the reward no longer needs to be learned: RL with Verifiable Rewards.

GRPO is the engine of DeepSeek-R1: by optimizing verifiable correctness, long chains of thought emerge (self-verification, backtracking, “aha” moments) — the “o1” style.

Self-consistency at inference (Wang et al., 2023): sample n reasonings, answer by majority vote — accuracy climbing at \Theta(\sqrt n)-ish as long as errors are weakly correlated.

Costs: 10× more tokens; recent works regularize length (ch. 10: “Shorter but not Worse”). Exploration (bandits, RL module ch. 4) becomes central: the GRPO group is structured exploration.

Overview SFT (imitate) → RLHF (optimize preferences) → DPO (preferences without RL) → RLVR/GRPO (optimize verifiable truth). A “modern” LLM chains: base → SFT → rejection sampling → DPO/GRPO.

6. Running an LLM: inference

A trained model still has to produce text, one token at a time, under memory and latency constraints. This chapter explains how tokens are chosen (decoding), where the memory goes (the KV-cache), and the three main ways to make serving faster or cheaper without changing the output much: speculative decoding, quantization and smarter batching.

6.1. Decoding: formulas and effects

Definition 6.1 — From greedy to nucleus At each step, logits z over |V|;

  • Temperature: p_i = \dfrac{\exp(z_i/T)}{\sum_j \exp(z_j/T)} — T\to0: argmax (greedy); large T: uniformization;
  • Top-k: truncate to the k best logits then renormalize;
  • Top-p (nucleus): smallest set of tokens with cumulative probability \ge p (adaptive size: wide on an uncertain step, narrow on a deterministic step);
  • Repetition penalty: divide the logit of already emitted tokens (factor 1.1-1.3); min-p: threshold relative to the best token.
Setting Effect on quality Effect on diversity Use
T = 0 (greedy) deterministic, possible repetitions none extraction, code, factual RAG
Moderate T (0.7) + top-p 0.9 fluent, controlled moderate general dialogue
High T (1.0+), top-p 0.95 more hallucinations strong brainstorming, synthetic data

6.2. KV-cache: the memory arithmetic

Proposition 6.2 — Cache memory = \mathcal{O}(n\cdot d), quantified In autoregression, each new token must attend to the keys/values of the whole past — they are cached (prop. 2.4): \text{bytes/token} = 2\,N_{\text{layers}}\,n_{\text{KV}}\,d_{\text{head}}\times \text{precision}.

Llama-3-8B (32 layers, 8 KV heads, 128 dim, fp16) → 128 KiB/token: 8k context ≈ 1 GB, 100k ≈ 12.8 GB, 1M ≈ 128 GB (weights excluded!).

Three ways out: GQA (÷4 here), int8 cache quantization (÷2), and eviction/recomputation (sliding window).

Engineering rule: context length is first a memory bandwidth problem, not a FLOPs problem — hence the techniques of the next sections.

6.3. Speculative decoding: the correction proved

Theorem 6.3 — Speculative decoding (Leviathan et al., 2023) A small model q proposes \gamma tokens; the large model p computes the \gamma distributions in a single forward.

Each proposal y is accepted with probability \min(1, p(y)/q(y)); at the first rejection, one resamples from the normalized residual \mathrm{norm}\big(\max(0,\,p-q)\big).

Then the marginal distribution of each produced token is exactly p — quality unchanged, latency divided by ~2-3 when q\approx p.

Proof. For one token:

  1. acceptance contribution: q(y)\min(1,p(y)/q(y)) = \min(q(y),p(y));
  2. rejection contribution: the total rejected mass equals \sum_x q(x)\big(1-\min(1,p(x)/q(x))\big) = \sum_x \max(0,q(x)-p(x)) = R, and the resampled residual adds R\cdot\frac{\max(0,p(y)-q(y))}{R} = \max(0,p(y)-q(y)).

Total: \min(q,p)+\max(0,p-q)=p. ∎

6.4. Quantization: principles and errors

  • Post-training int8: nearly lossless (batch calibration, per-channel scales); int4: the standard compromise;
  • GPTQ (Frantar et al., 2022): layer by layer, minimize \|Wx-\hat W x\|_2^2 on a calibration set — column-by-column quantization with error compensation on the remaining columns (via the inverse of the Hessian \mathbf{H}=2\mathbf{X}\mathbf{X}^\top);
  • AWQ (Lin et al., 2023): protect the “salient” channels (high activations) with per-channel scaling before quantization — the error is shifted toward weakly active channels;
  • Typical errors: int8 ≈ +0.0-0.1 PPL; well-calibrated int4 ≈ +0.1-0.5 PPL (often imperceptible); below 4 bits, degradation accelerates (2-3-bit quantization = research); in production, always re-validate on your benchmarks, not PPL alone.

6.5. Serving: continuous batching, PagedAttention, costs

  • Continuous batching (vLLM, Orca): schedule at the decoding step — finished sequences leave, new ones enter the same batch; throughput multiplied by ~10-20× vs static batching;

  • PagedAttention (Kwon et al., 2023): the KV-cache split into pages (like virtual memory) — no more fragmentation; sharing of common prefixes (system prompt); ~2-4× memory gain → larger batches;

  • Costs: two regimes — API (on the order of $/M tokens, steadily decreasing) vs on-prem (amortized GPU-hour: an H100 at ~3$/h serving ~2-5k tokens/s on an int4-quantized 8B → a few $/M tokens under heavy load).

    The real cost of an agent = repeated input tokens × history length (ch. 8); the “ML Ops” angle is deepened in the dedicated M2 module.

7. RAG in depth

A model only knows what was in its training data, up to its cutoff date, and cannot cite sources. Retrieval-augmented generation fixes this by fetching relevant documents at query time and placing them in the context; this chapter goes through each stage of such a pipeline and how to evaluate it.

Definition 7.1 — RAG (Retrieval-Augmented Generation) p(y \mid q) \approx p_\theta\big(y \mid q, \mathrm{top}_k\, \mathrm{sim}(e_q, e_d)\big) Index documents by embeddings, retrieve those closest to the prompt, inject them into the context.

Reduces hallucinations, updates knowledge, handles proprietary data without retraining.

7.1. Chunking

  • Fixed with overlap: 256-1024 tokens, stride 10-20%; structural splitting (sections, paragraphs) > blind splitting (cut sentences destroy retrieval);
  • Semantic chunking: cut where the embedding similarity between successive windows drops (topic change);
  • Multi-granularity: index by passages, but return the parent section to the LLM (small-to-big); for structured documents, keep titles/metadata in the chunk (pre-retrieval filters).

7.2. Retrieval: BM25, dense, hybrid — with numbers

Retriever Principle BEIR (NDCG@10, ~18 tasks) Strengths / weaknesses
BM25 probabilistic weighting (NLP ch. 2) ≈ 0.44 on average zero training, exact (lexical matches); misses reformulations
Dense (E5/BGE, …) SBERT embeddings + ANN (FAISS/HNSW) ≈ 0.50-0.52 for the best captures paraphrase; errors on jargon/exact refs, must be indexed
Hybrid + reranker fusion (RRF) then cross-encoder ≈ 0.53-0.55 practical state of the art; reranking cost O(top-100)

Cross-encoder rerankers The bi-encoder scores s(q,d)=\cos(e_q,e_d) separately (indexable); the cross-encoder scores s(q,d)=f_\theta([q\,;d]) jointly — it sees the exact term interaction (mini-attention) but must run on every candidate.

Hence the cascade architecture: dense/BM25 (top-100) → cross-encoder (top-5). Typical gain: +3 to +5 points of NDCG@10.

The “lost in the middle” effect (Liu et al., 2023): even with the right passages, the LLM exploits better those at the beginning/end of the context → reorder the best ones at the extremes.

Definition 7.2 — Vector indexes: flat, IVF, HNSW, PQ Dense retrieval needs the k nearest neighbours of the query embedding among n stored vectors of dimension d.

Flat (exact) search computes all n scores: for n=10^7 and d=768, that is 7.7\times10^{9} multiply-adds per query and 30.7 GB of float32 vectors. Approximate (ANN) indexes give up a little recall for orders of magnitude of speed or memory. Their quality is \mathrm{recall@}k=\frac{\big|\,\text{returned top-}k\;\cap\;\text{exact top-}k\,\big|}{k}, always read against latency (or queries per second) and memory, never alone.

Index Idea Work per query Memory (n=10^7, d=768) Knob

7.3. RAG evaluation

RAGAS-type metrics (Es et al., 2023)

  • Faithfulness: decompose the answer into atomic claims (by an LLM judge); faithfulness = fraction supported by the retrieved context;
  • Answer relevance: the LLM generates candidate questions from the answer — average similarity with the true question;
  • Context precision / recall: are the useful chunks there and well ranked? / does the corpus contain what was missing?

Lab protocol: QA set with reference context (golden context), compare faithfulness with/without reranking, measure the cost (tokens, latency) of each stage.

7.4. GraphRAG and variants

  • HyDE (Gao et al., 2022): generate a hypothetical answer to the question and search with its embedding — the imaginary answer is closer to the documents than the question;
  • GraphRAG: retrieval traverses a knowledge graph (entity-relation extraction by NER/RE — NLP ch. 6; communities-summaries; multi-hop queries; Example 7.3 below); detailed in the Graph ML module ch. 10 — the LLGA heart; Buscaldi’s work (AI-KG/CS-KG, NLP ch. 9) builds exactly such graphs from scientific corpora;
  • Structured queries: text → graph query (graph linearization, see the publications in ch. 10) or SQL (text-to-SQL): the LLM writes the query, the database answers — maximal auditability.

Example 7.3 — GraphRAG by hand: six documents, one multi-hop question Six chunks of about 250 tokens each (invented names); their key sentences are:

  • D1 “Velatinib inhibits the kinase KRX7.”
  • D2 “KRX7 is overexpressed in Moren syndrome.”
  • D3 “Moren syndrome causes joint inflammation, which KRX7 amplifies.”
  • D4 “Velatinib reduces joint inflammation in mice.”
  • D5 “Velatinib was developed by Lab Aster, based in Lyon.”
  • D6 “Lab Aster tested the vaccine VX-2 in Lyon.”

Question: which drug could be relevant to Moren syndrome?

  1. Vector RAG, top-2. The question is closest to D2 and D3, the only chunks that name the disease. D1, D4 and D5, the only chunks that name Velatinib, share no word with the question. The LLM sees no drug: it answers “unknown”, or invents one.
  2. Indexing. An extractor (the relation extraction of NLP ch. 6, or an LLM with a JSON schema) turns each chunk into (head, relation, tail, source) triples: (Velatinib, inhibits, KRX7, D1), (KRX7, overexpressed in, Moren syndrome, D2), (Velatinib, developed by, Lab Aster, D5), and so on. Leiden clustering of the entity graph finds two communities, {Velatinib, KRX7, Moren syndrome, joint inflammation} and {Lab Aster, Lyon, VX-2}, and an LLM writes one summary per community.
  3. Query. Link “Moren syndrome” to its node and expand two hops. Two paths reach a drug: Moren syndrome ← KRX7 ← Velatinib (D2, D1) and Moren syndrome → joint inflammation ← Velatinib (D3, D4). The bridging entities (KRX7, joint inflammation) are in neither the question nor the answer: vector similarity cannot find them, the graph does.
  4. Token cost. Indexing calls the LLM once per chunk (about 400 prompt + 250 chunk + 80 output tokens) and once per community summary (about 300): about 5,000 tokens for a 1,500-token corpus, three times the corpus, against one cheap encoder pass for the vector index. At query time both contexts are about 500 tokens (two chunks, plus about 20 tokens of path for GraphRAG).

GraphRAG moves the cost to indexing. It pays off for multi-hop questions, and for global ones (“which themes does the corpus cover?”) answered from the community summaries; a single-fact look-up does not need it.

Graphs as soft tokens (G-Retriever) Instead of pasting triples as text, G-Retriever (He et al., 2024) first retrieves a small connected subgraph that covers the nodes most similar to the question, by solving a prize-collecting Steiner tree problem.

A GNN (Graph ML ch. 5) encodes this subgraph and its node states are pooled into one vector. A small MLP projector maps that vector into the LLM’s embedding space, where it enters the context as a soft token next to the subgraph written as text.

Only the GNN and the projector are trained (optionally with LoRA adapters on the LLM, ch. 4). It is the same pattern as an image entering a vision-language model (8.2). Developed in Advanced Topics in LLMs ch. 8.

8.2. Multimodality: how an image enters a context

A multimodal LLM leaves the language model unchanged: an encoder turns each image (or sound, or graph) into vectors, and a small projector places them in the context as if they were token embeddings. This section is self-contained; it needs only the transformer block of ch. 2.

Definition 8.2 — Image tokens, CLIP pre-training, projector ViT tokens. A vision transformer cuts an image of side H into P\times P patches, flattens and linearly embeds each one, adds position embeddings and runs the block of ch. 2 without the causal mask. It outputs one vector per patch, (H/P)^2 tokens.

CLIP (Radford et al., 2021) pre-trains such an image encoder together with a text encoder on batches of N (image, caption) pairs. With unit-norm embeddings u_i (image) and v_i (caption), a learned temperature \tau and scores s_{ij}=u_i^\top v_j/\tau, the symmetric InfoNCE loss is \mathcal{L}_{\text{CLIP}}=\frac{1}{2N}\sum_{i=1}^{N}\Big[-\log\frac{e^{s_{ii}}}{\sum_{j}e^{s_{ij}}}\;-\;\log\frac{e^{s_{ii}}}{\sum_{j}e^{s_{ji}}}\Big]. It is a cross-entropy that picks the right caption among N for each image, and the right image among N for each caption.

Projector. A linear map or a two-layer MLP g sends each patch vector z_p to g(z_p)\in\mathbb{R}^{d_{\text{LLM}}}, placed in the context next to the text tokens.

Token counts. LLaVA-1.5 feeds a CLIP ViT-L/14 at 336 px, so (336/14)^2=24^2=576 image tokens: 14 % of a 4,096-token context for one image. Whisper turns 30 s of audio into 3,000 log-Mel frames (10 ms hop); its convolutional stem halves the rate, giving 1,500 encoder vectors (one per 20 ms). Video at one frame per second with 576 tokens per frame costs 34,560 tokens per minute: video models must pool or subsample.

LLaVA’s two stages (Liu et al., 2023). Stage 1, alignment: the vision encoder and the LLM are frozen and only the projector is trained on image–caption pairs, with the next-token loss of ch. 3 on the caption. Stage 2, visual instruction tuning: the projector and the LLM are trained on (image, instruction, answer) conversations with the loss mask of ch. 4, the vision encoder still frozen.

The same recipe (frozen encoder, small projector, next-token loss) plugs in audio through Whisper features and graphs through a GNN (G-Retriever, 7.4). Ex. 12 builds a small version.

  • Video: sampled frames (1–4 per second) plus temporal pooling — the sampling step is a compression choice;
  • Documents: pages as images plus interleaved OCR text (the number 1 enterprise use case — contracts, reports).

9. Evaluation and safety of LLMs

A score on a benchmark is only useful if it measures what we think it measures, and a deployed model must resist misuse. This chapter covers how benchmarks are built and skewed, the biases of LLM judges, hallucinations, attacks on LLM systems, and a statistical test to detect machine-generated text.

9.1. Benchmarks: construction and contamination

Definition 9.1 — MMLU-type benchmark (Hendrycks et al., 2020) Multiple-choice questions (57 subjects for MMLU; variants: MMLU-Pro, GPQA, HELM for multi-faceted evaluation). Two scoring modes: log-likelihood of the options (deterministic, but biased by answer length/frequency) vs generation then extraction (realistic, but prompt- and parsing-dependent).

Rule: always specify the protocol — rankings change with the mode.

Contamination: the measurement that skews everything If the benchmark is in the pre-training data (the web!), the score measures memorization, not competence.

Detection: n-gram overlap (8-13 grams) between questions/training data, canary strings (hidden markers), cloze recall tests.

Remedies: private/rotating evaluations, dynamic question generation, temporal re-splits (post-cutoff questions).

Recent work on this: memorization in fine-tuning and multilingual hallucinations — ch. 9 of the M1 NLP module (Buscaldi’s work: MUCH, memorization prediction).

Statistics of LLM evaluation An accuracy is a proportion: at 80 % on n=1{,}000 items its standard error is \sqrt{0.8\cdot0.2/n}\approx1.3 points. Detecting 80 % → 82 % with two independent test sets (two-sided 5 % test, 80 % power, \bar p=0.81) needs n=\frac{\big(1.96\sqrt{2\bar p(1-\bar p)}+0.84\sqrt{p_1(1-p_1)+p_2(1-p_2)}\big)^2}{(p_2-p_1)^2}\approx 6{,}040\ \text{items per model}, more than the 1,319 test problems of GSM8K.

Paired designs are far cheaper: both models answer the same items, and only the items where they disagree carry information. Let b count the items A gets right and B wrong, c the reverse. McNemar’s test: under H₀ (equal accuracy), b\sim\mathrm{Bin}(b+c,\tfrac12), and for large b+c \chi^2=\frac{(b-c)^2}{b+c}\;\sim\;\chi^2_1 . If the models disagree on 10 % of the items, the same 2-point gap needs about 1,960 items in total.

The paired bootstrap resamples the items with replacement, recomputes acc(A) − acc(B) each time, and reads a 95 % interval from the 2.5 % and 97.5 % quantiles.

Other variance. Sampling seeds, prompt templates and answer parsing move scores by points: report a mean and a spread over at least 3 seeds and several templates.

Many tasks. Comparing on m benchmarks at 5 % each produces false wins. Benjamini–Hochberg sorts the p-values p_{(1)}\le\dots\le p_{(m)} and declares significant the k smallest, k the largest index with p_{(k)}\le kq/m; this controls the false discovery rate at q under independence (Refresher Statistics).

9.2. LLM-as-judge: convenient, but biased

  • Positional bias: the judge prefers the first (or second) answer depending on order — mitigation: evaluate in both orders and average;
  • Verbosity / style bias: long, well-formatted answers are overrated — mitigation: rubrics (explicit criteria), constrained format;
  • Self-preference: a judge favors answers from its own model family — mitigation: judge ensembles, judges trained for calibration (references: MT-Bench, G-Eval);
  • Calibration: a judge score is not a probability — verify on a set where ground truth exists (fraction of judgments matching humans); cheap distilled metrics (FrugalScore, ch. 10) were born exactly from this need.

9.3. Hallucinations

Taxonomy 9.2 Intrinsic: the answer contradicts the source/context (RAG: wrong citation); extrinsic: unverifiable (invented) claims; prompt fidelity: silent disobedience to instructions.

Causes: sampling (temperature), knowledge cutoff, the “always answer” training bias (no learned abstention), sycophancy (telling the user yes).

Mitigations: RAG + verifiable citations (ch. 7), self-consistency (ch. 5), low temperature for factual tasks, abstention training, post-hoc verification by decomposition into claims (the heart of RAGAS “faithfulness”).

9.4. Attacks: jailbreaks and prompt injections

  • Direct jailbreaks: role-play (“DAN”), hypothetical framing, encoding (base64, unicode), multi-turn crescendo — circumventing safety instructions;

  • Indirect injections: the retrieved content (web page, PDF, tool result) contains malicious instructions — the number 1 attack on RAG/agent systems (ch. 7-8);

  • Defense in depth: input/output classifiers (Llama Guard type), spotlighting (delimiting and marking untrusted content), least privilege on tools (the retriever does not write to the database!), prompt/data separation (ch. 1 — special tokens: the same hygiene), human in the loop for irreversible actions.

    No defense is complete — one reduces the attack surface.

9.5. Watermarking

Theorem 9.3 — Statistical watermark (Kirchenbauer et al., 2023) Before each token, hash the prefix → a pseudo-random seed that partitions the vocabulary into “green”/“red” (fraction \gamma, e.g. 1/2); generation penalizes reds. On a text of T tokens containing s_G green ones: z = \frac{s_G - \gamma T}{\sqrt{T\,\gamma(1-\gamma)}} \;\xrightarrow{T\ \text{large}}\; \mathcal{N}(0,1)\ \text{under H}_0 . Reject “human text” if z exceeds the threshold (p-value) — under H1 (marked), z grows like \sqrt T times the introduced bias.

Proof. Under H₀ (unmarked text), each token is green with probability \gamma independently, so s_G\sim\mathrm{Bin}(T,\gamma); the standardized variable tends to the normal (CLT), hence the z-score. The partition depends on the prefix: impossible to remove without the seed.

Limitations (follow-up paper, Kirchenbauer et al. 2023): paraphrasing, truncation, and false positives on short texts — the test is statistical, not deterministic. ∎

9.6. Privacy, memorisation, law and cost

A model can repeat its training data, falls under data-protection and AI law, and spends energy at every token: here is the minimum an LLM engineer must know.

Definition 9.4 — Differential privacy and DP-SGD A randomised training algorithm M is (\varepsilon,\delta)-differentially private if, for all datasets D, D' differing in one example and all sets S of outputs, \mathbb{P}[M(D)\in S]\;\le\;e^{\varepsilon}\,\mathbb{P}[M(D')\in S]+\delta . DP-SGD (Abadi et al., 2016) clips each per-example gradient to norm C, adds Gaussian noise of scale \sigma C to their sum, then averages over the batch \mathcal{B}: \tilde g=\frac{1}{|\mathcal{B}|}\Big(\sum_{i\in\mathcal{B}}g_i\min\big(1,\tfrac{C}{\|g_i\|}\big)+\mathcal{N}(0,\sigma^2C^2I)\Big). A privacy accountant turns the number of steps and the sampling rate into one (\varepsilon,\delta) for the run. The price is per-example gradients and some utility: DP fine-tuning of LoRA adapters is practical, DP pre-training rare.

Memorisation and extraction. Plant a random canary (“my PIN is 4-8-1-5-9-2”) in the training data and rank all candidates of that format by perplexity: its exposure is \log_2 of the number of candidates minus \log_2 of its rank (Carlini et al., 2019), maximal when the model has singled it out. Extraction attacks keep the generations with abnormally low perplexity; on GPT-2 they recovered verbatim training text, names and phone numbers included (Carlini et al., 2021).

Mitigation. A sequence repeated in the corpus is regenerated far more often than a unique one (Kandpal et al., 2022): the MinHash deduplication of 3.1 is a privacy measure too, completed by filtering personal data and DP fine-tuning.

GDPR erasure versus weights. Regulation (EU) 2016/679 (art. 17) gives a right to erasure. Removing a person’s data from trained weights means retraining without it, or machine unlearning, not certified for LLMs today; the European Data Protection Board (Opinion 28/2024) holds that a model trained on personal data is anonymous only after a case-by-case assessment. Personal data kept in the RAG index rather than in the weights can be deleted like a database row.

The EU AI Act (Regulation (EU) 2024/1689, in force since 1 August 2024). Its obligations for providers of general-purpose AI models apply from 2 August 2025 (art. 53): technical documentation, information for downstream providers, a policy to respect EU copyright law (including text-and-data-mining opt-outs) and a public summary of the training content. Models above 10^{25} training FLOP are presumed to carry systemic risk (art. 51) and must also be evaluated adversarially, report serious incidents and be secured (art. 55).

Transparency (art. 50, applicable from 2 August 2026 in the adopted text). People must be told when they interact with an AI system, and providers of systems that generate text, audio, images or video must mark the outputs in a machine-readable, detectable way, robust “as far as this is technically feasible”. The green-list watermark of 9.5 is one candidate for text; its weakness to paraphrase is exactly the open problem.

These dates are those of the Regulation as adopted in 2024. The “Digital Omnibus on AI”, Regulation (EU) 2026/1744 of 8 July 2026, amended them. It gives generative systems placed on the market before 2 August 2026 until 2 December 2026 to mark their outputs (art. 50(2)), and moves the high-risk requirements to December 2027 and August 2028. The ethics seminar page gives the full timeline; check the consolidated text on EUR-Lex before relying on a date.

Energy per 1,000 tokens. At batch size 1, each decoded token reads all the weights from GPU memory (6.2): for an 8B model in fp16 (16 GB) on an H100 SXM (about 3.35 TB/s), at least 4.8 ms, about 210 tokens/s. At the board’s 700 W this gives about 3.4 J per token, 0.9 Wh per 1,000 tokens — an order of magnitude, not a measurement.

Int4 weights divide it by about 4, and batching shares each weight read among requests until the KV-cache reads of Prop. 6.2 dominate. Measure (CodeCarbon, nvidia-smi) and add the data-centre overhead.

Q2 (4 pts) — From the KL-penalised objective to DPO. For a fixed prompt x, show that the maximiser of \mathbb{E}_{y\sim\pi}\big[r(x,y)\big]-\beta\,\mathrm{KL}\big(\pi\,\|\,\pi_{\mathrm{ref}}\big) is \pi^\star\propto\pi_{\mathrm{ref}}\,e^{r/\beta}. Proof. Marking points

  • Rewrite the objective as -\beta\,\mathrm{KL}\big(\pi\,\|\,\pi_{\mathrm{ref}}e^{r/\beta}/Z\big)+\beta\log Z(x) (1.5 pts).
  • The KL vanishes at \pi^\star=\pi_{\mathrm{ref}}e^{r/\beta}/Z(x) (0.5 pt).
  • Invert: r(x,y)=\beta\log\frac{\pi^\star(y\mid x)}{\pi_{\mathrm{ref}}(y\mid x)}+\beta\log Z(x) (1 pt).
  • In \sigma(r^+-r^-) the term \beta\log Z(x) is the same for both responses and cancels, which gives Thm 5.2 with \pi_\theta in place of \pi^\star (1 pt). Common error: letting Z depend on y.

Q3 (3 pts) — The Chinchilla optimum. Using C=6ND and D^\star\approx20N^\star (Thm 3.1), compute N^\star and D^\star for C=5.76\times10^{23} FLOP. Llama-3-8B was trained on 15T tokens: compute its compute budget and its tokens per parameter, and explain why it is far from the optimum on purpose.

Proof. Marking points

  • C=6N\cdot20N=120N^2, so N^\star=\sqrt{C/120}\approx6.9\times10^{10} (69B) and D^\star\approx1.4\times10^{12} tokens, the Chinchilla model itself (1 pt).
  • Llama-3-8B: C=6\times8\times10^{9}\times15\times10^{12}=7.2\times10^{23}\ \text{FLOP}, and 1,875 tokens per parameter; the Chinchilla optimum for that budget is about 77B (1 pt).
  • The law minimises training loss at a fixed training budget; a small, over-trained model is cheaper at inference, which dominates the total cost (1 pt). Common error: calling Llama-3-8B “undertrained”.

Q4 (3 pts) — Speculative decoding. (a) Show that one step of Thm 6.3 outputs a token distributed according to p. (b) With acceptance rate \alpha=0.75, \gamma=3 draft tokens and a draft step costing c=0.1 target forward, compute the expected number of tokens per target forward and the speed-up.

Proof. Marking points

  • Acceptance contributes \min(q,p) and the resampled residual \max(0,p-q); their sum is p (1.5 pts).
  • Expected tokens per round (Ex. 10): \frac{1-\alpha^{\gamma+1}}{1-\alpha}=\frac{1-0.75^{4}}{0.25}\approx2.73 (1 pt).
  • Speed-up 2.73/(1+\gamma c)=2.73/1.3\approx2.1 (0.5 pt). Common error: 1/(1-\alpha)=4, which ignores the truncation at \gamma.

Q5 (3 pts) — Watermark test. A detector with green fraction \gamma=0.25 reads T=200 tokens and counts 70 green ones. Compute z (Thm 9.3) and decide at the one-sided 1 % level. A user keeps only the first 50 tokens, with the same green fraction: what happens?

Proof. Marking points

  • The z-score: z=\frac{70-50}{\sqrt{200\times0.25\times0.75}}=\frac{20}{6.12}\approx3.27 (1 pt).
  • One-sided p-value \approx5\times10^{-4}<0.01: reject “human text” (1 pt).
  • With the same green fraction, z scales like \sqrt{T}: 3.27\times\sqrt{50/200}\approx1.63, below even the 5 % threshold 1.645, so the mark is no longer detected (1 pt). Common error: using \gamma=1/2 in the variance.

Q6 (3 pts) — Is model A better than model B? Both models answer the same 1,000 questions: A is right on 812, B on 790; A is right and B wrong on 62 items, the reverse on 40. A colleague runs an unpaired two-proportion test and finds p\approx0.22. Run the right test and conclude.

Proof. Marking points

  • The design is paired, so McNemar’s test applies (9.1) (1 pt).
  • \chi^2=(62-40)^2/(62+40)=484/102\approx4.75, p\approx0.03 with one degree of freedom (exact binomial test: 0.037): significant at 5 % (1 pt).
  • The unpaired test treats the 750 items both models get right and the 148 both get wrong as noise; only the 102 discordant items carry information (1 pt). Common error: concluding “no difference” from the unpaired test.

8. Agents, multimodalité et perspectives

8.1. La boucle ReAct, avec une trace réelle

Définition 8.1 — Agent LLM (ReAct, Yao et al., 2022) Boucle perception-action (module RL ch. 7) : Thought (raisonner) → Action (appeler un outil) → Observation (lire le résultat) → itérer, jusqu'à Final Answer. Le LLM décide quand et comment agir ; les outils bornent ses capacités (calcul exact, recherche, code).

Planification et multi-agents
  • Tree-of-Thoughts (Yao et al., 2023) : chercher un arbre d'étapes de raisonnement, évaluer les nœuds par le LLM, backtracker — au-delà de la chaîne linéaire (CoT) ;
  • Multi-agents : orchestrer un DAG d'agents spécialisés (planifieur → retrieveur/codeur → vérificateur → synthèse), frameworks type LangGraph ; chaque agent = un LLM avec prompt/outils/mémoire propres ; motifs : superviseur, débat, générateur-critique. Lien RL ch. 7 : la décomposition des politiques ; lien Graph ML : l'orchestration est un graphe exécuté ;
  • Mémoire : scratchpad (le contexte courant), mémoire vectorielle (RAG sur les échanges passés), mémoire épisodique (résumés structurés des sessions), mémoire de travail externe (fichiers) — c'est le RAG ch. 7 réutilisé sur soi-même.
Évaluer (et facturer) un agent Benchmarks : GAIA (assistant généraliste), SWE-bench (tickets GitHub réels), WebArena/tau-bench (outils et dialogues). Métriques : taux de réussite de bout en bout, coût en tokens par tâche (un agent multi-tours consomme facilement 10⁵-10⁶ tokens — d'où l'importance du ch. 6 : petit modèle pour les pas routiniers, gros pour les décisions), sûreté (taux d'injection subies — ch. 9). L'évaluation des agents est un sujet de recherche ouvert — et un débouché majeur du master.

8.2. Multimodalité : comment une image entre dans un contexte

  • Vision : un encodeur ViT découpe l'image en patchs 16×16 → un token par patch (module Deep Learning ch. 5 pour ViT) ; un projecteur (MLP ou Q-Former) aligne ces tokens sur l'espace d'embedding du LLM → l'image devient « du texte » dans le contexte (schéma LLaVA) ; l'encodeur est souvent pré-entraîné en contrastif image-texte — l'espace latent commun rappelle CLIP (module Multimodal GenAI ch. 5) ;
  • Audio : spectrogrammes mel → encodeur (style Whisper) → tokens ; la sortie « transcription + style » alimente le LLM (assistant vocal = pipeline encodeur → LLM → synthèse) ;
  • Vidéo : images échantillonnées (1-4/s) + pooling temporel — coût en tokens très élevé : le choix du pas d'échantillonnage est un choix de compression ;
  • Documents : pages = images + texte OCR entrelacés (le cas d'usage entreprise n°1 — contrats, rapports).

8.3. Perspectives

  • Architectures alternatives : hybrides attention+SSM (ch. 2), xLSTM, transformers à latence (déraisonnement des diffusion LMs — cf. ch. 10) ; le transformer n'a pas le monopole ;
  • Small Language Models & distillation : le compromis qualité/coût/latence gouverne le déploiement entreprise (ch. 6) ;
  • Recherche ouverte : raisonnement (ch. 5), mémoire longue durée, LLMs sur graphes (linéarisation vs embeddings structurés — ch. 10.3 et module Graph ML/Advanced GNN), évaluation (ch. 9).
Lab final Construire un assistant documentaliste : corpus technique → pipeline RAG (chunks, embeddings, reranking) ; mesure de la fidélité (citations vérifiables) contre le RAG vectoriel vs une version GraphRAG ; rapport coûts (tokens, latence). Extension : version agentique (ch. 8) qui choisit entre retrieval vectoriel et requête de graphe selon le type de question.

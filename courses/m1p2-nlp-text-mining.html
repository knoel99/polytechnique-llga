0. Rappels : espace vectoriel et probabilités

Rappels L3 mobilisés
  • Espaces vectoriels : base, dimension, projection ; similarité cosinus \(\cos(u, v) = \frac{u^\top v}{\|u\|\|v\|}\) ; l'ACP (module ML) pour réduire des dimensions de vocabulaire ;
  • Probabilités conditionnelles et Bayes : \(\mathbb{P}(c \mid d) \propto \mathbb{P}(d \mid c)\,\mathbb{P}(c)\) — le classifieur Naive Bayes en découle directement ;
  • Chaînes de Markov et programmation dynamique (Refresher CS) : l'algorithme de Viterbi (ch. 6) est un Bellman sur une chaîne ;
  • Vraisemblance et MLE : word2vec et LDA sont des maximisations de vraisemblance (par SGD pour l'un, par EM/variational pour l'autre).

1. La chaîne de traitement texte

Pipeline standard Texte brut → nettoyage (HTML, casse, accents) → tokenisation (découpe en unités : mots, sous-mots, caractères) → normalisation (stemming racine brut / lemmatisation forme canonique ; mots vides) → représentation (ch. 2-4) → modèle (ch. 5-7) → évaluation.
  • Tokenisation : espaces + ponctuation en Europe ; mais le chinois n'a pas d'espaces, l'allemand compose — d'où les tokeniseurs sous-mots (BPE, WordPiece, Unigram ; SentencePiece) des LLMs : vocabulaire fixe (~32k-128k), toute chaîne décomposable ;
  • Mots vides (stopwords) : à retirer pour le text mining classique, à garder pour les transformers (la syntaxe compte) ;
  • N-grammes : séquences de \(n\) tokens ; « New York » (bigramme) ≠ « New » + « York » ; la capture des collocations est cruciale en entreprise (référentiels produits, entités).
import re
from collections import Counter

doc = "Le graphe de connaissances relie les entités; le graphe, il les relie bien."
tokens = re.findall(r"\w+", doc.lower())          # tokenisation naive
print(Counter(tokens).most_common(5))

# n-grammes
bigrams = zip(tokens, tokens[1:])
print(Counter(bigrams).most_common(3))

2. Sac de mots et TF-IDF

Définition 2.1 — Sac de mots (BoW) Un document = un vecteur de comptages sur le vocabulaire \(V\) (ordre perdu) : \(d \in \mathbb{N}^{|V|}\). Matrice documents × termes \(\mathbf{X} \in \mathbb{N}^{n \times |V|}\) — extrêmement creuse (représentation sparse, cf. Refresher CS).
Définition 2.2 — TF-IDF $$\mathrm{tfidf}(t, d) = \mathrm{tf}(t, d) \times \log\frac{n}{\mathrm{df}(t)},$$ \(\mathrm{tf}\) = fréquence du terme dans le document, \(\mathrm{df}\) = nombre de documents contenant le terme. Pénalise les termes omniprésents, valorise les termes discriminants.
Géométrie des documents Chaque document devient un point de \(\mathbb{R}^{|V|}\) ; on mesure des similarités (cosinus), on classe (Naive Bayes, SVM), on regroupe (k-means). La limite du BoW : sac = aucun ordre ni sémantique ; « le chat mange la souris » ≈ « la souris mange le chat ». Les embeddings (ch. 3) et les transformers (ch. 7) y répondent. 
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

corpus = ["graphe de connaissances entreprise",
          "réseau de neurones profond",
          "graphe neuronal et réseau d'entreprise"]
X = TfidfVectorizer().fit_transform(corpus)      # matrice sparse (3, |V|)
print(cosine_similarity(X).round(2))             # docs 0 et 2 les plus proches

3. Word embeddings

word2vec (Mikolov et al., 2013) : distributionnel, 2013 Hypothèse distributionnelle : « un mot est caractérisé par la compagnie qu'il fréquente ». Skip-gram : maximiser $$\sum_{t} \sum_{c \in \text{fenêtre}(t)} \log p(w_c \mid w_t), \qquad p(w_c \mid w_t) = \frac{\exp(z_{w_c}^\top z_{w_t})}{\sum_{v \in V}\exp(z_v^\top z_{w_t})}$$ — softmax sur tout le vocabulaire trop coûteux ⇒ negative sampling : binaryer « \(w_c\) est-il un vrai contexte ? » contre \(k\) négatifs tirés de la loi unigramme \(p^{3/4}\). CBOW : l'inverse (prédire le mot par le contexte).
  • GloVe : factoriser la matrice de co-occurrence (log) ; fastText : sous-mots (n-grammes de caractères) — gère les fautes et les mots rares ;
  • Propriétés émergentes : relations linéaires \(\vec{\text{roi}} - \vec{\text{homme}} + \vec{\text{femme}} \approx \vec{\text{reine}}\) ; biais sociétaux hérités des corpus (interroger et corriger — lien M2 fairness) ;
  • Document embeddings : moyenne pondérée des mots (SIF), doc2vec, ou encodeurs transformer (ch. 7) ; c'est le cœur du RAG vectoriel (indexer = embedder ; retrouver = plus proches voisins cosinus).
Texte ↔ graphe, l'autre pont LLGA word2vec sur des marches aléatoires donne DeepWalk/node2vec (module Graph ML, ch. 3) ; réciproquement, un Graph of Words (nœuds = mots, arêtes = co-occurrence) permet du text mining par outils de graphes (travaux du professeur du cours) : la boucle mots ↔ graphes est un signature du master.

4. Topic models

Modèle 4.1 — LDA (Blei et al., 2003) Processus génératif : pour chaque document \(d\), tirer un mélange de thèmes \(\theta_d \sim \mathrm{Dir}(\alpha)\) ; pour chaque position, tirer un thème \(z \sim \theta_d\) puis un mot \(w \sim \varphi_z\), \(\varphi_z \sim \mathrm{Dir}(\beta)\). Inférence : variational Bayes ou Gibbs sampling — la vraisemblance est intractable (thèmes latents). Deux rappels s'y connectent : EM du module ML (variantes) ; chaînes de Markov (échantillonneur).
  • LSA : SVD tronquée de la matrice TF-IDF (l'ACP du texte) ; topics = directions latentes ;
  • Usage entreprise : cartographier des corpus (tickets support, revues, contrats), détecter des thématiques émergentes ; les topic models sur graphes (TopicSBM, travaux du cours) étendent l'idée aux réseaux ;
  • Évaluation : perplexité (mais mal corrélée à l'humain : rappel important du text mining !), cohérence de topics (NPMI, \(C_v\)).

5. Classification de textes

Naive Bayes (baseline obligatoire) $$\hat c = \arg\max_c \log \mathbb{P}(c) + \sum_{t \in d} \log \mathbb{P}(t \mid c)$$ avec l'estimation « à la Laplace » \(\mathbb{P}(t \mid c) = \frac{n_{t,c} + 1}{n_c + |V|}\). L'hypothèse d'indépendance (fausse !) marche étonnamment bien en grande dimension creuse — toujours la première baseline d'un projet texte.
  • Régression logistique / SVM linéaire sur TF-IDF : l'état de l'art « classique » avant 2018, encore redoutable sur petits corpus ;
  • Réseaux : CNN de phrases (Kim, 2014), BiLSTM ; puis fine-tuning de transformers (ch. 7) ; le choix dépend de la taille du corpus (courbes d'apprentissage : transformers > tout à partir de ~1k exemples étiquetés) ;
  • Métriques spécifiques : macro-F1 en classes déséquilibrées, matrice de confusion par intention (chatbots).
from sklearn.pipeline import make_pipeline
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.datasets import fetch_20newsgroups
from sklearn.metrics import f1_score

train = fetch_20newsgroups(subset="train", remove=("headers","footers","quotes"))
test  = fetch_20newsgroups(subset="test",  remove=("headers","footers","quotes"))
pipe = make_pipeline(TfidfVectorizer(min_df=3, ngram_range=(1,2), sublinear_tf=True),
                     LogisticRegression(C=10, max_iter=2000))
pipe.fit(train.data, train.target)
print("macro-F1 :", f1_score(test.target, pipe.predict(test.data), average="macro"))

6. Séquences : NER, HMM, CRF

Définition 6.1 — Étiquetage de séquences Attribuer à chaque token une étiquette : POS (catégorie grammaticale) ou NER (entités nommées : PER, ORG, LOC…) en BIO (« Begin/Inside/Outside ») : « Kim » = B-PER, « Noel » = I-PER. Le NER est la porte d'entrée de la construction de graphes de connaissances (extraction d'entités + relations).
Algorithme 6.2 — HMM et Viterbi HMM : états cachés (étiquettes), émissions \(\mathbb{P}(w_t \mid z_t)\), transitions \(\mathbb{P}(z_t \mid z_{t-1})\). Le meilleur chemin d'étiquettes se calcule par programmation dynamique : $$\delta_t(z) = \max_{z'} \big[\delta_{t-1}(z')\, \mathbb{P}(z \mid z')\big]\ \mathbb{P}(w_t \mid z)$$ — \(\mathcal{O}(T K^2)\) au lieu de \(\mathcal{O}(K^T)\) ; exactement Bellman (module RL, ch. 2) sur une chaîne de Markov (rappel L3). Les CRF conditionnent sur toute la séquence (features arbitraires ; transitions apprises) — longtemps l'état de l'art NER.
Aujourd'hui Les transformers étiquettent token par token (per-token softmax + décodage BIO) ; les librairies spaCy et transformers(ner pipeline) donnent l'état de l'art en quelques lignes ; le TP construit un extracteur entités-relations qui alimente le mini-GraphRAG du module Graph ML.

7. Transformers pour le NLP

  • Architecture : reprise du module Deep Learning (attention multi-tête, encodeur/décodeur) ; ici on l'applique ;
  • BERT (encodeur bidirectionnel) : pré-entraînement masked language modeling (15 % des tokens masqués) ; fine-tuning par tâche ; GPT (décodeur causal) : causal LM, génération ; T5 : tout en text-to-text ;
  • HuggingFace : pipeline, AutoTokenizer, AutoModel, Datasets ; fine-tuning avec Trainer ; embeddings de phrases (sentence-transformers) pour le RAG vectoriel ;
  • Coût : distillation (DistilBERT), quantification — un modèle 66M params vs GPT-4 : le compromis performance/coût est un critère d'ingénieur ; approfondi en M2 (LLMs, ML Ops).
from transformers import pipeline

classifier = pipeline("text-classification",
                      model="distilbert-base-uncased-finetuned-sst-2-english")
print(classifier("Graph RAG is a game changer for enterprise search."))

ner = pipeline("ner", aggregation_strategy="simple")
print(ner("Michalis Vazirgiannis teaches at Ecole Polytechnique."))

8. Text mining en entreprise

  • Veille et classification : classification de tickets, e-mails, contrats ; déduplication, similarité de documents ;
  • Extraction : entités, relations, dates, montants — vers des graphes de connaissances (le pipeline NER + relation extraction alimente GraphRAG) ;
  • Résumé : extractif (sélection de phrases : TextRank = PageRank sur graphe de phrases !) vs abstractif (génération) ;
  • Question-réponse et RAG : retriever (BM25 — le descendant direct du TF-IDF — et/ou dense ;hybrid search) + générateur ; le module de référence reste le M2 LLMs ;
  • Le français et le multilingue : corpus, modèles multilingues (mBERT, XLM-R) ; juridique/français = difficultés spécifiques (travaux du cours).
Projet fil rouge Pipeline complet de veille : corpus de 500 articles → nettoyage/tokenisation → TF-IDF + LDA (thématiques) → classification supervisée fine-tunée → NER + relations → export vers le mini-GraphRAG (module Graph ML) ; évaluation à chaque étage (perplexité, cohérence, macro-F1, F1 NER).

Exercices

  1. TF-IDF papier. Sur 3 documents donnés, calculer à la main la matrice TF-IDF (log naturel) du vocabulaire réduit, puis la similarité cosinus de chaque paire ; vérifier avec TfidfVectorizer (attention à la normalisation L2).
  2. Naive Bayes. Dériver l'estimateur de \(\mathbb{P}(t \mid c)\) par MLE, montrer le problème des probabilités nulles et justifier le lissage de Laplace ; implémenter et comparer à MultinomialNB sur 20 Newsgroups.
  3. Skip-gram. Écrire la perte du negative sampling : \(\log \sigma(z_c^\top z_t) + \sum_{k}\mathbb{E}_{w_k \sim p_n}\log \sigma(-z_{w_k}^\top z_t)\) ; implémenter sur un petit corpus et vérifier que les mots de contexte proche ont des embeddings proches.
  4. Viterbi. Implémenter Viterbi pour un POS tagger jouet (2 étiquettes, vocabulaire de 5 mots) ; vérifier l'optimalité contre l'énumération exhaustive ; complexité \(\mathcal{O}(TK^2)\).
  5. Analogies. Avec des embeddings pré-entraînés (GloVe fr), tester 10 analogies et mesurer le taux de réussite ; discuter les biais (métiers/genre) et une mitigation simple (projection neutre).
  6. Comparatif. Sur une tâche de classification de votre corpus : Naive Bayes / TF-IDF+SVM / CamemBERT fine-tuné — tracer accuracy vs taille d'entraînement (50, 200, 1000, tout) et commenter le crossover.
